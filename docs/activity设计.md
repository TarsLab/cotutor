# activity 文件:一个功能一个文件,家长看得懂、Claude Code 查得了(设计稿,2026-10-12)

> 调研见《wip/activity调研.md》(2026-10-12):方向印证;它第五节「要改的」已并进本稿(拍板 1–5)。
>
> 样板:你说我画。材料:`agents/chinese-tutor.md` 的「你说我画」一节、`src/paint/prompt.ts`、`cotutor.json paint`、`cards/tutor/card.md`、`src/lib/card-guards.ts`、《首页设计.md》§3.3 §六、《wip/你说我画设想.md》。拍板在文末(2026-10-12 拍完)。

## 一、为什么

孩子开不了头:他说不清要什么,说话又多半是语音,一开口就容易跑偏。头得家长来开:家长在首页做好一个一个功能,孩子点进去就能用。首页老师卡的「按钮 + 讲法」已经是这条路,缺的是**功能本身看不见**:

- 「你说我画」「看图说话」两套完整流程写在语文老师文件的正文里(140 行里占了 100 行)。家长在首页只看到一个按钮,看不出点了以后走哪套流程,只能靠老师从讲法里猜。
- 讲生字的时候,这两套流程也一直在语文老师的系统提示里。再加几个 activity,老师越来越糊。
- 给工具人的那段字(画家、认字、口语课)硬写在 TS 里或孤零零躺在 cotutor.json:`src/paint/prompt.ts` 拼版式与分幅,`src/talk/prompt.ts` 整段写死,`dictation.prompt` 看得到但看不出它管哪一步。
- 家长填的参数混在讲法的人话里(「这周学了:播种、睡大觉……」),应用查不了,老师也可能漏看。
- 应用定的规矩(一个话题最多两张、一天几张)只写在老师的提示里,老师看不到剩几张。

要的是:**一个功能一个文件**。家长打开就知道这个功能怎么走、自己要填什么、老师和画家各收到什么;Claude Code 能照着写、能查。

## 二、activity 文件是什么

- **activity** = 孩子从首页一个按钮进去的一种做法:你说我画、看图说话、听写、口语课……
- 一个 activity 一个文件,归一位老师,放在**老师的家**里:workspace `agents/<老师>/activities/<名>.md`;仓里 `agents/<老师>/activities/<名>.md`,init 拷进去。
  <!-- 为什么放老师的家(会话 cwd)而不放 .claude/agents/:Claude Code 会把 .claude/agents/ 下的 md 都当老师文件读;qwen 读 cwd 外的文件要人同意,没人答就挂(CLAUDE.md「坑」)。 -->
- 出厂件:拷贝不链,hash 记 shipped.json,upgrade 只换没改过的,改过的报 diff。和老师文件一样。
- 老师文件只留人设与这一科;某个 activity 的做法全在 activity 文件里。

### 2.1 一个文件好几个读者:按节分

《写提示词.md》§二说「一个文件只对一个读者说话」。activity 文件要破这条:把功能拆成好几份文件,家长就又看不全了。改成**一节只对一个读者说话,标题就是读者**:

| 节 | 谁读 | 怎么到它手里 |
|---|---|---|
| `## 家长填的` | 家长、应用 | 应用解析,首页按钮照它填 |
| `## 应用算的` | 家长看;老师收到算好的值 | 应用解析,值进上下文包 |
| `## 应用拦的` | 家长看;应用照着拦 | 应用解析,一行一条,规则名是应用认得的 |
| `## 老师怎么带` | 有脸的老师 | 剥掉注释,话题第一条放进 `<cotutor-activity>` |
| `## 画家收到什么`(工具人一位一节) | 工具人 | 应用填上插槽,原样交出去 |
| 别的节(孩子看到什么、记下什么) | 只给家长看 | 应用不读 |

- 应用只认上面几个标题,别的节随家长写,不会进模型。
- 老师那节照旧守《写提示词.md》的全部规矩;注释剥掉不占 token。

### 2.2 两种字,两种语法

| | 给老师的 | 给工具人的 |
|---|---|---|
| 是什么 | 人话,LLM 读 | 一段模板,模型照着出东西 |
| 参数怎么进去 | **不插值**。参数作为结构化的一段放进上下文包的 `activity:`,正文按名字提它(「`词` 是这周学的词」) | **插槽** `{{分幅}}`,应用填 |
| 条件 | `{{有 词}}` … `{{/有}}`:这次填了 `词` 才留这段 | 没有 |
| 循环 | 没有 | 没有;列表由插槽一次填好 |

- `{{有 …}}` 就是现在按卡留段的那个(`src/lib/card-guards.ts`),多认一种:写的是参数名(汉字)就看参数填没填,写的是卡的种类(英文小写)就看这位老师有没有这种卡。
- 老师的字不插值:「有词就先念出来」这种分支 LLM 读人话就会,插进去反而让家长读不懂;值走上下文包,老师在哪都看得到原样。
- 工具人的字要插值:文生图模型不读 YAML,也不会「看情况」。插槽只能用这一节的工具人认得的名字(画家:`版式` `角色` `分幅`),应用查。

孩子编一个故事,语文老师一问一答帮他说清楚,画家照着画成一张四格连环画。图是奖励,要教的是把一件事说清楚。

## 家长填的

```参数
词: 词表,可空 —— 这周学的词。填了就是「我来出题」,画出来是一道看图说话题
最多画: 数,缺省 2,1 到 4 —— 一个话题最多画几张(第二张起是孩子改了一句重画)
```

## 应用算的

```应用算
还能画: 数 —— 这个话题还能画几张:最多画减已画,再和今天剩的(cotutor.json paint.daily)取小的
缺: 字 —— 上一张画图卡没画的原因(下面「应用拦的」哪一条没过);画了就是空的
```

## 应用拦的

老师写了 `paint` 卡,应用先查这几条,都过了才交给画家。没过就不画,下一条告诉老师缺哪条;孩子那边停在分好的几幅。删掉一行就不拦那一条。

```应用拦
连说过一遍 —— 话题里有一张三行以上的 read 卡,孩子在它后面开过口
还能画 —— 还能画大于 0
```
<!-- 为什么应用拦:「说没说清楚」应用判不了,只能靠老师;「整段放出来、孩子连着说过」看板书就知道。图花钱、画了收不回,能查的不靠老师自觉。《wip/activity调研.md》§五 -->

## 老师怎么带

第一句:说画家来了,想听一个故事。请孩子先说是谁的故事。

1. 问开头:谁、在哪里、什么时候。整个故事问一次。
2. 问经过:先、接着、最后。三到四件事,一件一幅。
3. 问结尾:结果怎样,心里怎么想。
4. 每节放一张 `read` 卡,只写孩子这次说的,整理成一句。
5. 画家要知道的都说清楚了,整段放一张 `read` 卡,一行一句。请孩子看着连起来说一遍。
6. 孩子说完一遍,和孩子分幅。放一张 `read` 卡,一行一幅:「第 1 幅:……」。
7. 写一张 `paint` 卡。讲稿说「画家开始画了」,末句问孩子猜画家会怎么画。

{{有 词}}
### 我来出题

`activity:` 里的 `词` 是这周学的词,孩子是出题人,画好的就是一道看图说话题。

- 第 1 步之前:先把词念出来,请孩子挑三四个。
- 第 6 步之后:一个词落到一幅,问孩子看图的人怎么看得出来。
- 写 `paint` 卡之前:请孩子说要问看图的人什么,你整理成题干,念给孩子听。
- 一幅最多落两个词。画不出来的词(突然、终于)只放进 `词:`。
{{/有}}

### 画家要知道的七件事

谁、在哪里、什么时候;先、接着、最后;每幅一件事;看得出来;前后对得上;说得通;结果和心情。

### 怎么问

- 用画家的口吻问:「画家想知道……」。不说「你没说清楚」。
- 前后对不上:把孩子说过的两句并排放一张 `read` 卡,问画家画哪个。
(……其余照搬,略)
<!-- 为什么用画家的口吻:二年级说不清楚,多半是不知道听的人缺什么;画家是个具体的读者,追问就不是评判。《wip/你说我画设想.md》§1.1 -->

### 画好以后

- 你看不到图。`cards:` 里那一行说画好了没有。
- 画好了:问孩子「哪里和你想的一样?哪里不一样?」。别说图上画了什么。
- 孩子想改:`还能画` 不是 0,就改那一句,再写一张 `paint` 卡。
- `缺` 是 `连说过一遍`:说「画家想再听你连着讲一遍」,把整段的 `read` 卡再放一次。孩子讲完,再写 `paint` 卡。
- `还能画` 是 0,或没画成:说「画家今天画累了,明天再画」。请孩子看着分好的几幅,自己讲一遍。

收:问完「哪里一样、哪里不一样」,或请孩子自己讲完一遍,就夸一句他讲的故事,收。

## 四、首页按钮怎么写

老师卡多一种按钮行 `activity <名> [孩子看到的字]`,字不写就用 activity 名。参数照 `讲法:` 的样子挂在下面,一行一个:

````markdown
```tutor chinese-tutor
activity 你说我画

activity 你说我画 我来出题
词: 播种、睡大觉、满满、一筐、羞愧
讲法: 他上周把「羞愧」说成「害羞」,落到幅上时问一句
```
````

- 解析器(`src/cards/tutor.ts`)是纯函数,不读文件:`activity` 按钮下面所有 `名字: 值` 行都收进 `params`,`讲法` `留到` 照旧。
- 对不对由首页检查(`src/server/home.ts`)读 activity 文件查:activity 在不在、参数认不认、必填的填没填、类型对不对。和现在查老师在不在、话题在不在同一级。
- `讲法:` 照旧有:这一次的特别交代。activity 是「怎么做」,讲法是「这次注意什么」。
- props 加一种:`{ kind: 'activity', label,activity: string, params: Record<string, string>, brief?, until? }`。`params` 和 `brief` 一样,下发孩子前剥掉。
- **参数跟着话题走**:孩子点进来那一刻的参数与讲法,记进这个话题第一条消息的 `via`。家长中午改了「词」,上午那个话题接着聊还是上午的词;改了只管以后点进来的。现在「接着今天的话题」每次从 published.json 现查讲法,要改成读 via。
<!-- 为什么:Copilot Studio 里旧会话一直用旧配置,直到说「重新开始」,两份配置混着用更糟。一个话题从头到尾一份参数,老师不会前后说两套词。《wip/activity调研.md》§三 -->

### 4.1 收着的规则

`## 应用拦的` 里的规则名是应用认得的,一条一个纯函数,输入是这个话题的板书与孩子的消息,输出过或没过。第一批:

| 规则 | 什么时候查 | 过的条件 |
|---|---|---|
| `连说过一遍` | 板书里有 `paint` 卡,交给画家前 | 这个话题里有一张三行以上的 `read` 卡,它所在那一节之后孩子发过一条消息 |
| `还能画` | 同上 | `还能画` 大于 0 |

- 写在 activity 里、应用不认得的规则名,`activity check` 报错。规则只能加在代码里,家长只能删、不能编。
- 没过:这张卡照「没画成」处理(孩子端停在分好的几幅,不说没画成),`paint.json` 记哪条没过;下一条的 `activity.state.缺` 写那条规则名,`cards:` 那一行也写「没画:还没连着说一遍」。
- 没过的不占 `还能画`,也不占一天的张数。

## 五、老师收到什么

孩子点进来的那一条(带 via 的),上下文包多一段,后面接 activity 正文:

```yaml
cotutor:
  at: 2026-10-12T16:20
  ...
  home:
    button: 我来出题
    brief: "他上周把「羞愧」说成「害羞」,落到幅上时问一句"
  activity:
    name: 你说我画
    params:
      词: [播种, 睡大觉, 满满, 一筐, 羞愧]
    state:
      还能画: 2
---
<cotutor-activity name="你说我画">
(「老师怎么带」那节:剥了注释、按 {{有 词}} 裁过)
</cotutor-activity>
我来出题
```

- 同一话题后面几条:`activity:` 每条都带(`state` 会变,画了一张 `还能画` 就少一);`<cotutor-activity>` 只第一条带,后面同守则一样写「未变」。
- `activity:` 放在上下文包 `cotutor:` 段的最后,键序固定(name、params、state,参数照「家长填的」的顺序)。
<!-- 为什么放最后、键序固定:提示词缓存按前缀命中,键序一变后面全失效;目标和剩几张放在离孩子的话最近的地方,老师不容易忘。《wip/activity调研.md》§五 -->
- `params` 取自话题第一条的 via(见四),不是现在的 published.json。
- 话题记下自己的 activity:消息的 `via` 加 `activity: <名>`。顺手给第二个问题用(「接着刚才的」按 activity 分开,见八)。
- 守则(cotutor-tutor)加一行:「有 `<cotutor-activity>`,照它带;它和老师文件不一样,以它为准。」
- `上下文包.md` 加 `activity:` 一行(skills.test 会逼着加)。

### 5.1 卡跟着 activity 走

`paint` 卡从语文老师的 `cards` 里拿掉,只在 `你说我画` 的话题里有(activity 头上的 `cards: read paint` 是「这个 activity 要用的卡」,应用拿老师的卡并上它)。

- 好处:孩子在新话题里随口说「我想画画」,老师没有 `paint` 卡,不会不问清楚就画;画是奖励,只在 activity 里给。
- 系统提示与工具不动:板书写法照旧按老师的卡预载(`BOARD_GUIDE_IN_SYSTEM`);activity 多出来的卡,它的 `card.md` 剥了 expect 跟在 `<cotutor-activity>` 后面,只第一条带。
<!-- 为什么不改系统提示:缓存的顺序是工具 → 系统提示 → 消息,系统提示每个话题不一样,后面全部重算;加减工具也一样。《wip/activity调研.md》§二、§五 -->
- 板书写法里 `{{有 paint}}` 那几段(如有)这时裁掉了;实现时查 `cards/板书怎么写.md` 有没有只对 paint 的段,有就挪进 `cards/paint/card.md`。

## 六、怎么检查

`cotutor activity check [<老师> [<名>]]`,纯函数,离屏可测:

| 查什么 | 例 |
|---|---|
| 头上:`name` 与文件名一样,`cards` 里每种都是认得的卡 | `cards: read paintt` → 没有 paintt 这种卡 |
| 「家长填的」每行能解析,类型认得 | `词: 词组` → 类型只有 字、词表、数、日期、课包 |
| `{{有 X}}` 的 X 是参数或卡,配对 | `{{有 单词}}` → 没有「单词」这个参数 |
| 正文提到的卡,在老师的卡并上 activity 的卡里 | 正文写 `tianzige`,两边都没有 |
| 工具人那节的插槽认得、要的都在 | 删了 `{{分幅}}` → 画家收不到分幅 |
| 「应用算的」每个名字应用都会算 | `今天画了: 数` → 应用不算这个 |
| 「应用拦的」每条规则应用都认得,用到的卡这个 activity 有 | `说清楚了` → 没有这条规则 |
| 正文写了第一句和收 | 没有「第一句:」「收:」两行 |

- `tests/activity.test.ts`:出厂的每个 activity 过 check;`{{有}}` 裁出来的老师正文和期望一致(像 card.md 的 expect)。
- `cotutor doctor`:老师文件里还留着某个 activity 的那节(老 workspace 改过语文老师文件、upgrade 没换掉)→ 报「两处都有,删老师文件里那节」。
- `cotutor pack <老师> --activity <名> --<参数> <值>`:看老师实际收到什么。家长改完先看这个。
- Claude Code:cotutor-home 技能会列 activity、照「家长填的」填参数、写完跑 home check;改 activity 本身归 cotutor-tune,改完跑 activity check、pack,再跑这个 activity 的回归。tune 只做小改动,不整篇重写。

### 6.1 每个 activity 一套回归
