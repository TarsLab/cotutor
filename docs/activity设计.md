# activity 文件:一个功能一个文件,家长看得懂、Claude Code 查得了

> 2026-10-12 起。activity = 孩子从首页一个按钮进去的一种做法:你说我画、看图说话、小课堂看完怎么聊、口语课、听写。一个 activity 一个文件,放在老师的家 `agents/<老师>/activities/<名>.md`;出厂八份(语文:你说我画、看图说话、小课堂、听写;英语:口语课、小课堂、听写;数学:小课堂),init 拷进 workspace。有「老师怎么带」的,孩子点进来的那个话题,系统提示就是它,不读老师文件;没有的(听写)不起老师的会话。
>
> 代码:形状 `src/schema/activity.ts`;解析、检查、裁段、填插槽、拦法 `src/lib/activity.ts`;拷贝、升级、check `src/cli/activities.ts`;应用算的与画图前的拦 `src/server/activity-state.ts`;系统提示与上下文包 `src/server/runner.ts`(`activityParts`、`attachActivity`);首页按钮 `src/cards/tutor.ts`、`src/lib/home.ts`、`src/server/home.ts`;回归 `src/lib/activity-eval.ts`、`src/server/activity-eval.ts`;工作台的 activity 页 `src/server/dev-activities.ts`。测试 `tests/activity.test.ts`、`tests/activity-flow.test.ts`(假 CLI 全流程)、`tests/dev-activities.test.ts`。调研见《wip/activity调研.md》(本机草稿,不进 git)。拍板在文末。
>
> 正文 2026-10-22 收成现状;原稿(设想、调研、分期)原文在 git 历史 facdd86。

## 一、为什么

孩子开不了头:他说不清要什么,说话又多半是语音,一开口就容易跑偏。头得家长来开:家长在首页摆好按钮,孩子点进去就能用。按钮后面的做法要看得见,原来看不见:

- 一套流程(你说我画、看图说话)写在语文老师文件的正文里,家长看不出按钮点了走哪套;讲生字时它也在系统提示里,漏进别的话题。
- 给工具人的字(画家、认字)硬写在 TS 里或躺在 cotutor.json;家长填的参数混在讲法的人话里,应用查不了。
- 能查的规矩(一个话题最多几张、连着说一遍才画)只写在老师的提示里,全靠老师自觉。

所以**一个功能一个文件**:家长打开就知道这个功能怎么走、自己要填什么、老师和工具人各收到什么;Claude Code 能照着写、能查。

## 二、activity 文件是什么

- 一个 activity 一个文件,归一位老师,放在**老师的家**:workspace `agents/<老师>/activities/<名>.md`;仓里同一个相对位置,init 拷进去。
  <!-- 为什么放老师的家(会话 cwd)而不放 .claude/agents/:Claude Code 会把 .claude/agents/ 下的 md 都当老师文件读;qwen 读 cwd 外的文件要人同意,没人答就挂(CLAUDE.md「坑」)。 -->
- 出厂件:拷贝不链,hash 记 shipped.json 的 `activities`(键「老师/名」),upgrade 只换没改过的,改过的报 diff;`cotutor upgrade --force <老师>/<名>` 回出厂,原文留 .bak。和老师文件一样。
- 头上平铺 `name`、`description`、`cards`(这个 activity 要用的卡,空格隔开);不起老师的写 `page:`(见十二)。
- 老师文件只留人设与这一科,管自由话题;某个 activity 的做法全在 activity 文件里。

### 2.1 一个文件好几个读者:按节分

《写提示词.md》§二说「一个文件只对一个读者说话」。activity 文件破这条:把功能拆成好几份文件,家长就又看不全了。改成**一节只对一个读者说话,标题就是读者**:

| 节 | 谁读 | 怎么到它手里 |
|---|---|---|
| `## 家长填的` | 家长、应用 | ```` ```参数 ```` 围栏一行一个;首页按钮下面的参数行照它查、补缺省 |
| `## 应用算的` | 家长看;老师收到算好的值 | ```` ```应用算 ```` 围栏;值每条现算,进上下文包 `activity.state` |
| `## 应用拦的` | 家长看;应用照着拦 | ```` ```应用拦 ```` 围栏一行一条,规则名是应用认得的 |
| `## 老师怎么带` | 有脸的老师 | 剥掉注释、按参数与卡裁段,就是这个话题的系统提示 |
| `## <工具人>收到什么` | 工具人(画家、认字) | ```` ```<工具人> ```` 围栏是模板,应用填插槽,原样交出去;```` ```<工具人>不要 ```` 可选 |
| 别的节(孩子看到什么、记下什么、怎么挂……) | 只给家长看 | 应用不读 |

- 应用只认上面几个标题,别的节随家长写,不会进模型。同一个标题写两节,check 报错。
- 独占一行的 `<!-- … -->` 是给人看的,递给模型前剥掉(`src/lib/human-notes.ts`)。出厂的每份头上一段「给人看」:谁读、能改什么、改完怎么验;起老师的还写记忆在哪。
- 老师那节照旧守《写提示词.md》的全部规矩。

### 2.2 两种字,两种语法

| | 给老师的 | 给工具人的 |
|---|---|---|
| 是什么 | 人话,LLM 读 | 一段模板,模型照着出东西 |
| 参数怎么进去 | **不插值**。参数放进上下文包的 `activity:`,正文按名字提它(「`词` 是这周学的词」) | **插槽** `{{分幅}}`,应用填 |
| 条件 | `{{有 词}}` … `{{/有}}`:这次填了 `词` 才留这段 | 没有 |
| 循环 | 没有 | 没有;列表由插槽一次填好 |

- `{{有 …}}` 就是按卡留段的那个(`src/lib/card-guards.ts`),多认一种:写的是参数名就看参数填没填,写的是卡的种类(英文小写)就看这个话题有没有这种卡;写几个名字要都有才留。
- 老师的字不插值:「有词就先念出来」这种分支 LLM 读人话就会,插进去反而让家长读不懂;值走上下文包,老师在哪都看得到原样。
- 工具人的字要插值:文生图模型不读 YAML,也不会「看情况」。插槽只能用这位工具人认得的名字(画家:`版式` `角色` `分幅`;认字:`格式`),一个都不能少;工具人那节不能用 `{{有}}`。

## 三、样板:你说我画

整份在 `agents/chinese-tutor/activities/你说我画.md`,头上 `cards: read paint`。家长填 `词`(可空,填了就是「我来出题」)、`最多画`(可空,不填不限);应用算 `还能画`、`缺`,拦 `连说过一遍`、`还能画`(见 4.1);老师那节是人设、第一句、七步、`{{有 词}}` 包着的「我来出题」、怎么问、画好以后、收;画家那节是 `{{版式}}`、几行画风、`{{角色}}`、`{{分幅}}`,```` ```画家不要 ```` 交给百炼当反向提示词。

这一份顺手解掉了几件事:

- 「你说我画」「我来出题」两个按钮是**同一个 activity**,差一个 `词`。
- 词从讲法的人话里挪出来,应用能查、老师看得到原样。
- 「一个话题最多几张」从老师自觉变成应用算好的 `还能画`;老师看得到剩几张,说法不会错。
- 「连说一遍才画」应用也拦;「说没说清楚」仍归老师。

## 四、首页按钮怎么写

老师卡多一种按钮行 `activity <名> [孩子看到的字]`,字不写就用 activity 名。参数照 `讲法:` 的样子挂在下面,一行一个:

````markdown
```tutor chinese-tutor
activity 你说我画

activity 你说我画 我来出题
词: 播种、睡大觉、满满、一筐、羞愧
讲法: 他上周把「羞愧」说成「害羞」,落到幅上时问一句
```
````

- 解析器(`src/cards/tutor.ts`)是纯函数,不读文件:`activity` 按钮下面 `名: 值` 的行都收进 `params`,`讲法` `留到` 照旧。props 是 `{ kind: 'activity', label, activity, params, brief?, until? }`;`params` 和 `brief` 一样,下发孩子前剥掉。孩子那边它就是个开场按钮。
- 对不对由首页检查读 activity 文件查(`src/lib/home.ts`、`src/server/home.ts`):文件在不在、文件自己有没有要改的、参数认不认、要填的填没填、类型对不对。孩子端只出这几样都过了的按钮(《首页设计.md》拍板 30)。
- `讲法:` 照旧有:这一次的特别交代。activity 是「怎么做」,讲法是「这次注意什么」。
- 小课堂按钮看完照这位老师的 `小课堂` 聊,下面写一行 `activity: <名>` 就照那个,参数用缺省(见十一)。口语课不在首页挂(见七)。
- **参数跟着话题走**:孩子点的那一刻按 activity 文件解析、补缺省、按类型转,记在话题第一条消息的 `activity` 字段(`{ name, params }`),话题后面每条都照它带。家长中午改了「词」,上午那个话题还是上午的词。跨天「接着」一个 activity 话题,新会话沿用它的 activity 与参数。
- 没有首页也能起:`cotutor send <老师> --activity <名> --param '名=值;名=值'`(`cotutor pack` 同样的旗标干跑)。
<!-- 为什么跟着话题走:一个话题从头到尾一份参数,老师不会前后说两套词;两份配置混着用更糟。 -->

### 4.1 收着的规则

`## 应用拦的` 里的规则名是应用认得的(`ACTIVITY_GATES`),一条一个纯函数(`gatePasses`),输入是这个话题的消息与应用算好的值,输出过或没过。现在两条:

| 规则 | 什么时候查 | 过的条件 |
|---|---|---|
| `连说过一遍` | 老师写了 `paint` 卡,交给画家前 | 这一轮之前有一节放过三行以上的 `read` 卡,它后面孩子开过口(点继续、交答案不算) |
| `还能画` | 同上 | `还能画` 大于 0;家长没填「最多画」就不限,照过 |

- 写在 activity 里、应用不认得的规则名,`activity check` 报错。规则只能加在代码里,家长只能删、不能编。
- 在画图队里现查(`src/server/activity-state.ts` 的 `paintGate`),同一轮第二张看得到第一张已经在画。
- 没过:这张卡照「没画成」处理(孩子端停在分好的几幅,不说没画成),`paint.json` 记 `gate:<规则>`;下一条的 `activity.state.缺` 写那条规则名,`cards:` 那一行也写为什么没画(如「没画:孩子还没看着整段连着说一遍」)。
- 没过的不占 `还能画`。

## 五、老师收到什么

做法在系统提示里(见九点五),值在上下文包里。activity 话题的每一条,`cotutor:` 段里多两样(`cotutor pack <老师> --activity <名> --param '…'` 看全):

```yaml
cotutor:
  at: 2026-10-12T16:20
  activityGuide: "已在你的系统提示里(这个话题的 activity,照它带)"
  ...
  home:
    button: "我来出题"
    brief: "他上周把「羞愧」说成「害羞」,落到幅上时问一句"
  activity:
    name: "你说我画"
    params:
      "词":
        - "播种"
        - "羞愧"
      "最多画": 2
    state:
      "还能画": 2
      "缺": ""
```

- `activity:` 每条都带,`state` 每条现算(画了一张,`还能画` 就少一)。
- `activity:` 放在 `cotutor:` 段的最后,键序固定(name、params、state,参数照「家长填的」的顺序)。
<!-- 为什么放最后、键序固定:提示词缓存按前缀命中,键序一变后面全失效;剩几张这种每条会变的,放在离孩子的话最近的地方,老师不容易忘。 -->
- `params` 取自话题第一条记的那份(见四),不是现在的 published.json。
- 守则(cotutor-tutor)写着:做法在系统提示里,有 `<cotutor-activity>` 照它带;`references/上下文包.md` 讲 `activity`、`activityGuide` 两行。
- 实时的嘴(《实时老师设计.md》)不拿 activity 的做法,只接话、照念讲稿;做法只递给脑(老师 CLI)。
- 退路:运行时模板既没有 `{systemBody}` 也没有 `{agentsFile}`(别的 CLI),activity 进不了系统提示,就照老师文件起,「老师怎么带」裁好放进话题第一条的 `<cotutor-activity>`,`activityGuide` 写文件路径;同一话题后面几条没改过写「未变」。

### 5.1 卡跟着 activity 走

`paint` 卡不在任何老师的出厂 `cards` 里,只在「你说我画」头上的 `cards: read paint` 里。

- 孩子在新话题里随口说「我想画画」,老师没有 `paint` 卡,不会不问清楚就画;画是奖励,只在 activity 里给。
- activity 话题里老师的卡 = activity 头上的 `cards` 加 `text`,不并老师的;板书写法只讲这几种(写到 `.cotutor/board/<老师>-<hash>.md`),守则里按卡裁的段也按它。
- 走退路时,卡是老师的并上 activity 的;老师没有的那几种,写法跟在 `<cotutor-activity>` 后面(「这个 activity 多用的卡」)。

## 六、怎么检查

`cotutor activity check [<老师> [<名>]]`,纯函数(`lintActivity`),离屏可测,带行号,分「要改」与「提醒」:

| 查什么 | 例 |
|---|---|
| 头上:`name` 与文件名一样、有 `description`,`cards` 里每种都是板书的卡 | `cards: read paintt` → 不是板书的卡 |
| 「家长填的」每行能解析,类型认得;不叫 `讲法` `留到`、不和卡同名;缺省、范围对得上类型 | `词: 词组` → 类型只有 字、词表、数、日期、课包 |
| 「应用算的」每个名字应用都会算,类型对 | `今天画了: 数` → 应用只会算 还能画、缺 |
| 「应用拦的」每条规则应用都认得 | `说清楚了` → 没有这条拦法 |
| `{{有 X}}` 的 X 是参数或卡,配对 | `{{有 单词}}` → 不是参数,也不是卡 |
| 正文写的「`` `x` 卡 ``」,在老师的卡并上 activity 的卡里 | 正文写 `tianzige` 卡,两边都没有 |
| 老师那节有人设(以「你是」开头的一句)、`第一句:`、`收:` | 没有「收:」那行 |
| 工具人认得;插槽认得、要的都在;不用 `{{有}}` | 删了 `{{分幅}}` → 画家收不到分幅 |
| `page:` 认得;写了 `page:` 就不要「老师怎么带」 | `page: dictation` 又写了老师那节 |

- 既没有「老师怎么带」也没写 `page:`:只提醒一句(这个 activity 不起老师)。
- `tests/activity.test.ts`:出厂的都过 check;画家那段的画风和 `PAINT_PROMPT_DEFAULT`、认字那段和 `DICTATION_PROMPT_DEFAULT` / `_EN_DEFAULT` 一字不差。
- `cotutor doctor`:每份一行(出厂 / 改过 / 可升级 / 几条要改);老师文件里还留着同名那节(老 workspace 改过老师文件)→ 报两处说法会打架。
- `cotutor pack <老师> --activity <名> --param '…'`:看老师实际收到什么,不起模型。
- 工作台 `/dev` 的 activity 页:看、改、边改边查、和出厂比、恢复出厂(《工作台设计.md》第四节)。
- Claude Code:cotutor-home 列 activity、照「家长填的」填参数;改 activity 本身归 cotutor-tune,一句一条地改、先给 diff,改完跑 check 与回归。
<!-- 为什么不让 LLM 整篇重写:LLM 写的 agent 文件反而让结果变差、成本涨两成以上(HumanLayer 引 ETH 的研究)。 -->

### 6.1 每个 activity 一套回归

check 只查文件写得对不对,查不了老师带得好不好。activity 旁边放一份例子 `<名>.例子.md`,和 activity 一起出厂,check 不把它当 activity。出厂三份:你说我画(五个例子)、看图说话(四个)、数学的小课堂(三个)。

- 一个 `## ` 一个例子:孩子心里的故事、人设、写死的几句、照片或先看的课、参数(同首页按钮)、最多轮、几条判。
- 判只看板书(讲稿与卡),应用就能判,不再请模型;认得的判在 `src/lib/activity-eval.ts` 的 `GRADERS`(出不出画图卡、每节末句是问句、并排、放课里一段……)。
- 两层:
  - `pnpm test` 里假老师、假孩子跑(`tests/activity-flow.test.ts`):只验管道(注入、拦、state 刷新、eval 落盘),不花钱。
  - `cotutor activity eval <老师> <名> [--runs n] [--only <例子>]`:真老师 + 模拟孩子(千问的对话模型,缺省 `qwen3.8-flash`)多轮,画家是假的;一个例子缺省跑三次,次次都过才算过;落 `evals/`,不进孩子的对话、不写记忆。花钱,改 activity 正文时手跑。
- 例子从真跑的失败里攒:家长端看到一次跑偏,就记成一个例子。
<!-- 为什么三次都过:孩子面前的老师一次跑偏就是一次跑偏,看的是每次都对,不是平均对。Anthropic《Demystifying evals for AI agents》的 pass^k。 -->
- 改「老师怎么带」,这一套绿了才算改完。

## 七、出厂的 activity

| activity | 老师 | 家长填的 | 应用算的 / 拦的 | 老师怎么带 | 工具人 | 从哪进 |
|---|---|---|---|---|---|---|
| 你说我画 | 语文 | 词、最多画 | 还能画、缺 / 连说过一遍、还能画 | 有 | 画家 | 首页 `activity 你说我画` |
| 看图说话 | 语文 | 无 | 无 | 有 | 无 | 首页 `activity 看图说话`,或小课堂按钮下面 `activity: 看图说话` |
| 小课堂 | 语文、数学、英语各一份 | 无(哪堂课由按钮定) | 无 | 有 | 无 | 首页 `小课堂 <课包> <字>`,看完开口 |
| 口语课 | 英语 | 口语单、打电话几分钟、家长的话 | 无 | 有 | 无 | 口语课页「先热身,再打电话」 |
| 听写 | 语文、英语各一份 | 无 | 无 | 没有,不起老师(`page:`) | 认字 | 首页的 `dictation <老师>` 卡、老师卡上常驻的「拍照听写」 |

- 口语课:口语课页(`/talk`)拍一页、读出口语单、孩子改好,交给英语老师的实时页跑这个 activity(`src/server/talk-run.ts`);口语单来自那份 `talk.json`,打电话几分钟、家长的话来自 cotutor.json 的 `talk.minutes`、`talk.note`。见《口语课实时设计.md》。
- 听写没有「老师怎么带」,文件就只有给家长看的几节和认字(见十二)。家长读到的形状一样,不硬造一份提示词。

## 八、和「接着刚才的」的关系

话题记下自己从哪个入口进来(`src/lib/home.ts` 的 `resumeKey`):小课堂按课包,activity 按名字(参数不比),新话题按钮或没有按钮进来的算自由话题。首页老师卡上没有应用加的「接着刚才的」,每个按钮进去都是新话题:

## 十一、小课堂搬成 activity(2026-10-13)

小课堂按钮 `小课堂 <课包> <字>`,孩子先看完课再开口;看完怎么聊,在这位老师的 `agents/<老师>/activities/小课堂.md`。

### 11.1 形状

- **一位老师一份**:语文、数学、英语(卡里有 `lecture` 的三位),各写各的人设。卡是这位老师讲解用的几种加 `lecture`:语文 `read choice tianzige lecture`,数学 `choice canvas lecture`,英语 `read choice word lecture`。记忆照拍板 14,如 `记忆/数学老师·小课堂.md`。
- **按钮不变**(要先看完、首页要查课包,和普通 activity 按钮不一样)。没写 `activity:` 行的,看完照这位老师的 `小课堂` 起;写了的照写的那个。看完开口那条起,整个话题都按这个 activity。
- **家长填的、应用算的、应用拦的**:都没有。课的事实(课名、每句的时间和原话、看的情况、画过的几处)应用照旧放进上下文包的 `lecture:`。
- **老师怎么带**:先接他这句、对着他画的地方说,课里讲过的别再讲一遍,要讲道理就放课里一段。各科的差别在人设一句和一两条(数学:入口文件说没学的方法别用)。

### 11.2 守则

- 守则(cotutor-tutor)里「孩子刚看完小课堂」那段搬进了三份 `小课堂.md`;表格里 `lecture:` 那行留着,「怎么用」写「看完怎么聊在你的系统提示里」。`## 想要小课堂`(老师在自由话题里跟家长要一堂课)留在守则。
- 这位老师没有 `小课堂.md`:首页检查报要改,孩子端小课堂按钮不出。

### 11.3 回归

- 例子多三栏:`课:`(课包或视频的 id)、`看:`(停过几次)、`画:`(一行一处:时刻和画的地方盖着什么,原样给老师;以前的 `圈:` 照认)。课要在 workspace 的 `bundles/` 或 `lectures/` 里;出厂的数学例子用「13 减 8,怎么拆」那份(`2026-09-18-po13-jian-8`)。
- 判:`放课里一段`、`一节最多一段`、`说到: X`。「别把课再讲一遍」判不了,靠 replay 看。

## 十二、听写搬成 activity(2026-10-13)

听写不起老师的会话:孩子在 `/dictation` 页上听、写、自己对,认词交给百炼视觉模型。所以它的 activity 文件没有「老师怎么带」,只有给家长看的几节和一个工具人「认字」。它要老师的脸(按钮在这位老师的牌上,念词用他的音色 `tutors.<老师>.voice`,没配就提示叫家长,不念浏览器合成声),所以照样归一位老师:语文、英语各一份 `听写.md`。

### 12.1 形状

- 头上 `page:` 写了就不起老师,没有「老师怎么带」、第一句、收。认得的页在 `ACTIVITY_PAGES`:`dictation`(`/dictation`)、`dictation-en`(英文单词 `/dictation?lang=en`)。
- 节:「这周的词」「要再练的」只给人看;「认字收到什么」交给视觉模型;孩子看到什么、记下什么。
- 「认字」的插槽只有 `{{格式}}`:回什么格式应用接(`src/dictation/recognize.ts` 的 `FORMAT` / `FORMAT_EN`),家长改字不会把解析改坏。

### 12.2 入口

入口没变:首页上家长设的这周的词(`dictation <老师>` 卡),和老师卡上常驻的「拍照听写」。认词的要求每次现读 workspace 里头上写着这一页的那份听写 activity「认字收到什么」(按老师排第一份);没有就照出厂的(`DICTATION_PROMPT_DEFAULT` / `_EN_DEFAULT`)。cotutor.json 只留 `dictation.model`。和画家那节一样,工具人那节是真读的(`fillSlots`)。

### 12.3 回归

没有老师,不用 `activity eval`;认字照旧靠 `tests/dictation.test.ts`,工具人的例子没做(见十)。
