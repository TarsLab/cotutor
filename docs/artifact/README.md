# 协议设计稿

给开发者看、提议的设计稿。放的是协议类的东西:页面上谁画什么、叠在哪层、什么时候收,孩子按下去会怎样。这类规则没有现成的验证办法,对不对要孩子真用起来才看得出,所以先摆出来让大家改。

一份设计稿一个目录,里面一页 HTML(浏览器直接打开,不依赖仓库里的代码),要核实的东西附上脚本。

| 设计稿 | 讲什么 |
| --- | --- |
| [页上记号](页上记号/规范.html) | 一节课的页上:老师和孩子的记号(刷、圈、划、遮、盖、孩子的笔)、层级、什么时候退下、浮层、认出页上的田字格和填空让孩子写 |
| [册与开场](册与开场/规范.html) | 课本、练习册、作业本当成一「册」:目录、上一章下一章、记住翻到哪;进来老师不先开口,等孩子先说;课本 activity 合并、作业本按天攒、首页竖版卡 |
| [书架](书架/规范.html) | 每位老师一个书架:课本和家长放的科普书;PDF、EPUB、照片怎么转成同一种样子(认字、封面、目录),孩子首页一本一张卡,家长端怎么放、怎么整理(样稿 https://claude.ai/artifact/QQJY12McnohWQ5F7a1PW6G) |

## 怎么提议

- 每条规则都有编号(`P1`、`C2`、`R3.4`…),每条标着现状、改样子、提议、待定。提议时说编号、碰到的情况(哪一课、哪一页、孩子做了什么)和你想怎么改。
- 拿不准的放进页里的「待讨论」(`Q` 开头),写清几个选项和推荐哪个。
- 页上的样张是画出来的,不是截图。课本页、教材截图不进仓库(教材只在家长的 vault 里)。

## 定下来以后

规则定了、代码照着做了,就搬进对应的 `docs/dev/` 那篇(那里写现在是什么样),设计稿里那条改标「现状」。整份都做完、没什么可议的了,就从这里删掉,历史在 git 里。
