A流程

cotutor 只做量得准的事:读文字层、量格子、出页图、检查、存。哪几行是一块、是什么、叫什么,由模型看图看字定。

现状改一课

  1. cotutor第一次用到这一册时,规则整册出一份(.cotutor/textbooks/zones/)
  2. 模型和家长说要改哪几课、多久,等点头
  3. cotutorpull --lesson:草稿 + 候选(千分比的框)+ 页图
  4. 模型在草稿上改,从候选里抄框
  5. cotutorcheck → preview → push 进 vault

提议整册初始化

  1. cotutorprep:整册的 book.md,每页一份页面数据 + 页图(D)
  2. 模型先定整册:每页是什么页、页名、样式表各是什么(A2)
  3. 模型一课一课写分块,字行写行号,不抄坐标(P6)
  4. cotutor一课写完就 check → preview → push,孩子马上能用;进度记下
  5. 模型全册完了交一份报告

D3.1纵坐标、缩进、字号、空都用 pt。和字号同一个单位,空 25 对 16 号字就是一行半,模型一眼能比。页眉的水印和页底那行裁掉以后从顶算(同 bookCut)。提议

D3.3一行里空出一个字宽以上写 ␣,隔开的每一截有自己的号(L4.1),一截能单独成块。提议
D3.4加点的字用 〈〉 括起来(F1)。注音不进字里,单列一行「注音」,点读和念法照旧从索引取。提议
D3.5并排的小字(泡泡、图里的字)单独一行,标「并排」,不打断旁边那一列的空。提议
D3.6页上的图只记位置(画图指令里图的变换矩阵,不解图),写成空里的一行「图 I0」。模型认插图块不用自己量。待核实
D3.7能写的格、表格、小方框照现在的候选列(C0…、T0…),写成一张表,不再另出 candidates.json。提议
D3.8同一份数据也写一份 <页名>.data.json,模型写脚本量图时直接读。提议

D4 · 索引不算协议

.cotutor/textbooks/<指纹>.json 照旧是运行时的缓存:每个字的框给点字、拼音、点读用,一整册一个文件,读得快。它不给人看、不给模型看,格式随索引版本变,谁也不该依赖。模型要的东西都在页面数据里,一页一份。提议

K从孩子的角度怎么分

一块 = 孩子会单独点着说「念给我听」、或老师会说「看这里」的东西。分到这里就停。

K1 · 粒度

编号规则
K1.1不再往下拆的:孩子不会单独点的(一行里并排的几个短语、一个词)、拆了老师也不会单独叫的。提议
K1.2要拆的:一题里有几问的,一问一块(数学最常见);一首诗一句一块(孩子跟着读);诗、泡泡、注释各自一块,不混进旁边的题。提议
