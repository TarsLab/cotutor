# 在 iPad / iPhone 上用孩子端

> 把家里的 iPad 或 iPhone 接到 Mac 上跑着的 cotutor:签一张证书、让设备信任它、用地址打开、加到主屏幕变全屏。
> **每台设备都要独立做一遍**——iPad 上弄好了不代表 iPhone 就能用。
> 只想知道日常怎么用的看《家长手册.md》,改代码的看《开发者手册.md》。

## 0. 为什么要这么麻烦

孩子端的「按住说话」用的是浏览器的语音识别,浏览器只在 **HTTPS** 页面上给麦克风权限。局域网里没有真域名,所以用 [mkcert](https://github.com/FiloSottile/mkcert) 给这台 Mac 自签一张证书,再让 iPad / iPhone 信任签它的那个根证书。

装的是**只属于这台 Mac 的开发用根证书**,信任它只等于信任这台 Mac 自己签出来的证书,不会让别人的网站变可信。`rootCA-key.pem`(私钥)留在 Mac 上,任何时候都不要传给别人。

不配证书也能用,只是孩子只能打字,不能按住说话。

## 1. 先把两个信息记下来

在 Mac 上:

```sh
hostname                 # 主机名,形如 <主机名>.local
ipconfig getifaddr en0   # 局域网 IP,形如 192.168.x.x
```

端口在 workspace 的 `cotutor.json` 里(`server.port`),出厂是 **5180**。

下面统一写成 `<局域网 IP>` 和 `<端口>`。

## 2. 在 Mac 上签证书(只做一次)

```sh
brew install mkcert
mkcert -install
cotutor cert
```

`cotutor cert` 会打印证书位置、覆盖的主机名,以及根证书 `rootCA.pem` 的路径。它签的是**这台机器**:主机名、`<主机名>.local`、当前所有局域网 IP、`localhost`、`127.0.0.1`。证书是机器级的,放在 `~/.config/cotutor/certs/`,几个孩子的 workspace 共用同一张。

想直接在访达里定位根证书:

```sh
open "$(mkcert -CAROOT)"
```

> 路径里带空格,在终端里引用它一定要加引号。

签完重启服务:

```sh
cotutor serve
```

它会打印几个 `https://…` 地址,后面要用。

## 3. 把根证书装到设备上

把 `rootCA.pem` 传到 iPad / iPhone——隔空投送最快,用邮件、"文件"App、iCloud 云盘也行。

设备上收到后:

1. 打开 **设置**,顶部会多出一条 **已下载描述文件**,点它(没看到就去 设置 › 通用 › **VPN 与设备管理** 里找)
2. 右上角 **安装**,按提示输密码,再 **安装**
3. 装完在 设置 › 通用 › VPN 与设备管理 里能看到一条 `mkcert <用户名>@<主机名>`

不同 iOS 版本的文案略有出入,但路径大体是这两处。

## 4. 打开信任开关(最容易漏的一步)

**装好描述文件不等于信任它。** 还要手动开一个开关:

> 设置 › 通用 › **关于本机** → 划到最底 → **证书信任设置** → 把 `mkcert <用户名>@<主机名>` 的开关**打开**

这一项只有在装了根证书描述文件之后才会出现;找不到它,就说明第 3 步没真装到这台设备上。

这个开关**每台设备各管各的**。iPad 上打开过,iPhone 上还得再打开一次。

## 5. 打开网页:用 IP,别用 `.local`

在 Safari 里打开:

```
https://<局域网 IP>:<端口>/
```

地址栏没有警告、显示锁头,就对了。

**为什么不用 `https://<主机名>.local:<端口>/`**:主机名走 mDNS 解析,同一个名字会同时解析出 IPv4 和 IPv6 好几个地址,有些设备优先挑了 IPv6 那条,而那条路在家用路由器下不一定通——表现就是一直转圈,最后报「服务器停止响应」。同一个 Wi-Fi 里,iPad 挑中了能通的、iPhone 挑中了不通的,是很常见的事。证书里 IP 也签了,直接用 IP 最省事。

## 6. 加到主屏幕:全屏

在 Safari 里打开孩子端之后:

> 顶部 **分享** 按钮 → **添加到主屏幕** → 添加

以后从桌面那个图标进来就是全屏的,没有地址栏也没有工具栏,孩子按不到别的网页,地址也不用再输第二次。图标是应用自己画的一张橙色小卡片,名字取 `cotutor.json` 里的 `title`。

改了 `title` 之后桌面上已有的图标不会跟着变——删掉重加一次即可。

留在 Safari 里不加主屏幕的话做不到真全屏,最多是地址栏左边的页面菜单里「隐藏工具栏」。

## 7. 麦克风:要授权,而且要授权两次

第一次按住说话会弹窗问麦克风权限,允许即可。

注意**主屏幕图标打开的独立窗口和 Safari 是两套权限**,在 Safari 里允许过,从桌面图标进去还会再问一次。

识别全在设备本地的浏览器里做,服务端不接收也不保存任何声音。

## 8. 什么时候要重做

| 发生了什么 | 要做什么 |
|---|---|
| 路由器给 Mac 换了局域网 IP | Mac 上重跑 `cotutor cert`,重启 `cotutor serve`,设备上把主屏幕图标删掉按新地址重加。**根证书不用重装** |
| 换了 Wi-Fi / 家里换了路由器 | 同上 |
| 多了一台 iPad / iPhone | 只做第 3、4、5、6 步(证书不用重签) |
| 换了一台 Mac | 从第 2 步全部重来,设备上要装新 Mac 的根证书 |
| 改了 `cotutor.json` 的 `title` | 删掉主屏幕图标重加一次 |
| 根证书到期(mkcert 签 10 年) | 重跑 `mkcert -install` 与 `cotutor cert`,设备上重装 |

## 9. 不对劲时

| 看到什么 | 什么意思 | 怎么办 |
|---|---|---|
| 「不安全」「此连接非私人连接」 | 网络**是通的**,TCP 已经连上,只是根证书在这台设备上没被信任 | 回第 4 步,把信任开关打开。开关不存在就回第 3 步重装描述文件 |
| 转圈很久 → 「服务器停止响应」 | 连不上 | 换成 IP 地址(第 5 步);确认设备和 Mac 在同一个 Wi-Fi(2.4G / 5G 分成两个名字时也要对上,别连访客网络);确认 Mac 上 `cotutor serve` 还在跑 |
| 「找不到服务器」 | 名字解析不到 | 换成 IP 地址 |
| 「证书信任设置」里找不到那一项 | 描述文件没装到这台设备上 | 回第 3 步,重新传一次再装 |
| 锁头是绿的,但首页老师头像全是灰的 | 后端不通,或者今天问够了 | Mac 上看 `cotutor serve` 有没有报错;每日上限见《家长手册》里的 `dailyMessages` |
| 按住说话没反应,只能打字 | 麦克风没授权,或者当前不是 HTTPS | 看地址栏是不是 `https://`;删掉主屏幕图标重加,让它重新问一次权限 |
| 页面能开但点什么都没反应 | 多半是 `serve` 那边挂了 | Mac 上重起 `cotutor serve`(改过 `src/` 的话本来就要重起) |

Mac 这边想先自查,不用碰设备:

```sh
lsof -nP -iTCP:<端口> -sTCP:LISTEN                    # 服务在不在
curl -sk https://<局域网 IP>:<端口>/api/health         # 局域网地址通不通
openssl x509 -in ~/.config/cotutor/certs/cert.pem -noout -ext subjectAltName -enddate
```

最后一条列出这张证书覆盖了哪些主机名和 IP。**你在设备上输的地址必须在这个列表里**,否则即使根证书被信任了也照样报「不安全」。
