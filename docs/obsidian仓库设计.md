# obsidian 仓库设计:vault 是长期记忆

> 2026-09-14 拍板,2026-09-17 改按属性定位(拍板记录在 §8)。前提:一孩一 workspace 一 vault;Ray 的 vault 是 `ray-vault`(git 仓库)。本文回答三件事:vault 里**装什么、每样东西长什么样、cotutor 怎么写进去又怎么取出来**。

## 0. 三条准则,一个判据

家长定的三条准则:

1. **透明可读,方便修改**:全是 markdown,家长在 Obsidian 里能读能改,机器写的东西也不例外。
2. **排版美观,符合 Obsidian 审美**:属性写 frontmatter,引用用 `[[wikilink]]`,提示用 callout,不用 HTML 注释、不用块 id、不用机器标签。
3. **写入即上下文**:vault 不是流水账。每一次写入都要先回答「将来哪次对话会用到它、怎么取出来」。

由此一个判据,**写入前三问**(机器与老师都按它走):

| 问 | 过不了怎么办 |
|---|---|
| 一年后家长还会想翻到它吗? | 不写 vault,留在 workspace(对话索引、账本、课包) |
| 老师下次讲同类东西时需要它吗? | 同上 |
| 能不能被**机械地**取出来进上下文包或被 Read / Grep 到? | 改形状再写:固定标题、固定行头、wikilink |

## 1. 定位:两层记忆,读的方向

| | 装什么 | 谁写 | 老师怎么读 |
|---|---|---|---|
| **vault(长期记忆)** | 档案、课程、日记、教材目录、计划、记忆、参考 | 家长手写;机器按 §6 的封闭清单写 | 话题第一条带档案、入口文件、记忆的原文,每轮带本周计划、最近观察;讲解前按需 `Read` 教材那一节、`Grep` 日记 |
| **workspace(运行记录)** | 对话索引与转录、课包 bundles、照片 `captures/`、产物账本 | 机器 | 家长在家长端 `/parent` 看板书、在工作台 `/dev` 看原文;老师基本不回头读 |

三条硬规则:

- **谁写谁是真相**:家长写的字机器永不改。
- **机器写 vault 一律新建或追加**,从不删、不改已有内容。
- **代码不认任何分类学**:没有「题型」「册子」这种代码里的概念,也没有标签。代码只认 §2 里那几种文件和一个通用锚点——**教材单元的标题**。家长想按题型、按薄弱点、按什么都行地整理,自己建笔记、在教材那一节的口径里 `[[链过去]]`,老师读那一节时跟链接走一跳。

**观察的真相在日记**:老师记账时**只回结构化文本、应用只写日记**,上下文包里的「最近观察」从日记的观察行机械抽——家长在日记里改一句、删一行,下次对话就跟着变。账本 jsonl 只留产物(课包 id / 费用 / 状态),那是机器的事。

## 2. 目录

```
ray-vault/                       Ray 的 vault(git 仓库);文件按 frontmatter `cotutor:` 找,下面是习惯放法
  profile.md                档案 `cotutor: profile`,原文进上下文包                      家长写,机器只读
  课程/<学期>/<学科>.md     入口文件 `cotutor: subject`,原文进上下文包                   家长写,机器只读
  教材/                     `cotutor: textbook`,一册一篇一单元一节,节下是家长口径          家长写
  记忆/<显示名>.md          `cotutor: memory` + `agent:`,一个 agent 一篇                  机器追加,家长可改
  日记/2026-09-14.md        一天一篇:话题 H2 + 孩子问 + 摘要与骨架(打分够才有)+ 观察行   机器追加,家长可写
  计划/2026-W38.md          周计划                                                       家长写
  参考/                     政策、家长自己的分类与笔记(题型、薄弱点……随便建)              家长写,机器只读
```

vault 里不存照片(落 workspace `captures/`)、不存课包终帧、不设周记(并进计划)。

## 3. 每种笔记:形状 + 提取路径

### 3.1 档案

档案 = `cotutor: profile` 的那篇,**原文整篇**进上下文包(`<vault-note>`,按 `entryChars` 截)。

### 3.2 `日记/<日期>.md`

一天一篇,文件名 `YYYY-MM-DD`(与 `.obsidian/daily-notes.json` 一致,doctor 对一次)。**一个话题一个 H2**,H2 = `学科 · 话题名`(话题名是老师记账时起的,≤ 12 字)。H2 下最多五种东西,行头固定:

```markdown
## 数学 · 找规律填数(递减)

> [!question] 孩子问
> 80 再少 2 为什么是 78 不是 88?
> 那 90、80、70 也是每次少的吗?

讲了人教一下每日一练 3.1 第 1 小题(88、86、84 ➝ 82、80、78)。难点换到「80 再少 2 要退到七十几」那一格,步 5 停下慢了一拍。检查那步第一次改成画红色回头箭头。 ★★★★ → [[人教数学一下#4 100以内数的认识]] · 课包 2026-09-05-guilv1
骨架:抄数列 → 相邻连箭头给规律起名 → 一格一格减着填 → 圈住答案 → 倒着加回去检查

- 观察:两位数减一位数跨十时会停一拍,「两个两个倒着数」能过去
- 家长:他自己说想再做一道 90、80、70 的
```

| 部件 | 何时出现 | 谁写 | 提取 |
|---|---|---|---|
| `> [!question] 孩子问` | **总是**,孩子在这个话题里每一句非空的话(「继续」、交卡不算) | 应用从对话索引机械抄 | 家长翻 |
| 摘要段(1–3 句 + `★` + 教材单元链接 + 课包 id) | **只有话题打分 ≥ 阈值** | 老师记账时写句子,应用拼行 | 老师 `Grep "[[人教数学一下#4"` 找以前讲过的 |
| `骨架:` 行 | 打分 ≥ 阈值且这是讲解(有卡)的话题 | 老师记账时写,应用写行 | 同上:下次讲同一单元,先看上次骨架 |
| `- 观察:` | 老师记账时觉得值得记的,0–3 条 | 老师写 claim,应用写行 | **上下文包 `recent:`**:最近 14 天所有 `- 观察:` 行,按政策截条数;家长改文字、删行,下次即生效 |
| `- 家长:` 或任何其它行 | 家长随时手写 | 家长 | 机器不动 |

没打分或打分低的话题:只留 H2 + 孩子问。**孩子的问题是永远值得记的;回答值不值得记看打分**。一个话题没有孩子的话(纯家长发的)且没打分,那天日记就不出现它。

打分够的讲解只沉淀在这里,**没有别的地方**:「讲法骨架」就是那一行文字,不存终帧、不拷课包;「以前怎么讲的」= 按教材单元链接 Grep 日记,Obsidian 里 = 教材那一节的反链面板。

### 3.3 `教材/<册>.md` 教程目录 —— 唯一的锚点

一册一篇,一单元一节,节下 `### 口径` 家长写;不用标签。知识点的身份就是标题本身:别处引用写 `[[人教数学一下#4 100以内数的认识]]`,Obsidian 的反链面板天然列出哪些日记讲过这一单元——这就是标签原来想干的事,而且家长不用维护任何东西。

```markdown
## 4 100以内数的认识
页 33–50
### 口径
找规律填数这类题他已经会了,别再从头讲;口算跨十要慢一拍。讲法偏好见 [[找规律填数]]。
```

- 教材家长自己写或转录,机器不写。英语教材(Unit)同一形状。
- **提取**:老师讲某单元前 Read 那一节;口径里的 `[[链接]]` 跟一跳(家长自己的题型笔记、薄弱点笔记就是这样被带上的);想知道「这单元以前讲过什么」用 `Grep "[[人教数学一下#4" 日记/`。
- 记账时老师要指认这个话题属于哪一册哪一节(`textbook:`),指认不了就不写链接,摘要照记。

### 3.4 `参考/` —— 家长自己的分类住这里

家长自由区,代码只读。想按题型整理就建 `参考/找规律填数.md`,想按薄弱点整理就建 `参考/跨十.md`,想都不建也行。让老师看到的办法只有一个:在教材那一节的口径里链过去,或者在档案里链过去。

### 3.5 `计划/<周>.md`

计划文件家长自己写,可以在前面加一段 `## 上周`,不另设周记。

## 4. 打分:哪些回答值得记

- **打分的单位是话题(thread),不是轮**。一次讲解跨好几轮,一个分就够;日记里一个话题一个 H2,正好对上。
- **在哪打**:家长端 `/parent` 清单上每个话题行尾五颗星(2026-09-22 起),工作台 `/dev` 对话页话题头部也有一排(未打 = 0);孩子端永远没有打分。也给 `cotutor rate <老师> <话题> <分>` 一条命令。
- **存哪**:workspace 对话索引,`threads` 层加 `rating`(1–5,可改)。**vault 里不出现分数以外的评判**,星号只是「这次值得记」的标记。
- **阈值**:`vault.keepScore`,出厂 4。打分 ≥ 阈值 → 日记有摘要段与骨架行;< 阈值或没打 → 只留孩子问。
- **打分与记账的关系**:记账那一步(家长点「记账」,或 `cotutor bookkeep`)才写 vault;打分可以在记账前随时改,记账后改分不回写(日记已经是那天的样子了;要改家长自己在 Obsidian 改)。
- 场景作业(scene-maker 的话题)与普通讲解一样打分;高分课包沉淀的是讲稿骨架与 id。

## 5. 图片:存文字,不存图

- 照片(作业页)落 workspace `captures/<日期>/<HHMM>-<n>.jpg`,`/api/kid/image` 从那里给;vault 不存照片。
- 老师看过照片后**认出来的东西**才进 vault:日记摘要里写「人教一下每日一练 3.1 第 1 小题(88、86、84)」——册子、页、题号、题目文字。这些是将来能 Grep 到的;jpg 不能。
- 课包终帧同理(§3.2)。

## 6. 机器写 vault 的封闭清单

| 文件 | 动作 | 时机 |
|---|---|---|
| `日记/<日期>.md` | 追加(文件不在就建) | 记账 |
| `记忆/<显示名>.md` | 追加(文件不在就建) | 回复带「## 记忆」段 |

**永不**:写 `#标签`、写图片、改家长写过的字、删文件、建代码认得的分类目录、写档案、入口文件、计划、`参考/`。老师(LLM)**不直接写 vault 文件**:记账时它回一段固定形状的文本,应用解析后按上表落盘——形状由代码保证,老师写错了应用报 warning、不落。

记账的输入形状(老师在正文末尾写,应用只认这个段;写法在老师文件与 `cotutor-vault` 技能里):

```markdown
## 记账
- thread: <话题 job>
  name: 找规律填数(递减)                     ← 话题名,≤ 12 字
  textbook: 人教数学一下#4 100以内数的认识     ← 这个话题属于哪册哪节;认不出就不写
  summary: 讲了…难点在…                       ← 1–3 句;只有打分够时才要
  steps: 抄数列 → … → 倒着加回去检查          ← 讲解的骨架;只有打分够时才要
  observations:
    - 两位数减一位数跨十时会停一拍…
```

## 7. 老师读 vault 的路径

> 2026-09-15:这一节的内容住在技能 `cotutor-vault`(仓库 `skills/cotutor-vault/SKILL.md`,init 拷进 workspace 的 `.claude/skills/`);老师文件尾巴点名它。路径从上下文包的 `vault:` 段取,老师不读 cotutor.json。

| 何时 | 读什么 | 怎么读 |
|---|---|---|
| 每轮 | 档案、入口文件、记忆原文(话题第一条)、本周计划、最近观察、今天已有的话题名 | 应用拼进上下文包,老师不用工具 |
| 讲某单元之前 | `教材/<册>.md` 那一节的口径,口径里的 `[[链接]]` 跟一跳 | Read |
| 想知道「以前讲过什么、怎么讲的」 | `Grep "[[人教数学一下#4" 日记/`,看那几段的摘要与骨架 | Grep |
| 想知道孩子最近问过什么 | `Grep "孩子问" -A3 日记/` | Grep |

问答(缺省模式)照旧不用工具;只有讲解与任务模式才读。
