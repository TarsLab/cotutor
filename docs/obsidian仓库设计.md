# obsidian 仓库设计:vault 是长期记忆

> 前提:一孩一 workspace 一 vault;Ray 的 vault 是 `ray-vault`(git 仓库)。本文回答三件事:vault 里**装什么、每样东西长什么样、cotutor 怎么写进去又怎么取出来**。

## 0. 三条准则,一个判据

家长定的三条准则:

1. **透明可读,方便修改**:全是 markdown,家长在 Obsidian 里能读能改,机器写的东西也不例外。
2. **排版美观,符合 Obsidian 审美**:属性写 frontmatter,引用用 `[[wikilink]]`,提示用 callout,不用 HTML 注释、不用块 id、不用机器标签。
3. **写入即上下文**:vault 不是流水账。每一次写入都要先回答「将来哪次对话会用到它、怎么取出来」。

由此一个判据,**写入前三问**(机器与老师都按它走):

| 问 | 过不了怎么办 |
|---|---|
| 一年后家长还会想翻到它吗? | 不写 vault,留在 workspace(对话索引、账本、课包) |
| 老师下次讲同类东西时需要它吗? | 同上 |
| 能不能被**机械地**取出来进上下文包或被 Read / Grep 到? | 改形状再写:固定标题、固定行头、wikilink |

## 1. 定位:两层记忆,读的方向

| | 装什么 | 谁写 | 老师怎么读 |
|---|---|---|---|
| **vault(长期记忆)** | 档案、课程、日记、教材目录、计划、记忆、参考 | 家长手写;机器按 §6 的封闭清单写 | 话题第一条带档案、入口文件、记忆的原文,每轮带本周计划、最近观察;讲解前按需 `Read` 教材那一节、`Grep` 日记 |
| **workspace(运行记录)** | 对话索引与转录、课包 bundles、照片 `captures/`、产物账本 | 机器 | 家长在家长端 `/parent` 看板书、在工作台 `/dev` 看原文;老师基本不回头读 |

三条硬规则:

- **谁写谁是真相**:档案、入口文件、教材与计划由家长维护;记忆文件允许应用按下述规则更新。
- **机器写入限于日记与记忆**:日记新建或追加,记忆可以增改删;删话题时按原文撤回该话题留下的内容(§8)。
- **代码不认任何分类学**:没有「题型」「册子」这种代码里的概念,也没有标签。代码只认 §2 里那几种文件和一个通用锚点——**教材单元的标题**。家长想按题型、按薄弱点、按什么都行地整理,自己建笔记、在教材那一节的口径里 `[[链过去]]`,老师读那一节时跟链接走一跳。

**观察的真相在日记**:老师记账时**只回结构化文本、应用只写日记**,上下文包里的「最近观察」从日记的观察行机械抽——家长在日记里改一句、删一行,下次对话就跟着变。账本 jsonl 只留产物(课包 id / 费用 / 状态),那是机器的事。

## 2. 目录

```
ray-vault/                       Ray 的 vault(git 仓库);文件按 frontmatter `cotutor:` 找,下面是习惯放法
  profile.md                档案 `cotutor: profile`,原文进上下文包                      家长写,机器只读
  课程/<学期>/<学科>.md     入口文件 `cotutor: subject`,原文进上下文包                   家长写,机器只读
  教材/                     `cotutor: textbook`,一册一篇一单元一节,节下是家长口径          家长写
  记忆/<显示名>.md          `cotutor: memory` + `agent:`,一个 agent 一篇                  机器增改删,家长可改
  记忆/孩子.md              `cotutor: memory` + `agent: all`,孩子的记忆,有脸的老师共用     机器增改删,家长可改
  日记/2026-09-14.md        一天一篇:话题 H2 + 孩子问 + 摘要与骨架(打分够才有)+ 观察行   机器追加,家长可写
  计划/2026-W38.md          周计划                                                       家长写
  参考/                     政策、家长自己的分类与笔记(题型、薄弱点……随便建)              家长写,机器只读
```

vault 里不存照片(落 workspace `captures/`)、不存课包终帧、不设周记(并进计划)。

## 3. 每种笔记:形状 + 提取路径

### 3.1 档案

档案 = `cotutor: profile` 的那篇,**原文整篇**进上下文包(`<vault-note>`,按 `entryChars` 截)。

### 3.2 `日记/<日期>.md`

一天一篇,文件名 `YYYY-MM-DD`(与 `.obsidian/daily-notes.json` 一致,doctor 对一次)。**一个话题一个 H2**,H2 = `学科 · 话题名`(话题名是老师记账时起的,≤ 12 字)。H2 下最多五种东西,行头固定:

```markdown
## 数学 · 找规律填数(递减)

> [!question] 孩子问
> 80 再少 2 为什么是 78 不是 88?
> 那 90、80、70 也是每次少的吗?

讲了人教一下每日一练 3.1 第 1 小题(88、86、84 ➝ 82、80、78)。难点换到「80 再少 2 要退到七十几」那一格,步 5 停下慢了一拍。检查那步第一次改成画红色回头箭头。 ★★★★ → [[人教数学一下#4 100以内数的认识]] · 课包 2026-09-05-guilv1
骨架:抄数列 → 相邻连箭头给规律起名 → 一格一格减着填 → 圈住答案 → 倒着加回去检查

- 观察:两位数减一位数跨十时会停一拍,「两个两个倒着数」能过去
- 家长:他自己说想再做一道 90、80、70 的
```

| 部件 | 何时出现 | 谁写 | 提取 |
|---|---|---|---|
| `> [!question] 孩子问` | **总是**,孩子在这个话题里每一句非空的话(交卡不算;老数据里的「继续」也不算) | 应用从对话索引机械抄 | 家长翻 |
| 摘要段(1–3 句 + `★` + 教材单元链接 + 课包 id) | **只有话题打分 ≥ 阈值** | 老师记账时写句子,应用拼行 | 老师 `Grep "[[人教数学一下#4"` 找以前讲过的 |
| `骨架:` 行 | 打分 ≥ 阈值且这是讲解(有卡)的话题 | 老师记账时写,应用写行 | 同上:下次讲同一单元,先看上次骨架 |
| `- 观察:` | 老师记账时觉得值得记的,0–3 条 | 老师写 claim,应用写行 | **上下文包 `recent:`**:最近 14 天所有 `- 观察:` 行,按政策截条数;家长改文字、删行,下次即生效 |
| `- 家长:` 或任何其它行 | 家长随时手写 | 家长 | 机器不动 |

没打分或打分低的话题:只留 H2 + 孩子问。**孩子的问题是永远值得记的;回答值不值得记看打分**。一个话题没有孩子的话且没打分,那天日记就不出现它。

打分够的讲解只沉淀在这里,**没有别的地方**:「讲法骨架」就是那一行文字,不存终帧、不拷课包;「以前怎么讲的」= 按教材单元链接 Grep 日记,Obsidian 里 = 教材那一节的反链面板。

### 3.3 `教材/<册>.md` 教程目录 —— 唯一的锚点

一册一篇,一单元一节,节下 `### 口径` 家长写;不用标签。知识点的身份就是标题本身:别处引用写 `[[人教数学一下#4 100以内数的认识]]`,Obsidian 的反链面板天然列出哪些日记讲过这一单元——这就是标签原来想干的事,而且家长不用维护任何东西。

```markdown
## 4 100以内数的认识
页 33–50
### 口径
找规律填数这类题他已经会了,别再从头讲;口算跨十要慢一拍。讲法偏好见 [[找规律填数]]。
```

- 教材家长自己写或转录,机器不写。英语教材(Unit)同一形状。
- **提取**:老师讲某单元前 Read 那一节;口径里的 `[[链接]]` 跟一跳(家长自己的题型笔记、薄弱点笔记就是这样被带上的);想知道「这单元以前讲过什么」用 `Grep "[[人教数学一下#4" 日记/`。
- 记账时老师要指认这个话题属于哪一册哪一节(`textbook:`),指认不了就不写链接,摘要照记。

### 3.4 `参考/` —— 家长自己的分类住这里

家长自由区,代码只读。想按题型整理就建 `参考/找规律填数.md`,想按薄弱点整理就建 `参考/跨十.md`,想都不建也行。让老师看到的办法只有一个:在教材那一节的口径里链过去,或者在档案里链过去。

### 3.5 `计划/<周>.md`

计划文件家长自己写,可以在前面加一段 `## 上周`,不另设周记。

## 4. 打分:哪些回答值得记

- **打分的单位是话题(thread),不是轮**。一次讲解跨好几轮,一个分就够;日记里一个话题一个 H2,正好对上。
- **在哪打**:家长端 `/parent` 清单上每个话题行尾五颗星,工作台 `/dev` 对话页话题头部也有一排(未打 = 0);孩子端永远没有打分。也给 `cotutor rate <老师> <话题> <分>` 一条命令。
- **存哪**:workspace 对话索引的 `ratings[thread]`(1–5,可改)。**vault 里不出现分数以外的评判**,星号只是「这次值得记」的标记。
- **阈值**:`vault.keepScore`,出厂 4。打分 ≥ 阈值 → 日记有摘要段与骨架行;< 阈值或没打 → 只留孩子问。
- **打分与记账的关系**:记账那一步(家长点「记账」,或 `cotutor bookkeep`,或自动记账)才写 vault;打分可以在记账前随时改,记账后改分不回写(日记已经是那天的样子了;要改家长自己在 Obsidian 改)。
- **自动记账**(2026-10-30,`vault.autoBookkeep`,缺省关):serve 开着时每 10 分钟看一次。今天的话题空闲 2 小时就记,不整理记忆;昨天没记的第二天补上,记完整理一次记忆(那天还没整理过才整理);前天及更早的不补,要记家长点「记账」。只记有脸的老师、有孩子的话或打了分的话题;记账没成的一个话题最多试两次。不等打分:没打分就只写话题名、孩子问与观察。成本:每个话题多一次老师调用,约等于这个话题当前的上下文(ray 上实测 1.6 万–5.5 万输入 token)。

## 5. 图片:存文字,不存图

- 照片(作业页)落 workspace `captures/<日期>/<HHMM>-<n>.jpg`,`/api/kid/image` 从那里给;vault 不存照片。
- 老师看过照片后**认出来的东西**才进 vault:日记摘要里写「人教一下每日一练 3.1 第 1 小题(88、86、84)」——册子、页、题号、题目文字。这些是将来能 Grep 到的;jpg 不能。
- 课包终帧同理(§3.2)。

## 6. 机器写 vault 的封闭清单

| 文件 | 动作 | 时机 |
|---|---|---|
| `日记/<日期>.md` | 追加(文件不在就建);删话题时摘掉这个话题记账时追加的那段 | 记账;家长端删话题 |
| `记忆/<显示名>.md` | 增 / 改 / 删(文件不在就建);删话题时把这个话题的增改删倒着撤 | 回复带「## 记忆」段;记账后的整理;家长端删话题 |
| `记忆/孩子.md`(`agent: all`) | 同上;最多 20 条,满了新增的不进 | 有脸的老师的「## 记忆」段里 `孩子:` 开头的行;家长端删话题 |

**永不**:写 `#标签`、写图片、改家长写过的字(记忆文件除外)、删文件、建代码认得的分类目录、写档案、入口文件、计划、`参考/`。老师(LLM)**不直接写 vault 文件**:记账时它回一段固定形状的文本,应用解析后按上表落盘——形状由代码保证,老师写错了应用报 warning、不落。

记账的输入形状(老师在正文末尾写,应用只认这个段;写法在记账那条消息里,`src/memory/diary.ts` 的 `bookkeepingPrompt`):

```markdown
## 记账
- thread: <话题 job>
  name: 找规律填数(递减)                     ← 话题名,≤ 12 字
  textbook: 人教数学一下#4 100以内数的认识     ← 这个话题属于哪册哪节;认不出就不写
  asked:
    - 80 减 2 怎么减                          ← 孩子的原话挑 1–3 句,可以只抄一截;应用核对过才进「孩子问」
  summary: 讲了…难点在…                       ← 1–3 句;只有打分够时才要
  steps: 抄数列 → … → 倒着加回去检查          ← 讲解的骨架;只有打分够时才要
  observations:
    - 两位数减一位数跨十时会停一拍…
```

「孩子问」(2026-10-30):老师挑的 `asked` 拿孩子在这个话题里的话核对(和记忆的证据同一条规则,去空白标点后包含就算),对上的最多 3 句;对不上的进提醒。一句都没对上或没写,由应用从孩子的话里筛:去掉标点、语气词与「老师」这类称呼后不到四个字的不要,重复的只留一句,最多 5 句。语音转写里「嗯,老师,呃」「语文老师。」这种碎句因此不进日记;原话全文在 workspace 的录像里。

## 7. 老师读 vault 的路径

> 老师看到的只有守则(cotutor-tutor)里的一句「读教材先 Grep,只读命中的那一节」;下表是应用这边的设计。路径从上下文包的 `vault:` 段取,老师不读 cotutor.json。

| 何时 | 读什么 | 怎么读 |
|---|---|---|
| 每轮 | 档案、孩子的记忆、入口文件、记忆原文(话题第一条)、本周计划、最近观察、今天已有的话题名 | 应用拼进上下文包,老师不用工具 |
| 孩子问到一个字、提到某一课(有脸的老师) | 这科这学期教材的 `识字:` / `写字:` 行;那一课的 `### 口径`;最近 30 天日记里链到那一课的 `骨架:` 行 | 应用检索后放进上下文包(`lookup:` 与 `<vault-note role="lesson">`,`src/memory/retrieval.ts`),老师不用工具 |
| 讲某单元之前 | `教材/<册>.md` 那一节的原文,口径里的 `[[链接]]` 跟一跳 | Read |
| 想知道「以前讲过什么、怎么讲的」(比 lookup 更多的) | `Grep "[[人教数学一下#4" 日记/`,看那几段的摘要与骨架 | Grep |
| 想知道孩子最近问过什么 | `Grep "孩子问" -A3 日记/` | Grep |

孩子说的话缺省不带工具,上表后三行只在这轮带工具时才读。ray 的记录里老师真读 vault 的,8 次里 6 次是 Grep 一个字在不在生字表,所以这一样由应用每轮替老师查(2026-10-30)。

**取材怎么认**(只做关键词与标题匹配,不做语义检索):孩子问字的说法认「X怎么写 / 读 / 念 / 拼 / 组词」「X字的…」「“X”」,拼音、作文、这道题不算;字查这科这学期教材(`cotutor: textbook`)各课的识字、写字行,写「会认」「会写」或「不在这学期的识字、写字表里」;提到的课认课题(去掉编号后至少两个字)与「第 N 课」,再加问到的字要会写的那一课,最多两课。每一样都记来源路径、整篇的 hash 与为什么查,进这一轮的 `run.json`(`sources.retrieved`);带了原文的每篇笔记也记一笔(`sources.notes`:role、路径、那段的 hash 与字数、截没截),事后重建得出老师看到的是哪一版。

## 8. 文件定位、记忆与撤回

### 文件与学期

- 按 frontmatter 的 `cotutor: profile | subject | textbook | memory` 找笔记,不依赖家长采用的文件名或目录。程序读取的属性用英文,只给人看的属性可用中文。
- 当前学期从档案的 `school_start: YYYY-MM` 推算:9–1 月为上学期,2 月寒假,3–6 月下学期,7–8 月暑假;可用 `semester` 明确覆盖,如 `二年级上`。
- 学科入口文件须同时匹配 `cotutor: subject`、老师的 `subject` 与当前 `semester`。教材按学科和学期查,入口文件不必列出教材路径。
- 找不到本学期入口文件时不沿用上学期。上下文包标缺失,doctor 说明该建的文件与属性;init 不自动编写课程内容。
- 档案、入口文件和记忆在话题第一条带原文;续聊按路径与 hash 判断,未变则不重复,改过再带一次。其余教材与 wikilink 指向的资料在 `refs` 给路径。
- 每篇原文按 `policy.contextPack.entryChars` 限长,缺省 4000 字。档案与入口文件留开头;记忆留末尾,从整行起截取并注明。doctor 提醒过长文件。
- 入口文件的讲法偏好优先于老师文件;孩子端不展示评判、老师不直接写文件和不派子代理等公共约束仍有效。

### 记忆的读写

每个 agent 独立记忆,按 `cotutor: memory` 与 `agent: <名>` 定位,缺失时由应用建 `记忆/<显示名>.md`。activity 用 `<老师>/<activity>` 作为身份,与普通聊天隔开。不使用 CLI 自带的 memory。

老师在回复尾部写下面的段落,应用解析后落盘,孩子看不到:

```markdown
## 记忆
- 喜欢用小棒解释平均分
- 改:喜欢用小棒解释平均分 → 能用小棒解释平均分
- 删:能用小棒解释平均分
```

新增会加日期并去重。改、删按原话匹配:整行相同,或至少四字且唯一包含。记忆中家长写的行也允许改、删;找不到或匹配不唯一就不动并提醒。讲课每轮最多两项操作,回放不写。家长可在 Obsidian 编辑,原文变化后再带入上下文。

每条是一个**建议**(2026-10-30)。行末可以带 `证据:「孩子的原话」`,应用拿它对孩子在这个话题里说过的话(整理轮对当天的),去掉空白与标点后包含就算对上;对不上的那条不记并提醒,没写证据的照记。证据与对没对上记在这一轮索引的 `memoryProposals` 上,不进 vault。

**孩子的记忆**(2026-10-30):`cotutor: memory` + `agent: all` 的那篇,缺省 `记忆/孩子.md`,第一次有人记时应用建。放关于孩子本人、换一科也成立的事(情绪、读写、注意力、家里谁在旁边);讲法与题型的经验仍记在各老师自己的记忆里。有脸的老师在「## 记忆」里写 `孩子:` 开头的行(改、删写成 `孩子:改:…`、`孩子:删:…`),应用去掉前缀记进这篇;工具人写的照旧进自己的。所有有脸的老师在话题第一条都拿到它的原文(`<vault-note role="child">`,按 `entryChars` 截、留末尾),activity 话题也是同一篇——activity 的记忆互相隔开,这篇是有意的例外。和档案冲突时以档案为准;家长觉得某行该长期成立,自己挪进档案。最多 20 条,满了新增的不进并提醒家长删,不为它另起整理轮。已有各老师记忆里关于孩子的行不自动搬。

这一轮里家长改过记忆文件(老师看到的那版和写入时的文件对不上),改、删只认整行相同的原话,包含匹配不算,免得把家长刚补上的半句盖掉。写之前再读一次文件,和算的时候不一样就这轮不写。

记账完成后,已有记忆的老师另起一次系统会话整理记忆,带记忆原文与当天日记路径。整理不限制操作条数,要求保留不超过 30 条;不算孩子的话题,家长端显示改动。

### 删话题时撤回

应用按各轮的 `memoryLines`(孩子的记忆是 `childLines`)倒序撤回:新增的删除、改过的改回、删除的补到末尾。日记只移除记账时记录的 `diaryBlock` 原文。内容被家长或后续整理改过、无法匹配时保留现状并提醒,不强行覆盖。

写 vault 分三步:先在这一轮的索引上记 `pending`(要写什么、写到哪、写之前的版本),再写 vault,写完换成 `memoryLines`、`diaryBlock` 与 `booked`。写完 vault、没写进索引就断了的,下次记账和删话题之前先对照文件:写成了就补记(日记不追加第二遍,删话题照样撤得回),没写成就丢掉,再点记账会重记。
