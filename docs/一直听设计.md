# 一直听:不用按住说话(只给口语课)

> 2026-10-20 起。现在只有口语课(热身、打电话)总是一直听;别的老师缺省按住说话,孩子端没有开关,家长要试在 `cotutor.json` 的 `live.listen` 写 `"open"`(拍板 4)。正文 2026-10-22 收成现状;10-20 的设计稿、分步、进度、量什么与待拍板,原文在 git 历史 facdd86。嘴、脑、连接这些在《实时老师设计.md》。
> **词**:「按住说」= 现在的按住说话(手动轮次);「一直听」= 本稿要加的常开麦(服务端 VAD 判轮次)。「开口 / 说完」= VAD 的 `speech_started` / 判停并 commit。「一句」= VAD 切出来、转写回来的一段孩子的话。「收下 / 放过」= 应用判这一句算不算孩子对老师说的。

结论先行:**一直听 = 进老师页麦就开着,孩子张嘴算按下、说完算松手,后面嘴、脑、照念全不动。轮次交给百炼的 VAD(缺省 `server_vad`、静 1600 毫秒算说完,拍板 3),回不回、掐不掐由应用定(`create_response: false`、`interrupt_response: false`);每一句转写回来先过「收下 / 放过」,空的、只有语气词的、是嘴自己回声的都放过。全双工(拍板 1):孩子插嘴时嘴的声音先压到三成,转写收下了才掐;回声靠设备的回声消除,漏过来的和嘴刚说过的字一比就放过。**

## 一、为什么现在能做,难在哪

能做:
- 常开那路麦克风**已经开着**:老师页为了按下就有声,进页面就 `micWarm()` 开好一路一直不关(`kid-page.ts` 麦克风那段,iPad 上只留一个 AudioContext,32d47a8)。「一直听」只是把「按着才推」改成「开着就推」,采音、放音、AudioContext 都不换。
- 服务端 VAD 这条线**口语课在用**:聊那段 `semantic_vad`,孩子开口就掐嘴、清孩子端(`relay.ts` 的 `onSpeech`);ray 10-17 那次的聊段(半双工,老师说话时不推)VAD 判开口 10 次、转写回来 9 句。假百炼(`tests/_fake-realtime.ts`)也已经会 VAD:有声的块回 `speech_started`,有声之后全零的块回 `speech_stopped` + commit + 转写。
- 拍板 5 把接口定好了:hold / release 换成开口 / 说完,`call.ts` 后面那串(接住、交给脑、照念、打断报到哪句)不用重写。

难在四样(按险排):

| | 是什么 | 证据 | 本稿的办法 |

## 二、孩子看到的

- 口语课页交过来、点「先热身,再打电话」开始以后,那颗大按钮是麦克风开关:「我在听,直接说就行」,外圈跟着音量;点一下关麦(「麦关了,点右边的麦克风再听」),再点开。和家长说话、不想让老师听时用。
- 说完了同松手:嘴照念脑写的,中间什么都不用按。
- 打断:直接说。嘴先变小声,认出是孩子在说就停;是「嗯」、笑声、回声就恢复音量接着说。
- 卡的声音在念、在放小课堂那一段、在响铃、在重放时不推声音(那不是对老师说的)。
- 没做:屏幕常亮、几分钟没人说话自己收麦——一直听时 iPad 的自动锁定要设成「永不」(《家长手册.md》3.7)。

## 三、QLH 怎么做的,搬什么

QLH 是 Electron 桌面应用(Mac),通话时麦一直开着,**生产上就是全双工常开麦**。路径缩写:H = `packages/qwen-live-harness-host`,D = `packages/qwen-live-harness/src`。

| | QLH | 我们 | 为什么不同 |

**搬的**:`semantic_vad` + `create_response: false` 这组(生产在用,qwen3.8-omni-flash-realtime 上);只认 committed;拒收是非致命的;孩子在说时不开新的口、排着的不丢;断了攒声音补推;关麦时心跳。**不搬的**:`interrupt_response: true`(一年级孩子的咳嗽、笑、「嗯」都会掐掉老师,不续)、两个 AudioContext 与关了重建(iPad)、转写失败就挂、没有「你在说」。

## 四、服务端:一句话的一生(`src/live/call.ts` + 新纯函数 `src/live/lib/listen.ts`)

**会话配置**(`realtime.ts` 的 `turnDetection`,一直听时):

```
turn_detection: { type: 'server_vad', threshold: 0.5, prefix_padding_ms: 300, silence_duration_ms: 1600,   // 拍板 3:原 semantic_vad
                  create_response: false, interrupt_response: false }
```

- `create_response: false`:嘴每次开口都由应用给词(《实时老师设计.md》§三「嘴」,P1 实测),VAD 自己回一句就破了规矩。
- `interrupt_response: false`:掐不掐由应用定——要先判是不是回声、是不是「嗯」,还要清孩子端、丢没念的拍、记孩子听到第几句(`interrupt()` 已有)。
- 按住说 ↔ 一直听:**换一条连接,不在通话里切 `turn_detection`**。type 虽然能随时切(`setTurn`),silence 却只有新连接能给(realtime.ts 头注释,10-10 实测);QLH 9-19 也把通话中切轮次拿掉了。在安静时换(嘴没在说、脑没在写),走并行在做的现连那条路,孩子端只看到胶囊变样。
- `semantic_vad` + `create_response: false` 在 qwen3.8-omni-flash-realtime 上 QLH 生产在用;`interrupt_response: false`、semantic 认不认 silence、事件顺序与时刻,第 0 步探针验(10-14 口语课想验 `create_response: false` 时撞上端点 403,那是端点的事,10-19 之后业务空间端点一直通)。
- 现在 `realtime.ts` 不认的两个事件要接:VAD 拒收的 `error`(不当错,当放过)、`conversation.item.input_audio_transcription.failed`(当转写失败)。

**一句话的一生**(`listen.ts`,纯函数,假钟测):

| 来了 | 做什么 |
|---|---|
| `speech_started` | 记一条 `mouth` 事件(`hold`,how: `vad`);照念的排队**暂停**(不交新的拍,也不丢)——不是「按下」:还不知道是不是对老师说的。全双工且嘴在放:让孩子端压低嘴的声音(§五) |
| VAD 拒收(`error`「not accepted by semantic turn detection」) | 当放过:排队接着走、恢复音量;不发 `err` 给孩子端 |
| `speech_stopped` + `committed` | 记 `release`;等转写(0.3–0.5 秒)。只认 committed,之前的 `conversation.item.created` 不算 |
| 转写失败(`…transcription.failed`)| 这句不到 1 秒:放过;1 秒以上:嘴说「没听清,再说一遍吧」(同按住说的空转写) |
| 转写回来 | 判收下 / 放过(下表)。放过:排队接着走、压低的声音恢复,记一条 `skip`(为什么),不进脑、嘴不出声。收下:这时才算「按下 + 松手」——`interrupt()`(掐嘴、清孩子端、丢这一轮没念的拍、记孩子听到第几句)+ `turn('voice')`(嘴接住)+ 交给脑 |
| 收下后 600 毫秒内又 `speech_started` | 接着说的:交给脑的那句先压着,等这一句的转写,并成一条再交 |
| 脑在写时又收下一句 | 同现在:排着,脑写完合并成一条发(`waiting`) |

**收下 / 放过**(按顺序,放过的都记原因,工作台、录像看得到):

1. 转写是空的 → 放过(按住说时空的要说「没听清」,一直听时不说:咳嗽、碰桌子不该让老师开口)。
2. 去掉标点只剩语气词(嗯、啊、哦、呃、哈,一两个字),**而且老师上一句不是问句** → 放过。老师刚问了(`asked`,acce4dd 起有),「嗯」「对」就是回答,收下。
3. 回声:和嘴最近 10 秒说过的字(`tutor` 的 done)按字比,重合过六成 → 放过。半双工时孩子端不推,这条几乎不触发;全双工靠它兜 AEC 漏过来的。
4. 不是对老师说的(孩子跟家长、家长说话)→ 现在不判,见 §九 1。
5. 其余收下。

**要等转写**:一直听时一句要先过收下 / 放过才交给脑,比按住说多等 VAD 判停(server_vad 静 1.6 秒)加转写 0.15–0.3 秒,是不用按的代价。

**心跳、断了**:一直听时声音一直在推,百炼的 `user_idle_timeout`(300 秒没输入)不会到,并行在做的心跳(`RealtimeSession.heartbeat`)只在按住说时跳。但 10-20 的 idle 探针看到「缓冲里有输入、一直没回答」300 秒报 `response_idle_timeout` 会话就死——一直听 + `create_response: false` 下,放过的句子都是「commit 了没回答」,会不会撞上要探针验(第 0 步 A4)。断了现连(并行在做的 `revive` + backlog)照用:连上之前孩子端推来的声音攒着、连上按序补推,VAD 自己切(QLH 同,攒 ≤ 60 秒);一直听时只攒最近 10 秒,更早的孩子早不等了。关麦时没有输入,心跳照并行在做的规则跳。

**录像**:开口、说完、放过(带原因)都记进录像的消息;录音政策见 §九 2。

## 五、回声

做的是全双工(拍板 1),半双工没做。孩子端一直推,开麦显式要 `echoCancellation`,开麦那行诊断记 `getSettings()`。打断分两步:`speech_started` 且嘴在放 → 孩子端把嘴的声音压到三成(`duck`),服务端什么都不掐;转写回来收下 → 掐(同按下),放过 → 恢复音量接着念。10-20 晚真用,放过的里没有回声(aec 开着)。

iPad 上已知的坑:开着麦时页面放声发「噼啪」([WebKit 326286](https://bugs.webkit.org/show_bug.cgi?id=326286))、开麦后放声降采样变单声道([311451](https://bugs.webkit.org/show_bug.cgi?id=311451)),按住说话时就有,不是一直听带来的。

## 六、孩子端

`liveStep`(`src/lib/live-board.ts`)多四个量:`open`(一直听)、`hearing`(服务端说孩子在说)、`ducked`(嘴的声音压低着)、`muted`(关了麦);推不推声音是状态的函数 `liveGate`,一变就告诉服务端 `gate`。表在《工作流程.md》§孩子端「实时老师」的一直听那几行,测试在 `tests/live-player.test.ts`。服务端「一句话的一生」在 `src/live/lib/listen.ts`(`tests/live-listen.test.ts`),接在 `call.ts` 上。

## 七、探针

**第 0 步 A**(2026-10-20,`scripts/probe-live-vad.mjs`,Ray 的 6 段真录音,按真时间推;报告在本机 scratchpad。第 0 步 B 的 iPad 回声、C 的旁边的话没做):
- `semantic_vad` + `create_response: false` + `interrupt_response: false` + silence 收下了(`session.updated` 原样回);一次都没有自己回(没有 `response.created`)。`conversation.item.created` 在孩子还在说时就来(QLH 说的「建了不算」),`speech_stopped` 与 `committed` 同一刻,committed 到转写 0.14–0.30 秒(中位 0.17)。说着的时候就有转写片段(`…transcription.delta`,字在 `stash` 里,还带 `emotion`)。
- 孩子真说完(按响度)到最后一句 committed:silence 1200 → 1.0–1.5 秒;1600 → 0.8–1.8;2000 → 0.8–2.2。说完整的短句 semantic 会提前判(0.8 秒,比 silence 还短)。
- **切碎**:Ray 那段 30 秒的看图说话(1119-9,中间有长停顿),silence 1200 切成 6–7 句,1600 切成 2 句,2000 切成 2–3 句;句与句之间,上一句判停的位置到下一句开口只有 0–300 毫秒——孩子停一下接着说。所以缺省 silence 1600,再加「交给脑之前又开口就并成一句」。
- **短的会丢**:「好的」(1119-10)semantic_vad 跑了五遍一次都没认(server_vad 认了),「Siri」时有时无——semantic 会把附和声当噪声过滤。缺省 semantic,VAD 种类做成配置(`live.vad`),今晚不顺可以热改成 server_vad(切得更碎、短的也认)。
- **掐不掐基本是孩子端的事**:嘴念一段 12 秒的话,服务端 2.3 秒就出完了(`response.done` 早于孩子开口),`interrupt_response` 开关只管还在出的那一小段;孩子听到的声音靠孩子端清。
- **`response_idle_timeout` 撞上了**:推一句(commit)不回答、一直推静音,304 秒报 `response_idle_timeout`,连接不断但会话死了(之后要回答没回音)。一直听时放过的句子就是这样:离上次回答 240 秒、中间有 commit 过,就在安静时换连接(换连接现成的那条路);真撞上了照现在的办法(idle 超时当场关、马上现连)。

**第 0 步后补:上下文与噪声**(2026-10-20 下午,`probe-live-vad.mjs context / noise`,评估口语课时跑的):
