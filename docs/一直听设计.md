# 实时老师:常开麦(设计稿)

> 2026-10-20,设计稿,代码没动,分支 `live`;10-20 上午的提交(心跳与现连、换连接、垫话、activity 与小课堂走实时、英语老师走实时)对一直听的影响在 §四之二。设计图(画布)<https://claude.ai/artifact/Fbq71k2ndLhjAAWx9SfNis>:A 孩子端六个状态、B 一句话的一生、C 半双工 / 全双工同一段 13 秒。接《实时老师设想.md》P5 与拍板 5(「按住说话是现在技术上的约束;一轮的开始 / 结束(hold / release)以后换成 VAD 的开口 / 停,别处不动」)。
> 材料:Qwen-Live-Harness 源码(`~/Projects/github/Qwen-Live-Harness`,下称 QLH,§三)、口语课的两种不用按(聊那段 `semantic_vad` + 半双工、跟读段应用按响度判,`src/talk/`)、`src/live/`(含并行在做的心跳与断了现连)、ray 10-17 那次口语课的真数据(`talk/2026-10-17-1106/`)、《实时交互评估.md》§二 6。
> **词**:「按住说」= 现在的按住说话(手动轮次);「一直听」= 本稿要加的常开麦(服务端 VAD 判轮次)。「开口 / 说完」= VAD 的 `speech_started` / 判停并 commit。「一句」= VAD 切出来、转写回来的一段孩子的话。「收下 / 放过」= 应用判这一句算不算孩子对老师说的。

结论先行:**加一种「一直听」,和按住说并存:进老师页麦就开着,孩子张嘴算按下、说完算松手,后面嘴接住、脑写板书、照念全不动。轮次交给百炼的 VAD(拍板 3 起缺省 `server_vad`,原写 `semantic_vad`),但回不回、掐不掐由应用定(`create_response: false`、`interrupt_response: false`);每一句转写回来先过一道「收下 / 放过」,空的、只有「嗯」的、是嘴自己回声的、(待拍板)不是对老师说的都放过。第一版半双工:嘴在说时孩子端不推声音,要插嘴点头像;iPad 回声探针过了再开全双工(先压低嘴、确认是孩子再掐)。**

## 一、为什么现在能做,难在哪

能做:
- 常开那路麦克风**已经开着**:老师页为了按下就有声,进页面就 `micWarm()` 开好一路一直不关(`kid-page.ts` 麦克风那段,iPad 上只留一个 AudioContext,32d47a8)。「一直听」只是把「按着才推」改成「开着就推」,采音、放音、AudioContext 都不换。
- 服务端 VAD 这条线**口语课在用**:聊那段 `semantic_vad`,孩子开口就掐嘴、清孩子端(`relay.ts` 的 `onSpeech`);ray 10-17 那次的聊段(半双工,老师说话时不推)VAD 判开口 10 次、转写回来 9 句。假百炼(`tests/_fake-realtime.ts`)也已经会 VAD:有声的块回 `speech_started`,有声之后全零的块回 `speech_stopped` + commit + 转写。
- 拍板 5 把接口定好了:hold / release 换成开口 / 说完,`call.ts` 后面那串(接住、交给脑、照念、打断报到哪句)不用重写。

难在四样(按险排):

## 二、孩子看到的

- 老师页和现在一样(左栏大头像 + 字幕,右边白板)。底下那条在「一直听」时不是蓝色的「按住说话」,而是一颗麦克风胶囊:
  - **在听**:浅色,音量条随声音动,写「我在听」。
  - **你在说**(VAD 判开口):变蓝、「在听你说」,同按住时的样子。
  - **老师在说**:半双工时变灰、「老师在说,点我的头像可以打断」;全双工时照旧「我在听」。
  - **关着**:点一下胶囊关麦(灰、划线、「麦关了,点一下再听」),再点开。和家长说话、不想让老师听时用。
- 说完了:同松手,嘴接住、脑写、卡铺上来、嘴照念。中间什么都不用按。
- 打断:半双工 → 点头像(= 现在的按下再上滑:掐嘴、清孩子端、没念的丢掉,不开新一轮),然后直接说;全双工 → 直接说,嘴先变小声,认出是孩子在说就停。
- 打字、拍照、交卡、卡上的「?」照旧(`send`)。
- 录音卡在录、卡上的声音在念、在放小课堂那一段(讲稿的 `[[play]]`):麦克风这时不推(卡的声音、课里原来的声音不当成孩子的话;录音卡录的是给卡的,不是给老师的)。
- 几分钟没人说话:麦自己关(胶囊写「老师先歇一会儿,点我接着聊」),屏幕可以锁了。
- 怎么切到「一直听」、谁来切:待拍板 1。

## 三、QLH 怎么做的,搬什么

QLH 是 Electron 桌面应用(Mac),通话时麦一直开着,**生产上就是全双工常开麦**。路径缩写:H = `packages/qwen-live-harness-host`,D = `packages/qwen-live-harness/src`。

| | QLH | 我们 | 为什么不同 |
|---|---|---|---|
| 推声音 | 一直推,20 毫秒一块;客户端不判开口(没有响度门),只有关麦、不在通话时不推(H `live-state-policy.ts`:listening / thinking / speaking 都在采) | 一直推,100 毫秒一块(现成的 worklet);卡的声音在念、录音卡在录、关麦时不推;半双工时嘴在说也不推 | 卡的声音什么时候响孩子端全知道,不用模型认(《实时交互评估.md》§二 6) |

## 四、服务端:一句话的一生(`src/live/call.ts` + 新纯函数 `src/live/lib/listen.ts`)

**会话配置**(`realtime.ts` 的 `turnDetection` 现在写死 `create_response: true, interrupt_response: true`,改成可配):

```
turn_detection: { type: 'server_vad', threshold: 0.5, prefix_padding_ms: 300, silence_duration_ms: 1600,   // 拍板 3:原 semantic_vad
                  create_response: false, interrupt_response: false }
```

- `create_response: false`:嘴每次开口都由应用给词(设想稿 §三「嘴」,P1 实测),VAD 自己回一句就破了规矩。
- `interrupt_response: false`:掐不掐由应用定——要先判是不是回声、是不是「嗯」,还要清孩子端、丢没念的拍、记孩子听到第几句(`interrupt()` 已有)。
- 按住说 ↔ 一直听:**换一条连接,不在通话里切 `turn_detection`**。type 虽然能随时切(`setTurn`),silence 却只有新连接能给(realtime.ts 头注释,10-10 实测);QLH 9-19 也把通话中切轮次拿掉了。在安静时换(嘴没在说、脑没在写),走并行在做的现连那条路,孩子端只看到胶囊变样。
- `semantic_vad` + `create_response: false` 在 qwen3.8-omni-flash-realtime 上 QLH 生产在用;`interrupt_response: false`、semantic 认不认 silence、事件顺序与时刻,第 0 步探针验(10-14 口语课想验 `create_response: false` 时撞上端点 403,那是端点的事,10-19 之后业务空间端点一直通)。
- 现在 `realtime.ts` 不认的两个事件要接:VAD 拒收的 `error`(不当错,当放过)、`conversation.item.input_audio_transcription.failed`(当转写失败)。

**一句话的一生**(`listen.ts`,纯函数,假钟测):

| 来了 | 做什么 |
|---|---|
| `speech_started` | 记一条 `mouth` 事件(`hold`,how: `vad`);照念的排队**暂停**(不交新的拍,也不丢)——不是「按下」:还不知道是不是对老师说的。全双工且嘴在放:让孩子端压低嘴的声音(§五) |
| VAD 拒收(`error`「not accepted by semantic turn detection」) | 当放过:排队接着走、恢复音量;不发 `err` 给孩子端 |
| `speech_stopped` + `committed` | 记 `release`;等转写(0.3–0.5 秒)。只认 committed,之前的 `conversation.item.created` 不算 |
| 转写失败(`…transcription.failed`)| 这句不到 1 秒:放过;1 秒以上:嘴说「没听清,再说一遍吧」(同按住说的空转写) |
| 转写回来 | 判收下 / 放过(下表)。放过:排队接着走、压低的声音恢复,记一条 `skip`(为什么),不进脑、嘴不出声。收下:这时才算「按下 + 松手」——`interrupt()`(掐嘴、清孩子端、丢这一轮没念的拍、记孩子听到第几句)+ `turn('voice')`(嘴接住)+ 交给脑 |
| 收下后 600 毫秒内又 `speech_started` | 接着说的:交给脑的那句先压着,等这一句的转写,并成一条再交(嘴的接住照旧只说一次) |
| 脑在写时又收下一句 | 同现在:排着,脑写完合并成一条发(`waiting`) |

**收下 / 放过**(按顺序,放过的都记原因,工作台、录像看得到):

1. 转写是空的 → 放过(按住说时空的要说「没听清」,一直听时不说:咳嗽、碰桌子不该让老师开口)。
2. 去掉标点只剩语气词(嗯、啊、哦、呃、哈,一两个字),**而且老师上一句不是问句** → 放过。老师刚问了(`asked`,acce4dd 起有),「嗯」「对」就是回答,收下,接住照旧只「嗯」一声(`answer`)。
3. 回声:和嘴最近 10 秒说过的字(`tutor` 的 done)按字比,重合过六成 → 放过。半双工时孩子端不推,这条几乎不触发;全双工靠它兜 AEC 漏过来的。
4. 不是对老师说的(孩子跟家长、家长说话)→ 待拍板 3。
5. 其余收下。

**接住等不等转写**:按住说时松手就接住、不等转写(设想稿拍板 3:0.60–0.68 秒);一直听时要先过收下 / 放过,只能等转写。孩子停下到听到接住 ≈ VAD 判停(semantic 视句子完不完整,最长 silence 1.2 秒)+ 转写 0.3–0.5 + 嘴首包 0.6,约 1.5–2.3 秒。比按住说慢一秒,是不用按的代价;第 0 步探针量真数(待拍板 4)。

**心跳、断了**:一直听时声音一直在推,百炼的 `user_idle_timeout`(300 秒没输入)不会到,并行在做的心跳(`RealtimeSession.heartbeat`)只在按住说时跳。但 10-20 的 idle 探针看到「缓冲里有输入、一直没回答」300 秒报 `response_idle_timeout` 会话就死——一直听 + `create_response: false` 下,放过的句子都是「commit 了没回答」,会不会撞上要探针验(第 0 步 A4)。断了现连(并行在做的 `revive` + backlog)照用:连上之前孩子端推来的声音攒着、连上按序补推,VAD 自己切(QLH 同,攒 ≤ 60 秒);一直听时只攒最近 10 秒,更早的孩子早不等了。关麦时没有输入,心跳照并行在做的规则跳。

**录像**:`CallRecorder` 现在只记按着时推的声音。一直听时只记 VAD 判出来的段(开口前 300 毫秒到 commit),放过的也记、标 `skip`,别的声音不留。录音政策见待拍板 5。

## 四之二、和 10-20 上午的提交怎么接

那几个提交都是按住说写的,「孩子的动作」默认是按下 / 松手 / 发来;一直听时孩子不按,下面几处要跟着改。

| 提交 | 现在 | 一直听时 |
|---|---|---|
| b5b505f 心跳与现连 | 嘴断了**等孩子下次按下或发来**才现连;按着说的声音攒着(≤ 1 分钟);孩子没按着就 30 秒一次心跳,最后一次动静 15 分钟后停跳 | 没有「下次按下」:**麦开着就马上现连**;攒声音不看 `backlogHolding`,只留最近 10 秒;声音一直在推就不跳心跳,关麦、收麦以后照现在的规则跳 |
| 1b7f40d 换连接 | 输入过了 3000 token、`quiet()` 时开新连接换上 | `quiet()` 多两条:VAD 没在判开口、没有等着判收下 / 放过的一句。放过的句子也进连接的历史,一直听会换得勤些——正好把旁边的话丢掉 |

## 五、回声:先半双工,探针过了全双工

**半双工(第一版)**:孩子端在嘴的声音还在放(`liveStep` 状态 `mouth`)、再加 300 毫秒余音时不推声音,同口语课 `interrupt: false`;卡的声音在念、录音卡在录、在放小课堂那一段时也不推。不推之前若 VAD 正判着开口(不会常有:嘴只在孩子说完后开口,照念的拍在孩子说时暂停),告诉服务端 `gate`,那头 `clearAudio`。打断靠点头像。

**全双工(`live.bargeIn: true`,第 0 步 B 过了再开)**:孩子端一直推,靠设备的回声消除。老师页现在开麦是 `getUserMedia({ audio: true })`,两家浏览器缺省都开 `echoCancellation`,但没人看过真开了没有:改成显式要 `echoCancellation` / `noiseSuppression` / `autoGainControl`,开麦那行诊断(`where: 'mic'`)带上 `track.getSettings()`。嘴的声音走同一个 AudioContext 放(QLH 是两个,iPad 上我们只留一个)。QLH 的全双工直接交给 `interrupt_response: true`,咳嗽一声就掐;我们打断分两步:

1. `speech_started` 且嘴在放 → 孩子端把嘴的声音压到三成(`makeAudio` 加一个总音量的 GainNode,`duck(0.3)`),服务端什么都不掐。
2. 转写回来:收下 → 掐(同按下);放过 → 恢复音量,接着念。压低超过 2.5 秒还没转写(孩子在说长句)→ 当收下掐掉。

**iPad 上已知的坑**:WebKit 有两个用户报的 bug 和这条路有关(没看到苹果的结论)——开着麦时页面放声发「噼啪」(iOS 27,`echoCancellation: true` 时,[326286](https://bugs.webkit.org/show_bug.cgi?id=326286)),开麦后放声降采样、变单声道([311451](https://bugs.webkit.org/show_bug.cgi?id=311451))。这两个现在按住说时就有(麦本来常开),不是一直听新带来的;探针时顺手听。
