# 作业照片:先看一眼、裁一裁圈一圈、配一句话再发

> 2026-09-18 起,当天落地。孩子端老师页上的拍照从「选了就发」改成「发照片屏」:看一眼、可裁剪、可圈画、可配一句话,再一条消息发给老师;相册可一次选多张。拍板在文末;本文给流程、编辑的做法、与播放仲裁的关系、代码怎么分与测试。材料:`src/server/kid-page.ts` `sendPhoto`、`src/server/app.ts` `uploadPhoto` / `photosOf`、`src/server/runner.ts` `send`、`src/cards/docs.ts` 作业照片一段、裁剪参考 growth-apps `apps/web/src/PhotoCrop.tsx`。

结论先行:服务端、runner、上下文包都不动(`{text, photos[]}` 本来就支持);改的全在孩子端页面,加一个纯函数模块 `src/lib/photo-edit.ts` 管裁剪 / 旋转 / 笔画的坐标,页面只管画和点。

## 一、改之前

- 输入条左边相机钮、「＋」里「相册」「拍照」,三个入口都是 `files[0]`:选了一张 → 缩到长边 1600 → 上传 → 立刻发一条文字为空的消息,服务端记「(拍了一张)」。
- 拍糊了只能等老师回「再拍一张」,白跑一轮;孩子没法说「第 3 题不会」,老师靠猜;两页作业得分两轮发。
- 先缩到 1600 再用:以后要裁一小块题目,裁完只剩几百像素。
- 图解不出来、上传失败都走「不通」(头像灰),照片也丢了要重拍。
- 节头的小图点了是「再听这一节」,孩子端看不了大图。

## 二、流程

```
相机钮 ──拍 1 张──┐
＋ → 拍照 ─1 张──┼──→ 发照片屏(盖在老师页上) ──发给老师──→ 逐张上传 → 一条消息 {text, photos[]}
＋ → 相册 ─1–4 张─┘         │
                         取消 → 回老师页,什么都没发
```

- 拍照一次一张(相机本来就是一次一张);相册 `multiple`,**最多 4 张**,多选的只取前 4 张。服务端上限 9 张不变,家长端不变。
- 首页不能拍(2026-09-14 定的「在哪位老师页拍就给谁」),本文不改。
- 老师在想(pending)、今天条数到顶(limit)、看以前的话题(readonly)时入口照旧不可点。

## 三、发照片屏

从上到下:

| 区 | 内容 |
|---|---|
| 大图 | 当前那张,显示编辑后的样子 |
| 缩略图条 | 两张以上才有;点一张切过去;每张角上 ×,去掉最后一张 = 取消 |
| 工具 | **裁剪** · **圈画** · **转 90°** |
| 说一句 | 与输入条同一套:按住说话(浏览器识别)、点一下打字;认出的字显示在图下,可重说、可清掉;不说也能发 |
| 底 | 「取消」 · 「发给老师」 |

- 不强制编辑:拍完直接能发。
- 进裁剪 / 圈画是屏里的一个模式,工具条换成「整张 · 好了」/「撤销 · 清空 · 好了」,缩略图条、说一句、底部都藏起来;模式里改的只作用于当前那张。
- 屏里没有任何错误字样(孩子端的约定)。

## 四、裁剪

照 growth-apps `PhotoCrop.tsx` 的取舍,改写成页面里的原生 JS(孩子端是模板字符串页面,不引 React):

- 自由比例,四角拖 + 框内平移;手柄命中区 44px,框最小边 64 显示 px。
- 转 90°(顺时针):框永远轴对齐。PhotoCrop 是重画底图、框重置铺满;这里改成**坐标变换**,已有的框和笔画跟着转,不重置(见 §六)。
- 不做任意角微调、滤镜。

与参考实现的一处不同:**在原图分辨率上裁,导出时才缩到长边 1600**。iPad 相机约 12MP(4032×3024),在 iOS 单张 canvas 16.7MP 的上限内;只在导出时开一张 canvas。

## 五、圈画

目的是「指出问哪道」,不是在作业上答题(答题仍是老师出的 `canvas` 卡)。所以:

- 只有一支笔:红、半透明(`rgba(230,40,40,.65)`),线宽 = 起笔时看到那块的长边 × 1.5%(裁小了线也细,屏上看起来一样粗;起笔后定死,之后再裁不变);「撤销」「清空」;没有换色、没有橡皮。一次只认一根手指,手掌压着屏不算第二笔。
- 笔画存**原图坐标**(旋转之后的那个坐标系,见 §六),裁剪不裁笔画,导出时自然被裁掉。
- **只上传编辑后的那张**:旋转 → 裁剪 → 画笔画 → 缩到长边 1600 → jpeg 0.82。不另传原图。

老师那边(`src/cards/docs.ts` 作业照片一段,生成进 cotutor-board 技能)加一句:照片上的红圈是孩子自己圈的,先讲圈住的那道;消息里的字是孩子对这几张照片说的话。

## 六、坐标:`src/lib/photo-edit.ts`(纯函数)

一张照片的编辑状态:

```ts
interface PhotoEdit {
  w: number; h: number;          // 原图(已按 EXIF 摆正)的宽高
  rot: 0 | 1 | 2 | 3;            // 顺时针转了几个 90°
  crop: Rect | null;             // 在「转过之后的图」坐标里;null = 整张
  strokes: { width: number; pts: Pt[] }[];   // 同上坐标系;线宽也是图坐标
}
```

- `rotatedSize(e)` / `region(e)`:转过之后的宽高;看到 / 导出的那块(有框是框,没框是整张)。
- `rotateEdit(e)`:rot + 1;crop 与每个点按 `(x, y) → (H − y, x)` 变过去(H = 转之前的高)。转 4 次回原样。
- `dragCrop(rect, grip, dx, dy, W, H, min)`:四角 / 平移,夹在图内、不小于 min。页面把显示 px 换成图坐标后调它。
- `setCrop(e, rect)`:框铺满整张就记成 null(没裁)。`newStroke(e, pt)`:起一笔,线宽按当前那块定。
- `rotMatrix(e)`:原图 → 转过之后的图 的 canvas 变换;页面画底图用它,笔画已经在转过之后的坐标里,两边由测试对齐。
- `exportPlan(e, maxSide)`:输出宽高(裁后长边 ≤ maxSide,不放大)、源矩形、缩放。页面的 `paintEdit` 照它画:先 `setTransform(缩放, 平移到源矩形原点)`,再 `rotMatrix` 画底图,再画笔画。屏上显示也是同一个 `paintEdit`,只是底图换成长边 2048 的显示用副本。

与 `kid-board.ts` 一样剥掉类型后内联进页面(`boardLibSource` 泛化成 `libSource(name)`)。常量也在这里:长边 1600、相册 4 张、笔色与线宽比、框最小边。

## 七、发送与失败

- 点「发给老师」:逐张重新解原图 → `exportPlan` → canvas → jpeg 0.82 → `POST …/photos` 拿 path;全部拿到后关屏,发一条 `{text, photos}`(之后与打字发一样:等老师、忙 / 上限 / 不通照旧)。`text` 空时服务端照旧记「(拍了 N 张)」。
- **上传失败不丢编辑**:发照片屏不关、编辑留在内存,「发给老师」恢复可点;已传上去的 path 记在那张上,再点只传没传上的,改过的那张作废重传。页面自己不把头像变灰;真断网由心跳判定,老师页照旧关、发照片屏跟着关。老师不在了(404)→ 关屏回首页。
- 图解不出来(`Image.onerror`):那张不进缩略图条;一张都解不出 → 不开屏。不再当成「不通」。iPad 的 Safari 能解 HEIC,这条是兜底;Android 没验过。
- 原图只留 objectURL 与一张长边 2048 的显示用副本,导出时才再解原图:几张 12MP 常驻内存 iPad 吃不消。

## 八、看大图

- 节头小图 `stopPropagation`,点开全屏看图;节头其他地方点照旧是再听。
- 图适配屏幕;双指缩放、单指拖、双击复位(复用图片舞台的 `pinch`);右上角 × 关(点任意处关会和缩放打架);一节几张时左右两个翻页钮 + 「2 / 3」,从点的那张开始。
- **不碰播放**:老师接着念,孩子边听边看自己的作业。
