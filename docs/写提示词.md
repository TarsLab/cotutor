# 写提示词

`grades/grade-<n>/agents/`、`skills/`、`cards/*/card.md` 里的字最后都给模型读,但改它们的是人。本篇是写这些字的规矩:人读得懂、改得动,模型照样读得懂。

自造的词见《词表.md》。下文 `agents/` 的出厂文件路径均相对于所选年级包;workspace 内的路径不变。

## 一、先认读者

动笔前先查这张表:这个文件谁读、怎么到它手里、改完怎么验。

| 文件 | 谁读 | 怎么到它手里 | 改完怎么验 |
|---|---|---|---|
| `agents/*-tutor.md` | 有脸的老师 | 系统提示。init 拷进 workspace;家长改过的,upgrade 只报 diff | `cotutor replay` |
| `skills/cotutor-tutor/SKILL.md` | 有脸的老师 | 应用去掉 frontmatter 和注释,在话题第一条放进 `<cotutor-rules>` | `cotutor pack` 看注入,再 replay |
| `cards/板书怎么写.md` 和 `cards/<种类>/card.md` | 有脸的老师 | gen:skills 拼成 `skills/cotutor-board/`。SKILL.md 预载进系统提示,或放进 `<cotutor-board>`;references 就是 card.md 原样,老师按需 Read | cards.test、skills.test,再 replay |
| `skills/cotutor-tutor/references/上下文包.md` | 有脸的老师;cotutor-analyze | 按需 Read | `cotutor pack` 对一眼 |
| `skills/cotutor-vault/SKILL.md` | 有脸的老师 | 老师按需 Read | replay 一轮讲解;记账跑 `cotutor bookkeep` |
| `agents/<老师>/activities/<名>.md` | 一节一个读者:「老师怎么带」给有脸的老师,「<工具人>收到什么」给工具人,别的节给家长 | init 拷进老师的家;孩子从首页的 activity 按钮进来,这个话题的系统提示就是老师那节(Qwen 的 `{systemBody}`;不读老师文件) | `cotutor activity check`,再真跑 |
| `skills/cotutor-home/`、`cotutor-tune/`、`cotutor-analyze/` | workspace 根的编程助手(家长用) |编程助手按 description 挑 | 在试用 workspace 里开编程助手说一次 |
| references 里标「机器生成」的 | 同所在技能 | 由 `src/lib/*-doc.ts` 或 card.md 生成 | 改源,跑 `pnpm run gen:skills` |

- 仓里改完的出厂件要 `cotutor upgrade` 进试用 workspace 才验得到。
- 措辞一变,行为就可能变。只动了标点也要验。

## 二、一个文件只对一个读者说话

- 正文只写给上表里那个读者。
- 给人看的话(谁读、能不能改、改了怎么验)放进文件头的注释,紧跟 frontmatter:

```markdown
<!-- 给人看
谁读:有脸的老师,应用在话题第一条放进 <cotutor-rules>
能改:机器件,upgrade 覆盖。某位老师要不同做法,写进那位老师的文件
改了:cotutor pack 看注入,再 replay 对照
-->
```

- activity 文件是例外:一个功能的东西放一个文件,家长才看得全。改成一节只对一个读者说话,标题就是读者(见上表)。
- description 只写一件事:读者什么时候用它。
-编程助手挑的技能,description 写「什么时候用」加一句「不是什么」。
- 应用注入的技能(tutor、board)没人挑,description 一句话说它是什么就够。

## 三、一条规矩一句话

- 列表里每条只讲一件事。一条说了三件事,就拆成三条。
- 一句大约 40 字以内。超了,多半是塞了两条规矩,或者把理由塞进了括号。
- 括号只放一个短补充,不套括号。例外和理由挪出去。
- 有先后的写成编号步骤,没先后的写成列表,要对照的写成表。
- 先给例子,再写规矩。一段完整的好回复,比十条规矩好懂。
- 多说做什么,少说别做什么。要禁一件事,同时写清改做什么。

改前:

```markdown
- 练习放在一节末尾,一节一问:认意思用 `choice`(看英文选中文,或反过来);拼一个词、句子里缺一个词用 `word` 卡给他看、请他说;要孩子说一整句(对话、造句)就在讲稿里问,孩子说话答。练对话时你演一个角色说一句,请孩子接下一句。
```

改后:

```markdown
### 练

- 练习放在一节末尾,一节只问一次。
- 认意思用 `choice` 卡:看英文选中文,或反过来。
- 拼一个词:用 `word` 卡给他看,请他说出来。
- 要孩子说一整句,就在讲稿里问,孩子开口答。
- 练对话:你演一个角色说一句,请孩子接下一句。
```

## 四、规矩写做什么,理由写在注释里

- 不显然的规矩,下面用注释写为什么:

```markdown
- 原图只 Read 一次。
<!-- 为什么:每读一张图都是一轮工具调用,孩子在等。 -->
```

- 有了理由,人才知道这条能不能改、改了会坏什么。
- 注释直接写当前约束与理由;需要解释实现时指向相关代码或测试。
- 注释要独占一行(可以跨几行)。行内的注释不剥。
- 守则(cotutor-tutor)的注释,应用注入时剥掉,不占模型的 token(`stripHumanNotes`)。
- 板书写法的手写部分(`cards/板书怎么写.md`)的注释,生成 SKILL.md 时就剥掉。
- card.md 原样出厂成 references,老师按需 Read,里面的注释会进模型。`<!-- expect -->` 是例子的测试,生成 SKILL.md 时剥掉。
- 老师文件和编程助手读的技能,注释原样进模型,所以要短。

## 四点五、只对某几种卡有用的段落

- `cards/板书怎么写.md` 与守则(cotutor-tutor)里,只对某几种卡有用的段落用 `{{有 x y}}` … `{{/有}}` 包起来,各占一行。
- 递给某位老师时,他的 `cards` 里 x、y 都有才留(《卡片协议.md》「谁拿到哪些卡」)。能套。
- 包起来的段落删了以后,前后要还读得通:别包编号列表中间的一步,挪成单独一段。
- 改完 `pnpm run gen:skills`;`cotutor pack <老师>` 看这位老师拿到的那份。
- activity 文件的「老师怎么带」也能用,名字还可以是这个 activity 的参数:填了才留。`cotutor activity check` 查名字认不认得、配没配对。

## 五、一件事只手写在一处

同一条规矩只在一个文件里写全。别处要提,写一句,再指过去。

| 什么事 | 写在哪 |
|---|---|
| 所有有脸的老师都守的 | `skills/cotutor-tutor/SKILL.md` |
| 某一科怎么教 | 那位老师的文件 |
| 板书的通用写法、作业照片怎么接 | `cards/板书怎么写.md` |
| 一种卡怎么写 | `cards/<种类>/card.md` |
| vault 怎么读,记忆、记账怎么写 | `skills/cotutor-vault/SKILL.md` |
| 上下文包每一行是什么 | `skills/cotutor-tutor/references/上下文包.md`,手写;和 `src/schema/context-pack.ts` 靠 skills.test 对上,加了字段忘了写就红 |
| 关于这个孩子的 | 家长的 vault,不进仓 |

- 给不同读者各提醒一句可以。比如 analyze、tune、home 各说一句「别把老师当子代理派」。
- 同一段解释抄两遍不行。
- 机器生成的副本不算重复:改源,跑 gen:skills。

## 六、用词表里的词

- 自造的词先查《词表.md》。表里有,就用表里那个,不另起名字。
- 要用新词,先加进词表,再用。
- 一个词只指一样东西。「会话」是 CLI 的,「话题」是孩子看到的,别混用。

## 七、老师文件的样子

家长最常改的就是老师文件。每位老师用同一个样子,家长改哪条都能找到地方。

````markdown
---
(frontmatter:name / description / maxTurns / permissionMode,不加别的)
---
你是这个家的数学老师,对面是一个孩子。(人设两三句:性格、说话的样子)

上下文包怎么看、三种回复、记忆段、不变的规矩,在每个话题第一条的 `<cotutor-rules>` 里,照着做;这里只写数学老师自己的。

## 数学这一科

### 讲之前
### 讲
### 练
### 孩子这样说时

### 一段好的回复

(一节完整的板书:讲稿、卡,讲完就停)
````

- 指向 `<cotutor-rules>` 那一行不能删,老师靠它知道守则在哪。
- 用不上的小节可以不写。
- 关于这个孩子的事不写在这里,写进 vault。

## activity 文件的最小写法

普通聊天的系统提示来自老师文件;activity 使用自己的「老师怎么带」,不继承老师正文。共同守则、板书写法和 vault 上下文仍由应用提供。

````markdown
---
name: 预习
description: 根据材料试着理解一个新内容
cards: photo choice
---

## 家长填的

```参数
范围: 字,可空 —— 本次课文、题目或单元
```

## 老师怎么带

你是这个家的数学老师,带孩子预习。
本次范围在上下文包的 activity.params 里。
第一句: 材料不足时请孩子拍照;有材料时只带一个小步骤。
每节写给孩子听的讲稿,需要回答时只问一个问题。
收: 完成一个小步骤或孩子想停时结束。

## 怎么挂

首页老师卡写 activity 预习,下面可填「范围:」。
````

参数类型为 `字`、`词表`、`数`、`日期`、`课包`;可声明 `可空`、`缺省 X`、数值的 `A 到 B`。参数值不插进老师正文,从上下文包读取;条件段用 `{{有 参数名}}` 与 `{{/有}}`。`cards` 列出此 activity 所需卡片。

「应用算的」「应用拦的」与「<工具人>收到什么」只按已实现的名字声明,不能靠提示词增加能力。支持的名字与插槽见 `src/schema/activity.ts`,解析与检查见 `src/lib/activity.ts`。其他小节给家长读。需要起老师的 activity 必须写「老师怎么带」及人设、`第一句:`、`收:`;`page` 指向专用页面时不写这一节。

改完先跑 `cotutor activity check <老师> <activity>`,再用 `cotutor pack <老师> --activity <activity>` 看实际提示。例子放同目录的 `<名>.例子.md`,评估要求见《年级教学包.md》。

## 八、改完自查

1. 读者:正文里有没有对别的读者说的话?
2. 长句:有没有一条塞了两件事?
3. 理由:不显然的规矩下面有没有注释?
4. 重复:这条在别的文件里还写着吗?(拿关键词 grep 一下)
5. 验:按第一节的表跑一遍。
