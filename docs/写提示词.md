# 写提示词

`grades/grade-<n>/agents/`、`skills/`、`cards/` 下的 md 里的字最后都给模型读,但改它们的是人。本篇是写这些字的规矩:人读得懂、改得动,模型照样读得懂。

自造的词见《词表.md》。下文 `agents/` 的出厂文件路径均相对于所选年级包;workspace 内的路径不变。

## 一、先认读者

动笔前先查这张表:这个文件谁读、怎么到它手里、改完怎么验。

| 文件 | 谁读 | 怎么到它手里 | 改完怎么验 |
|---|---|---|---|
| `skills/cotutor-tutor/SKILL.md` | 老师 | 应用去掉 frontmatter 和注释,在话题第一条放进 `<cotutor-rules>` | `cotutor pack` 看注入,再 replay |
| `cards/动作怎么写.md` | 老师 | 剥掉注释,跟在 activity 的「老师怎么带」后面进系统提示(讲稿与动作怎么写) | acts.test、cards-doc.test,再 replay |
| `cards/<种类>/card.md`(首页的老师牌、听写牌) | 家长的编程助手 | gen:skills 拷进 `skills/cotutor-home/references/` | cards-doc.test、skills.test |
| `skills/cotutor-tutor/references/上下文包.md` | 老师;cotutor-analyze | 按需读 | `cotutor pack` 对一眼 |
| `agents/<老师>/activities/<名>.md` | 一节一个读者:「老师怎么带」给老师,「<工具人>收到什么」给工具人(认字),别的节给家长 | init 拷进老师的家;话题都从一个 activity 开始,这个话题的系统提示就是老师那节;家长改过的,refresh 只报 diff | `cotutor activity check`,再真跑 |
| `skills/cotutor-home/`、`cotutor-tune/`、`cotutor-analyze/` | workspace 根的编程助手(家长用) |编程助手按 description 挑 | 在试用 workspace 里开编程助手说一次 |
| references 里标「机器生成」的 | 同所在技能 | 由 `src/app/skills/*-doc.ts` 或 card.md 生成 | 改源,跑 `pnpm run gen:skills` |

- 仓里改完的出厂件要 `cotutor refresh` 进试用 workspace 才验得到。
- 措辞一变,行为就可能变。只动了标点也要验。

## 二、一个文件只对一个读者说话

- 正文只写给上表里那个读者。
- 给人看的话(谁读、能不能改、改了怎么验)放进文件头的注释,紧跟 frontmatter:

```markdown
<!-- 给人看
谁读:老师,应用在话题第一条放进 <cotutor-rules>
能改:机器件,refresh 覆盖。某位老师要不同做法,写进那位老师的文件
改了:cotutor pack 看注入,再 replay 对照
-->
```

- activity 文件是例外:一个功能的东西放一个文件,家长才看得全。改成一节只对一个读者说话,标题就是读者(见上表)。
- description 只写一件事:读者什么时候用它。
-编程助手挑的技能,description 写「什么时候用」加一句「不是什么」。
- 应用注入的技能(tutor)没人挑,description 一句话说它是什么就够。

## 三、一条规矩一句话

- 列表里每条只讲一件事。一条说了三件事,就拆成三条。
- 一句大约 40 字以内。超了,多半是塞了两条规矩,或者把理由塞进了括号。
- 括号只放一个短补充,不套括号。例外和理由挪出去。
- 有先后的写成编号步骤,没先后的写成列表,要对照的写成表。
- 先给例子,再写规矩。一段完整的好回复,比十条规矩好懂。
- 多说做什么,少说别做什么。要禁一件事,同时写清改做什么。

改前:

```markdown
- 练习放在一节末尾,一节一问:认意思先 `[[看 …]]` 那个词,请他说中文;拼一个词 `[[写 …]]` 在白纸条上给他看、请他说;要孩子说一整句(对话、造句)就在讲稿里问,孩子说话答。练对话时你演一个角色说一句,请孩子接下一句。
```

改后:

```markdown
### 练

- 练习放在一节末尾,一节只问一次。
- 认意思:`[[看 …]]` 那个词,请他说中文。
- 拼一个词:`[[写 …]]` 在白纸条上给他看,请他说出来。
- 要孩子说一整句,就在讲稿里问,孩子开口答。
- 练对话:你演一个角色说一句,请孩子接下一句。
```

## 四、规矩写做什么,理由写在注释里

- 不显然的规矩,下面用注释写为什么:

```markdown
- 原图只用 read_file 读一次。
<!-- 为什么:每读一张图都是一轮工具调用,孩子在等。 -->
```

- 有了理由,人才知道这条能不能改、改了会坏什么。
- 注释直接写当前约束与理由;需要解释实现时指向相关代码或测试。
- 注释要独占一行(可以跨几行)。行内的注释不剥。
- 守则(cotutor-tutor)的注释,应用注入时剥掉,不占模型的 token(`stripHumanNotes`)。
- 讲稿与动作的写法(`cards/动作怎么写.md`)的注释,进系统提示前剥掉。
- 首页牌的 card.md 原样拷进 `cotutor-home` 的 references,编程助手按需读,里面的注释会进模型。`<!-- expect -->` 是例子的测试。
- 编程助手读的技能,注释原样进模型,所以要短。

## 四点五、只在家长填了参数时才要的段落

- activity 文件的「老师怎么带」里,只在家长填了某个参数时才要的段落用 `{{有 参数名}}` … `{{/有}}` 包起来,各占一行。能套。
- 包起来的段落删了以后,前后要还读得通:别包编号列表中间的一步,挪成单独一段。
- `cotutor activity check` 查名字是不是参数、配没配对。

## 五、一件事只手写在一处

同一条规矩只在一个文件里写全。别处要提,写一句,再指过去。

| 什么事 | 写在哪 |
|---|---|
| 所有老师都守的 | `skills/cotutor-tutor/SKILL.md` |
| 某一科怎么教 | 那位老师每个 activity 的「<科>这一科」(例外:几份一字不差,测试盯着) |
| 讲稿的通用写法、动作怎么写、作业照片怎么接 | `cards/动作怎么写.md` |
| 首页的一种牌怎么写 | `cards/<种类>/card.md` |
| 记忆怎么写、带工具时 vault 怎么读 | `skills/cotutor-tutor/SKILL.md` |
| 记账怎么写 | 记账那条消息本身(`src/memory/diary.ts` 的 `bookkeepingPrompt`) |
| 上下文包每一行是什么 | `skills/cotutor-tutor/references/上下文包.md`,手写;和 `src/schema/context-pack.ts` 靠 skills.test 对上,加了字段忘了写就红 |
| 关于这个孩子的 | 家长的 vault,不进仓 |

- 给不同读者各提醒一句可以。比如 analyze、tune、home 各说一句「别把老师当子代理派」。
- 同一段解释抄两遍不行。
- 机器生成的副本不算重复:改源,跑 gen:skills。

## 六、用词表里的词

- 自造的词先查《词表.md》。表里有,就用表里那个,不另起名字。
- 要用新词,先加进词表,再用。
- 一个词只指一样东西。「会话」是脑那头接着聊的历史,「话题」是孩子看到的,别混用。

## 七、「<科>这一科」那一节的样子

没有老师文件:一位老师怎么教,全写在他家里的每个 activity 里。一科通用的做法(换哪个按钮进来都成立的)在每个 activity 的「## 老师怎么带」里写一遍,样子一样,家长改哪条都能找到地方。

````markdown
## 老师怎么带

你是这个家的数学老师,带孩子检查作业。(人设:这个 activity 里老师是谁、在做什么)

第一句: …

### 数学这一科

<!-- 一科通用的做法:这位老师的每个 activity 里一字不差(tests/activity.test.ts 盯着);改一处,几份一起改。 -->

- 说话慢,一次只讲一个想法;先用具体情境,再说抽象方法。
- …

### (这个 activity 自己的小节:板、第一轮、带着做……)

收: …
````

- 这一节在这位老师的几个 activity 里一字不差。出厂的三科有测试盯着;改一处,几份一起改。
- 一条一句;只放这一科在哪个按钮里都成立的。某个按钮才有的放那个 activity 自己的小节。
- 上下文包怎么看、两种回复、记忆段、不变的规矩在 `<cotutor-rules>` 里,这里不重复。
- 关于这个孩子的事不写在这里,写进 vault。

## activity 文件的最小写法

话题的系统提示就是 activity 的「老师怎么带」,后面跟着讲稿与动作怎么写(`cards/动作怎么写.md`)。共同守则和 vault 上下文由应用提供。

````markdown
---
name: 预习
description: 根据材料试着理解一个新内容
base: photo
---

## 家长填的

```参数
范围: 字,可空 —— 本次课文、题目或单元
```

## 老师怎么带

你是这个家的数学老师,带孩子预习。
第一句: 材料不足时请孩子拍照;有材料时只带一个小步骤。

### 数学这一科

(这位老师每个 activity 里一字不差的那一节,见第七节)

本次范围在上下文包的 activity.params 里。
每节写给孩子听的讲稿,需要回答时只问一个问题。
收: 完成一个小步骤或孩子想停时结束。

## 怎么挂

首页老师牌写 activity 预习,下面可填「范围:」。
````

参数类型为 `字`、`词表`、`数`、`日期`、`课包`、`练习册`(vault `练习册/` 下一册的文件夹名);可声明 `可空`、`缺省 X`、数值的 `A 到 B`。参数值不插进老师正文,从上下文包读取;条件段用 `{{有 参数名}}` 与 `{{/有}}`。

头上的 `base:` 说这一节课铺哪种页(不写当 `base: photo`):

- `base: photo`:孩子点进来先拍照(或从相册选、选课本页,不拍就是一张白纸),照片一发就铺上照片页(几张从上往下连着),不等老师;照片上认出的字(要写「认字收到什么」)是这一页的文字层。参考二年级三科的「检查作业」「复习」、英语「预习」。
- `base: textbook`:页上铺 vault `教材/` 下这一科的课本 PDF,不拍照:孩子点进来先铺目录。参考二年级数学、语文的「预习」。
- `base: workbook`:页上铺 vault `练习册/` 下的一册(「家长填的」里要有一个类型是 `练习册` 的参数,首页按钮填它),不拍照:孩子点进来就铺那一册,用笔直接在页上做。题框、能写的格子、给老师的答案都在那一册的 `workbook.json` 里,老师看第几题、圈字照它找。参考二年级数学的「做练习册」。
- `base: lecture`:页上铺一堂小课堂(课包或视频),孩子从头看完才能开口;老师写 `[[看 0:19–0:30]]` 放课里一段。从首页小课堂按钮进来的话题都铺它。参考三科的「小课堂」。
- 看图说话这种「图铺成页、孩子说」的,就是 `base: photo` 加 `listen: open`(参考语文「看图说话」)。

页上老师不写卡,对页做什么写在讲稿的句子后面(`[[翻 坐井观天]]`、`[[看 第 3 题]]`、`[[圈 井沿]]`、`[[摆 点阵 6 行 6 个]]`、`[[请 圈]]`、`[[翻 白纸]]`),那一句念完应用才做。动作的写法给老师的那页是 `cards/动作怎么写.md`,应用放进系统提示;「老师怎么带」里只写这个 activity 怎么用它们,例子直接写成讲稿加动作,不套围栏(套了老师会照着写围栏)。每一轮上下文包多一段 `board:`(底、你画的、开放、孩子做的、最近点的、孩子在看),页上印的字第一次看到那一页时给一条 `<page>`。孩子写完停了笔,应用替他交给老师(`live:` 里 `app: pen`)。

头上还能写两样:

- `listen: open`:一直听,孩子不用按着说(一问一答多、请他说多的,如英语「口语课」)。不写照 cotutor.json 这位老师的 `live.listen`,缺省按住说。
- `reply: mouth`:嘴先答。老师一轮最后一句请孩子说一句(`[[请 说 他该说的]]`),他答了嘴先接:说中了嘴接一句、老师接着写下一步;没说中嘴提示一下再等他,两次还不行才交给老师。不写是老师(脑)先答,嘴只照念。数学都用脑;英语里简单、要快的才写它。

哪个 activity 都能请孩子说:讲稿那句后面写 `[[请 说 duck]]`,那句念完应用停下等他说,他说了接着念下一句(老师这句里自己说了那个词是跟我说,没说是你先说)。

以前头上写的 `board: page`、`cards:` 不用再写了:读进来就丢,照 `base` 走(没写当 `base: photo`),`cotutor activity check` 提一句。

「<工具人>收到什么」只按已实现的名字声明,不能靠提示词增加能力。支持的名字与插槽见 `src/schema/activity.ts`,解析与检查见 `src/runtime/activity.ts`。其他小节给家长读。activity 必须写「老师怎么带」及人设、`第一句:`、`收:`。听写不是 activity:挑词的要求在老师家里的 `听写.md`。

改完先跑 `cotutor activity check <老师> <activity>`,再用 `cotutor pack <老师> --activity <activity>` 看实际提示。例子放同目录的 `<名>.例子.md`,评估要求见《年级教学包.md》。

## 八、改完自查

1. 读者:正文里有没有对别的读者说的话?
2. 长句:有没有一条塞了两件事?
3. 理由:不显然的规矩下面有没有注释?
4. 重复:这条在别的文件里还写着吗?(拿关键词 grep 一下)
5. 验:按第一节的表跑一遍。
