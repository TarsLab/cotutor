# 写提示词

`agents/`、`skills/`、`cards/*/card.md`、`themes/*/post.md` 里的字最后都给模型读,但改它们的是人。本篇是写这些字的规矩:人读得懂、改得动,模型照样读得懂。

自造的词见《词表.md》。

## 一、先认读者

动笔前先查这张表:这个文件谁读、怎么到它手里、改完怎么验。

| 文件 | 谁读 | 怎么到它手里 | 改完怎么验 |
|---|---|---|---|
| `agents/*-tutor.md` | 有脸的老师 | 系统提示。init 拷进 workspace;家长改过的,upgrade 只报 diff | `cotutor replay` |
| `agents/scene-maker.md` | 画图老师 | 同上 | 放一张新场景卡,看它做出课包 |
| `skills/cotutor-tutor/SKILL.md` | 有脸的老师 | 应用去掉 frontmatter,在话题第一条放进 `<cotutor-rules>` | `cotutor pack` 看注入,再 replay |
| `cards/<种类>/card.md` | 有脸的老师 | gen:skills 生成 `skills/cotutor-board/`。SKILL.md 预载进系统提示,或放进 `<cotutor-board>`;references 老师按需 Read | board.test、skills.test,再 replay |
| `skills/cotutor-vault/SKILL.md` | 有脸的老师 | 老师按需 Read | replay 一轮讲解;记账跑 `cotutor bookkeep` |
| `skills/cotutor-home/`、`cotutor-tune/`、`cotutor-analyze/` | workspace 根的 Claude Code(家长用) | Claude Code 按 description 挑 | 在试用 workspace 里开 Claude Code 说一次 |
| `themes/default/post.md` | 后期的快模型 | 每拍填好占位符发出去 | `pnpm test` 看快照,再跑 `scripts/post-eval.ts` |
| references 里标「机器生成」的 | 同所在技能 | 由 `src/lib/*-doc.ts` 或 card.md 生成 | 改源,跑 `pnpm run gen:skills` |

- 仓里改完的出厂件要 `cotutor upgrade` 进试用 workspace 才验得到。
- 措辞一变,行为就可能变。只动了标点也要验。

## 二、一个文件只对一个读者说话

- 正文只写给上表里那个读者。
- 给人看的话(谁读、能不能改、改了怎么验)放进文件头的注释,紧跟 frontmatter:

```markdown
<!-- 给人看
谁读:有脸的老师,应用在话题第一条放进 <cotutor-rules>
能改:机器件,upgrade 覆盖。某位老师要不同做法,写进那位老师的文件
改了:cotutor pack 看注入,再 replay 对照
-->
```

- description 只写一件事:读者什么时候用它。
- Claude Code 挑的技能,description 写「什么时候用」加一句「不是什么」。
- 应用注入的技能(tutor、board)没人挑,description 一句话说它是什么就够。

## 三、一条规矩一句话

- 列表里每条只讲一件事。一条说了三件事,就拆成三条。
- 一句大约 40 字以内。超了,多半是塞了两条规矩,或者把理由塞进了括号。
- 括号只放一个短补充,不套括号。例外和理由挪出去。
- 有先后的写成编号步骤,没先后的写成列表,要对照的写成表。
- 先给例子,再写规矩。一段完整的好回复,比十条规矩好懂。
- 多说做什么,少说别做什么。要禁一件事,同时写清改做什么。

改前:

```markdown
- 练习放在一节末尾,一节一问:认意思用 `choice`(看英文选中文,或反过来);拼一个词、句子里缺一个词用 `fill`;要孩子说一整句(对话、造句)就在讲稿里问,孩子说话答。练对话时你演一个角色说一句,请孩子接下一句。
```

改后:

```markdown
### 练

- 练习放在一节末尾,一节只问一次。
- 认意思用 `choice` 卡:看英文选中文,或反过来。
- 拼一个词、补句子里缺的词,用 `fill` 卡。
- 要孩子说一整句,就在讲稿里问,孩子开口答。
- 练对话:你演一个角色说一句,请孩子接下一句。
```

## 四、规矩写做什么,理由写在注释里

- 不显然的规矩,下面用注释写为什么:

```markdown
- 原图只 Read 一次。
<!-- 为什么:每读一张图都是一轮工具调用,孩子在等。 -->
```

- 有了理由,人才知道这条能不能改、改了会坏什么。
- 理由来自拍板记录的,写上出处:`<!-- 为什么:……《工作流程.md》拍板 3 -->`。
- 老师文件和 Claude Code 读的技能,注释原样进模型,所以要短。
- 待做:应用注入 `<cotutor-rules>`、`<cotutor-board>` 时剥掉注释(`tutorRulesBody`、`boardGuideBody`)。做之前,注释也原样进模型。

## 五、一件事只手写在一处

同一条规矩只在一个文件里写全。别处要提,写一句,再指过去。

| 什么事 | 写在哪 |
|---|---|
| 所有有脸的老师都守的 | `skills/cotutor-tutor/SKILL.md` |
| 某一科怎么教 | 那位老师的文件 |
| 一种卡怎么写 | `cards/<种类>/card.md` |
| vault 怎么读,记忆、记账怎么写 | `skills/cotutor-vault/SKILL.md` |
| 上下文包每一行是什么 | `src/schema/context-pack.ts`(待做:生成一份 reference,其余地方指过去) |
| 关于这个孩子的 | 家长的 vault,不进仓 |

- 给不同读者各提醒一句可以。比如 analyze、tune、home 各说一句「别把老师当子代理派」。
- 同一段解释抄两遍不行。
- 机器生成的副本不算重复:改源,跑 gen:skills。

## 六、用词表里的词

- 自造的词先查《词表.md》。表里有,就用表里那个,不另起名字。
- 要用新词,先加进词表,再用。
- 一个词只指一样东西。「会话」是 CLI 的,「话题」是孩子看到的,别混用。

## 七、老师文件的样子

家长最常改的就是老师文件。每位老师用同一个样子,家长改哪条都能找到地方。

````markdown
---
(frontmatter:name / description / maxTurns / permissionMode,不加别的)
---
你是这个家的数学老师,对面是一个孩子,有时是家长。(人设两三句:性格、说话的样子)

上下文包怎么看、三种回复、记忆段、不变的规矩,在每个话题第一条的 `<cotutor-rules>` 里,照着做;这里只写数学老师自己的。

## 数学这一科

### 讲之前
### 讲
### 练
### 孩子这样说时

### 一段好的回复

(一节完整的板书:讲稿、卡、末句问孩子)
````

- 指向 `<cotutor-rules>` 那一行不能删,老师靠它知道守则在哪。
- 用不上的小节可以不写。
- 关于这个孩子的事不写在这里,写进 vault。

## 八、改完自查

1. 读者:正文里有没有对别的读者说的话?
2. 长句:有没有一条塞了两件事?
3. 理由:不显然的规矩下面有没有注释?
4. 重复:这条在别的文件里还写着吗?(拿关键词 grep 一下)
5. 验:按第一节的表跑一遍。
