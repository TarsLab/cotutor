# 卡片协议(给改代码的人)

板书的一节 = 卡(围栏)+ 讲稿(段落)。卡按**能力**分种类:text / read / choice / fill / image / tianzige / word / lecture / canvas / record / code,十一种(场景卡 2026-10-07 删了,《agent层设计.md》拍板 13),不按样子分——样子(底色、字号)在主题(`themes/<name>/`)里取值、由机械规则(`kid-board.ts` 的 `tintFor` / `lookFor`)或围栏行上写的修饰词定;并排由孩子端按卡量出来的宽度排(`kid-board.ts` 的 `rowsFor`,《工作流程.md》§二「排版」);都不进卡的协议。

给**老师**看的那一半是 `cards/<kind>/card.md`(`pnpm run gen:skills` 生成到包根 `skills/cotutor-board/` 入库:`SKILL.md` 是总表,`references/<kind>.md` 逐张,`references/README.md` 索引;init / upgrade 拷进 workspace 的 `.claude/skills/cotutor-board/`,机器件、每次覆盖);这份是给**开发者**看的:一种卡由哪几个文件组成、加一种卡怎么做、怎么验。

## 一种卡有哪几个文件

| 文件 | 管什么 | 谁读 |
|---|---|---|
| `src/cards/<kind>.ts` | 服务端定义 `CardKind`:`props` 契约(zod)、`parse(body, mods)` 围栏正文 → props(抛错 = 没解析成,退文字卡 + warning)、`strip` 剥答案、`state` 契约、`describe(props, state)` 给老师的一句、`assets(props)` 要预生成的配音 | 解析器、`/api/kid/*`、上下文包 |
| `cards/<kind>/card.md` | 协议文档,八个固定栏目(下面);**例子即测试** | 老师(出厂到 workspace)、`tests/cards-doc.test.ts`、语法表生成 |
| `cards/<kind>/card.css` | 这种卡的结构样式(选项行、空、缩略图……),只用主题变量(`--tint-*` `--pen-*` `--line` …);服务把它们拼在主题 css 前面 `/kid/theme.css`,主题写同名选择器能盖 | 孩子端页面、舞台包 |
| `src/lib/kid-board.ts` | 页面那一半的纯逻辑:`cardTexts`(能被标注的字)、`hasState` / `isHeavy`、`cardTitle`、`stateSummary`、机械规则 `tintFor` / `lookFor` / `penFor`,按 kind 名 switch;**不能有运行时 import**(剥类型内联进页面) | 服务端与页面同一份 |
| `src/server/kid-page.ts` `renderCard` | 紧凑态与舞台态怎么画,按 kind 名分支;重卡(lecture / canvas)的舞台在 `src/stage/`(iframe 里的舞台包);田字格卡(tianzige)没有舞台,点字就写,数据由 `src/server/tianzige.ts` 从 hanzi-writer-data 现读、路由 `/api/kid/tianzige/<字>`;单词卡(word)的字母笔顺由 `src/server/letters.ts` 从 drawtell/glyphs 采点、路由 `/api/kid/letters/<词>` | 孩子端 |

四处靠 kind 名对上;`src/cards/index.ts` 是登记表(`CARD_KINDS`),`src/cards/docs.ts` 读 md / css。

## 卡用在哪:板书与首页

`CardKind.where` 说这种卡能用在哪(缺省只板书)。首页(《首页设计.md》)是家长批准的那页,和板书同一个解析器(`parseBoard(text, {place: 'home'})`):

- 只首页:`tutor`(老师卡)。它不进 `cotutor-board` 技能,老师在板书里写了退文字卡 + 提醒;协议进 `cotutor-home` 技能的 references/。
- 板书与首页:`text` `read` `image` `tianzige` `word`。
- 只板书:`choice` `fill` `canvas` `record` `code`(做完要交给某位老师);首页写了退文字卡,首页检查报「要改」。

加一种首页卡同样是下面七步,区别:`where: ['home']`;第 5 步画在 `kid-page.ts` 的 `renderHome`(老师卡)或 `renderCard(c, i, null, false)`(`secIdx` 为 null = 首页,不开舞台);第 6 步放进 mock 的样例首页(`mockHomeMd`);`pnpm run gen:skills` 会把它写进 `skills/cotutor-home/references/`。

## card.md 的八个栏目

1. **是什么**(一句)
2. **什么时候用 / 别用**(`- 用:` / `- 别用:` 各至少一条,别用要给替代)
3. **写法**(围栏标签、修饰词、正文规则)
4. **例子**(≥ 1 个,每个围栏前一行 `<!-- expect {"kind":"…","props":{…}} -->`:测试把围栏喂 `parseCard`,kind 要对、列出的 props 逐个深比、`warning: true` 才允许有 warning)
5. **反例**(常见错法 + 解析器怎么退化;同样带 expect)
6. **孩子看到什么**(紧凑态、舞台、能标注的字在哪、有没有交互)
7. **你会收回什么**(`cards:` 段那一行长什么样;没有状态写「没有」)
8. **状态的形状**(有的话,JSON 一行)

总表 `SKILL.md` 由每张的 1、3、4 栏拼成(expect 注释去掉),frontmatter 的 description 列出全部种类;README 由 1 与「- 用:」拼成。改了 md 跑 `pnpm run gen:skills`(`tests/skills.test.ts` 断言入库的和生成的一致),workspace 里的由 `cotutor init` / `cotutor upgrade` 换新。

## 加一种卡(七步)

1. `src/cards/<kind>.ts`:照 `choice.ts` 写 `CardKind`;有交互就给 `state` + `describe`;答案类字段在 `strip` 里剥。
2. `src/cards/index.ts`:import + `CARD_KINDS` 加一项。
3. `cards/<kind>/card.md`:八个栏目;例子带 expect。`cards/<kind>/card.css`:结构样式,只用主题变量。然后 `pnpm run gen:skills` 重生成 `skills/cotutor-board/`。
4. `src/lib/kid-board.ts`:`cardTexts` 加一个 case(哪些字能标注);有交互加进 `hasState`;在 iframe 里开的加进 `isHeavy`;`tintFor` / `penFor` 给缺省。
5. `src/server/kid-page.ts` `renderCard`:紧凑态一个分支(`box(cls, …)` 会带 `data-tint` / `data-look`);有舞台交互再写 `stage=true` 的分支;重卡在 `src/stage/main.tsx` 装组件。
6. `src/server/mock.ts`:某位老师的脚本里放一张;`tests/mock.test.ts` 加一条。
7. 验:`pnpm test`(`cards-doc.test.ts` 会跑你的例子),`cotutor mock` 开 `/?tutor=<老师>&stage=<节>.<卡>` 截图(手机 `--force-device-scale-factor=2 --window-size=780,1688`,平板 `--window-size=1180,820`)。

新种类缺省全宽;要能半宽,加进 `kid-board.ts` 的 `canHalf`,并在 `fitsHalf` 里说怎么算放得下。

## 提问卡

**老师最后那一问必须在板上有一张卡。**起因:2026-09-20 语文老师讲《堆雪人》填空,末句「这是要堆什么?」没配卡,念完只剩字幕一行,孩子回头找不到老师问了什么——而这一问是整节最要紧的一句(播放器只在末句问句停下等孩子,中间的问句念完就过)。

两头都做:

- **老师那头**(`cotutor-board` 总表开头):告诉老师只有末句会停(中间的问句念完就过,问几个不限);末句这一问能选配 choice、能填配 fill;开放的问题不用配卡,也别自己写。
- **应用兜底**(`parseBoard`,机械规则,不靠老师听话):定稿的板书(不是 partial、不是首页)末句是问句、这句没带 cue,且它指的卡(标注 / 锚点)和节里最后一张卡都不是能答的卡(`hasState`)→ 在节尾补一张 `{kind:'text', props:{text:<念的那句>, ask:true}}`。问答(没有卡的一两句话)末句是问句也补——规则只有一条:**播放器会停下等的地方,板上就有一张卡**。

不另立种类:按能力分它就是文字卡,`ask: true` 只是记号(`isAskCard`),老师写不出来(围栏语法里没有)。围着它的机械规则:

- 末句的锚点不动,还在它讲的那张卡的拍里;提问卡自己一拍、没有讲稿,底色紫(和做题的卡一色)、独占节尾一行;`rowsFor` 认「layout 盖到提问卡之前」为合法。
- 念末句时亮的还是它讲的那张卡;**停下等答时亮提问卡**(`nowCard`);提问卡的喇叭 = 再听末句(`replayLines`)。
- 流式时不补(那时的末句不一定是最后一句),老师写完、定稿换上时才铺出来。
- 家长端:板书里标「提问(应用补的)」;「看原文」里末句标「问句,停下等(补提问卡)」,只有末句问句标「停下等」。

## 单词卡

英语版的田字格:一个英文词写在四线三格里,笔顺是 drawtell/glyphs 的 52 个印刷体字母(和讲解动画同一套字形),页面用内联 SVG 画、不开舞台包(整词动画 SVG 上兆,iPad 会卡)。起因:2026-09-28 ray 问 apple、banana、ice cream,老师出的是一行的点读卡「apple 苹果」,看不出是一个词,想单听 apple 的音只能连中文一起听。

- **卡上没有中文**:意思靠 emoji 和讲稿(老师照旧「英文在前、中文在后」说)。老师写了中文,解析器悄悄切掉,不退文字卡(退了反而把中文露出来)。
- **两层速度**:紧凑态讲到时按正常速度写,「听」按正常速度念;点卡开舞台,自动慢念的同时按自然拼读分段一段一段慢写(两色、段间空开)→ 合拢、颜色退掉 → 再慢念。分段只在舞台里出现。两色只按段号交替(第 1、3 段墨色,第 2、4 段橙色),不表示元音或别的,所以合拢就退掉,免得孩子以为橙色的字母特别(2026-10-01 yellow 分成 y-e-ll-ow,e 与 ow 恰好是橙色,看着像标了元音)。
- **慢念 = 同一段 mp3 放 0.7 倍**(`playbackRate`,音高不变),不另合成;换 src 会把倍速重置成 `defaultPlaybackRate`,所以别处换音源都 `audioRate(1)`。听着不行再换 voxtell `--rate` 另合成一段(要给配音命令模板加占位)。
- **分段不配音**:配音念「ple」这种音块靠不住,怎么读由老师在讲稿里说。
- **标注**:`cardTexts` 给这个词,讲稿的 `[apple]` 落到这张卡(讲到时亮这张);页面不画——卡上只有这一个词,选中态的描边已经说了是它,涂荧光盖住字形(2026-10-01 真机看着难看)。
- 看录像时舞台只读地开:不出声、不写。
- **大小同步就定**(2026-10-01):排版的量具(`halfOf`)在卡一画出来时就量、量完缓存,所以格子的大小不能等笔画数据。52 个字母(加连字符、撇号)的宽、字间距、空格宽由服务端拼进页面(`__WORD_ADV__`,`letterAdvances()`),`wordGrid` 同步排好、画出带准确宽高的 SVG 与格线,`/api/kid/letters/<词>` 的笔画晚到只往里填。原来要等数据才画,量的那一刻格子宽 0,手机上被判成半宽,数据到了「听」挤到第二行。

## 小课堂卡(lecture)

老师答孩子时放小课堂里的一段,不另讲一遍(《小课堂设计.md》§六,拍板 2、9)。围栏第一行 `<课包 id> 0:19-0:30`,时间照上下文包 `lecture.lines` 抄;第二行可以写一句给孩子的话。

- **只放现成的课**:这张卡拿家长做好的课包或视频,只放那一段,出课里原来的声音。场景卡(放新 id 就起画图老师现做)2026-10-07 删了;老对话里存下的场景卡下发孩子前退成一段字。
- **快照下发时补**:课名、真放的起止、末帧停在 SVG 的哪一刻(`still`)、能不能放(`ready`)由 `enrichLectures`(`src/server/lecture.ts`)从课包现算。`lines:` 的时间是段起点取整到秒,老师照抄的「0:19」其实是 19.4 秒:起止落在段界前后一秒内就对齐到段界(`lectureRange`),不多放前一段的尾巴、不切掉这一段的末字。不写止 = 放起点那一段。
- **讲稿交给小课堂**:`[[play]]` 念完这句铺满放那一段(仲裁表「交给小课堂」)。**放完舞台不关**,停在末帧,讲稿接着念:老师是对着这一帧往下说的。孩子关了也接着念(`closeByKid`)。
- **舞台**:舞台包里的小课堂播放器(`src/stage/lecture.tsx` 的 `range`),是卡的样子:没有自己的顶栏、字幕行、提示,不能圈;进度条上那一段描一道蓝。放着 / 停着 / 放完发 `phase`,页面字幕行显示课里那一句,字幕行的按钮转给播放器(`control`)。放完存状态 `{done: true}`。iPad 不让出声(`play()` 被拒)就停下,出「放这一段」等孩子点。
- **紧凑态**:课名、老师那句、那一段末帧的画面(同圈的卡的缩略图:克隆课包的 SVG 停在 `still`)、「0:19–0:30 ▷」。课包读不出来写「课还没放进来」,点不开,`[[play]]` 不停。
- 板书顶上 / 节前那张「再看一遍」的小课堂卡是页面画的(`c-lc`),不是这种卡。

## 不变的原则

- **页面只认 JSON**:索引里存 `{kind, props, look?}`,不存老师原文;页面不认识的 kind 退成文字卡显示 props 里的字。
- **答案不下发**:`strip` 在 `kidConversation` 里机械执行,孩子端的 JSON 里没有对错;对错只在老师嘴里。
- **不设版本号**:props 新字段一律可选;删种类时页面分支留着(老板书要渲染),从注册表与 md 拿掉。
- **坏了 = 没有**:解析失败退文字卡、主题坏了退出厂件;孩子端永远没有错误文案。
