# 卡片协议(给改代码的人)

板书的一节 = 卡(围栏)+ 讲稿(段落)。卡按**能力**分种类:text / read / choice / image / tianzige / word / lecture / canvas / paint / photo / code,十一种,不按样子分——样子(底色、字号)在主题(`themes/<name>/`)里取值、由机械规则(`board/presentation.ts` 的 `tintFor` / `lookFor`)或围栏行上写的修饰词定;并排由孩子端按卡量出来的宽度排(`board/presentation.ts` 的 `rowsFor`);都不进卡的协议。

给**老师**看的那一半是 `cards/<kind>/card.md`(`pnpm run gen:skills` 生成到包根 `skills/cotutor-board/` 入库:`SKILL.md` 是总表,`references/<kind>.md` 逐张,`references/README.md` 索引;init / upgrade 拷进 workspace 的 `.claude/skills/cotutor-board/`,机器件、每次覆盖);这份是给**开发者**看的:一种卡由哪几个文件组成、加一种卡怎么做、怎么验。

## 一种卡有哪几个文件

| 文件 | 管什么 | 谁读 |
|---|---|---|
| `src/board/cards/<kind>.ts` | 服务端定义 `CardKind`:`props` 契约(zod)、`parse(body, mods)` 围栏正文 → props(抛错 = 没解析成,退文字卡 + warning)、`strip` 剥答案、`state` 契约、`describe(props, state)` 给老师的一句、`assets(props)` 要预生成的配音 | 解析器、`/api/kid/*`、上下文包 |
| `cards/<kind>/card.md` | 协议文档,八个固定栏目(下面);**例子即测试** | 老师(出厂到 workspace)、`tests/cards-doc.test.ts`、语法表生成 |
| `cards/<kind>/card.css` | 这种卡的结构样式(选项行、空、缩略图……),只用主题变量(`--tint-*` `--pen-*` `--line` …);服务把它们拼在主题 css 前面 `/kid/theme.css`,主题写同名选择器能盖 | 孩子端页面、舞台包 |
| `src/board/presentation.ts` | 页面那一半的纯逻辑:`cardTexts`(能被标注的字)、`hasState` / `isHeavy`、`cardTitle`、`stateSummary`、机械规则 `tintFor` / `lookFor` / `penFor`,按 kind 名 switch;**不能有运行时 import**(剥类型内联进页面) | 服务端与页面同一份 |
| `src/ui/kid/kid-page.ts` `renderCard` | 紧凑态与舞台态怎么画,按 kind 名分支;重卡(lecture / canvas)的舞台在 `src/ui/stage/`(iframe 里的舞台包);田字格卡(tianzige)没有舞台,点字就写,数据由 `src/ui/kid/tianzige.ts` 从 hanzi-writer-data 现读、路由 `/api/kid/tianzige/<字>`;单词卡(word)的字母笔顺由 `src/ui/kid/letters.ts` 从 drawtell/glyphs 采点、路由 `/api/kid/letters/<词>` | 孩子端 |

四处靠 kind 名对上;`src/board/cards/index.ts` 是登记表(`CARD_KINDS`),`src/board/cards/docs.ts` 读 md / css。

## 卡用在哪:板书与首页

`CardKind.where` 说这种卡能用在哪(缺省只板书)。首页是家长批准的那页,和板书同一个解析器(`parseBoard(text, {place: 'home'})`):

- 只首页:`tutor`(老师卡)。它不进 `cotutor-board` 技能,老师在板书里写了退文字卡 + 提醒;协议进 `cotutor-home` 技能的 references/。
- 板书与首页:`text` `read` `image` `tianzige` `word`。
- 只板书:`choice` `canvas` `paint` `photo` `code`(做完要交给某位老师,或要后台画);首页写了退文字卡,首页检查报「要改」。

## 谁拿到哪些卡

板书能用的十一种,不是每位老师都用得上:英语老师用不着画板,数学老师用不着田字格。cotutor.json 老师条目的 `cards` 列出这位老师讲哪几种:

```json
"english-tutor": { "display": "英语老师", "cards": ["text", "read", "choice", "image", "word", "lecture"] }
```

- **只裁递给老师的写法**。`boardGuideFor(kinds)`(`src/board/cards/docs.ts`)按清单从包里现拼板书写法:「卡的种类」只拼这几种,`cards/板书怎么写.md` 与守则(cotutor-tutor)里 `{{有 x y}}` … `{{/有}}` 包着的段落,x、y 都在才留(`src/board/card-guards.ts`)。写到 `.cotutor/board/<老师>-<hash>.md`,`{boardFile}` 指它;文件名带内容的 hash,清单一改预热进程就对不上、不会拿旧写法去答。
- **解析器不动**。老师写了清单外的卡照常解析、照常显示,这轮记一条提醒(「板书里有清单外的卡」),家长据此调清单。
- **没写 `cards` = 全部**,递出厂的 `skills/cotutor-board/SKILL.md`,和以前一样。`text` 总在(写坏的卡退成它)。
- **出厂清单**在 `src/app/cli/skeleton.ts` 的 `TUTOR_DEFAULTS`,init 写进 cotutor.json;老 workspace 没写的,`cotutor upgrade --config` 补(doctor 的 `config.migrate` 点名),写过的不动。`cotutor doctor` 每位老师一行 `tutor.<老师>.cards`。
- **加一种卡**:新卡默认不进任何老师的清单。要哪位老师用,把它加进那位的 `cards`;写手写段落时,只对这种卡有用的段落用 `{{有 新卡}}` 包起来。
- 契约里的种类表 `BOARD_CARD_KINDS`(`src/schema/config.ts`)和注册表的 `kindsFor('board')` 靠 `tests/cards.test.ts` 锁住:加卡忘了改它就红。

加一种首页卡同样是下面七步,区别:`where: ['home']`;第 5 步画在 `kid-page.ts` 的 `renderHome`(老师卡)或 `renderCard(c, i, null, false)`(`secIdx` 为 null = 首页,不开舞台);第 6 步放进 mock 的样例首页(`mockHomeMd`);`pnpm run gen:skills` 会把它写进 `skills/cotutor-home/references/`。

## card.md 的八个栏目

1. **是什么**(一句)
2. **什么时候用 / 别用**(`- 用:` / `- 别用:` 各至少一条,别用要给替代)
3. **写法**(围栏标签、修饰词、正文规则)
4. **例子**(≥ 1 个,每个围栏前一行 `<!-- expect {"kind":"…","props":{…}} -->`:测试把围栏喂 `parseCard`,kind 要对、列出的 props 逐个深比、`warning: true` 才允许有 warning)
5. **反例**(常见错法 + 解析器怎么退化;同样带 expect)
6. **孩子看到什么**(紧凑态、舞台、能标注的字在哪、有没有交互)
7. **你会收回什么**(`cards:` 段那一行长什么样;没有状态写「没有」)
8. **状态的形状**(有的话,JSON 一行)

总表 `SKILL.md` 由每张的 1、3、4 栏拼成(expect 注释去掉),frontmatter 的 description 列出全部种类;README 由 1 与「- 用:」拼成。改了 md 跑 `pnpm run gen:skills`(`tests/skills.test.ts` 断言入库的和生成的一致),workspace 里的由 `cotutor init` / `cotutor upgrade` 换新。

## 加一种卡(七步)

1. `src/board/cards/<kind>.ts`:照 `choice.ts` 写 `CardKind`;有交互就给 `state` + `describe`;答案类字段在 `strip` 里剥。
2. `src/board/cards/index.ts`:import + `CARD_KINDS` 加一项。
3. `cards/<kind>/card.md`:八个栏目;例子带 expect。`cards/<kind>/card.css`:结构样式,只用主题变量。然后 `pnpm run gen:skills` 重生成 `skills/cotutor-board/`。
4. `src/board/presentation.ts`:`cardTexts` 加一个 case(哪些字能标注);有交互加进 `hasState`;在 iframe 里开的加进 `isHeavy`;`tintFor` / `penFor` 给缺省。
5. `src/ui/kid/kid-page.ts` `renderCard`:紧凑态一个分支(`box(cls, …)` 会带 `data-tint` / `data-look`);有舞台交互再写 `stage=true` 的分支;重卡在 `src/ui/stage/main.tsx` 装组件。
6. `src/app/mock/mock.ts`:某位老师的脚本里放一张;`tests/mock.test.ts` 加一条。
7. 验:`pnpm test`(`cards-doc.test.ts` 会跑你的例子),`cotutor mock` 开 `/?tutor=<老师>&stage=<节>.<卡>` 截图(手机 `--force-device-scale-factor=2 --window-size=780,1688`,平板 `--window-size=1180,820`)。

新种类缺省全宽;要能半宽,加进 `board/presentation.ts` 的 `canHalf`,并在 `fitsHalf` 里说怎么算放得下。

## 提问卡

实时回复由脑决定板上放什么,`parseBoard(..., {live: true})` 不自动补提问卡。能选的末句配 `choice`,开放问题由孩子开口回答;要照片时配 `photo`。

非实时板书的兜底仍保留:定稿且非首页,末句是问句、无 cue / echo / call,指向的卡和最后一张卡都不能作答,也没有 photo 卡时,应用在节尾补文字卡 `{kind:'text', props:{text:<末句>, ask:true}}`。流式 partial 不补。

`ask: true` 是应用记号,围栏语法不提供它。提问卡单独占一行,没有自己的讲稿;停下等答时亮起,喇叭重放末句。家长视图标注「提问(应用补的)」。实现见 `src/board/parse.ts` 与 `src/board/presentation.ts`,边界见 `tests/board.test.ts`。

## 单词卡

英语版的田字格:一个英文词写在四线三格里,笔顺是 drawtell/glyphs 的 52 个印刷体字母(和讲解动画同一套字形),页面用内联 SVG 画、不开舞台包(整词动画 SVG 上兆,iPad 会卡)。

- **卡上没有中文**:意思靠 emoji 和讲稿(老师照旧「英文在前、中文在后」说)。老师写了中文,解析器悄悄切掉,不退文字卡(退了反而把中文露出来)。
- **两层速度**:紧凑态讲到时按正常速度写,「听」按正常速度念;点卡开舞台,自动慢念的同时按自然拼读分段一段一段慢写(两色、段间空开)→ 合拢、颜色退掉 → 再慢念。分段只在舞台里出现。两色只按段号交替(第 1、3 段墨色,第 2、4 段橙色),不表示元音或别的,所以合拢就退掉,免得孩子以为橙色的字母特别。
- **慢念 = 同一段 mp3 放 0.7 倍**(`playbackRate`,音高不变),不另合成;换 src 会把倍速重置成 `defaultPlaybackRate`,所以别处换音源都 `audioRate(1)`。听着不行再换 voxtell `--rate` 另合成一段(要给配音命令模板加占位)。
- **分段不配音**:配音念「ple」这种音块靠不住,怎么读由老师在讲稿里说。
- **标注**:`cardTexts` 给这个词,讲稿的 `[apple]` 落到这张卡(讲到时亮这张);页面不画——卡上只有这一个词,选中态的描边已经说了是它,涂荧光盖住字形。
- 看录像时舞台只读地开:不出声、不写。
- **大小同步就定**:排版的量具(`halfOf`)在卡一画出来时就量、量完缓存,所以格子的大小不能等笔画数据。52 个字母(加连字符、撇号)的宽、字间距、空格宽由服务端拼进页面(`__WORD_ADV__`,`letterAdvances()`),`wordGrid` 同步排好、画出带准确宽高的 SVG 与格线,`/api/kid/letters/<词>` 的笔画晚到只往里填。原来要等数据才画,量的那一刻格子宽 0,手机上被判成半宽,数据到了「听」挤到第二行。

## 小课堂卡(lecture)

老师答孩子时放小课堂里的一段,不另讲一遍。围栏第一行 `<课包 id> 0:19-0:30`,时间照上下文包 `lecture.lines` 抄;第二行可以写一句给孩子的话。

- **只放现成的课**:这张卡拿家长做好的课包或视频,只放那一段,出课里原来的声音。
- **快照下发时补**:课名、真放的起止、末帧停在 SVG 的哪一刻(`still`)、能不能放(`ready`)由 `enrichLectures`(`src/runtime/lecture.ts`)从课包现算。`lines:` 的时间是段起点取整到秒,老师照抄的「0:19」其实是 19.4 秒:起止落在段界前后一秒内就对齐到段界(`lectureRange`),不多放前一段的尾巴、不切掉这一段的末字。不写止 = 放起点那一段。
- **讲稿交给小课堂**:`[[play]]` 念完这句铺满放那一段(见 `tests/live-player.test.ts` 的小课堂事件)。**放完舞台不关**,停在末帧,讲稿接着念:老师是对着这一帧往下说的。孩子关了也接着念(`closeByKid`)。
- **舞台**:舞台包里的小课堂播放器(`src/ui/stage/lecture.tsx` 的 `range`),是卡的样子:没有自己的顶栏、字幕行、提示,不能画;进度条上那一段描一道蓝。放着 / 停着 / 放完发 `phase`(页面据此在放完时接着念;课里的字与播放按钮都在舞台上)。放完存状态 `{done: true}`。iPad 不让出声(`play()` 被拒)就停下,出「放这一段」等孩子点。
- **紧凑态**:课名、老师那句、那一段末帧的画面(服务端用烤好的画面出的 `frame.svg`,停在 `still`)、「0:19–0:30 ▷」。课包读不出来写「课还没放进来」,点不开,`[[play]]` 不停。
- 板书顶上 / 节前那张「再看一遍」的小课堂卡是页面画的(`c-lc`),不是这种卡。

## 画图卡(paint)

「你说我画」里老师把孩子说清楚的故事分好幅,应用交给百炼文生图画成一张连环画。

- **画是这张卡的资产**,和点读的配音同一个时机:一轮跑完后台画(`src/scenes/paint/painter.ts` 的 `startPaints`),落在 `<日期>.<job>.cards/<n>/paint.png`,旁边 `paint.json` 是记录(在画 / 画好了 / 没画成与原因、拼好的提示词、模型、毫秒)。已有记录不重画;回放不画;一张一张排着画,一天画几张不限(今天画了几张在工作台概览)。
- **提示词**(`src/scenes/paint/prompt.ts`):版式(四格 2×2、两三格横排、一幅一张)、画风、角色、分幅,填进 activity 文件「画家收到什么」的模板(`{{版式}} {{角色}} {{分幅}}`,家长可改);不在 activity 话题里的,照出厂的画风(`PAINT_PROMPT_DEFAULT`)拼。题干与词语宝库不进画:画面里不要字,题干与词由页面排。
- **下发时补**(`enrichPaints`,同小课堂卡的 `enrichLectures`):`drawn`(drawing / done / none)、画好了 `pic`(相对 workspace 根,页面经 `/api/kid/image` 取);家长端再补 `note`。老师写不出这几个字段。「在画」五分钟没落成当没画成(服务重起过)。
- **孩子端**:还在画就隔 3 秒拉一次,props 变了重画这张卡,图淡入。没画成也不说,停在分好的几幅。宽屏上图(最宽 520)与词语宝库并排。
- **老师**看不到图:下一条消息的 `cards:` 里一行「画好了」或「没画成」(`paintLines`),老师问孩子画得怎样。
- 测:`tests/paint.test.ts`(假百炼、假老师全流程);页面 `scripts/probe-paint.mjs`(mock,发出后 20 秒算画好)。

## 拍给我看卡(photo)

老师要孩子拍一张照片发来:看图说话的那幅图、写好的那一页。用 photo 卡明确提供拍照入口,避免把要照片误呈现为等孩子口头回答。

- **它是一张问题卡,答案是照片**。`askCard` 认它:一节里有拍给我看卡就是它(最后那张),末句问不问都算;孩子下一条消息(照片 + 配的话)进它的答案栏(`kidSaid` 的 `photos`),节头不再回显那几张;只发了照片时服务端补的「(拍了一张)」不写。孩子没拍、直接说话,那句话也进它的答案栏。
- **解析器见了它不补提问卡**(`board.ts`,一节里有就不补)。
- **卡上不存状态**:照片随消息交给老师,和孩子自己拍的作业照片同一条路(`photos:` / `photoFiles:`)。
- **孩子端**:紫色,相机 + 要拍什么,独占一行,点卡不开舞台。在最后一节时下沿是「等你拍…」与「拍照」「相册」两颗(file input 和输入条的相机同一套 `wireFile`,进同一个发照片屏);孩子刚发出去、在等老师时收起。不跟「停下等答」(`body.waiting`)走:末句不一定是问句。
- **谁拿到**:出厂只在看图说话 activity 头上的 `cards`;要别的老师用,加进他的 `cards`。
- 测:`tests/kid-board.test.ts`(askCard、kidSaid、节头)、`tests/board.test.ts`(不补提问卡)、`cards-doc.test.ts`(例子);页面 `scripts/probe-photo-card.mjs`(mock 的英语老师第二节)。

## 不变的原则

- **页面只认 JSON**:索引里存 `{kind, props, look?}`,不存老师原文;页面不认识的 kind 退成文字卡显示 props 里的字。
- **答案不下发**:`strip` 在 `kidConversation` 里机械执行,孩子端的 JSON 里没有对错;对错只在老师嘴里。
- **不设版本号**:props 新字段一律可选;删种类时同步删除注册、文档和页面分支。旧记录里不认识的卡由 `stripSecrets` 退成安全文字,不下发答案;新回复中不认识的围栏标签按代码卡处理。
- **坏了 = 没有**:解析失败退文字卡、主题坏了退出厂件;孩子端永远没有错误文案。

## 田字格拼音与交卡状态

田字格卡第二行可写拼音,一字一个音节,调号与数字调都认。读音由老师按上下文给出。拼音不合法或数量对不上时仍显示汉字,家长视图给 `CardKind.note` 提醒;字与拼音写在同一行则解析失败,退成文字卡。

选择题与画板交给老师后锁住,舞台只读、不再显示提交按钮。服务端从交卡消息的 `focus.card` 得到 `submittedCards`,下发卡带 `submitted`;再次提交或修改状态返回 409。
