# 口播老师:koubo 接进 cotutor(设计)

> 2026-09-25 起,wip;2026-09-26 待拍板五条按倾向定了。来处:koubo 仓《koubo-产品功能设计.md》§5 主循环、§8「cotutor 侧要做的事」;koubo 侧 M1 / M2 已落地(`init doctor record assess contrast verdict review progress drill ls` + `koubo-cli` / `koubo-coach`,`KOUBO_ENGINE=replay:` 不花钱)。
> 初稿留在 `口播老师设计-初稿.md`。和初稿最大的三处不同:评测在**存录音时**就起、交给老师时只取结果;判**不进卡的状态**(孩子端拿不到);评测结果**跟着录音卡那一行**回老师,不另开 `koubo:` 段。

## 一句话

**口播老师 = 一位有脸的老师 + 一张录音卡(轻舞台)。** Jack 在孩子端按住录,服务端马上让 koubo 评;交给老师时,那张卡在 `cards:` 里的一行后面接上「判 重录:山 的 sh 19 < 65 …」,老师照 koubo-coach 用话说。koubo 不进对话;页面上不画分数、不画判。

数据怎么走:

```
舞台里按住录 → 松手 → PUT 卡状态 {audio: data:…, seconds}
                 └→ 服务端落 .cards/<n>/rec-<k>.webm,状态只留路径
                 └→ 后台起 `.cotutor/koubo card …`(串行队列)→ .cards/<n>/rec-<k>.heard.json
「交给老师」→ runner 拼上下文包:这张卡的 describe 行 + heard.json(没好就等,最多 timeoutMs)
            → cards: - 1620-1/2 record「老师上山看树」 已录 7.1 秒;判 重录:…;take=…
```

## 2. 录音卡 `record`

### 写法

````
```record
老师上【山】看【树】
```

```record pinyin focus=sh_s
shi4 si4 shi4 si4
是 四 是 四
```
````

- 正文一句。句子模式 ≤ 30 汉字;拼音模式(`pinyin`,SOE 的 evalMode 8)第一行是送评的拼音(`shi4` 这样,≤ 30 个),第二行是给人看的字。
- `【】` 括风险字:解析时剥掉括号进 `text`,位置记进 `risk`,页面标红。不括就不标。拼音模式的【】写在第二行。
- 拼音模式在页面上:大字是第二行的汉字,字下面一行小字是带调号的拼音(页面把 `shi4` 写成 `shì`);送评的是第一行。
- `focus=sh_s,n_ng`:风险组,传给 koubo 的 `--pairs`;省了是 `auto`(koubo 按混淆表找)。
- 超长、拼音行不合格式、多于两行 → 抛错,退文字卡 + warning(一张卡一句)。

### 契约

| 项 | 内容 |
|---|---|
| props | `{ text: string, show?: string, risk?: number[], mode: 'sentence' \| 'pinyin', focus?: string[] }`。`text` 送评;`show` 给人看(拼音模式的第二行,句子模式省) |
| strip | 无(没有答案) |
| state | `{ audio: string, seconds: number }`。`audio` 相对 workspace 根。**只有页面写**,评测结果不在这里 |
| PUT | `{ audio: "data:audio/webm;base64,…" \| "data:audio/mp4;…", seconds }` → 服务端落 `<日期>.<job>.cards/<n>/rec-<k>.<ext>`,状态里换成路径(照画板卡的 `image`)。上限 60 秒、2 MB |
| describe | `已录 7.1 秒`;评测那半句由 runner 接(§5) |
| assets | `[{ file: '1.mp3', text: show ?? text }]`:示范音,和点读卡同一条配音管线、老师的音色 |
| where | 只板书 |
| kid-board | `cardTexts` 给 `show ?? text` 的字;`hasState` 加 `record`;`isHeavy` 不加;底色缺省紫(做题的卡同色) |

四处代码与七步照《卡片协议.md》:`src/cards/record.ts`、`src/cards/index.ts` 登记、`cards/record/card.md`(八栏)+ `card.css`、`kid-board.ts`、`kid-page.ts` 的 `renderCard`;`pnpm run gen:skills`。

`scanCards` 只认 `<n>/<k>.mp3`,所以 `rec-*.webm` 与 `*.heard.json` 不会当资产发到孩子端;孩子端并进来的状态只有 `{audio, seconds}`。这两点都进测试。

## 3. 轻舞台与播放(拍板 2)

**紧凑态**(只读,点卡开舞台):句子(风险字红)、喇叭(示范音)、录没录:「没录 · 点开来录」/ 回放键「我的 · 7.1 秒」。

**舞台**(`st-body`,和选择卡、填空卡一样,不开 iframe):

- 大字的句子,喇叭听示范。
- 一个大圆键:按住录,松手停。按住时显示计时(0:04),键上方提示「往上滑,松手就取消」:手指滑出键的上方再松手,这一条丢掉不存。最长 60 秒;不到 0.5 秒当没按,不存。
- 录好了:「听我的 · 7.1 秒」和「示范」两个键并排;大圆键缩成描边的次键「按住再录」,仍然是按住。再录的新一条替掉旧的(旧文件留着)。
- 底部的主键:没录时灰着;录好了而这一节还有没录的录音卡 →「下一句」(舞台切到下一张,不发消息);都录了 →「交给老师」(`{action: 'submit', focus}`,和现在一样)。录好之后主键是它,不是「再录」。
- **交了就锁住**:交给老师之后,这一节的录音卡都锁住,紧凑态压淡、标「交给老师了」,舞台里只剩回放和示范,不能再录。要重录,等老师出新卡。页面的判法:发出去到老师回来之间按 pending 锁;之后看这一节是不是这个话题的最后一节,不是就锁。

**录音**:MediaRecorder,复用页面为按住说话先开的那一路 getUserMedia(Safari 那套,见 `kid-page.ts` 按住说话一节)。格式按浏览器挑 `audio/webm;codecs=opus`,不行就 `audio/mp4`。回放先用本地 blob;刷新之后走现有的 `GET /api/audio/<老师>/<日期>.<job>.cards/<n>/rec-<k>.<ext>`(和配音同一条路,正则放宽到 `rec-*`)。

**仲裁表加这几行**(先改《工作流程.md》的表,再改 `tests/player.test.ts`,最后改 `step`):

表在《工作流程.md》「播放器:谁能打断谁」末尾四行(录音卡);`step` 多两个事件 `recStart` / `recEnd`,页面状态多一个 `recording`,模型多一个 `held`(在录时被压住、录完接着念的那句)。要点:

- 按下录音键:停声音;老师在念的变暂停,录完接着念;再听回原位置。
- 在录:孩子这边能出声的都不响;老师那边来的(新的一拍、整节、写完、场景)不念、不推答题卡,该念的那句停成暂停。
- 松手、到 60 秒、上滑松手、关舞台、切后台都是停录;后三种丢掉这一条。

不变式加一条:在录时不出声、不推卡。

## 4. 评测:存录音时起,交给老师时取

- **起**:`putCardState` 存好录音,马上把这条交给后台队列(一个 workspace 一条,串行),按 `cotutor.json` 的 `koubo.card` 模板起子进程,cwd = workspace 根。结果落 `rec-<k>.heard.json`:成功是 `{ok: true, take, verdict, reasons, chars, accuracy, charsPerMin, costYuan, ms}`,失败是 `{ok: false, error}`。`chars` 是逐字分,只给家长端(§5.1)。Jack 听回放、录下一句的时候,评测就在跑。
- **取**:`runner.send` 拼 `cards:` 时(`changedCards` 那里),遇到录音卡看它当前 `audio` 对应的 heard.json:
  - 有 → 用;
  - 还在跑 → 等,从存录音那一刻起最多等 `timeoutMs`;
  - 没有也没在跑(服务重启过)→ 现在起,等 `timeoutMs`;
  - 等超了 → 写「还没评完」,不再挡。结果晚到照样落盘,家长端看得到。
- **失败 = 没有**:koubo 不在、退出码非 0、超时、JSON 不对,都记 `{ok: false}`,孩子端不显示。
- 重录的时候,旧的那条不取消(koubo 按内容缓存,花了就花了),结果不用。
- 花费与账本归 koubo(`ledger/assess.jsonl`、`dailyCostLimit`);cotutor 不重复记。
- `cotutor replay` 回放一轮时不起 koubo,读已有的 heard.json。

## 5. 老师收回什么:跟着卡的那一行(拍板 3)

不另开 `koubo:` 段。评测接在这张卡 `cards:` 那一行的后面,和选择卡那行带「(答案:…)」同一个路子:

```
cards:
  - 1620-1/0 record「shi4 si4 shi4 si4」 已录 2.4 秒;判 过;take=0925-1702-a1
  - 1620-1/1 record「老师上山看树」 已录 7.1 秒;判 重录:句准确度 36 < 80;山 的 sh 19 < 65,读成 s;树 的 sh 20 < 65;语速 92 字/分 < 160,太慢;take=0925-1703-b7
  - 1620-1/2 record「四是四十是十」 已录 5.0 秒;没评上(cost_limit)
```

- 判后面接 koubo `verdict` 的 `reasons` 原文,最多 6 条,多了写「…还有 N 条」;整行不超过 300 字。
- `take=` 留给老师深挖:`../../.cotutor/koubo verdict <take> --json`。
- 还没评完:`已录 7.1 秒;还没评完`。
- 实现:`describeCard(card, state, extra?)` 多一个参数,只有录音卡用;runner 从 heard.json 读了传进去。页面 PUT 的状态 schema 里没有这一块,孩子端也就拿不到。
- 老师怎么读这行,写在 `cards/record/card.md` 的「你会收回什么」里(判的口径、「读成 X」只是提示要说「可能」),跟着 cotutor-board 到老师那里。

这样做的好处:
- `ContextPackSchema` 不用改,守则和 `references/上下文包.md` 也不用加段。
- 家长端「孩子在板书上做的」存的就是这一行,初稿里「家长端要不要显示分数」这一问自然就有了答案。
- 以后再有要机器评的卡,走同一条路,不用每种加一段。

代价:字级的 `brief` 不进来,进来的只有不过的字(`reasons` 里点了名)。要更细的,老师自己用 `take=` 去查。

### 5.1 家长端旁注

家长板书页(`/parent`)里,每张录音卡旁边挂一块旁注(不是卡),全从 heard.json 读:

- 档(过 / 可救 / 重录 / 没评上)· 句分 · 语速 · 秒数;
- 逐字分一排小标,不过的标红,「读成 s?」带问号(只是提示);
- 老师收到的那一行原文;
- 录音文件 → take、评了多久、花了多少。没评上的写原因(timeout、cost_limit……)。

表头的「koubo ¥」是当天 heard.json 的 `costYuan` 加总,不读 koubo 的账本。孩子端一个字节不变。

## 7. koubo 侧要加的:`koubo card`

```
koubo card --audio <任意格式> --text "…" [--mode 1|8] [--pairs auto|sh_s,…] [--json]
```

- 用 ffmpeg 转成 16k / 16bit / 单声道(koubo 的 `record` 已经依赖 ffmpeg,cotutor 就不用再装)→ `createTake`(`source: 'cotutor'`)→ assess → contrast(缺省只问低分字)→ verdict。
- 输出一份 JSON:`{command: 'card', take, seconds, verdict, reasons, accuracy, charsPerMin, chars, costYuan, cached}`。`chars` 是逐字分:`[{ch, phone?, score, readAs?, missing?}]`,cotutor 只拿去画家长端旁注。
- 失败走 koubo 现有的退出码约定,输出 `{error, message}`;超了每日上限是 `cost_limit`。
- koubo-coach 里「上下文包里的 `koubo:` 段」改成「cotutor 上下文包 `cards:` 里录音卡那一行」。

## 8. 接线

- **依赖**:走 drawtell 的路。cotutor 的 package.json 加 `"koubo": "link:../koubo"`(发 npm 后换版本),`kouboBin()` 照 `drawtellBin()` 写,壳脚本 `.cotutor/koubo` 照 `writeToolShim`,init / upgrade 刷新。
- **`cotutor.json`**:加 `KouboSchema`,缺省
  ```json
  "koubo": {
    "card": [".cotutor/koubo", "card", "--audio", "{audio}", "--text", "{text}", "--mode", "{mode}", "--pairs", "{pairs}", "--json"],
    "timeoutMs": 20000
  }
  ```
  `{mode}` 填 1 或 8,`{pairs}` 填 `focus.join(',')`,没有就填 `auto`。`upgrade --config` 补缺。门槛、上不上云、每日上限在 koubo 自己的 `koubo.json`。

  - .gitignore 加 `takes/`。

  - `.cotutor/koubo --version` 能跑;
