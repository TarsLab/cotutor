# 备课:家长在家长端开一个话题和老师备课,满意了交给孩子

> 2026-09-22 起;2026-09-24 重写(拍板 10–16),同日一期落地(探针 `scripts/probe-parent-board.mjs` 的「备课」几腿):推翻「试用落 `evals/`、钉开场时复制进孩子的话题」那一套,改成**家长开的话题就是备课,交给孩子 = 同一个话题、同一个会话接着**。09-23 已落地的分叉、`resumed:`、`opening` 按钮要退掉(第五节)。起因:家长想像 Claude Code 的「对话回滚」那样,和老师先聊出一段(备课),孩子在孩子端接着这段聊。材料:`src/lib/kid-view.ts`(`kidConversation` / `kidThreads` / `kidMessageCount`)、`src/lib/diary.ts`、`src/server/runner.ts`(一老师一次一条、记忆那处的 guard)、`src/server/app.ts` 孩子端 messages 路由里 `continue` 按钮那段、`src/server/home.ts` `resolveVia` / `publishHome`、`src/server/kid-page.ts` `pickButton`、《家长板书页设计.md》§5。拍板在文末。
> **词**:「备课话题」= 家长在 `/parent` 上点「新话题」开的话题(第一条消息带 `prepThread`;工作台 `/dev` 与 `cotutor send` 开的不算)。「备课轮」= 备课话题里孩子开口之前的每一轮。「开场」= 家长点「从这里给孩子」的那一节,孩子从它看起。「交给孩子」= 定开场 + 首页排一个「接着」按钮。「商量」「排练」不再是步骤,是家长在备课话题里做的两种事(用大人的话定讲法 / 看老师真写一版)。

结论先行:程序本来就知道一句话是从哪一端发的(路由分 `/api/kid/…` 与 `/api/conversations/…`,每条消息存 `from`),孩子端该看什么、记忆该不该写、记账与上限该不该算,**都按「谁开的话题、孩子开口没有」判断**,不用另一个目录。家长在 `/parent` 上给某位老师点「新话题」,就是备课:落 `conversations/`、新会话(老师文件与 vault 的改动照样生效)、孩子看不到、不写记忆。满意了在某一节尾点「从这里给孩子」,首页多一个「接着」按钮;孩子按下去,看到的就是那一节起家长看过的板书(原样、零费用),孩子答了,老师在**同一个会话**里接着讲。没有试用模式、没有分叉、没有复制、没有 `resumed:`、没有新的按钮种类。

## 一、第一性原理:家长要什么,要守什么

家长在 `/parent` 上要的就三件事:**看**(孩子今天学了什么,已有)、**定**(老师接下来怎么讲:商量讲法、看一版效果)、**给**(孩子从家长看过的那一版开始)。

要守的只有四条,每一条都能从已有的数据得到:

| 要守的 | 看什么(都从「话题第一条带不带 `prepThread`、孩子开口没有」推) | 今天已经在这么判断的 |
|---|---|---|
| 孩子看不到家长和老师备课的话 | 话题第一条的 `from`、开场在哪 | `kidConversation` 的问句只认 `from: kid`;`kidThreads` 只列孩子开过口的话题 |
| 备课不写进孩子的记忆 | 这一轮是不是备课轮 | runner 记忆那处已经按 `replayOf` / `tryout` 分支 |
| 备课不算进记账 | 话题里孩子开口没有 | `diary.ts` 只收 `from: kid` 的 |
| 备课不占孩子的每日上限 | 消息的 `from` | `kidMessageCount` 只数 `from: kid` |

## 二、为什么推翻 09-22 / 09-23 的做法

09-22 的起点是「试用落 `evals/`」,四条都靠换目录守住。代价是一串跟着来的机关:试用不能挡孩子,所以起第二个 runner;备课在 `evals/`、孩子在 `conversations/`,给孩子就得跨目录复制(`forkThread`);复制过去的话题没有会话,所以要 `resumed:`;复制哪几节得有规则,所以有「开场」的定义和「回到这一节」;孩子要有入口,所以有 `opening` 按钮、按过就藏、备课话题删了就藏。家长端也就多了试用模式、「试一试」「试过的」「重来」「以前试过的」「回到这一节」「排到首页」「已排到首页」。

原文第一节反对「孩子接着同一段会话」的四条理由,换到同一个目录之后逐条看:

1. **孩子会看到老师对家长说的话** → 孩子端只下发开场及以后的轮;开场之前的轮不下发。
2. **记账会把备课记成孩子学过的** → 记账只算孩子开过口的话题;日记本来就只收 `from: kid`。
3. **会话层回滚做不了** → 不回滚。家长说「第二节重写,别出 2/4」,老师在同一个会话里改;被否掉的那一版留在会话里,老师反而知道家长不要什么。
4. **老师本来就不靠会话记忆** → 还是对的,只是这里用不着另拼一段上下文:会话本身就是连着的。

## 三、备课话题

### 3.1 开

- 清单(《家长板书页设计.md》§2.2)每位老师一块的右上角「新话题」(替掉「试一试」):进这位老师的板书页,空白态,输入条在,家长说第一句。
- 发的是 `POST /api/conversations/<老师>/messages`(家长真发那条,`from: parent`),`newThread: true, prep: true`;第一条记 `prepThread: true`,落 `conversations/`,新会话。工作台 `/dev` 与 `cotutor send` 也走这条接口、缺省也是 `from: parent`,它们不带 `prep`,开的话题照旧孩子看得到——「从哪个端发起」看的是这个字段,不是 `from`。
- 家长在备课话题里按「继续」、做卡「交给老师」:这条接口收 `action`;做卡走 `PUT /api/conversations/<老师>/cards/<job>/<n>`,只认备课轮的卡(孩子的话题里 409)。孩子端往没交的备课话题里发 400。
- 老师看得出是家长:上下文包 `from: parent`(已有)。

### 3.2 规则

| | 备课轮(家长开的话题,孩子开口之前) | 其余的轮 |
|---|---|---|
| 孩子端 | 没交给孩子:不下发;交了:开场及以后的节下发,家长的话不下发(`question` 本来就是 `null`) | 照旧 |
| 记忆段 | **不写** vault,原文进 `memoryDraft`,家长端旁注「本来会记住的」 | 照旧 |
| 每日上限 | 不算(本来就只数 `from: kid`) | 照旧 |
| 记账 | 不记(孩子没开过口的话题不起记账) | 照旧 |
| 配音、板书后期 | 开(要听、要看孩子会看到的样子) | 照旧 |
| 卡 | 家长能做(看效果);交给孩子时开场及以后那几轮的卡的状态清掉 | 照旧;家长在孩子的话题里仍不能替孩子答 |
| 费用 | 家长端每轮一个小标签(家长在花钱) | 家长端不显示 |

「孩子开口」= 话题里出现第一条 `from: kid` 的消息。之后家长在这个话题里再发,和家长真发进孩子的话题一样。

### 3.3 在里面怎么备

就是说话。「今天讲分数,用披萨,先出三道选择」是讲法也是第一句;「继续」看下一节;「第二节重写,只比大小」让老师改;想只商量不出板书,说「先别写板书」。一期不做「只商量」开关,真跑下来家长嫌老师不听再加(上下文包 `board: off`,已有)。

## 四、交给孩子

### 4.1 家长端

- 备课话题每节尾(旁注区)一行「从这里给孩子」;孩子开口之后不再出现。
- 点开一小块(不弹窗,和「记账」「删」一个做派):**按钮字**(≤ 16 字,预填这一节第一句截 16 字)、「交给孩子」。不填讲法:老师在同一个会话里,家长交代过什么它都记得。
- 交了 = 服务端做三件事:
  1. 索引 `openings[话题] = <这一节的 job>`;
  2. 删掉这个话题里开场及以后各轮的 `.cards/<n>.json`(家长做过的,孩子要自己做);
  3. 往 `home/draft.md` 这位老师的老师卡追加一行 `接着 <今天> <话题> <按钮字>`(没有草稿就从已发布那份的原文起;没有这张卡就补一张)+ `publishHome`。检查有「要改」就不发,把要改的列在这一小块里,草稿里已追加的那行留着。
- 孩子开口前可以改开场:在另一节点「从这里给孩子」= 改 `openings`,草稿里那一行不再追加第二遍。
- 清单上这个话题标「备课」,交了标「已交给孩子:<按钮字>」;孩子开口后标「首页 · <按钮字>」,和孩子的话题一样。
- 只交**今天的**备课话题;按钮指别的日期的备课话题,检查报「要改」(晚上备第二天的课,见第七节二期)。

### 4.2 孩子按下去

- 首页老师卡上就是一个「接着」按钮(↻,和别的「接着」一样,孩子不用分)。
- 今天「接着」按钮的做法是把按钮字当孩子的第一句发出去(`pickButton` 的 `send: b.label`)。**指向交出去的备课话题的按钮不发字,只打开**:`kidButtons` 给这种按钮带 `open: true`,孩子端 `openTutor(t, { kind: 'thread', thread, via })`,从开场第一句播,末句问句停。不起老师、零费用、一个字不变。
- 孩子开口以后再按这个按钮也只打开(话题还是那个话题,同「接着刚才的」)。

### 4.3 孩子开口

- 孩子的第一句照常 `thread: <话题>` 发;runner 照常 resume 这个话题的会话。上下文包 `from: kid`,不带 `home:` / `continue:`。
- `skills/cotutor-tutor/SKILL.md` 加一句:「话题前面是 `from: parent` 的、这一条是 `from: kid`:家长备好课交给孩子了,孩子看到的是家长选的那一节起的板书。直接答孩子这句、往下讲;别复述家长的话,别提家长交代过什么。」
- 从这一轮起一切照旧:记忆落 vault、上限算、晚上记账(老师读索引时看得到前面是备课,和家长真发一个样)。

### 4.4 家长端回看

同一个话题,清单里一行。开场之前的轮,节前旁注标「备课 · 孩子看不到」;开场那一节前标「从这里给了孩子」。
