## 一、第一性原理:家长要什么,要守什么

家长在 `/parent` 上要的就三件事:**看**(孩子今天学了什么,已有)、**定**(老师接下来怎么讲:商量讲法、看一版效果)、**给**(孩子从家长看过的那一版开始)。

要守的只有四条,每一条都能从已有的数据得到:

| 要守的 | 看什么(都从「话题第一条带不带 `prepThread`、孩子开口没有」推) | 今天已经在这么判断的 |
|---|---|---|
| 孩子看不到家长和老师备课的话 | 话题第一条带不带 `prepThread`、交给孩子没有 | `kidConversation` 的问句只认 `from: kid`;`kidThreads` 只列孩子开过口的话题 |
| 备课不写进孩子的记忆 | 这一轮是不是备课轮 | runner 记忆那处:回放不写、备课轮不写 |
| 备课不算进记账 | 话题里孩子开口没有 | `diary.ts` 只收 `from: kid` 的 |
| 备课不占孩子的每日上限 | 消息的 `from` | `kidMessageCount` 只数 `from: kid` |

## 三、备课话题

### 3.1 开

- 清单(《家长板书页设计.md》§2.2)每位老师一块的右上角「新话题」:进这位老师的板书页,空白态,输入条在,家长说第一句。
- 发的是 `POST /api/conversations/<老师>/messages`(家长真发那条,`from: parent`),`newThread: true, prep: true`;第一条记 `prepThread: true`,落 `conversations/`,新会话。工作台 `/dev` 与 `cotutor send` 也走这条接口、缺省也是 `from: parent`,它们不带 `prep`,开的话题照旧孩子看得到——「从哪个端发起」看的是这个字段,不是 `from`。
- 家长在备课话题里按「继续」、做卡「交给老师」:这条接口收 `action`;做卡走 `PUT /api/conversations/<老师>/cards/<job>/<n>`,只认备课轮的卡(孩子的话题里 409)。孩子端往没交的备课话题里发 400。
- 老师看不出是家长:上下文包不再有 `from: parent`,家长发的一律按孩子拼包(《工作流程.md》拍板 13)。家长端开的备课话题因此等于「家长扮孩子」,和试用一样;要和模型商量着备课,在 workspace 里用 cotutor-prep。消息在索引里照旧记 `from: parent`,下表各行(不算上限、不写记忆、孩子看不到)不变。

### 3.2 规则

| | 备课轮(家长开的话题,孩子开口之前) | 其余的轮 |
|---|---|---|
| 孩子端 | 没交给孩子:不下发;交了(从课文件建的话题,§10.5):整段下发,课文件里的几节就是几轮 | 照旧 |
| 记忆段 | **不写** vault,原文进 `memoryDraft`,家长端旁注「本来会记住的」 | 照旧 |
| 每日上限 | 不算(本来就只数 `from: kid`) | 照旧 |
| 记账 | 不记(孩子没开过口的话题不起记账) | 照旧 |
| 配音 | 开(要听、要看孩子会看到的样子) | 照旧 |
| 卡 | 家长能做(看效果);交给孩子时这节课那几张卡的状态清掉 | 照旧;家长在孩子的话题里仍不能替孩子答 |
| 费用 | 订阅之下 CLI 报的美元数没有参考价值,家长端(清单的 `$`、节尾的旁注)一律不显示,只在工作台「看原文」与 `cotutor show` | 家长端不显示 |

「孩子开口」= 话题里出现第一条 `from: kid` 的消息。之后家长在这个话题里再发,和家长真发进孩子的话题一样。

## 四、这节课:备课话题里老师写的那几张卡

备课话题里老师写出来的卡就是「这节课」;挑卡、改字不在板书上做,在课文件里做(第十节)。

### 4.1 哪些卡进这节课

- 备课话题里老师写出来的每张卡都进这节课,正常显示。
- 没有卡的轮(只说话的、出错的)不进这节课,孩子本来也看不到。
- 顺序就是生成的顺序。

### 4.2 怎么改

**卡上不放任何控件**。想挑卡、改字、调顺序,去课文件里改(§10.3)。

### 4.3 底部「这节课」

- 备课话题的输入条上面常驻一条:「这节课 · N 张卡」+ 卡名一行(截断)+「交给孩子」。一张卡都没有时按钮灰着。
- **交给孩子**:一小块只填按钮字(≤ 16 字,预填第一张卡上的第一句截 16 字)。服务端先把这几节写成课文件,再从文件交(§10.5)。
- 只交今天的。

### 4.4 孩子那边

- 首页就是一个 ↻「接着」,孩子端 JSON 带 `open`:按了只打开、不发字、不起老师、零费用。
- 怎么播、孩子的第一条老师拿到什么,见 §10.5。

## 九、真跑要盯的

- **一个老师同时只跑一条**:家长备课、老师还在写的时候,孩子找这位老师会被挡。先接受;真撞上了再改成按话题锁。

## 十、课文件:备课的结果是一份 md,排版也在里面

> 起因:家长想把备课的东西变成一个 markdown 文件——卡的集合加排版——在 Claude Code 会话里让 LLM 改,自己也能手改。看下来这不是新格式:板书本来就是 md(普通行 = 讲稿一句,围栏 = 卡),`home/draft.md` 已经走通「workspace 里一份 md,技能改、家长手改、`cotutor home check / publish`」这条路,`tests/fixtures/board/*.md` 就是「一节课一个文件」的样子。差的只是把解析器、配音、交给孩子、首页「接着」对着一个文件串起来。

### 10.1 为什么是文件

文件能做、索引里一叠卡做不了的:改一个字、调顺序、合并两轮的卡;用 Claude Code 备课(比 iPad 上一轮一轮等老师便宜得多,能 Read 教材、读日记,不起配音);晚上备明天的课(文件没有日期,交出去那一刻才建话题);复用与 diff(下学期、给老二再用是复制一个文件,会话搬不走)。

代价:孩子开口时老师是**新会话**,靠上下文包知道孩子看到了什么。家长不要什么,靠文件尾巴那段显式的讲法——家长看得见、能改。换来的:被拿掉的卡在新会话里根本不存在,家长的话只有写进尾巴的才给老师,会话不再越来越长。

### 10.2 文件

放 workspace 的 `lessons/<名>.md`,不放 vault(理由同《首页设计.md》§二:围栏语法与卡 id 是运行件,过不了「一年后还想翻」那一问;vault 的规矩是机器只追加不改,LLM 在会话里改文件正好违反它)。`lessons/` 不进骨架,技能写时自己建。

~~~~markdown
---
tutor: math-tutor
device: tablet-landscape        # 可省,缺省平板横屏;就是 layout.for
---

我们拿两个一样的三角形拼一拼。

```text tint=sky

```

两个一样的三角形一拼,就是一个[平行四边形]。

```text formula look=big same
三角形面积 = 底 × 高 ÷ 2
```

所以三角形的面积就是[底]乘[高],再除以 2。

## 讲法

他上周把「底」认成斜边,第一张卡多指两遍。答对了别急着往下,让他自己再出一道。
~~~~

- frontmatter:`tutor`(必填,cotutor.json 里有脸的老师)、`device`(可省)、`for`(可省,给哪天用)。别的键报提醒。
- 正文 = 板书语法,一个字不改;**`---` 独占一行分节**(围栏里的不算,解析器本来就先认围栏),一节就是孩子端的一轮(末句问句停下等孩子,和老师写的一样;提问卡照补)。
- **排版写在围栏行上**,作为通用修饰词,解析器在按种类解析之前先摘掉:`same`(和上一张并排;不写 = 孩子端按卡的宽度排,2026-10-01 拍板 35)、`tint=<槽>`、`look=<槽>`、`emoji=<一个>`。行由各卡的 `same` 拼成 `layout.rows`,样子进 `look`,契约不变;槽名对着主题的 `theme.json` 验,不认识的 check 报「要改」。标题行、画板、录音卡、讲解动画永远独占一行,这条机械规则文件盖不过(选择题、填空题 2026-10-01 起能并排)。标注仍是讲稿里的 `[词]`;笔与 `said` 不给写。
- 不另开布局文件:排版只能靠卡的下标指回去,中间插一张、删一张就整个错位,而且改的人要开两个文件对着看;围栏行在卡头上,挪卡跟着走,diff 一眼看出「只动了排版」。
- 第一个 `## ` 起是尾巴,给老师的讲法(`brief`),孩子看不到;写法同首页老师卡的「讲法:」。

### 10.3 谁写它

三种方式,汇到同一个文件、同一条交出去的路:

1. **Claude Code**:机器技能 `cotutor-prep`(照 cotutor-home 的骨架:看今天、读入口文件与教材、商量、家长点头才写文件、家长明说才交)。
2. **家长手改**:任何编辑器。
3. **家长端备课话题**:和老师聊出来的那几节,「交给孩子」**先写成课文件(全部卡都进)再交**;想挑卡、改字,去文件里改。导出的文件名是 `lessons/<日期>-<话题>.md`,聊天话题的 `lessons[].source` 记它但不记 `handedAt`(给孩子的是从文件建的那个话题)。

### 10.4 排版是写课文件的一部分;交出去时不排版

- (拍板 31)排版不是独立的一道工序:课文件从哪来,排版就在哪一步做。家长端备课话题导出的,节上的样子与标注导出时写成修饰词与 `[词]`;cotutor-prep 技能写的,写卡时就按 `references/排版.md`(一行最多 3 张、独占、标注只从卡上取、每句每卡的配额,槽名从主题现读)排好;家长手写的不排也能交。`cotutor lesson post <课名> --write` 只留给手写的文件:同一份规则 + 全文一次交给模型(运行时 `claude-fast`,缺省 haiku,`--model` 可换),它回整份文件,正文剥掉排版后必须逐字相同(不同整份不要),手写过的修饰词当已定。家长端课文件页上没有排版按钮。
- 交给孩子时不排版:排版全在文件里。
- 孩子端实时的一轮(没备过课的)没有后期(《工作流程.md》拍板 11),只有老师写的 `[词]` 与机械规则的样子。`section.layout` / `look` 的形状一样,**页面不用知道来路**。
- 修饰词老师也写得出来:解析器认,`cotutor-board` 技能不教;老师写了就当已定。真跑发现老师乱写样子再收。

### 10.5 交给孩子

`cotutor lesson hand <文件> [--label <按钮字>]`,家长端「交给孩子」按钮与工作台预览上的按钮都调它:

1. 解析、check;有「要改」不交、列出来。
2. (拍板 32)配音在后台:先做 3、4,不到一秒就回;然后每句一个文件、点读卡每段一个(同文本缓存,改过的句才花钱),都落盘了再重读索引、只把这几轮的 `audio` 填上。孩子这时按按钮,没配到的句走浏览器的声(和实时那一轮一样)。CLI 等配齐再退出,路由不等。
3. 在 `conversations/<老师>/<今天>.json` 建一个备课话题:一节一条 `from: parent`、`result: ok`、`section` 就是文件的节(`layout` 与 `look` 从修饰词来)、第一条 `prepThread: true`;`lessons[thread] = { handedAt, source: 'lessons/<名>.md' }`。没有会话(`sessions` 里没有它)。
4. 首页草稿追加「接着」行再发布(`appendContinue`;检查有「要改」就不发、列出来,草稿里那行留着);孩子按了只打开、零费用。
5. (**拍板 34**)孩子端怎么播:孩子开口前打开这个话题,一节一节念。卡念到哪露到哪,每节末句问句停下;孩子按继续、交卡、说话、拍照都在页面里接着念下一节,不发出去。说的与拍的攒着,最后一节之后孩子再开口,才随那一条一起交给老师(`lessonSaid`)。
6. 交了、孩子没开口:再 hand 覆盖同一个话题(卡状态清掉,同 `handLesson`);孩子开口后再 hand 是新话题。

孩子的第一条:没有会话可 resume,新会话;上下文包 `lesson:` 一张一行,另加 `brief`(尾巴);课文件原文由应用放进包里的 `<lesson-file>`,老师不用自己 Read(孩子那轮老师不带工具,《工作流程.md》拍板 12)。守则那句是「有 `lesson:` 就是家长备好的课,孩子看到的就是文件里那几节;直接答孩子这句、往下讲;`brief` 是家长的讲法,别复述给孩子」。从这一轮起一切照旧:记忆落 vault、上限算、晚上记账。

### 10.6 实时渲染:在家长端 `/parent`,整份铺开

- **入口在清单**:每位老师块里话题下面多一栏「课文件 · lessons/」,一行一份:名字、还没交 / 已交给孩子:按钮字 / N 条要改、几节几张卡、从备课话题写出来的、改于几分钟前。只在今天那页(交出去的话题在今天)。接口:`/api/overview/<日期>` 每位老师多 `lessons[]`。
- **点进去整份铺开**,家长板书页同一个页面、同一套卡的画法(`renderCard` / `rowsFor`,底色、字形、并排照真的画):节头「第 N 节 · 几张卡 · 几句 · 第几行起」+ 喇叭(想听才听,浏览器的声,不走播放器);卡按行铺;**讲稿以「说」旁注插在它讲的那张卡的那一行后面**(锚在这行的卡上的句;卡前的开场白在第一行前),`[词]` 高亮,末句问句带「停下等答」;check 的「要改 / 提醒」是旁注钉在那张卡下面、带行号(`LessonIssue` 多 `section` / `card`);答案照家长页的样子标在卡上;末尾一条黄旁注「讲法 · 给老师的,孩子看不到」。接口:`GET /api/lessons/<名>/page`(答案不剥,带交没交、从哪个备课话题来的)。
- **底部还是「这节课」条**:张数、还没交 / 已交 · 首页「…」/ N 条要改;「交给孩子」(有要改的灰掉;弹框填按钮字,同备课话题那一个)与「试用」(§12.1)。没有排版按钮(拍板 31)。
- **课文件建的轮**(拍板 33):消息带 `lessonSection`(第几节,0 起),它不是谁说的话,节前不出「家长」旁注,话题开头一条「课文件 <名> · N 节 · lessons/<名>.md」;清单标题不带「家长:」。

## 十一、素材:备课备的是对话里等不起的东西

> 2026-10-02 定(拍板 36–41)。起因:家长 10-01 记的想法——孩子真用时一开口,备好的讲稿就跟不上,备课省下的时间马上没了;讲的话老师当场就能说,孩子问了也马上能改,备课值得花时间的是当场做不出来的东西。乐高动画(figshot,《脑暴-乐高动画讲题的场景.md》)一段十几分钟到半小时,在对话里等不起;家长在备课时还要对它的颜色、比例、动作、空间布局提意见。

### 11.1 按等不等得起分,不按语言 / 画面分

| 多久出来 | 例子 | 在哪做 |
|---|---|---|
| 秒级 | 文字、题、田字格、单词卡(老师只写一个字,笔画数据现成) | 对话里老师直接写 |
| 几分钟 | drawtell 课包(画图老师一轮) | 两边都行;对话里现做走场景卡,备课时做好、家长审过的当素材 |
| 十几分钟以上 | 乐高动画 | 只能备课时做 |

**素材** = 备课时做好、家长审过、对话里老师按需拿出来的慢东西。讲稿不是素材:老师当场写,按孩子当时的样子写。

### 11.2 一份素材长什么样

放 workspace 的 `materials/<id>/`(id 规则同课包:小写字母、数字、连字符),一份 `material.md` + 媒体。不放 vault,理由同课文件(§10.2):是运行件,过不了「一年后还想翻」那一问。`materials/` 不进骨架,技能写时自己建。

- 乐高的:分段的 mp4 放在目录里,`1.mp4` `2.mp4` …,一段一个文件。
- drawtell 的:课包仍在 `bundles/<id>/`(画图老师只写那里),`material.md` 的 frontmatter 写 `bundle:` 指过去;课包的一步就是一段。

完整的一份见 `tests/fixtures/materials/pingjunfen/material.md`(2026-10-02 照 figshot 的 share-2 / 3 / 6 三段真片子写的,也是解析器的测试输入)。形状:

| 部分 | 写什么 | 应用怎么用 |
|---|---|---|
| frontmatter | `tutor:`(哪位老师的)、`media: clips`(本目录 `1.mp4` `2.mp4` …)或 `bundle` + `bundle: <课包 id>` | `materials:` 按 `tutor` 挑 |
| `<!-- 给人看 -->` | 谁读、片子从哪来(figshot 的场景文件、日期)、改了怎么验;三四行 | 不用;原文进上下文包时老师会读到,所以要短 |
| `# 标题` | 演的是哪个道理,一句 | `materials:` 那一行 |
| 能讲: / 不能讲: | 各几条;不能讲写清片子的边界(总数、有没有余数) | 「能讲」第一条进 `materials:` 那一行 |
| `## 画面里的东西` | 对照表:题目里的 → 画面里的;下面写画面里**没有**的 | 不解析 |
| `## 一段一段` | 编号一段一条:讲什么、几秒,下面几行画面,最后一行「停在:」末帧是什么 | 段数要和 mp4 个数对上(check) |
| `## 什么时候用` | 几种孩子的情形 → 放哪几段 | 不解析 |

- **映射表是核心**(「画面里的东西」):题目里的什么,对应画面里的什么。它是备课第 1、2 步(读懂题目、在 2D / 3D 里找等价物)的产出,家长审的就是它,老师引用时也靠它知道画面里有什么。
- **一段 = 一个动作或一个关系**,播完停在末帧。末帧要写出来(「停在:」):老师是对着这一帧往下说的。
- **不配音**:段里没有讲稿、没有声音、不出字幕,老师按孩子当时的样子说(拍板 38)。drawtell 课包当素材放时,课包自带的讲稿与配音也不放。
- **按题型做、能换参数**:「平均分(人数可变)」「相遇(速度可变)」,而不是「练习册第 12 页第 3 题」。每题半小时、家长每题都要审,按题做攒不起来;生成脚本在 figshot 那边(`scenes/share.gen.ts` 改一个 `n` 出三问),cotutor 只收成品。「能讲 / 不能讲」两行写清哪些题能拿它讲。
- **正文只写给老师**(《写提示词.md》第二节):家长审的就是这份正文;片子从哪来、怎么重做放进文件头的「给人看」注释。老师读它是为了知道画面里有什么、什么时候拿,不是照念。
- **写出画面里没有的**:没有字、没有数字、没有声音。老师会对着画面说话,不写它就可能说「你看上面写着 9」。

### 11.3 老师怎么知道有、怎么拿

- **上下文包 `materials:`**:这位老师名下的素材(`tutor:` 对得上),一行一个:`<id> · <标题> · 能讲:<第一条>`;课文件尾巴 `## 素材` 列了的排前面、一定在,别的按改动时间新的在前,一共最多 20 条;只在有脸的老师、新会话的第一条、板书没关时带。细节老师不用自己 Read:前 5 份 `material.md` 的原文由应用放进包里的 `<material>`(《工作流程.md》拍板 12)。
- **素材卡**(种类 `material`):围栏里只写 id。讲稿 `[[play 2]]` 锚到第 2 段:念到那句,先念完,再铺满播第 2 段,播完停在末帧,接着念下一句;`[[play]]` 不带数 = 从第 1 段起一段段播完。孩子点卡也能自己播,每段末停住等「继续」。

  ````markdown
  ```material
  pingjunfen
  ```
  ````

  状态:看到第几段、看完没(同场景卡)。没有答案,不用剥。
- **不复用场景卡**:场景卡放新 id 就起画图老师、花一轮钱;素材 id 写错不该起任何东西,该退文字卡 + 提醒(家长端看得见)。两种卡的意思也不同:场景卡是「现做」,素材卡是「拿现成的」。
- 守则(`cotutor-tutor`):有 `materials:` 就是家长备好的现成动画;孩子卡住、或做完要讲道理时拿;先让孩子说,再放;话要配着画面说,画面里没有的别说成有。

### 11.4 课文件跟着变:缺省一节、一两张卡

- `cotutor-prep` 技能缺省写**一节**:题(choice / fill / text)+ 末句问句;要用的素材列在尾巴 `## 素材`(一行一个 id),**不铺在板上**——孩子先做题,做完老师再拿。解析器从尾巴里摘出 `## 素材` 那段,别的照旧是讲法(`brief`)。
- **拍板 34 不推翻**:一节的课文件,「最后一节之后孩子再开口才真发」就是「孩子一开口就交给老师」。多节照旧能写、照旧那样播;check 超过两节给提醒「孩子要听完 N 节才能打断」。
- 英语老师要知道的「最近学了哪些词、句型」不是素材,是上下文:记在 vault 的学习进度里,单词卡老师当场就写得出来。

## 十二、试用:家长在孩子端扮孩子跑一遍,第二天删

### 12.1 规则

| | 试用 | 备课话题 | 孩子的话题 |
|---|---|---|---|

| 记忆 | 不写,`memoryDraft` 照记(家长端「本来会记住的」) | 同左 | 写 |
| 记账、日记、每日上限 | 不算 | 不算 | 算 |
| 孩子看得到 | 看不到 | 交出去前看不到 | 看得到 |
| 首页「接着」 | 不指向它 | 交了才有 | — |
| 留多久 | 第二天删 | 一直 | 一直 |

- 开:家长端课文件页一个「试用」(`POST /api/lessons/<名>/try`)——照 hand 的路子从文件建话题,但标 `tryThread`、不追加首页。每位老师块的「试用」(空白的试用话题,看孩子没备课直接问时老师怎么接):打开 `/?try=<老师>/new` 空板,第一句带 `try: 'new'` 开试用话题。

### 12.2 在孩子端试,回家长板书页查

- **试**在孩子端页面(`/?try=<老师>/<话题>`):要看的是孩子听到的节奏——一拍一拍念、配音、哪里停下等、能不能打断、素材什么时候出来;家长板书页整份铺开,看不出这些。页面顶上一行小字「试用 · 明天删」。(2026-10-04 真机)打开先出「开始试用」,点了才念:真孩子是点首页按钮进来的,那一下解锁了声音;试用是从家长端跳过来的,不点这一下 iPad 不放老师的 mp3,退成浏览器的声。`/try` 也等配音配完再回。孩子端只多认这一种话题;返回按钮是 `history.back()`(孩子端页面里不能写家长端的路径,`server.test` 护着)。
- **查**在家长板书页的这个话题:看原文、读了什么、上下文包、本来会记住的。话题列表里标「试用」、不打星。

### 12.3 删

存储正好方便删:一天一个索引 `conversations/<老师>/<日期>.json`,一轮的文件都以 `<日期>.<job>.` 开头。删一个试用话题 = 从索引里摘掉这个话题的消息与 `sessions` 那一项,再删这几轮的文件。不用跨目录。

- 删:消息与每轮的文件(转录、events、run.json、mp3、卡的状态、按住说话的原声);这些消息引用的照片(`captures/`);claude 的会话文件。
- 不删:钱(索引的 `costUsd` 合计不减,账要对得上);试用里起的课包(钱花了,本身就是素材)。
- 时机:serve 起来时、每天第一次读概览时扫一遍,删日期早于今天的试用话题。今天试的今晚都在。
- 「留着」(家长板书页话题头点了就不删)先不做,看真用时会不会遇到「当晚没空改、第二天想回头看」。
