# 实时老师:语文、数学老师松手就开口(设想)

> 2026-10-19 起,设想稿,代码没动,分支 `live`;怎么做在《实时老师开发计划.md》。材料:《2026-10-10-qwen3.8-omni调研.md》(realtime 的价、时延、音色)、《口语课设计.md》(`src/talk/`:realtime 中转、跟读、录像)、《工作流程.md》(一拍一就绪、仲裁表)、《看图说话设计.md》、Qwen-Live-Harness(`~/Projects/github/Qwen-Live-Harness`,下称 QLH:压缩换连接、注入时机、回执、音色复刻)、Qwen-MM-Plugins(`~/Projects/github/Qwen-MM-Plugins`,下称 QMP:说话人格式、VL 框、裁图)。
> **词**:「实时」= 老师用 realtime 模型开口、老师 CLI 在后面写卡的做法;现在的叫「板书」。「嘴」= realtime 那头,出声。「脑」= 老师 CLI(老师文件、技能、vault 照旧),出卡、出要讲的、出更正。「连接」= 一条 realtime WebSocket(「会话」留给 CLI 的 session);一个话题可以换几条连接。

结论先行:**语文、数学两位老师改成实时:孩子松手约 1 秒听到老师(现在语文 4.6 秒、数学 17.9 秒),卡由脑写、晚几秒铺上来,嘴知道板上有什么、说到卡就指着说;嘴说错了脑来更正。** 第一期按住说话(不常开麦、不认人),第一个真用的是看图说话。英语老师、听写、口语课、小课堂播放不动。

## 一、为什么

ray 10-13 到 10-18 的真数据(`conversations/*/<日期>.json` 的 `timing.firstReadyMs`,孩子发出到第一句能念):

| | 中位 / 九成 | |
|---|---|---|
| 语文老师(qwen3.8-max,随口的话不想) | 4.6 / 8.1 秒 | 看图说话那串 10 轮,每轮 4–8 秒 |
| 数学老师(同模型,effort medium = 每轮想 low) | 17.9 / 33.2 秒 | 拍照那几轮 27–51 秒;10-18 一个话题 25 轮 |
| 口语课(realtime) | 首包 0.6–0.8 秒 | 加上孩子停顿的判定,体感约 2 秒 |

- 一问一答的场景(看图说话:孩子一句短话、老师一句)每轮等 4–8 秒,一个话题十轮,大半时间在等。
- 数学慢在想:同一个模型不想是 4–5 秒。想是要的(讲题要对),但不该让孩子在想的时候干等。
- 实时把「开口」和「想」拆开:开口的(嘴)快而浅,想的(脑)慢而深,脑不在孩子等的路上,数学反而可以想得更多。
- Ray 不说英语,口语课测不出这条路;语文、数学是他天天用的,真用就是测。

## 二、孩子看到的

- 老师页和现在一样:板、字幕行、按住说话、相机。头像、名字是那位老师。
- 两种声音(待拍板 4):老师的声音(realtime)能对话,说话时头像外一圈亮;卡的声音只在点卡上的喇叭时响,念卡上的字,不接话。听声音就知道能不能回嘴。
- 松手 → 约 1 秒老师开口。卡随后铺上来;老师说到它时说「你看板上这张」。
- 老师在说时按住说话 → 老师停,听孩子的。
- 拍照:老师先说「我看看」;作业由脑读(手写要读对),看图说话的图嘴也看(印刷的画,读错代价小)。
- 孩子端的约定照守:没有错误与评判,卡上不画对错,答案不下发到孩子端。改口只说老师自己:「老师刚才数错了,是 3 只」。
- realtime 连不上(网、端点、钱),这一轮自动回到板书,孩子不知道。

## 三、嘴和脑怎么分工

**嘴**(realtime,`qwen3.8-omni-flash-realtime`):
- 系统指令整个连接不变:老师人设 + 守则里管说话的那几条 + activity 的「老师怎么带」(有就带)。动态的(档案、话题前情、板面快照)作为引用数据在开头塞进去,板面变了换快照(学 QLH 的 `[MEMORY_CONTEXT]`)。
- **每次开口都由应用给词**(2026-10-19 P1 实测定的,见下面 P1 结果):`response.instructions` =「先用一句话接孩子刚才说的(不评对错),再原样说:『…』」。词来自脑的「接下来」、讲稿、更正,或口语课那样的应用状态机。
- 嘴自己只做两件事:接住孩子的话、把给的词照说。不讲新内容、不判作业、不说卡的答案、不评对错;没有词时(孩子说的不在剧本里、脑还在想)只接一句 +「我想想」,等脑。

**脑**(现在的老师 CLI,resume 同一个会话):
- 每轮拿到:孩子的话、嘴说了什么(只算孩子听到的那段,被打断的后半句不算)、这期间板上的事(出了哪张卡、孩子答了什么、划了哪里)。
- 回的照旧是板书:卡 + 讲稿 + 尾巴。区别:讲稿不再配音,交给嘴当「要讲的」;尾巴多两段给嘴的——`接下来`(下一问、预期答案、答偏了的台阶)与 `更正`(嘴说错的那句原话 + 改成什么),孩子、家长都看不到。**脑要领先一步**:每次回都带上孩子下一次回答之后嘴要说的那句,嘴才能 1 秒接上。记忆、记账、想要小课堂照旧。
- 脑在跑时孩子又说了:排着,脑回来后把攒下的一次给它(不并发两个脑)。

**应用**(`src/live/`):
- 把这些按注入时机塞给嘴:卡铺上了(卡的字与答案)、孩子答卡(应用判,答案本来就在服务端)、板上的动作、脑的讲稿 / 接下来 / 更正。孩子在说、嘴在说、声音没放完都不塞,静 800 毫秒再塞(QLH `injector.ts`)。
- 更正分轻重(脑在 `更正` 里标):不碍事的不改;一般的下一轮带上;会让孩子照着错的去答的(数字、题意、卡上的答案),当场掐掉嘴(`response.cancel`)再说。
- 连接快满(QLH:输入 token 90%)或孩子回到旧话题:文字摘要 + 最近几条 + 板面快照,开新连接接上。

**两科的比例**(写在提示词里,代码一样):

| 场景 | 嘴 | 脑 |
|---|---|---|
| 看图说话 | 接孩子的话、照词问下一个 | 读完图一次写出六问的词(带提示、二选一),应用一问一问交给嘴;每轮把孩子那句整理成 `read` 卡(晚出不碍事);整段、顺口溜;更正 |
| 语文新话题(「三明治怎么写」,孩子问) | 1 秒接住孩子这句(说接下来做什么,不复述、不答内容;拍板 10);脑的讲稿一拍一拍照念;讲完就停 | 田字格等卡与讲稿,末句陈述(《agent层设计.md》拍板 19「答完就停」) |
| 数学讲题 | 接孩子的话、照词说;嘴自己不算(P1:随口接就算错) | 领内容:讲稿、选择 / 填空卡、预期答案与对得上 / 对不上两路的下一句;effort 可以调高 |
| 数学拍照 | 垫话:「我看看…你先把题目读给我听?」 | 读图、判、出卡(现在 27–51 秒,孩子读题的工夫正好) |

## 四、分期

每期本地提交、测试过才进下一期;要拍板的停。

**P0 抽 `src/live/`,不改行为**(1 天)
- 从 `src/talk/` 抽通用的:`realtime.ts`(连接、事件)、`ws.ts`(零依赖 WebSocket 服务端)、`lib/mix.ts` 与 `lib/wav.ts`(按到达时刻混成 `call.wav`)、录像的通用部分(消息带毫秒落 `reel.json`、钟)、孩子端采音放音(`page.ts` 里的 AudioWorklet 16k 上行、24k 排队播放)抽成共用内联源(同 `word-draw.ts` 的做法)。
- 口语课改用它们;跟读、提示卡、口语单这些场景的东西留在 `src/talk/`。
- 验收:`tests/talk*.test.ts` 全过、`probe-talk-page`、`probe-talk-webkit` 全过,`pnpm test` 全过。

**P1 探针,不进产品**(2–3 天,真连几毛钱)
1. 挑声音:语文、数学老师各挑一个 realtime 音色;再挑一种卡的声音(voxtell,中文、英文单词都念得好,和两位老师一听就不同)。三个放在一起念同一段,Jack 听。
2. 听 Ray:Ray 的 40 段真录音(`conversations/*/*.voice.webm`,中文)按手动轮次喂给 realtime,量转写对不对、松手到首包多久。
3. 守不守:语文老师人设 + 看图说话「老师怎么带」作系统指令,用 Ray 的录音当孩子跑一整遍,看一次一问、不说答案、不评判、复述孩子原话。
4. 指着板说:塞一条「[板上] 出了一张 read 卡:…」,看嘴会不会接着说「你看板上」;塞一条更正,看它怎么改口。

**P1 结果**(2026-10-19,`scripts/probe-live.mjs`;报告与 wav 在本机 scratchpad,不在仓里)
1. **快**:Ray 的 40 段真录音,松手(commit)到第一块声音中位 0.84 秒、九成 1.09 秒、最慢 2.8 秒;孩子那句的转写 0.3–0.5 秒就回来(长段约 1 秒)。现在语文 4.6 秒、数学 17.9 秒。
2. **听得准**:realtime 自带的转写比当时浏览器认的好得多:三个Siri → 三个 three、是否 → 四 four、腿的英语 → 鸡腿的英语、太太太爱心 → 太太太开心、Siri → Sandwich、乘法口诀那段从乱码变成「一一得一,一二得二…」、¥18 → 十八块。认错的:您好 → 银行、强强 → 讲讲。
3. **看得见图**:看图说话那幅图缩到长边 1024(约 128 KB)交进去,问「图上的小朋友在干什么」,答「有的在打乒乓球,有的在跳绳,还有的在踢毽子」,对,首包约 1 秒。一帧上限 262144 字节,长边 1280 的一发整条连接就断(`appendImage` 已拦)。
4. **音色**:这个模型认 Tina、Serena、Jennifer、Ryan、Dylan、Sunny、Kiki、Momo;Bella、Pip、Ethan、Chelsie 回 InvalidPara。八个都照念了同一段;卡的候选六个(两位老师现在的声音作对照)。等 Jack 听(待拍板 4)。
5. **嘴自己带不了**:
   - 看图说话照 activity 带:开场编了一句「你看板上写着『谁』」、没问问题;之后六轮只接话(「对,他们在操场上。」「哦,是下课的时候。」),一个问题都没问,活动走不下去;最后倒是背出了顺口溜。
   - 没前情时随口接 Ray 的话,数学会算错:「三个人分十四颗,每人三颗,还多两颗」。
   - 要说的话当用户消息发,它当成问题答:让它念「那一共有几个桃子呢?」,八个音色都说成「一共有十二个桃子」——答案漏了。
   - 塞「[板上] …」它不理;条件式的更正(「你要是说过……就改口」)它照改,改的是自己没说过的话,还把孩子那句的回应丢了。
   - 10-17 口语课的聊段也是这样(《实时交互评估.md》§二 1:孩子说「我不想读」,它译成 I don't want to read)。
6. **给词就照说**:要说的那句和「原样说」一起放进 `response.instructions`,4 遍 4 遍一字不差;孩子说完一句再给「先接孩子的话,再原样说『…』」,4 遍都是先自然地接一句(「同学们在一起真热闹。」)、再整句照说,没有自己答题。词和「原样念」一起当用户消息发也行;只放 system 消息不行(4 遍 3 遍只说「好,我们继续」)。

所以 §三「嘴」改成每次开口都由应用给词;脑要领先一步。

**P2 语文新话题实时版**(第一个真用,4–5 天;拍板 2:原写看图说话,改成孩子问的新话题)
- 原型先行(artifact):老师页的几屏——孩子按住问、嘴 1 秒接住、卡一拍一拍铺上来嘴照着念、孩子按住打断、讲完停;Jack 选了再做。
- 按住说话 = 手动轮次:按住推声音,松手 commit;没有回声、孩子想词停多久都行、家长插话也不会被当成孩子。
- 一轮:松手 → 嘴接住(「先用一句话接住孩子这句,复述他问的,说你写给他看;不答内容」)→ 孩子那句的转写交给脑(语文老师 CLI,不配音)→ 脑的板书一拍关一拍:卡铺上、这一拍的讲稿交给嘴照念(「原样说」)→ 讲完就停,轮到孩子。
- 嘴只接住、只照念,说不出错的内容,所以 P2 不用「接下来」「更正」(P3 看图说话再加)。
- 拍照:嘴先「我看看」,作业由脑读;嘴不看图。
- 孩子端播放:先改《工作流程.md》仲裁表(嘴的声音是一种新的「老师在念」;按住打断;卡晚到不打断嘴),再改 `tests/player.test.ts`,最后改播放的状态机。
- 录像:嘴、孩子的声音进 `call.wav`,板面事件进 `reel.json`,家长端记录点进去就是录像(同口语课)。
- 失败回落板书。工作台控制台多三道:`mouth`、`brain`、`inject`。
- 用一周,看录像:首声、卡比嘴晚多少、打断几次、回落几次。

**P3 语文老师全部实时**(3–4 天)
- 看图说话:脑读完图一次写出六问的词(带提示、二选一),应用一问一问交给嘴(孩子答了 →「先接,再原样说下一问」);脑在后面出 `read` 卡、整段、顺口溜、更正、尾巴;脑的回复多「接下来」「更正」两段。
- 小课堂看完后的问答、你说我画也走实时(听写不动)。
- 卡的再听:点卡上的喇叭,用卡的声音念卡上的字(点读、田字格本来就是这样)。不放嘴说过的录音:那是老师的声音,放出来孩子会以为能接话。卡的声音不自己响,不盖过嘴。
- 板上的动作进嘴:荧光笔划了哪、点了哪张卡、答了什么;每种定是只让老师知道,还是要老师接一句。
- 压缩换连接(话题长了、孩子回到旧话题)。

**P4 数学老师实时**(3–4 天)
- 脑领内容,effort 视效果调高;嘴带互动。
- 拍照垫话;选择 / 填空应用判,结果塞给嘴;「接下来」带预期答案。
- 照片读得准又快(先探针):VL 模型先框出孩子写答案的地方(QMP `api/vl/grounding.py`:`bbox_2d`,0–1000 归一化,认 EXIF 朝向),原图裁大了再读(QMP `core` 的 `crop`);拿 9-18 那张有真相的照片,和 qwen3.8-max 整张读(10-10:手写小字常错、数学拍照 27–51 秒)比。框也能给图片卡用:老师说「看我框的这道」,图上画框——卡片协议要加一种写法,另议。
- 更正分轻重、当场掐掉。

**P5 常开麦与家长**(等 P2–P4 用顺了再定)
- 常开麦:`semantic_vad` + `create_response:false`(应用决定回不回;口语课 10-14 想用 `server_vad` 那组,当时这台机器连端点就 403,没验成;QLH 生产在用这组,先探针)、iPad 回声、孩子长停顿。

- 卡片放的声音不用认:放的时候不推。

5. **嘴看不看照片**:看图说话看,作业不看。建议是。
6. **每天的量**:现在按条数(`dailyMessages` 30);实时一个话题孩子说十几轮。按分钟、按话题、还是不限(口语课不限,《口语课设计.md》拍板 19)。
7. **板上怎么排**:嘴的话只进字幕行,板上的卡全是脑写的;老师不问了,孩子的话多半照《工作流程.md》拍板 19 成节头。P2 的原型定。
8. **再听**:卡上的喇叭用卡的声音念卡上的字;嘴说过的话不按卡再听(随 4)。
9. **嘴每次开口都由应用给词**(P1 实测,§三「嘴」):嘴自己只接住孩子的话、照词说。证据在 P1 结果 5、6。

## 七、险

- **嘴守不守规矩**:口语课真连后提示词还改了几处(《口语课设计.md》拍板 16)。看图说话的「老师怎么带」很细,嘴是 flash 级,可能要删繁就简。
- **声音**:realtime 音色念中文给孩子听好不好、卡的声音和老师拉不拉得开,没人听过。两个声音像,孩子听到的是「老师声音不稳」,不是「这是两种东西」。
- **脑跟不上**:孩子说得快、脑一轮 4–18 秒,「接下来」可能是两轮前的;排队合并,看录像里过期多少。
- **两个作者**:卡和嘴说的对不上时,以卡为准,嘴改口。
- **iPad**:采音放音是口语课那套(Safari 走 WebKit 探针过了,AudioContext 与麦要在一次点击里起);常开麦的回声一直没验(P5)。

## 八、不做

- 英语老师不动(有口语课);听写、口语课、小课堂播放不动。
- 嘴不出卡、不写 vault;脑不派子代理(约定照旧)。
- 第一期不常开麦、不认人。
- 不 fork QLH:主从是反的(它是 Omni 派活给后台,我们是脑盯着嘴)、Host 是同机 Electron、大半用不上、记忆和 vault 的约定冲突;搬它的设计和几段代码(保留 Apache 2.0 版权头)。
