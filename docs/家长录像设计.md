# 看录像:家长端按时间重看孩子的一个话题(2026-09-29;拍板 1–5 已定,第一期、第二期已落地)

> 接《家长板书页设计.md》§六 4「PIN、录屏另议」的后半条。材料:`src/lib/kid-board.ts`(`step`、`shownCards`、`PlayerState`)、`src/lib/events.ts`(events.jsonl、`beatTimings`)、`src/schema/conversation.ts`(`timing`、`cards`、`photos`)、`src/server/store.ts`(`scanCards`、`writeCardState`、`deleteThread`)、`src/server/kid-page.ts`(`dispatch`、`loadDay`、`syncUnfold`、`PARENT` 的四处分支)、《孩子真实使用.md》。
> **词**(拍板 2;落地时进《词表.md》):「录像」= 一个话题按时间排好的一条轨道,说明每一刻板上是什么、在念哪句、孩子做了什么;代码里叫 `reel`。**不叫「回放」**:「回放」已经是 `cotutor replay`(evals/,`replayOf`),孩子端的「再听」在代码里是 `PlayerState.replay`,再用 replay 就三义了。

结论先行:**录数据,不录屏幕。** 孩子端页面本来就是「数据 → 画面」:卡和讲稿在索引里,每句的配音 mp3 在盘上,播放器 `step` 是纯函数。所以录像只需要一条带时间的轨道,回放时用孩子端那份渲染代码去画,家长听到的就是孩子当时听到的 mp3。分两期:第一期只用现有数据推算,9 月 13 日有 events.jsonl 之后的话题都能看;第二期让孩子端补记自己看到、听到、做了什么,录像从「推算」变成「实录」。

## 一、为什么不录屏幕

| 做法 | 不要的理由 |
|---|---|
| 真录屏(getDisplayMedia / 孩子端 MediaRecorder 录画面) | iPad Safari 不支持持续录屏;一个话题几十 MB;跳不到「孩子交卡那一刻」;Claude Code 分析不了 |
| 录 DOM(rrweb 一类) | DOM 是从数据派生的,录派生物又大又脆:页面改一版,旧录像就放不对;还会把孩子打字的中间态一起录下来 |
| 录播放器的输入事件,回放时重跑 `step` | 仲裁表几天改一次(再听、录音卡、课文件一节一节念都改过),旧录像用新代码重跑会跑出另一个样子 |
| **录结果**(本文) | 板上有什么、念到哪、卡的状态几点变成什么;和代码版本无关,体积按 KB 算,渲染照用现成的 |

## 二、现有数据能还原多少

| 要还原的 | 来源 | 精度 |
|---|---|---|
| 孩子几点开口、说了什么、按了继续 / 交给老师、带的照片 | 索引消息 `timing.startedAt`(毫秒)、`text`、`action`、`photos`、`via` | 准 |
| 孩子在板书上做的(交给老师时) | 消息的 `cards[]`(describe 出的那句) | 准 |
| 老师每张卡、每拍什么时候出来 | `<日期>.<job>.events.jsonl`:`main card`、`ready beat`、`main exit`(t 从 startedAt 起算) | 准 |
| 孩子等了多久听到第一个字 | `timing.firstReadyMs`(没有就按 events 的首个 `ready beat`) | 准 |
| 每句念多长 | 盘上 mp3 的时长(从帧头算);没配音的句按字数估 | 准 / 估 |
| 录音卡里孩子的声音 | `.cards/<n>/rec-<k>.*` | 准,录像里在当时那一刻播 |
| 每句**实际**什么时候念 | 没有 | 推算:就绪就顺着念 |
| 暂停、再听、点开舞台、关了自动念、切后台 | 没有 | 缺(第二期补) |
| 卡的中间状态(先选 A 又改 B) | `<n>.json` 只存最后一次,带 `at` | 只有终态(第二期补) |

## 三、第一期:用现有数据推算

### 3.1 纯函数 `src/lib/reel.ts`

```ts
buildReel(input: {
  messages: ConversationMessage[];          // 这个话题的,按顺序
  events: Record<job, RunEvent[]>;          // 每轮的 events.jsonl(没有的轮只用 timing)
  cardStates: CardStates;                   // scanCards 的 states(带 at)
  durations: Record<audioPath, number>;     // 每句 mp3 的毫秒数
  plays?: PlayRecord[];                     // 第二期:孩子端实录;有就优先
}) → Reel

Reel = {
  startAt: number; endAt: number;           // 墙钟毫秒
  precise: boolean;                         // 全程有实录才是 true
  marks: Mark[];                            // 进度条上的点
  gaps: Gap[];                              // 可压缩的空白
  frames: Frame[];                          // 按 at 排好的变化
}

frameAt(reel, t) → {
  sections: BoardSection[];                 // 到 t 为止出来了的节;流式那节截到就绪的拍(ready)
  player: PlayerState;                      // 在念哪句 / 停下等 / 老师在写
  cardStates: CardStates;                   // at ≤ t 的状态
  notes: Note[];                            // 到 t 为止该出的旁注
}
```

不碰 DOM、不读盘,`tests/reel.test.ts` 离屏测。

### 3.2 推算规则

- 每轮以 `timing.startedAt` 为原点,事件的 `t` 直接加上。没有 `timing` 的老轮按 `at`(分钟)放,并且不给这一轮推念句。
- **节什么时候出来**:流式的轮按 `ready beat` 一拍一拍露;整块出的轮(课文件交出去的、没流式的运行时)在 `index written` 那一刻整节出来,之后按 `shownCards` 念到哪露到哪(和孩子端第一遍念的一样)。
- **念句**:一拍就绪就从它第一句念起,一句念完、句间停顿按孩子端的间隔,再念下一句;下一拍还没就绪就停在「老师在写」。末句是问句的就停在「等孩子」,直到下一轮开口。
- **卡的状态**:从 `<n>.json` 的 `at` 起生效。孩子在两轮之间改了很多次,第一期只看得到最后一次。
- **孩子开口**:以 `startedAt` 为时刻,出旁注(孩子说的 / 首页按钮 / 继续 / 交给老师 / 照片 / 课上说的)。
- **出错的轮**:在 `main exit` 那一刻出一行「这轮没成」旁注,和家长板书页一致。

### 3.3 空白压缩

一个话题动不动二十分钟,大半是孩子在想、在做卡,或者走开了。

| 空白 | 真实时长 | 压成 |
|---|---|---|
| 孩子开口 → 老师第一声 | ≤ 10 秒 | 不压,这就是孩子感受到的慢 |
| 同上 | > 10 秒 | 前 10 秒照放,其余压成标签「⏳ 等老师 23 秒」 |
| 停下等孩子 / 念完了 → 孩子下一次开口 | > 5 秒 | 压成 1.5 秒的标签「⏩ 孩子想了 2 分 10 秒」 |

控制条上有个「跳过空白」开关,缺省开着;关掉就按真实时间放,一段都不压(2026-09-29 由「按真实时间」改名:原来的名字说的是打开以后怎样,可它平时关着,家长看不懂;同日从「靠边框颜色区分的按钮」改成带文字的开关(`role=switch`,滑块在右、底色填满 = 开着),和主流播放器的「跳过静音」一样)。压缩只改播放时钟,不改 `frameAt`,进度条下面的刻度照样是墙钟时间。

### 3.4 接口

`GET /api/conversations/<老师>/<日期>/threads/<id>/reel` → `Reel`(外加这个话题的节,形状和 `/board` 一样,答案不剥)。

- 服务端读索引、这些轮的 events.jsonl、`scanCards`、mp3 时长,再调 `buildReel`。页面不自己读 events。
- mp3 时长由新纯函数 `src/lib/mp3.ts` 算(读帧头,CBR 用文件大小 ÷ 码率,VBR 走 Xing 头),进程内按路径缓存。
- 老师还在写的话题照样给,`endAt` 截到现在。

### 3.5 页面

家长端 `/parent` 的板书页:

- 右上角喇叭左边一颗「看录像」(胶片图标)。只看孩子开过口的话题;备课话题、没交出去的课、课文件页不出。
- 进入后底部换成控制条:▶ / ⏸、1× / 1.5× / 2×、带标记点的进度条(孩子开口 ● / 老师第一声 ▲ / 交卡 ✓ / 停下等孩子 ⏸ / 出错 ✕)、当时的钟点「15:42:10」、「跳过空白」开关、「退出」。
- 拖进度条或点标记 = 调 `frameAt(t)`:把 `S.sections`、卡的状态设成那一刻,走现有的渲染与 `syncUnfold`,滚到在念的那句;在念的句从偏移处放它的 mp3。
- 播放时由一个时钟驱动,**不经过 `step`**。仲裁表和 `tests/player.test.ts` 一个字都不改。
- 旁注照家长板书页那张表出,只是按时间一条一条冒出来。录音卡在孩子录的那一刻,自动放孩子的录音。
- 卡全部只读,点开舞台只看(`S.readonly`)。场景卡在第一期里不自动开舞台(不知道孩子开没开)。
- 顶上标「推算」或「实录」;推算的旁边一个 ⓘ,点开写「孩子端第二期之前的话题:念句的时刻是按就绪顺着念推的,暂停、再听、卡的中间状态看不到」。

`kid-page.ts` 里,录像算 `PARENT` 的 chrome 与数据源两处分支里的一个子态(`S.reel`),驱动放进一个独立的函数块,别处不认识 `S.reel`。

## 四、第二期:孩子端补采集

### 4.1 记什么

只记孩子看到、听到、做了什么,不记输入事件(理由见 §一最后一行)。

| 记录 | 从哪来 | 形状 |
|---|---|---|
| 播放位置变了 | 页面 `dispatch` 之后,`S.state` 和上一条不同 | `{at, k: 'play', sec, line, status, replay?: true}` |
| 舞台开 / 关 | `openStage` / `closeStage` | `{at, k: 'stage', sec, card, open}` |
| 自动念开 / 关 | 喇叭 | `{at, k: 'autoplay', on}` |
| 切后台 / 回来 | `visibilitychange` | `{at, k: 'visible', on}` |
| 录音按下 / 松手 | `recStart` / `recEnd` | `{at, k: 'rec', sec, card, on}` |
| 卡的每次改动 | **服务端** `putCardState` 顺手追加 | `{at, k: 'card', job, n, state}` |

`sec` 用节的 job(`sections[sec].job`),不用页面里的下标;下标会因为 `liveDropped`、课文件攒节而错位。

### 4.2 存在哪

`conversations/<老师>/<日期>.<job>.play.jsonl`,job 取这个话题当时最后一轮的。于是:

- `store.deleteThread` 按 `<日期>.<job>.*` 删话题时,录像一起删,不另写清理。
- 孩子在以前的话题里只读地看,记进那个话题最后一轮的文件。
- 卡的改动记进这张卡所在轮的 `play.jsonl`(那一轮的 job 本来就在 `CardStateFile.turn` 和路径里)。

### 4.3 怎么发

- 路由 `POST /api/kid/conversations/<老师>/play`,body 是一批记录。服务端验形状(每批 ≤ 200 条、`at` 在今天、job 属于这位老师今天的索引),坏的丢掉,不回错(孩子端不报错)。
- 页面攒着,每 10 秒一批;`pagehide` 用 `sendBeacon`。发不出去就丢,不重试、不进 localStorage;录像少几条不要紧。
- 家长端的数据源是 `/api/conversations/*`,碰不到这条路由,所以家长自己看不会被记。这仍在「数据源」那一处分支里,不新增分支。
- mock 也收这条,测页面时不打盘。

### 4.4 不录的

- 孩子打字的过程,只有发出去的那句。

### 4.6 按住说话的原声(拍板 4,2026-09-29 已落地)

起因:9 月 28 日英语那段,孩子那句被认成「Apple苹」,家长看录像想知道是孩子说成这样,还是识别认错了。

- **录**:`listen()` 起识别前,在常开的那一路麦克风上起一个 MediaRecorder(和录音卡同一个 `recMime()`);收尾时停(松手 → 识别停 → `close(true)`),上滑取消、识别一起就断都丢掉。麦克风冷开那一下(约 1 秒)识别听不到,原声也录不到,两者一致。识别半路断了重开麦克风时,原声跟着重录。
- **发**:认出了字才发;原声停录是异步的,最多等 1.5 秒,等不到就只发字。消息多一个 `voice: {audio: data:audio/…;base64, seconds}`;孩子端与家长端两条发消息的路都收。形状不对、不是声音、超过 4 MB 的 base64 就当没带,**字照发、不回 400**。课文件还在一节一节念时攒着的话不带原声。发照片屏配的那句话也不带(第一版没接)。
- **存**:runner 在 `send` 里落成 `conversations/<老师>/<日期>.<job>.voice.<ext>`(webm / m4a / ogg / wav),消息记 `voice: {audio, seconds}`。删话题按 `<日期>.<job>.*` 一起删。
- **谁能拿到**:家长接口(`/board`、`/reel`)给;孩子接口、上下文包、老师都不给。`/api/audio` 认 `.voice.` 这个名字。
- **录像**:原声是一段 `clip`(`kind: 'voice'`),从发出去往前推 seconds 秒;开口的点挪到按下那一刻;孩子一按下孩子端就停声音,所以前一节念到那一刻为止。放原声时字幕写「🎙 孩子的原声 · 认成「…」」,好对一对。
- **家长板书页**:孩子那句旁注上一颗「▶ 原声 N 秒」,点了放、再点停(先 `halt`,不绕过 step)。
- 验收:`tests/voice.test.ts` 10 项(落盘、m4a、孩子接口与上下文包没有、家长接口有、`/api/audio` 能放、坏的照发、录像里的时刻、删话题一起删),`tests/reel.test.ts` 加 2 项;`scripts/probe-voice.mjs`(Chrome 假麦克风 + 注入的假识别器)4 项:松手带原声发、冷开录得短一截、上滑取消不发、麦克风开着按住 2 秒录到 1.9 秒。**iPad 上识别与录音同开一路麦克风还没真机看**:那台 iPad 的识别本来就脆(见 `kid-page.ts` 里「麦克风常开」那段),真机上要看识别有没有因此变差。

### 4.7 录像里的弹窗与「想了多久」(拍板 5)

起因:数学老师的答题卡在弹窗里说「右边空 ___ 格」「哪块板凸点多」,弹窗里只有这一张卡,「左边 / 右边」根本看不到;家长要看到孩子当时面对的是什么、在弹窗里想了多久才答。

- **弹窗开、关**:孩子端 `openStage` / `closeStage` 各记一条(包括讲稿推上来的答题卡、[[play]] 交给场景)。录像里按记录在那一刻只读地打开同一张卡的弹窗:和孩子端同一套渲染,板书压暗;弹窗里点不动、没有关闭钮,跟着记录关。
- **孩子在弹窗里的每一步**:卡的每一次存(选择题每点一下、填空停手 0.4 秒、画板每一笔、录音每录一次)服务端在 `putCardState` 里追加一条;录像里弹窗开着时,这些改动一步步出现在弹窗里(重卡的 iframe 重发一次 card 消息,不重装)。
- **想了多久**:弹窗打开到这张卡第一次改动,减去中间切到后台的时间;之后再改算「改过 N 次」。录像里弹窗开着、孩子还没动时字幕写「⏱ 想了 12 秒」(想得久照样压成 1.5 秒);家长板书页「做了」那条旁注后面写「想了 12 秒 · 改过 1 次」(这张卡从上一条消息到这条之间的所有弹窗加在一起:第一次打开到第一次改动)。只露「想了多久」这一种时长(拍板 1)。
- **没做**:家长端平时(不看录像)点卡开弹窗、弹窗里看不到的指代自动提醒——和录像无关,不做(拍板 5)。点读点了哪段、图片放大拖动不记。

### 4.8 第二期落地(2026-09-29)

和 §4.1–4.7 不一样、或没写到的:
