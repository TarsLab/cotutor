# 家长板书页:家长在 iPad 上看孩子的板书

> 2026-09-22 起;同日三期都落地:看(清单、板书、旁注、二维码、manifest)、试用(第五节)、家长真发与打星(第六节 3);只剩「试首页按钮的讲法」没做。起因:原来的 `/parent`(2026-09-22 起改叫工作台 `/dev`,拍板 13)是桌面页(没有一条 `@media`,`.stream` 定宽 940 加侧栏),面向配置与调试,要保留;家长拿起 iPad 想看「今天都学了什么、老师怎么讲的、孩子答了什么」,今天没有一页给这个用。第二个场景是**试用**:家长改了老师文件或 vault,想在 iPad 或 Mac 浏览器上看看老师现在会怎么讲,又不能进孩子的对话。拍板在文末。材料:`src/server/kid-page.ts`(板书渲染、只读回放、`__PREVIEW__`)、`src/lib/kid-view.ts` `kidConversation`、`src/server/app.ts` `kidDay` 与 `/parent/home-preview`、`src/server/parent-page.ts` 对话页、`src/server/replay.ts` `evalWorkspace`、`src/server/runner.ts` 记忆那处的 `replayOf` guard、《首页设计.md》§7.3、《产品规划.md》两个端。
> **词**:「板书页」= 孩子端的老师页,一位老师一个话题一页板书。「家长板书页」= 本文这一页,同一套渲染、家长的数据、只读。「旁注」= 家长板书页在节与节之间插的只读块(孩子说的、给家长的尾巴、记忆改动),**不是卡**。

结论先行:加一条家长侧的路由(当时是 `/parent/board`;2026-09-22 拍板 13 起就是 `/parent`,原 `/parent` 改 `/dev`),用孩子端页面本身渲染板书(和《首页设计.md》§7.3 首页预览一个做法:「渲染和孩子端一份代码,不会漂」),数据走家长接口(答案不剥、家长与系统发的话也在),节间插旁注,只读。同一页带 `try=1` 是**试用**:改了老师文件或 vault 想看效果,用孩子的方式和老师聊,落 `evals/`、不写记忆、孩子看不到(第五节)。孩子端一个字节不改;《产品规划.md》「孩子设备上没有通往家长端的入口」不动。

## 一、为什么不是孩子端「更多」里的一个开关

最初的想法是在孩子端「更多」菜单里放一个面向家长的开关,开了多显示几种「卡」。不这么做,三个理由:

1. **撞约定**。「孩子设备上没有通往家长端的入口」(《产品规划.md》两个端)。菜单里的开关就是入口,孩子一定会翻到。
2. **过滤失守**。记忆条目是老师对孩子的观察,家长尾巴是写给家长的评价,今天它们永远不进 `/api/kid/*`(《契约草案.md》§4,过滤在服务端做)。开关一开,要么孩子接口开始带家长数据,要么孩子页里长出第二条数据流去请家长接口。哪一种都在削「孩子端永远没有评判」这条约定。
3. **词会污染卡的协议**。仓里的「卡」是老师在围栏里写、`cards/<kind>/card.md` 八栏定义、点了进舞台、状态存服务端的东西。孩子的话、记忆改动不是老师写的、没有状态、不进舞台,做成卡种会让 `src/cards/` 注册表与 cotutor-board 技能多出一堆「老师不该写的卡」。

独立路由还有一个好处:后面迭代(家长发消息、打星、拍照)只动这一页,不碰孩子端的仲裁表。

## 二、页面

### 2.1 入口

- 路由 `/parent`,查询串 `?tutor=<名>&date=<日期>&thread=<话题>`;都不带就开在**今天的清单**(2.2)。
- `/qr` 页多印一个码「家长看」,编 `https://<主机名>.local:<端口>/parent`;工作台 `/dev` 顶部「扫码打开」旁有「家长端」。
- 自己的 manifest `/parent/manifest.webmanifest`(名字「<title> · 家长」,`start_url` 是这条路由),否则加到主屏幕拿到的是孩子端那份。
- 不设 PIN(见拍板 3)。一台 iPad 两个人用,主屏幕两个图标孩子都看得见——先看真用起来有没有问题,再决定要不要一个四位数。

### 2.2 今天的清单

家长在 iPad 上更常问的是「今天都学了什么」,是跨老师、跨话题的,板书页答不了,所以前面有一层:

- 顶上一个日期(缺省今天,能往前翻);下面每位有脸的老师一块:头像、显示名、今天几轮、花了多少。
- 块里一行一个话题:孩子第一句(截 20 字,首页按钮进来的标「首页 · 按钮字」)、几点、几节几张卡、停在哪(末句问句 / 在等孩子答 / 老师还在写)、家长打的星、记过账没有。
- 点一行进 2.3 的板书;家长、系统发起的话题也列(孩子端的「以前的」不列它们)。
- 行角上「删」(2026-09-22 加,孩子的与试过的都有):点一下变「确定删?」,3 秒内再点才删,没有弹窗;`DELETE /api/conversations|tryouts/<老师>/<日期>/threads/<id>` → `store.deleteThread`:索引里那个话题的消息、会话、星、记账标记去掉,那些轮的文件按 `<日期>.<job>.*` 整个删;老师还在写的 409。**不动**:vault 里的记忆与日记(家长的,去 Obsidian 改)、`captures/` 的照片;首页发布件里指向它的「接着」「再看看」按钮由既有的引用检查藏掉。
- 一位老师今天一句都没有就写「今天没聊」;后端不通整页灰,和孩子端一样。

数据和 cotutor-home 技能第二步读的是同一份(每位老师当天的索引),不另算。

### 2.3 板书

孩子端页面本身,`__MODE__ = "parent"`(见 4.1),差别只有四处:

| | 孩子端 | 家长板书页 |
|---|---|---|
| 数据 | `/api/kid/conversations/<老师>/<日期>` | `/api/conversations/<老师>/<日期>/board`(三、四) |
| 顶部 | 头像胶囊(回首页)、喇叭、更多 | 「‹ 清单」、老师与话题标签、喇叭;没有「更多」 |
| 底部 | 输入条(说话 / 打字 / 相机) | 没有;`S.readonly = true`,走「以前的」那条只读路径(选择 / 填空 / 画板不开) |
| 板书 | 节 | 节 + 旁注(三) |

- **只读**:不能发消息、不能改卡的状态、不能开新话题;卡照孩子端画,点一张卡进舞台只看(`readonly` 已经这么做)。
- **不自动念**:喇叭缺省关,家长想听哪句点哪句;不「从第一句播」。
- **老师还在写**:和孩子端一样流式露卡、轮询;孩子在另一台设备上答了,这边照服务端的状态重画(`loadDay` 已有这段)。
- **仲裁表不改**:`kid-board.ts` 的 `step` 一个字不动,家长页只是少发几种事件。
- 以上是看的模式;`try=1` 时输入条、喇叭、「更多」都回来,见第五节。

## 三、旁注

家长比孩子多看到的东西。全是只读块,插在节的前后或卡的下面,样式在 `kid.css` 里加一组 `.note-*`,主题槽表不加新槽。

| 旁注 | 来源(索引字段) | 放哪 | 说明 |
|---|---|---|---|
| 孩子说的 | `from: kid` 的 `text` | 节前 | 首页按钮进来的(`via`)标「首页 · <label>」,不当孩子说的;`action: continue` 显示「继续」,`submit` 显示「交给老师」 |
| 家长 / 系统说的 | `from: parent / system` 的 `text` | 节前 | 标「家长」「系统」;孩子端不显示这些,家长页显示 |
| 照片 | `photos[]` | 孩子那句话下 | 经 `/api/kid/image?p=`(已有,只认 captures/ 里的) |
| 孩子在板书上做的 | `cards[]`(id + describe 出的那句) | 孩子那句话下 | 就是老师在这轮上下文包里看到的 |
| 卡的答案 | 不经 `stripSecrets` 的 `section` | 卡下一行灰字 | `choice` 的对错、`fill` 的答案;孩子答了的照孩子端画(状态在服务端),旁边灰字是答案,**不画对错标记** |
| 停下等孩子 | 末句 `ask` | 讲稿末句后 | 和家长端对话页一样缀「⏸ 停下等孩子」 |
| 给家长的 | `parentText` | 节尾 | 去掉「## 家长」标题 |
| 记住了 / 整理了记忆 | `remembered[]` | 节尾 | `tidy` 的那轮单独一节,只有这个旁注 |
| 记账 | `bookkeep` 那轮 | 话题尾 | 「已记进日记」一行;不展开记账段(日记在 Obsidian) |
| 提醒 | `warnings[]` | 节尾 | 灰字;「API 流断了 N 次」也在这里 |
| 出错 | `result: error` | 节位 | 孩子端什么都不出现,家长页出一行「这轮没成:<error>」 |

**不放**:思考摘要、工具行(`tools`)、用时(`timing`)、费用、后期结果(`post`)、会话 id、看原文。那是调试面,留在工作台 `/dev`。iPad 上的家长是在看孩子学了什么,不是在看进程。

## 四、数据与代码

### 4.1 接口

都在家长命名空间下,孩子接口(`/api/kid/*`)与 `kidConversation` 不动。

## 五、试用:改了提示词或 vault,想试试效果

第二个场景:家长改了老师文件的正文、在 vault 里加了一节题型设计,想看老师现在会怎么讲——在 iPad 上,或者就在 Mac 的浏览器里。今天能做的是工作台 `/dev` 对话页发一条家长消息,或 `cotutor replay` 把旧问题按现在的提示词再问一遍看 diff。两个都不对路:前者**进孩子的对话**(老师会往 vault 写记忆、话题列进当天索引、记账时会被记),后者是拿旧问题比差异,不是拿新问题看效果,也不配音、不后期,看不到孩子会看到的样子。

### 5.1 试用是什么

**在孩子看不到的地方,用孩子的方式,和老师聊。** 一次试用 = 一个话题,落在 `evals/`(和 replay 同一个目录、同一套文件),永远新会话,所以老师文件与 vault 的改动一定生效;话题内可以接着问(resume),想从头再来就「重来」= 新话题新会话。

| | 孩子的对话 | replay | 试用 |
|---|---|---|---|
| 落在哪 | `conversations/` | `evals/` | `evals/` |
| 问题 | 孩子现问 | 旧问题原样 | 家长现问 |
| 会话 | 按话题 resume | 永远新 | 话题第一条新,话题内 resume |
| 记忆段 | 落 vault | 不写(`replayOf`) | **不写**(`tryout: true`,同一处 guard) |
| 每日上限 | 算 | 不算 | 不算 |
| 配音 | 开 | 关 | **开**(要听) |
| 板书后期 | 开 | 缺省关 | **开**(要看真实的样子) |
| 卡能不能做 | 能 | 不能 | **能**(状态存 `evals/…/.cards/`) |
| 孩子端 | 看得到 | 看不到 | 看不到 |
| 记账 | 记 | 不记 | 不记 |
| 费用 | 家长端看 | CLI 打印 | **板书上每轮一个小标签**(试用是家长在花钱,这一处例外) |

服务端就是 `replay.ts` 的 `evalWorkspace` 再开配音与后期,给 `Runner` 一个 evals 的 Workspace——和 replay 同一条路,跑的仍是 `gatherContext → buildContextPack → spawn → 解析 → 物化`,所以看到的就是孩子会看到的。serve 里另起一个 `Runner` 实例挂 evals(`running()` 按实例算,试用不会把孩子那边挡成 409,孩子也挡不了试用)。

### 5.2 在页面上

- 家长板书页 `?tutor=<名>&try=1`:**打开就是新话题空白态**,底部是孩子端自己的输入条(按住说话 / 打字,相机先不给),喇叭缺省开,末句问句照停、卡照做、「交给老师」照交——就是孩子端,只是数据落在 evals/。头像旁的小标签写「试用 · 不进孩子的对话」,一直亮着。
- 「更多」里只有「重来」(新话题新会话)与「以前试过的」(evals/ 里的话题;能接着聊,和孩子端「今天的话题」一个路子,不按天只读)。
- 旁注照第三节插(家长自己说的、答案、给家长的、**本来会记住的**——记忆段没写进 vault,但要给家长看老师想记什么、提醒)。
- 清单(2.2)每位老师一块的右上角一个「试一试」;块下面一栏「试过的」列 evals/ 里的话题。
- Mac 浏览器里一样开这一页;窄一点看手机版(`?device=phone`,和首页预览一个参数),板书后期也按这个端排。清单上每位老师块有「试一试」——工作台 `/dev` 自己不做试用,它的 composer 是发真消息的。
- 想试首页某个按钮的讲法:第二期,`&via=<草稿里的按钮>`,讲法从 `home/draft.md` 取。

### 5.3 接口与代码

- `/api/tryouts/<老师>/…` **形状同 `/api/kid/conversations/<老师>/…`**(`today` / `<日期>` / `messages` / `history` / `cards/<job>/<n>`),页面只换一个前缀;配音在 `/api/tryouts/audio/<老师>/<文件>`。`messages` 的 body 同孩子端(`text / thread / newThread / action / focus / device`),`from: parent`,消息带 `tryout: true`;没有 `photos`、没有 `via`、没有 429。下发的是家长的形状(`parentConversation`:答案不剥,多 `tryout / memoryDraft / costUsd`),只看 evals/ 里 `tryout` 的轮(那里还有回放)。
- `src/schema/conversation.ts`:`tryout: z.literal(true).optional()`、`memoryDraft?: string[]`(记忆段原文,没写 vault);`runner.ts` 记忆那处:`replayOf` 不写并提醒,`tryout` 不写、原文进 `memoryDraft`,不提醒。`bookkeep` 与 `kidMessageCount` 本来就不碰 evals/。
- `src/server/replay.ts`:`evalWorkspace(ws, { post, voice })`;`app.ts` 的 `tryoutWorkspace` = 两个都开,`AppContext.tryRunner` 挂在它上面;`parentDay(ctx, tutor, date, src)` 多一个 `DaySource`(哪个 ws、哪个 runner、只看哪些轮),清单每位老师多 `tryouts`。卡的状态两条路共用 `putCardState`(画板 png 的路径前缀是 `conversations` / `evals`)。
- `kid-page.ts`:`TRY = PARENT && ?try=1`;`CONV` / `AUDIO` 前缀、`AUTOPLAY_KEY` 三个常量;`openTutor` 里今天的不只读、以前的只读;chrome 回来但藏相机与相册,「更多」里改名「重来」「以前试过的」;旁注多「本来会记住的」与「费用」。清单上「试一试」「试过的」都是换 URL 进 `try=1`,页面自己不切模式。
- 测试:`tests/home-flow.test.ts`(假 CLI)试用一轮:`evals/` 有、`conversations/` 没有新文件、`/api/kid/…` 不变、vault 记忆文件没建、消息带 `tryout` 与 `memoryDraft`、接着同一话题是 resume、卡的状态落 evals/;`tests/mock.test.ts` 形状与清单。
- CLI 不加命令:要在终端试就 `cotutor replay`;技能 cotutor-analyze 读 evals/ 时把 `tryout` 的话题也列出来(「家长试过的」)。

## 六、分期
