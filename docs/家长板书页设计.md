# 家长板书页:家长在 iPad 上看孩子的板书

> 2026-09-22 起。起因:原来的 `/parent`(2026-09-22 起改叫工作台 `/dev`,拍板 13)是桌面页(没有一条 `@media`,`.stream` 定宽 940 加侧栏),面向配置与调试,要保留;家长拿起 iPad 想看「今天都学了什么、老师怎么讲的、孩子答了什么」,没有一页给这个用。第二个场景是**试效果**:家长改了老师文件或 vault,想在 iPad 或 Mac 浏览器上看看老师现在会怎么讲,又不能进孩子的对话。拍板在文末。材料:`src/server/kid-page.ts`(板书渲染、只读回放、`__MODE__`)、`src/lib/kid-view.ts` `kidConversation` / `parentConversation`、`src/server/app.ts` `kidDay` / `parentDay`、《产品规划.md》两个端。
> **词**:「板书页」= 孩子端的老师页,一位老师一个话题一页板书。「家长板书页」= 本文这一页,同一套渲染、家长的数据、只读。「旁注」= 家长板书页在节与节之间插的只读块(孩子说的、给家长的尾巴、记忆改动),**不是卡**。

结论先行:家长侧的路由 `/parent`,用孩子端页面本身渲染板书(渲染和孩子端一份代码,不会漂),数据走家长接口(答案不剥、系统发的话也在),节间插旁注,卡锁着,只看。试效果不在这一页:家长到孩子端当一回孩子,回来在清单上删掉那个话题(第五节)。孩子接口不动;《产品规划.md》「孩子设备上没有通往家长端的入口」不动。

## 一、为什么不是孩子端「更多」里的一个开关

最初的想法是在孩子端「更多」菜单里放一个面向家长的开关,开了多显示几种「卡」。不这么做,三个理由:

1. **撞约定**。「孩子设备上没有通往家长端的入口」(《产品规划.md》两个端)。菜单里的开关就是入口,孩子一定会翻到。
2. **过滤失守**。记忆条目是老师对孩子的观察,家长尾巴是写给家长的评价,今天它们永远不进 `/api/kid/*`(《契约草案.md》§4,过滤在服务端做)。开关一开,要么孩子接口开始带家长数据,要么孩子页里长出第二条数据流去请家长接口。哪一种都在削「孩子端永远没有评判」这条约定。
3. **词会污染卡的协议**。仓里的「卡」是老师在围栏里写、`cards/<kind>/card.md` 八栏定义、点了进舞台、状态存服务端的东西。孩子的话、记忆改动不是老师写的、没有状态、不进舞台,做成卡种会让 `src/cards/` 注册表与 cotutor-board 技能多出一堆「老师不该写的卡」。

独立路由还有一个好处:后面迭代(家长发消息、打星、拍照)只动这一页,不碰孩子端的仲裁表。

## 二、页面

### 2.1 入口

- 路由 `/parent`,查询串 `?tutor=<名>&date=<日期>&thread=<话题>`;都不带就开在**今天的清单**(2.2)。
- `/qr` 页多印一个码「家长看」,编 `https://<主机名>.local:<端口>/parent`;工作台 `/dev` 顶部「扫码打开」旁有「家长端」。
- 自己的 manifest `/parent/manifest.webmanifest`(名字「<title> · 家长」,`start_url` 是这条路由),否则加到主屏幕拿到的是孩子端那份。
- 不设 PIN(见拍板 3)。一台 iPad 两个人用,主屏幕两个图标孩子都看得见——先看真用起来有没有问题,再决定要不要一个四位数。

### 2.2 今天的清单

家长在 iPad 上更常问的是「今天都学了什么」,是跨老师、跨话题的,板书页答不了,所以前面有一层:

- 顶上一个日期(缺省今天,能往前翻);下面每位有脸的老师一块:头像、显示名、今天几轮。
- 块里一行一个话题:孩子第一句(截 20 字,首页按钮进来的标「首页 · 按钮字」)、几点、几节几张卡、停在哪(末句问句 / 在等孩子答 / 老师还在写)、家长打的星、记过账没有。
- 点一行进 2.3 的板书;系统发起的话题也列(孩子端的「以前的」不列它们)。
- 行角上「删」(2026-09-22 加):点一下变「确定删?」,3 秒内再点才删,没有弹窗;`DELETE /api/conversations/<老师>/<日期>/threads/<id>` → `store.deleteThread`:索引里那个话题的消息、会话、星、记账标记去掉,那些轮的文件按 `<日期>.<job>.*` 整个删;老师还在写的 409。**这个话题留下的痕迹一起撤**(2026-10-05,拍板 18):各轮写进 vault 记忆的行倒着撤(`memoryLines`)、记账写进日记的那段摘掉(`diaryBlock`),每日条数自然退回;那一行后来被家长或「整理记忆」改过就找不到、不动,记进回的 `undo.misses`;页面弹一句撤了几条记忆、日记摘没摘、哪条没撤成。**不动**:`captures/` 的照片;首页发布件里指向它的「接着」「再看看」按钮由既有的引用检查藏掉。
- 一位老师今天一句都没有就写「今天没聊」;后端不通整页灰,和孩子端一样。

数据和 cotutor-home 技能第二步读的是同一份(每位老师当天的索引),不另算。

### 2.3 板书

孩子端页面本身,`__MODE__ = "parent"`(见 4.1),差别只有四处:

| | 孩子端 | 家长板书页 |
|---|---|---|
| 数据 | `/api/kid/conversations/<老师>/<日期>` | `/api/conversations/<老师>/<日期>/board`(三、四) |
| 顶部 | 头像胶囊(回首页)、喇叭、更多 | 「‹ 清单」、老师与话题标签、喇叭;没有「更多」 |
| 底部 | 输入条(说话 / 打字 / 相机) | 没有输入条(2026-10-05 起,拍板 19);`S.readonly = true`,走「以前的」那条只读路径(选择 / 填空 / 画板不开) |
| 板书 | 节 | 节 + 旁注(三) |

- **卡锁着**:不能改卡的状态;卡照孩子端画,点一张卡进舞台只看(`readonly` 已经这么做)。
- **不自动念**:喇叭缺省关,家长想听哪句点哪句;不「从第一句播」。
- **老师还在写**:和孩子端一样流式露卡、轮询;孩子在另一台设备上答了,这边照服务端的状态重画(`loadDay` 已有这段)。
- **仲裁表不改**:`kid-board.ts` 的 `step` 一个字不动,家长页只是少发几种事件。

## 三、旁注

家长比孩子多看到的东西。全是只读块,插在节的前后或卡的下面,样式在 `kid.css` 里加一组 `.note-*`,主题槽表不加新槽。

| 旁注 | 来源(索引字段) | 放哪 | 说明 |
|---|---|---|---|
| 孩子说的 | `from: kid` 的 `text` | 节前 | 首页按钮进来的(`via`)标「首页 · <label>」,不当孩子说的;`action: continue` 显示「继续」,`submit` 显示「交给老师」 |
| 系统说的 | `from: system` 的 `text` | 节前 | 标「系统」;孩子端不显示这些,家长页显示。2026-10-05 起没有 `from: parent`,工作台与 `cotutor send` 发的记孩子 |
| 照片 | `photos[]` | 孩子那句话下 | 经 `/api/kid/image?p=`(已有,只认 captures/ 里的) |
| 孩子在板书上做的 | `cards[]`(id + describe 出的那句) | 孩子那句话下 | 就是老师在这轮上下文包里看到的 |
| 卡的答案 | 不经 `stripSecrets` 的 `section` | 卡下一行灰字 | `choice` 的对错、`fill` 的答案;孩子答了的照孩子端画(状态在服务端),旁边灰字是答案,**不画对错标记** |
| 停下等孩子 | 末句 `ask` | 讲稿末句后 | 和家长端对话页一样缀「⏸ 停下等孩子」 |
| 给家长的 | `parentText` | 节尾 | 去掉「## 家长」标题 |
| 记住了 / 整理了记忆 | `remembered[]` | 节尾 | `tidy` 的那轮单独一节,只有这个旁注 |
| 记账 | `bookkeep` 那轮 | 话题尾 | 「已记进日记」一行;不展开记账段(日记在 Obsidian) |
| 提醒 | `warnings[]` | 节尾 | 灰字;「API 流断了 N 次」也在这里 |
| 出错 | `result: error` | 节位 | 孩子端什么都不出现,家长页出一行「这轮没成:<error>」 |

**不放**:思考摘要、工具行(`tools`)、用时(`timing`)、费用、会话 id、看原文。那是调试面,留在工作台 `/dev`。iPad 上的家长是在看孩子学了什么,不是在看进程。例外是看录像(拍板 17):录像里露孩子感受得到的两种时长,等老师多久、孩子想了多久。

## 四、数据与代码

### 4.1 接口

都在家长命名空间下,孩子接口(`/api/kid/*`)与 `kidConversation` 不动。

- `GET /api/overview/<日期>`(或 `/api/overview/today`):2.2 的清单。每位有脸的老师:`{ name, display, avatar, turns, costUsd, threads: [{ thread, at, title, via, sections, cards, stoppedAt: 'ask' | 'waiting' | 'writing' | null, rating, booked }] }`。
- `GET /api/conversations/<老师>/<日期>/board`:形状 = `KidDay`(`messages / pending / thread`,没有 `remaining`),每条 `KidMessage` 多几个可选字段:`from`、`via`、`action`、`cards`、`parentText`、`remembered`、`warnings`、`error`、`bookkeep`、`tidy`;`section` **不剥答案**;`question` 不管谁发的都给。
- `GET /parent` → `kidPage(title, { parent: true })`;`GET /parent/manifest.webmanifest`。

### 4.2 代码改动清单

`src/lib/kid-view.ts` 的 `parentConversation(index, states, assets)` 和 `kidConversation` 是同一个循环,共用一个内部的 `withState`,免得漂:不 `stripSecrets`、不丢 `bookkeep / tidy` 轮、`question` 不看 `from`、带上 4.1 那几个字段。旁注与清单的 CSS 在页面里(是 chrome,不是皮肤),主题不用跟。

### 4.3 测试

- `tests/server.test.ts`:`/board` 有答案、有系统发的问句、有 `parentText / remembered`、出错的轮有 `error`;**同一份索引 `/api/kid/…` 的输出不变**(这条是本设计的护栏)。
- `tests/kid-view.test.ts`:`parentConversation` 与 `kidConversation` 对同一索引的差集恰好是 4.1 那几个字段。
- `tests/player.test.ts`:不改——仲裁表没动就不该动。

## 五、试效果:到孩子端当一回孩子,回来删

第二个场景:家长改了老师文件的正文、在 vault 里加了一节题型设计,想看老师现在会怎么讲。2026-10-05 起(拍板 18、19)**不在这一页做**:家长打开孩子端,当孩子和老师聊;聊完回到 `/parent` 清单上把这个话题「删」掉,它写进记忆、日记的一起撤,占的每日条数退回(2.2)。

- 在孩子端试,听到的就是孩子的节奏(一拍一拍念、配音、哪里停下等、能不能打断)。老师拿到的就是孩子的上下文包,老师文件与 vault 的改动在新话题里生效。
- Mac 浏览器一样开孩子端;要看手机版加 `?device=phone`。终端里要拿旧问题比差异仍是 `cotutor replay`(`evals/` 只剩它)。
