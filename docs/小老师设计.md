# 小老师:孩子边画边讲,家长和 Claude Code 先看懂,再追问(设想)

> 2026-10-09 起,设想稿,还没动代码。原型:<https://claude.ai/artifact/RyBTC8csepmjP4GVCMzcag>(五屏 iPad 横屏:家长出题、边画边讲、回看与改转写、Claude Code 的初步理解、当面追问;一张代码与数据的边界)。材料:《小课堂设计.md》(播放器、一句一段的进度条、`lecture.md`)、《看图说话设计.md》(卡片小课堂烤成视频)、《家长录像设计.md》(录数据不录屏幕)、《口播老师设计.md》(录音卡的 MediaRecorder)、`cards/canvas/`、`src/stage/canvas.tsx`、`skills/cotutor-analyze/`。
> **词**:「小老师」= 给一个题目,孩子在画板上一边画一边讲,讲的是他自己对这道题的理解。不叫「小课堂」:小课堂已经是「做好的课,孩子从头看到尾」。

最早的想法(原话):

> 给定一个题目,孩子在 drawtell 画布上,一边画,一边讲。针对孩子这段讲课,家长在幕后和 Claude Code 先做一下初步的理解。类似费曼学习法,老师问,孩子回答。

结论先行:**先在家长那边做,代码单独放**。单开一页 `/parent/xlaoshi`,家长出题、把 iPad 递给孩子;孩子边画边讲,记下每一笔的时刻和一条原声;家长回看、改转写,在 workspace 根开 Claude Code 写出初步理解和两三个追问;家长当面问。孩子端一行不改。用一段时间、验过下面那张表,再搬到孩子端。

## 一、为什么值得做

- **小课堂倒过来**。小课堂是老师讲、孩子看;小老师是孩子讲、大人看。形状一样:话 + 画 + 一个时钟。记下来的东西以后能导成一堂小课堂,追问时放他自己讲的那一段——费曼法里最难的一步(指着原话问)有现成的路。
- **合 ray 的长处**。他有阅读困难、写字有抵触,讲和画是他顺手的两样。
- **笔迹带时刻才看得出的东西**。原型第 4 屏的例子:嘴上说「一个一个地分」,笔迹却是十八个圈一开始就六个一行地画——他先知道了 6,不是分出来的。只看最后那张图、只听转写都看不出来。

## 二、为什么先在家长那边

- **没验证的都是家长兜得住的**:转写认错、录音丢了、模型看错图。在孩子端都不能露出来(约定:孩子端没有错误与评判);在家长的工具上可以摊开。
- **家长在旁边就是兜底**:追问先由家长当面问,不接老师。
- **不碰孩子端最重的两块**:`kid-page.ts`、`kid-board.ts` 的仲裁表;也不进录像、不算每日条数。
- **政策那条删了**(拍板 6):《产品规划.md》原来有「孩子的话的用途:只作问题,永不进批改路径」,小老师的本意就是拿孩子的讲解找缺口。留下的是约定「孩子端永远没有错误与评判」:缺口只给家长看,孩子只看得到问题,问法是「这里我没听懂」,不是「你错了」。现在在家长那边这样,搬到孩子端也这样。
- **不做进 `/parent`**:`/parent` 是孩子端页面带家长模式(`kid-page.ts` 里的 `PARENT` 分支),而且拍过「只看、没有输入条」。做进去就和「代码独立」反着来。

## 三、家长那边怎么走(原型五屏)

| 一步 | 谁在看 | 做什么 | 原型 |
|---|---|---|---|
| 出题 | 家长 | 写题目,选画板的底(空白 / 拍一张作业 / 小课堂的一帧),「交给他」;右边是讲过的几次和各自走到哪一步 | 1 |
| 讲 | 孩子 | 工具竖栏同小课堂播放器;右上一直显示「在录 1:08」;浏览器在后台识别,**不显示转写**,不分他的心;「讲完了」 | 2 |
| 回看 | 家长 | 按记下的笔迹现画、放原声,进度条一句一段;右边转写(浏览器的,或 paraformer 补转的,见五),点一句跳过去,点字就改;标出「认不准」的句子;读着不对可以「用 paraformer 重转」 | 3 |
| 交给 Claude Code | 家长 | 在 workspace 根开 Claude Code 说「看看 xlaoshi/<id>」;它读转写、笔迹时刻、自己抽几帧,写 `notes.md` | 3 底部 |
| 初步理解 | 家长 | 页面只读 `notes.md`:讲到了 / 说的和画的对不上 / 还没讲到,各带时刻;右边勾要问的追问 | 4 |
| 追问 | 孩子和家长一起看 | 问题大字、问法只用好奇的口气;放他讲的那段;录他的回答、让他再画一次;家长记一笔(进 `asks.json`,`timeline.md` 末尾「追问的回答」里看得到) | 5 |

- 开始了没讲也记一条(「家长记:他说不想录」),这是要验的第一件事。
- 理解这一步放在家长的 Claude Code 里:看图、听长段话的轮次慢(《小课堂设计.md》拍板 4:带工具的轮首拍中位 31.7 秒),在这里慢不碍事,认错了家长当场纠正。

## 四、代码与数据的边界(原型第 6 张)

1. **一个目录** `src/xlaoshi/`:`route.ts`(接口)、`page.ts`(五屏一页)、`store.ts`(读写目录)、`paraformer.ts`(补转)、`guide.ts`(给 Claude Code 的说明)、`lib/`(笔迹、出帧 PNG、转写、notes.md、timeline.md,纯函数离屏测);测试 `tests/xlaoshi.test.ts`、`tests/xlaoshi-flow.test.ts`;手动验收 `scripts/probe-xlaoshi.mjs`。
2. **依赖单向**:它引用 workspace 的类型、`RouteResult`、qwen 适配器里读百炼 key 的函数;cotutor 别处一个都不引用它,只有 `app.ts` 的 `route()` 里一行把 `/parent/xlaoshi` 与 `/api/xlaoshi/*` 交给它(xlaoshi-flow 测试兜着)。拆掉 = 删目录 + 删那一行和它的 import。
3. **数据自己一块** `workspace/xlaoshi/<id>/`(id = 日期-时分):`session.json` + `topic.md`(题目、家长记的一句)、`talk.json`(讲了多久、浏览器认出的段、每 100 毫秒的音量、补转的状态)、`strokes.json`(每一笔的点,点带时刻;撤销、清空记成那一笔的 `gone`)、`audio.<ext>`(原声)、`transcript.json`(浏览器的或 paraformer 的,带原因,家长改过的行带 `edited`)、`timeline.md` + `frames/`(由上面几样生成:一句一行、那段画了几笔、那段结束时的画面;服务端自己画 PNG,不加依赖)、`notes.md`(Claude Code 写)、`asks.json` + `asks/`(追问的回答:录音、笔迹、家长记)。不进对话索引、不进录像、不算条数;`store.ts`、`src/schema/` 不动。导出成小课堂时再生成 `lecture.md`。
4. **画布不用舞台包**:不走 `src/stage/`(excalidraw 画板,改了要 `build:stage`、会长首屏)。自己一张 `<canvas>` + pointer 事件,记「一笔 = 起止时刻 + 点列」,回放用同一份数据现画。drawtell 搬去孩子端时再接:点列转成手画笔画交给它。
5. **不碰 cotutor.json**:在不在看路由在不在。
6. **分析不做出厂技能**:给 Claude Code 的说明在 `src/xlaoshi/guide.ts`,服务列表时写成 workspace 的 `xlaoshi/怎么看.md`(每次覆盖);回看页给一句能复制的话「读 xlaoshi/怎么看.md,看看 xlaoshi/<id>」。出厂技能牵扯 `SHIPPED_SKILLS`、init、upgrade,成熟再说。
7. **留一个出口**:`export.ts`(成熟后)把一次讲课烤成 `lectures/<id>/`(`video.mp4` + `lecture.md`)——孩子端已经认的形状,导出后小课堂按钮、`lecture` 卡、老师卡的 `讲法:` 都能直接用。

## 五、要先解决的

- **转写:浏览器先认,不够才叫 paraformer**(拍板 7)。
  - **讲的时候浏览器在认**:照按住说话那套(`kid-page.ts` 的 `listen`)在 `page.ts` 里另写一份:一次认一句,Safari 停顿约 1.5 秒自己停,停了就再起一段(一起就断连着五回就不再起,只录原声);MediaRecorder 用同一路麦克风录原声(48 kbps,十分钟自己停)。每段开始的时刻就是转写的一行,不用另外分句。
  - **讲完自动看够不够**:下面任一条成立,就把整段原声交给 paraformer(现成的 DashScope key),用它那份;都不成立就用浏览器那份,不调。
    - 这台没有浏览器识别;
    - 有声没字:音量显示在说话,却超过 3 秒没认出字(先定 3 秒,真用再调);
    - 字太少:认出的字数和说话的时长差得远。
  - **家长也能叫**:回看页「用 paraformer 重转」;重转前家长改过的行留着。
  - **记一笔**:每次是哪路转的、为什么叫、家长改了几处,进 `transcript.json`,列表和 `timeline.md` 头上都看得到。用这份数据看浏览器那份什么时候就够了。
  - **追问的回答也一样**:浏览器没认出字、有录音、拿得到 key,就叫 paraformer 补那一条(`heardBy: paraformer`)。
  - **paraformer 怎么调**:ffmpeg 把原声转成 16k 单声道 PCM,走百炼实时识别的 WebSocket(`paraformer-realtime-v2`),约 5 倍速推;长句按词上的句读切成几行。key 先看 `DASHSCOPE_API_KEY`,再看本机 qwen、voxtell 的配置,只在内存里用。
  - 真机要验:讲几分钟,浏览器一段一段重起,段与段之间的那一下会不会漏字。
  - `voxtell transcribe`、koubo 的 `transcribe` 都还是 exit 3,不等它们。paraformer 要把原声传到阿里云,和《产品规划.md》待拍板 1(录音数据政策)有关。
- **iPad 上记笔迹**:手指和 Pencil 都要能画,手掌不误触;录音与笔迹用同一个钟。要 HTTPS(`cotutor cert`,同按住说话)。

## 六、家长用的这段时间要验的(「成熟」的标准)

| 要验的 | 怎么算过 |
|---|---|
| 孩子愿不愿意讲 | 一次能讲多长、一周几次、录的时候抗不抗拒 |
| iPad 上记笔迹 | 手指、笔都顺,不误触,笔迹和声音对得上 |
| 转写 | 孩子的口语认对多少,家长要改多少字;几次是浏览器那份就够、几次要叫 paraformer |
| Claude Code 找缺口 | 家长认可的比例;只靠转写 + 笔迹时刻够不够,要不要看图 |
| 家长花的时间 | 从讲完到问题写好几分钟;超过十几分钟就坚持不下去 |
| 问法 | 哪几种问题孩子接得住 |

后两项稳到家长基本不用改,才搬到孩子端:先把「讲」交给孩子自己(首页一个按钮),再考虑追问交给老师(导出成小课堂 + `讲法:`),最后才考虑去掉家长那一步。

## 七、第一版(2026-10-09 做了)

- 五屏照原型:出题与讲过的、边画边讲、回看与改转写、初步理解、当面追问。画板的底先只有空白;拍作业、小课堂的一帧、导出成小课堂后做。
- 打开:serve 起来后在 iPad 上开 `https://<本机>:<端口>/xlaoshi`(麦克风要 HTTPS;扫码页不带它)。
- 验:`pnpm typecheck`、`pnpm test` 54 个文件全过(`xlaoshi.test.ts` 28 项、`xlaoshi-flow.test.ts` 32 项)。真 paraformer:`say` 合成的 15 秒中文,webm/opus 与 m4a 都是约 4 秒转完,长句切成 5 行。探针(无头 Chrome,假麦克风放那段 wav,CDP 鼠标画 23 笔、撤销 1 笔):浏览器识别一个字没出 → 自动判「有声没字」→ paraformer 补转出 6 行;回看、改字、notes.md、追问(放那段、画一画、录、记一笔)18 项全过,截图看过;服务端出的帧对得上撤销。
- 还没验:iPad Safari 真机(浏览器识别和录音同时开、Pencil 与手掌、长讲时段与段之间漏不漏字、m4a 原声的回放与拖动)、真孩子讲、Claude Code 照 `怎么看.md` 写出来的 notes.md 好不好用。
- `xlaoshi/` 整个不进 workspace 的 git(拍板 10):服务写 `怎么看.md` 时顺手放一份 `xlaoshi/.gitignore`(`*`),骨架的 .gitignore 不动。

## 八、第一步:不写代码先试一次(已跳过,直接做了第一版)

1. 家长出题;ray 在 iPad 的备忘录或无边记上画,开系统录屏(带麦克风)讲。
