# 一轮问答的工作流程:一拍一就绪、控制台

材料:`src/server/runner.ts`(spawn)、`src/server/tts.ts`(DubQueue / LineDubber)、`src/server/kid-page.ts`(pending / partial / 转正)。

结论先行:**一拍一就绪**。一张卡加它后面的讲稿是一拍,一拍的配音齐了卡就铺;声音更早:讲稿从第一句起连着配好几句就能念几句,不等这一拍关、不等这一拍配齐(先出声、后出卡,拍板 15)。老师还在写后面的时候孩子已经在听第一句。配套一件事:运行时的每一道工序都发事件,控制台按道打印,家长端按道回看。

板上只有老师自己写的东西,见 §二 与拍板 11;孩子说的话老师不带工具,见 §四「孩子的话不带工具」与拍板 12。

## 一、目标流程:一拍一就绪

### 拍(beat)是什么

板书本来就是「卡、跟着它的几句讲稿、下一张卡、……」。一拍 = 一张卡 + 它后面直到下一张卡之前的讲稿句(讲稿句的锚点规则已经是这个:句子锚到上一张卡)。第一张卡之前的句子是第 0 拍(没有卡,只有话)。拍**不进契约**——`beatsOf(section)` 从卡与句的顺序现算,节的形状一个字不改。

拍什么时候「关」:下一张卡的围栏打开时,或老师进程退出时。关了的拍不再变(partial 解析器已经保证定稿的句子不变;围栏闭合的卡不变)。

### 一拍的就绪 = 配音齐

```
拍 k 关
 └─ tts   这拍的每句已经在配(定稿即配);全部落盘 → 配音齐 → 就绪
```

**能念的句子比卡早**(2026-10-08,拍板 15):讲稿从第一句起、连着配好了几句,就能念几句——不等这一拍关(下一张卡的围栏打开、或老师写完),也不等这一拍的几句都配齐;没配音色的老师照旧按拍。卡还是等它那一拍就绪才铺,所以第一张卡常是声音先到、卡后露。流式的节多一个 `voiced`(连着配好的句数),`playableLines` 取拍与它的大者。只有定稿的句子会去配音(partial 解析器压着没换行的最后一行),先念的不会是半句。

卡的样子不等任何人:底色、字形按卡的种类走机械规则(`tintFor` / `lookFor`),围栏行上写了 `tint=` / `look=` / `emoji=` 的用写的;重点只有老师在讲稿里标的 `[词]`,笔按机械规则(`penFor`)。

### 孩子端

- pending 条目**配好一句念一句、就绪一拍铺一拍**:第一句配好就开播;念完了下一句配好就接着;没配好就停在那,喇叭不响、不出错:第一拍前板上铺一张占位卡、字幕行「我写给你看」(8 秒后「再等我一下下」);拍与拍之间留着刚念那句,变暗加跳动的点。
- **卡在拍就绪时才铺**(不是围栏闭合时):铺的时候底色、字形、在哪一行都已定,不会先素后彩地闪。代价是卡晚露 1–3 秒;换来的是听到第一个字提早 5–10 秒。
- 老师退出、索引写入(转正)时,页面**不重画、不重播**:正式节 = 已关各拍的拼接,页面只把 pending 标记摘掉、补上老师尾巴之后的东西(家长段孩子看不到)。万一正式解析和各拍拼起来不一样(老师中途用了工具、段落规则选了别的段——`kidSource` 的规则两边同一份,理论上不会),播完当前拍再整节重画,并记一条 warning,让家长端能看见。
- 「交给老师」「新话题」的语义不变。「继续」(等答时让老师接着讲)2026-10-08 去掉了(拍板 16):孩子不会就说「不知道」。
- **写完的整节第一遍念,也是念到哪露到哪**:不是一拍一拍流式来的节(老师写完了页面才第一次看到的),照样一张一张露。念到第几句,就露到前面这些句锚到、标到、`[[play]]` 到的最后一张卡;停下等答、念完、孩子开口时整节都在。只在不静默、自动念的时候这样;打开以前的话题、关了自动念,还是整节铺开。算法在 `kid-board.ts` 的 `shownCards`。
- **再听**:**老师不说话的时候,每张有讲稿的卡和每个节头都有喇叭;老师说话或在想的时候都没有。**点卡上的喇叭,重念第一遍时让它亮起来的句(标注落在哪张算哪张,没标注看锚点;不按拍分——写在卡 0 后、标注在卡 1 的句按拍算会点 0 亮 1);点节头的喇叭整节重念;点字幕的字重念那句。只念句子与标注(撤掉重描),不执行 cue、不推答题卡;念完回到原位置(在念的变暂停,等答的还等着),重念中再点 / 点暂停就停。**板上安静才能再听**(停下等答、念完、孩子自己暂停):老师在想、正在念时喇叭全藏、点字幕不响——2026-09-18 真机,新回答念到一半点了旧卡的喇叭,回答停住、同一个声音念旧内容听着像答非所问。再听时字幕淡一档、前面一个小喇叭,钮是 ■ 停(不是暂停);停下后回到等答(等答时右边没有钮)。状态机在 `kid-board.ts` 的 `replayLines`(分组复用 `nowCard`)/ `startReplay`,`advance` 认 `replay`。

#### 播放器:谁能打断谁

孩子端所有改播放状态的事(孩子点的、声音念完的、老师新内容到的、舞台回来的)都走 `kid-board.ts` 的 `step(状态, 事件) → { 新状态, 要做的事 }`,页面只 `dispatch` 并照单执行,不直接改状态。由来:以前 27 处直接改状态、20 处停声音散在十几个入口,加再听时漏了两处,真机上新回答被打断、「继续」被误点发给老师。

**改规则的顺序:先改下面这张表 → 再改 `tests/player.test.ts` 里对应那行 → 最后改 `step`。** 表的每一格在测试里有一条;另有随机事件序列(3000 条 × 120 步)每步查不变式,和一条「页面里 `S.state =` 只有 dispatch 那一处」的检查。

| 正在…… | 来了…… | 结果 |
|---|---|---|
| 停下等答 / 念完 / 孩子暂停 | 点喇叭 · 点节头 · 点字幕 | 再听(喇叭不看这张卡念没念过,板上有讲稿的卡都有);念完回到原位置(暂停的还暂停,等答的还等答),不推答题卡、不发任何东西 |
| 老师在念 · 老师在想 · 等下一拍 · 交给小课堂 · 舞台开着 | 点喇叭 · 点节头 · 点字幕 | 不响(喇叭本来就藏着) |

| 交给小课堂 | 孩子关了 | 接着念下一句 |
| 老师在念 / 暂停 | 孩子说话、打字、交答案 | 停声音,算念完 |
| 再听 | 点 ■ / 再点同一个喇叭 | 停,回原位置 |
| 再听 | 点别的喇叭 | 换成那个;念完回的还是最初的位置 |
| 再听 | 一句念完 | 下一句;没了回原位置 |
| 再听 | 开舞台 · 拿起相机 · 孩子说话 · 新的一节到了 | 再听停,再照那件事的规则走 |
| 等下一句 | 又一句配好(或又一拍就绪) | 接着念(不自动念时只把标注画齐);卡等它那一拍就绪才铺 |
| 老师在念某节 | 老师写完这节 | 不重播;定稿句子对不上时按文字找回位置;等着的接上 |
| 任何 | 老师出错撤掉这节 | 停声音,停在最后一节末尾 |
| 老师在念 · 再听(录音卡舞台里)| 按下录音键 | 停声音;老师在念的变暂停、记着录完接着念;再听回原位置(《口播老师设计.md》§3) |
| 在录 | 点喇叭 · 点读 · 点回放 · 点字幕 · 点暂停 | 不响 |

不变式(每步都查):在录时不出声、不推卡;会让页面再 dispatch 的事(念、开舞台、推答题卡)最多一个且在最后;状态机不替孩子发话;再听只在板上安静、舞台没开时开始;要念就一定在念;再听不改「念到哪」;位置不越界;又一句配好、孩子没手动停,回答不会卡住。

「首句就绪」(firstReadyMs:第一句配好,能开口了;2026-10-08 前是第一拍配音齐)是头号埋点;家长端埋点 chip 那行显示它。

## 二、板上只有老师写的

原来这里是「快模型按拍调用」:每拍起一次 haiku,定这张卡的底色、字形、emoji,讲到每句时标哪个词。删了,理由三条:

- **老师看不见它做了什么**。后期改了板面,老师下一轮不知道哪些词被标了、卡成了什么颜色;10 月 4 日数学老师对着没播出来的动画讲了两轮,根子是同一个:板面上有老师不知道的东西。
- **在第一声的路上**。ray 的真实对话里 45 次后期,中位 3.6 秒,第一张卡要等它回来才能铺。
- **留下的东西少**。45 次里 10 次失败或超时(素版),一共留下 23 处标注;排版 10 月 1 日已经归了代码(拍板 9)。

现在:老师想强调就自己标 `[词]`(板书写法里写了一句最多两处);底色、字形、笔走机械规则;老师与 mock 的预装节照旧能在围栏行上写样子。`cotutor lesson post`(手写课文件整份排一版)与它用的运行时 `claude-fast` 2026-10-05 跟备课一起删了。

### 一个话题一节;孩子的话进问题卡(2026-10-08,拍板 17、19)

孩子端一次只铺一个话题。原来每节(老师的一轮回复)前面一个节头(时间 · 标题 · 喇叭 · 线),标题取第一张卡的字,一问一答时一节一张卡,节头占了半块板,孩子说的话板上又看不到。现在:

- **节头只留板上第一节**,和带作业照片的节(缩略图在节头上),和孩子单独说了话的节(见下);往下的节连成一条。整节再听跟着节头走,没节头的节靠每张卡自己的喇叭。家长端照旧每节一个节头(它有「孩子说的」旁注)。
- **孩子答在问题卡上**:上一节末句是问句、它锚着的是文字卡(或解析器补的提问卡),孩子开口答了,这句写进那张卡下沿的答案栏——和填空、选择一样,答案在卡里。末句锚着能做的卡(填空、选择、画板)而孩子是说的,或者上一节没问,这句就是这一节的节头(拍板 19):孩子的话(22px 加粗,语音的前面一个蓝底小话筒)—— 线 —— 时间(只板上第一节)、照片、整节再听,替掉老师那个标题。看完小课堂后的第一问写在小课堂卡下面,不带再听。算法是 `kid-board.ts` 的 `askCard` 与 `sectionsFromMessages` 填的 `said` / `saidOn`。
- **哪些不写**:交卡那轮(`action: submit`,答案已经在卡上)、首页按钮发的(`via`)、老数据里的「继续」。前面不加「你」。
- **语音只显示一部分**:按住说话的(消息带 `voice`)去掉「嗯、呃、那个、就是、……」这类口头禅(`tidySpoken`),一行放不下截成「…」,前面一个小话筒;点开看原话。只改显示,老师拿到的、索引里存的都是原话。打字的照原样。
- **刚发出去、老师还在想**:答案栏 / 节头先挂上(只有话和线);老师等着孩子答时,那张问题卡的答案栏写「等你说…」。

### 排版:卡量出来的宽度定一行几张

每张卡要么半宽、要么全宽。页面把卡放进屏幕外的量具,按这块板的半宽量一次:

| 卡 | 半宽的条件 |
|---|---|
| 文字卡、点读 | 半宽时不超过 4 行;手机不超过 2 行。小标题算一行 |
| 公式、代码、田字格、单词卡、选择题、填空题 | 半宽时不比全宽高:一折行就不算(选项挤成两行也算) |
| 标题行、提问卡、画板、录音卡、小课堂、图 | 永远全宽 |

横着溢出的也算全宽。

- 从左往右排,只看前面的卡:相邻两张半宽的并一行。
- 落单的半宽卡占左半,右边空着。已经出来的卡不挪:流式一张张来时,后来的卡只会填进右半,不会把前面的卡挤宽。
- 全宽的一行一张。
- 明写的并排照办:老师在围栏行上写的 `same`,最多 3 张。别的端排的到了手机上,超过 2 张或有不能半宽的就拆开,再按宽度排。
- 围栏行上的修饰词(`same` `tint=<底色槽>` `look=<字形槽>` `emoji=<一个>`)哪种卡都认,解析器先摘掉再按种类解析(`board.ts` 的 `splitMods`);`cotutor-board` 不教,老师写了就当已定。槽名没人对着主题查,对不上的 CSS 落回缺省。
- 量的结果按「端 + 半宽像素 + 卡的内容」缓存,看录像每次重画不再量。转屏或板宽变了,整节重排。
- 规则是纯函数,在 `kid-board.ts`:`canHalf` / `fitsHalf` / `rowsFor` / `rowCols`。量在 `kid-page.ts` 的 `halfOf`。验收走 `scripts/probe-layout.mjs`。

为什么不问模型:ray 9 月 18–28 日的后期共 34 次、51 张卡,都在平板横屏。模型只排了 3 次并排、41 次另起一行,另有 7 拍超时或失败、出了素版,横屏几乎一行一张。两张卡能不能并排,主要看字多不多,代码量得比模型猜得准,也不跟着后期超时走。

## 三、配音:一老师一音色,走 API

- 出厂就是这条路(voxtell → DashScope qwen-tts,一句约 2 秒,3 并行,同文本缓存零成本)。浏览器合成声只在 mock 里用(测页面,那里没有配音文件)。真服务上孩子端、家长端都不用:某一句的 mp3 放不出来,这句不出声,字幕按字数停够时间再走下一句(拍板 18)。
- doctor `tutor.<名>.voice`:开着的老师没配 voice 报 warn;家长端老师团那页音色空着的挂 chip。
- 就绪判定只认 mp3 落盘;没配 voice 的老师(只该出现在测试里)每句视为立刻齐。
- 卡上的配音(点读卡每段、单词卡、录音卡的示范音)继续后台配,不进就绪判定:那是孩子点了才念的。它比节晚一两秒落盘,孩子刚看到卡就点时还没好:页面每秒拉一次今天等它到(最多 12 秒),到了放老师的声,等不到就不出声;拉今天时已经铺上的节把晚到的 `card.assets` 补上(拍板 18)。

## 四、控制台:分道看每一道工序

### 事件是唯一来源

runner 在每个关键点发一条结构化事件(内存 EventEmitter + 追加到 `<日期>.<job>.events.jsonl`),消费者只有三个,都不各自再算一遍:

```
{ t: 6381, lane: 'main', kind: 'card', beat: 0, card: 0, label: 'text「勾股定理」' }
{ t: 6402, lane: 'tts',  kind: 'queued', line: 0, text: '先认边。' }
{ t: 8300, lane: 'tts',  kind: 'done', line: 0, ms: 1898, cached: false }
{ t: 9901, lane: 'ready', kind: 'beat', beat: 0, first: true }
{ t: 16433, lane: 'main', kind: 'exit', code: 0, costUsd: 0.111, turns: 3 }
{ t: 19030, lane: 'ready', kind: 'all' }
{ t: 19100, lane: 'index', kind: 'written' }
```

道(lane):`main`(老师:卡、句、工具调用、子代理、退出)、`tts`(每句排队 / 完成 / 失败)、`ready`(每拍就绪、首拍、全部)、`index`、`ledger`(记账写进日记)。老事件里的 `scene` 道(画图作业,2026-10-07 删了)读的时候滤掉。

### 三个消费者

1. **`cotutor send`** 现场逐行打印,`cotutor serve --trace` 对每一轮同样打印。一行一事件,左边相对秒,中间道名着色,右边一句话:

```
  0.00 main   起 claude(math-tutor,resume 3f2a…)
  6.38 main   卡 0 text「勾股定理」
  6.40 tts    句 0 排队「先认边。」
  8.30 tts    句 0 ✓ 1.9s
  9.90 ready  拍 0 ✓  ← 首拍就绪 9.9s
 11.20 main   卡 1 text「认边」 · 句 1、2 排队
 …
 16.43 main   退出 0  $0.111 · 3 turns
 19.03 ready  全部就绪(4 拍)
 19.10 index  写入
```

`--lane main,tts` 只看某几道;`--raw` 打 JSON 行。

### 断流:应用自己看,不等 CLI

claude CLI 的 API 流断了,它要等约 180 秒没数据才认,再补一句「接着说」重试。9 月 21 日真跑:「你好」断一次等了 3.1 分钟,「讲个故事」连断两次等了 6 分钟,模型真干活不到 10 秒;家长页一直是「老师在想……」。

- runner 看老师进程的 stdout:`policy.stall.ms`(缺省 30000)毫秒一个字节都没有、**也没有顶层工具在跑**(发了 tool_use 还没回 tool_result 的不算,Bash 跑一会儿是正常的)→ 杀掉进程。
- 拿到过会话 id 就 resume 同一个会话接着写,最多 `stall.retries`(缺省 2)次;新会话还没落盘的(模型一个事件都没回就断了——这时 resume 会报 No conversation found),原样从头再起一次。
- 被杀那段回复只流到了 stdout,没进会话。所以断在半截的正文原样递回给老师(`stallPrompt`:「孩子那边已经看到、听到的就是 <<< … >>>,从断处接着写」),收尾时拼在最后一段前面;孩子端 partial 板书在两次之间连着长,已经念了的句子不重来。
- 事件 `main stall`(几秒没动静、接着跑第几次、已写几个字),接着跑的那次再发一条 `main start`(resume);家长那条消息的 warnings 写「API 流断了 N 次」。次数用完还断,这轮按出错收尾(reason `stalled:…`)。
- `stall.ms = 0` 关掉,回到 CLI 自己 180 秒的重试。老师条目的 `policy.stall` 能单独盖:思考的增量很稀(9 月 22 日真跑一轮只有 5 条 thinking_delta),effort 高、一想想很久的老师嫌 30 秒误杀就给它单独放宽。真跑量过:claude 起进程到第一个字节约 3 秒,写完正文到 result 之间会静 2–3 秒,所以别配到 5 秒以下。

### 孩子的话不带工具

- 这一轮带不带工具,`send` 定:`policy.tools` 是 on、或这条是系统任务(`from: system`:记账、整理记忆)、或带了照片 → 白名单;否则空。填进模板的 `{tools}`。工作台与 `cotutor send` 发的也记孩子(拍板 14),同样不带。
- 模板里没有 `{tools}` 的运行时(qwen、老 workspace 没升级的 claude),应用管不了它的工具,上下文包也照旧带路径。
- 不带工具的那轮,`refs` / `vault` 不进包。老师文件里「`refs:` 里有教材就 Grep」这类规矩,见不到 `refs:` 自然不触发。
- 预热的进程按孩子的下一句起(`{tools}` 照孩子那轮填);带照片的 argv 对不上,那轮冷起。

### 预热:下一轮的老师进程提前起好

孩子每开口一次,runner 就新起一个 `claude -p --resume`:起进程、读会话、初始化,之后才发请求。9 月 18–28 日 42 个没断流的孩子轮次,这段中位 1.8 秒(p10 1.4、p90 2.4),英语老师一轮 3.7–5 秒里占三四成。9 月 29 日本机实测:冷起 `--resume` 进程开销 6–7 秒;提前 4 秒起好、在 stdin 上等着的进程,写进消息到首字 1.4–3 秒,进程开销约 0.07 秒;它开口前一个字节不吐(不花钱),接的是同一个会话。

- 运行时声明 `stdin: "stream-json"`:模板带 `--input-format stream-json`、不写 `{prompt}`;这个运行时的每一轮(孩子的、断流接着跑的、记账、整理记忆)消息都写进 stdin,看到 `result` 就关 stdin,进程自己退。还是一轮一个进程、一个 `.log`,退出 = 这轮完。
- argv 与消息无关了,所以能提前起:一位有脸的老师两个**备用进程**的位置——**fresh** 新开会话(新话题、「接着上次」,argv 都一样),**resume** 接某个话题的会话(页面选着的话题,没选 = 当天末条所在的话题,和 send 缺省一样;这个话题没有会话就不留)。
- 什么时候补齐两个位置:孩子那轮收尾;孩子端拉今天(选着话题就带 `?thread=`,同一话题 30 秒看一次)。家长板书页只看,拉今天不预热(拍板 14)。系统轮(记账、整理记忆)之后不补。60 分钟没用上就杀(闲着的进程不花钱,只占内存,真跑一个约 64MB;三位老师最多六个)。
- 对得上才用:send 算出的 argv、cwd、日期、**这个话题**末条 job(fresh 记空)和备用进程起来时的一模一样才接过来,不然杀掉走冷起;接哪个位置看这轮是不是 resume。argv 覆盖了换话题、换会话、跨天、老师正文、effort、cotutor.json 热重载;**末条 job 覆盖会话被别人写过**——备用进程起来时读的会话,之后别的进程(记账、另开的 `cotutor send`)往同一会话写过,它手里就是旧的,拿它写会分叉。只看这个话题的末条:别的话题说过话(孩子在另一个话题里说了一句)不让它作废;往同一会话写的轮都会在这个话题里记一条,防得住。
- 断流看门狗从写进消息那刻算。备用进程断流照旧:杀掉、resume 冷起接着写。
- 事件 `main start` 带 `warmMs`(备用进程等了多久),timing 带 `warm: true`;`t0` 仍是孩子开口那刻,冷热两种轮的 firstReadyMs 直接可比。
- 服务退了,备用进程的 stdin 断开,自己退出,不留孤儿。
