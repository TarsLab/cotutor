# 一轮问答的工作流程:一拍一就绪、控制台(2026-09-13,已拍板)

材料:`src/server/runner.ts`(spawn)、`src/server/tts.ts`(DubQueue / LineDubber)、`src/server/post.ts`、`src/server/kid-page.ts`(pending / partial / 转正);续《快模型方案.md》。

结论先行:**一拍一就绪**(原来是「一轮一节」:老师写完、配音配完、后期回来,全齐才转正)。一张卡加它后面的讲稿是一拍,一拍的配音齐了、后期回了就能播,老师还在写后面的时候孩子已经在听第一拍。配套两件事:快模型按拍调用并带上前面几张卡;运行时的每一道工序都发事件,控制台按道打印,家长端按道回看。

## 一、目标流程:一拍一就绪

### 拍(beat)是什么

板书本来就是「卡、跟着它的几句讲稿、下一张卡、……」。一拍 = 一张卡 + 它后面直到下一张卡之前的讲稿句(讲稿句的锚点规则已经是这个:句子锚到上一张卡)。第一张卡之前的句子是第 0 拍(没有卡,只有话)。拍**不进契约**——`beatsOf(section)` 从卡与句的顺序现算,节的形状一个字不改。

拍什么时候「关」:下一张卡的围栏打开时,或老师进程退出时。关了的拍不再变(partial 解析器已经保证定稿的句子不变;围栏闭合的卡不变)。

### 一拍的就绪 = 配音齐 + 后期回

```
拍 k 关
 ├─ tts   这拍的每句已经在配(定稿即配,现有);全部落盘 → 配音齐
 └─ post  起一次快模型:这拍的卡 + 讲稿,带前面 3–5 张已定的卡;回了 → 套上(标注 / said / 样子)
就绪 = 配音齐 ∧ (后期回 ∨ 后期超时)
```

后期超时 → 这一拍素版(机械规则选笔、缺省底色),**不重来、不再改**;孩子不知道有这道工序。超时值按拍设,缺省 10 秒:只有第 0/1 拍的后期在关键路径上,后面的拍在前一拍播放的时候跑,通常被声音盖住。

### 孩子端

- pending 条目不再是「露卡不播」,而是**就绪一拍播一拍**:第一拍就绪就开播;一拍播完下一拍就绪就接着;没就绪就停在那,喇叭不响、不出错:第一拍前板上铺一张占位卡、字幕行「我写给你看」(8 秒后「再等我一下下」);拍与拍之间留着刚念那句,变暗加跳动的点。
- **卡在拍就绪时才铺**(不是围栏闭合时):铺的时候底色、字形、在哪一行都已定,不会先素后彩地闪。代价是卡晚露 1–3 秒;换来的是听到第一个字提早 5–10 秒。
- 老师退出、索引写入(转正)时,页面**不重画、不重播**:正式节 = 已关各拍的拼接,页面只把 pending 标记摘掉、补上老师尾巴之后的东西(家长段孩子看不到)。万一正式解析和各拍拼起来不一样(老师中途用了工具、段落规则选了别的段——`kidSource` 的规则两边同一份,理论上不会),播完当前拍再整节重画,并记一条 warning,让家长端能看见。
- 「继续」「交给老师」「新话题」的语义不变。
- **写完的整节第一遍念,也是念到哪露到哪**(2026-09-28,《备课设计.md》拍板 34):不是一拍一拍流式来的节(课文件交出去的、老师写完了页面才第一次看到的),照样一张一张露。念到第几句,就露到前面这些句锚到、标到、`[[play]]` 到的最后一张卡;停下等答、念完、孩子开口时整节都在。只在不静默、自动念的时候这样;打开以前的话题、关了自动念,还是整节铺开。算法在 `kid-board.ts` 的 `shownCards`。
- **课文件交出去、孩子还没开口的话题**,页面先只铺第一节,后面的节攒着。每节末句问句停下;孩子按「继续」、交卡、说话、拍照都由页面接成「念下一节」,不发出去。说的与拍的攒着,最后一节之后再开口时一起发(`lessonSaid`)。「继续」与「念下一节」的对接在页面的 `send` 里,`step` 不知道课文件:它照常发出「继续」,页面见到还有攒着的节就改成念下一节。家长端打开这个话题同样如此(孩子没开口前它是备课话题,能做卡、能按继续)。
- **再听**(2026-09-18;2026-09-21 规则砍成一条):**老师不说话的时候,每张有讲稿的卡和每个节头都有喇叭;老师说话或在想的时候都没有。**点卡上的喇叭,重念第一遍时让它亮起来的句(标注落在哪张算哪张,没标注看锚点;不按拍分——写在卡 0 后、标注在卡 1 的句按拍算会点 0 亮 1);点节头的喇叭整节重念;点字幕的字重念那句。原来还要「这张卡的句全念完才露」,2026-09-21 去掉:真机上孩子在第一张卡念到一半时点暂停(多半是没听清),整屏一个喇叭都没有,最想再听的恰是正在念的这张。去掉不亏:卡本来就先铺开再念,提前听一遍没有损失;答案在下一节,下一节要孩子答了才上板,漏不了。只念句子与标注(撤掉重描),不执行 cue、不推答题卡;念完回到原位置(在念的变暂停,等答的还等着),重念中再点 / 点暂停就停。**板上安静才能再听**(停下等答、念完、孩子自己暂停):老师在想、正在念时喇叭全藏、点字幕不响——2026-09-18 真机,新回答念到一半点了旧卡的喇叭,回答停住、同一个声音念旧内容听着像答非所问。再听时字幕淡一档、前面一个小喇叭,钮是 ■ 停(不是暂停);停下后回到等答,「继续」灰 0.8 秒才能点——同一真机那次,想停再听的一下落在刚变出来的「▶ 继续」上,老师把「继续」当成答应了。状态机在 `kid-board.ts` 的 `replayLines`(分组复用 `nowCard`)/ `startReplay`,`advance` 认 `replay`。

#### 播放器:谁能打断谁(2026-09-18)

孩子端所有改播放状态的事(孩子点的、声音念完的、老师新内容到的、舞台回来的)都走 `kid-board.ts` 的 `step(状态, 事件) → { 新状态, 要做的事 }`,页面只 `dispatch` 并照单执行,不直接改状态。由来:以前 27 处直接改状态、20 处停声音散在十几个入口,加再听时漏了两处,真机上新回答被打断、「继续」被误点发给老师。

**改规则的顺序:先改下面这张表 → 再改 `tests/player.test.ts` 里对应那行 → 最后改 `step`。** 表的每一格在测试里有一条;另有随机事件序列(3000 条 × 120 步)每步查不变式,和一条「页面里 `S.state =` 只有 dispatch 那一处」的检查。

「首卡就绪」(firstReadyMs:第一拍配音齐且后期回)取代「首卡露出」成为头号埋点;家长端埋点 chip 那行显示它。

## 二、快模型按拍调用,带前文

提示词骨架整份在主题的 `post.md`(和 kid.css 同一套,占位符是生成的部分,《快模型方案.md》§一 A):HTML 方言,`{board}` 进、`{patch}` 出。每拍给模型这一拍的卡与讲稿,加前面 3–5 张已定的卡。

要点:

- **后期不排版**(2026-10-01,拍板 9):一行几张不问模型,孩子端按卡量出来的宽度排,见下面「排版」。老骨架让模型写的 `data-row` 不认。
- **前文只读**:已定卡的样子、行、已标的词都摆出来,规则里写「同一个词前面标过就别标;底色照顾前后呼应(同类卡同色)」。前文取 3–5 张是够的:再远的孩子已经滚过去了。
- **句子下标是拍内的**,校验器映射回节内下标;`said` 规则不变。
- 第 0 拍(没有卡只有话)不调后期:没有卡就没有可标的东西。
- 一节几张卡就几次调用(通常 3–6 次);haiku 走 CLI 每次 $0.004–0.05(冷起贵),走直连 API 约 $0.001–0.003。评测(《快模型方案.md》§一 C)`--serial` 按拍顺着起整节,和线上一模一样。
- `.post.json` 从一份变成一节一个数组(每拍:输入、原文、校验、耗时、费用);`repost` 按拍重跑整节。

### 排版:卡量出来的宽度定一行几张(2026-10-01)

每张卡要么半宽、要么全宽。页面把卡放进屏幕外的量具,按这块板的半宽量一次:

| 卡 | 半宽的条件 |
|---|---|
| 文字卡、点读 | 半宽时不超过 4 行;手机不超过 2 行。小标题算一行 |
| 公式、代码、田字格、单词卡、选择题、填空题 | 半宽时不比全宽高:一折行就不算(选项挤成两行也算) |
| 标题行、提问卡、画板、录音卡、场景、图 | 永远全宽 |

横着溢出的也算全宽。

- 从左往右排,只看前面的卡:相邻两张半宽的并一行。
- 落单的半宽卡占左半,右边空着。已经出来的卡不挪:流式一张张来时,后来的卡只会填进右半,不会把前面的卡挤宽。
- 全宽的一行一张。
- 明写的并排照办:课文件或老师在围栏行上写的 `same`,最多 3 张。别的端排的到了手机上,超过 2 张或有不能半宽的就拆开,再按宽度排。
- 量的结果按「端 + 半宽像素 + 卡的内容」缓存,看录像每次重画不再量。转屏或板宽变了,整节重排。
- 规则是纯函数,在 `kid-board.ts`:`canHalf` / `fitsHalf` / `rowsFor` / `rowCols`。量在 `kid-page.ts` 的 `halfOf`。验收走 `scripts/probe-layout.mjs`。

为什么不问模型:ray 9 月 18–28 日的后期共 34 次、51 张卡,都在平板横屏。模型只排了 3 次并排、41 次另起一行,另有 7 拍超时或失败、出了素版,横屏几乎一行一张。两张卡能不能并排,主要看字多不多,代码量得比模型猜得准,也不跟着后期超时走。

## 四、控制台:分道看每一道工序

### 事件是唯一来源

{ t: 6402, lane: 'tts',  kind: 'queued', line: 0, text: '先认边。' }
{ t: 7100, lane: 'main', kind: 'beat-close', beat: 0 }
{ t: 7101, lane: 'post', kind: 'start', beat: 0, context: 0 }
{ t: 8300, lane: 'tts',  kind: 'done', line: 0, ms: 1898, cached: false }
{ t: 9900, lane: 'post', kind: 'done', beat: 0, ms: 2799, kept: { marks: 1, look: 1, row: 'new' }, dropped: 0, costUsd: 0.004 }
{ t: 9901, lane: 'ready', kind: 'beat', beat: 0, first: true }
{ t: 16433, lane: 'main', kind: 'exit', code: 0, costUsd: 0.111, turns: 3 }
{ t: 19030, lane: 'ready', kind: 'all' }
{ t: 19100, lane: 'index', kind: 'written' }
{ t: 19150, lane: 'scene', kind: 'started', bundle: '2026-09-12-guilv', job: '1902-4' }
```

道(lane):`main`(老师:卡、句、工具调用、子代理、退出)、`tts`(每句排队 / 完成 / 失败)、`post`(每拍起 / 回 / 超时 / 丢了什么)、`ready`(每拍就绪、首拍、全部)、`index`、`scene`(场景卡起的画图作业,2026-09-17 前叫 `handoff`)、`ledger`。

### 三个消费者

1. **`cotutor send`** 现场逐行打印,`cotutor serve --trace` 对每一轮同样打印。一行一事件,左边相对秒,中间道名着色,右边一句话:

  6.38 main   卡 0 text「勾股定理」

  9.90 post   拍 0 ✓ 2.8s  标 1 · 样 sky · 丢 0 · $0.004
  9.90 ready  拍 0 ✓  ← 首拍就绪 9.9s
 11.20 main   卡 1 text「认边」 · 句 1、2 排队
 …
 16.43 main   退出 0  $0.111 · 3 turns
 19.03 ready  全部就绪(4 拍)

```

`--lane post,tts` 只看某几道;`--raw` 打 JSON 行。

2. **家长端「看原文」加一站「时间线」**:读 events.jsonl 画成横向甘特(一道一行,拍为块),点一块展开那条事件;超时、失败的块标红。「板书后期」那站按拍列。
3. **`cotutor trace <老师> <job>`** 离线回放一份 events.jsonl,格式同 1(排查昨天那轮用)。

### 索引里留什么

timing 加 `firstReadyMs`、`beats: [{card, closedMs, dubbedMs, postMs, readyMs}]`;旧的四个数保留。家长端那行 chip:首拍就绪 / 老师写完 / 全部就绪 / 后期几拍几超时。

### 断流:应用自己看,不等 CLI(2026-09-21)

claude CLI 的 API 流断了,它要等约 180 秒没数据才认,再补一句「接着说」重试。9 月 21 日真跑:「你好」断一次等了 3.1 分钟,「讲个故事」连断两次等了 6 分钟,模型真干活不到 10 秒;家长页一直是「老师在想……」。

- runner 看老师进程的 stdout:`policy.stall.ms`(缺省 30000)毫秒一个字节都没有、**也没有顶层工具在跑**(发了 tool_use 还没回 tool_result 的不算,Bash 跑一会儿是正常的)→ 杀掉进程。
- 拿到过会话 id 就 resume 同一个会话接着写,最多 `stall.retries`(缺省 2)次;新会话还没落盘的(模型一个事件都没回就断了——这时 resume 会报 No conversation found),原样从头再起一次。
- 被杀那段回复只流到了 stdout,没进会话。所以断在半截的正文原样递回给老师(`stallPrompt`:「孩子那边已经看到、听到的就是 <<< … >>>,从断处接着写」),收尾时拼在最后一段前面;孩子端 partial 板书在两次之间连着长,已经念了的句子不重来。
- 事件 `main stall`(几秒没动静、接着跑第几次、已写几个字),接着跑的那次再发一条 `main start`(resume);家长那条消息的 warnings 写「API 流断了 N 次」。次数用完还断,这轮按出错收尾(reason `stalled:…`)。
- `stall.ms = 0` 关掉,回到 CLI 自己 180 秒的重试。老师条目的 `policy.stall` 能单独盖:思考的增量很稀(9 月 22 日真跑一轮只有 5 条 thinking_delta),effort 高、一想想很久的老师(画图老师)嫌 30 秒误杀就给它单独放宽。真跑量过:claude 起进程到第一个字节约 3 秒,写完正文到 result 之间会静 2–3 秒,所以别配到 5 秒以下。

### 预热:下一轮的老师进程提前起好(2026-09-29)

孩子每开口一次,runner 就新起一个 `claude -p --resume`:起进程、读会话、初始化,之后才发请求。9 月 18–28 日 42 个没断流的孩子轮次,这段中位 1.8 秒(p10 1.4、p90 2.4),英语老师一轮 3.7–5 秒里占三四成。9 月 29 日本机实测:冷起 `--resume` 进程开销 6–7 秒;提前 4 秒起好、在 stdin 上等着的进程,写进消息到首字 1.4–3 秒,进程开销约 0.07 秒;它开口前一个字节不吐(不花钱),接的是同一个会话。

- 运行时声明 `stdin: "stream-json"`:模板带 `--input-format stream-json`、不写 `{prompt}`;这个运行时的每一轮(孩子的、断流接着跑的、记账、整理记忆)消息都写进 stdin,看到 `result` 就关 stdin,进程自己退。还是一轮一个进程、一个 `.log`,退出 = 这轮完。
- argv 与消息无关了,所以能提前起:一位有脸的老师两个**备用进程**的位置——**fresh** 新开会话(新话题、备课话题、「接着上次」、课文件交出去后孩子的第一句,argv 都一样),**resume** 接某个话题的会话(页面选着的话题,没选 = 当天末条所在的话题,和 send 缺省一样;这个话题没有会话就不留)。
- 什么时候补齐两个位置:孩子或家长那轮收尾;孩子端拉今天、家长板书页拉今天(两端同一个页面,选着话题就带 `?thread=`,同一话题 30 秒看一次)。系统轮(记账、整理记忆)之后不补。60 分钟没用上就杀(闲着的进程不花钱,只占内存,真跑一个约 64MB;三位老师最多六个)。
- 对得上才用:send 算出的 argv、cwd、日期、**这个话题**末条 job(fresh 记空)和备用进程起来时的一模一样才接过来,不然杀掉走冷起;接哪个位置看这轮是不是 resume。argv 覆盖了换话题、换会话、跨天、老师正文、effort、cotutor.json 热重载;**末条 job 覆盖会话被别人写过**——备用进程起来时读的会话,之后别的进程(记账、另开的 `cotutor send`)往同一会话写过,它手里就是旧的,拿它写会分叉。只看这个话题的末条:别的话题说过话(家长在备课话题里说了一句)不让它作废;往同一会话写的轮都会在这个话题里记一条,防得住。
- 断流看门狗从写进消息那刻算。备用进程断流照旧:杀掉、resume 冷起接着写。
- 事件 `main start` 带 `warmMs`(备用进程等了多久),timing 带 `warm: true`;`t0` 仍是孩子开口那刻,冷热两种轮的 firstReadyMs 直接可比。
- 服务退了,备用进程的 stdin 断开,自己退出,不留孤儿。
