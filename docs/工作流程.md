# 一轮问答的工作流程:现状、目标、控制台(2026-09-13,已拍板)

材料:`src/server/runner.ts`(spawn)、`src/server/tts.ts`(DubQueue / LineDubber)、`src/server/post.ts`、`src/server/kid-page.ts`(pending / partial / 转正)、9-12 三轮真跑的 timing;续《快模型方案.md》。

结论先行:**现在的流水线是「一轮一节」——老师写完、配音配完、后期回来,三件事全齐才转正,孩子才听到第一个字。** 目标改成「一拍一就绪」:一张卡加它后面的讲稿是一拍,一拍的配音齐了、后期回了就能播,老师还在写后面的时候孩子已经在听第一拍。配套两件事:快模型按拍调用并带上前面几张卡;运行时的每一道工序都发事件,控制台按道打印,家长端按道回看。

## 一、现状:一轮里发生了什么(按时间)

```
t=0     send → 上下文包 → spawn 老师 CLI(流式 stream-json)
        ├─ main  stdout 每块落盘 .log,喂 PartialReader,150ms 节流 parseBoard(partial)
        │        → active.partial = {cards, lines}(孩子端 pending 条目:卡一张张露出来,不播)
        │        → firstCardMs = 第一次有卡
        └─ tts   partial 里每定稿一句 → LineDubber.add → DubQueue(3 并行)→ <日期>.<job>.<n>.mp3
t=done  老师进程退出 → parseTranscript → deriveKidView(定稿的节)
        ├─ post  这时才起:整节一次 runPost(卡 + 讲稿 + 端 + 主题)→ 等 timeoutMs(4000)
        └─ tts   dubber.finish:等没配完的句
t=max(dubbed, post)  合并 → writeIndex(转正)
        孩子端下次 poll:pending 换成正式节,整节重画,从第一句开始播
之后    转交(起目标老师)、点读段资产(后台)
```

9-12 三轮的数字(毫秒,从进程起算):

| 轮 | 首卡露出 | 老师写完 | 配音齐 | 后期 | 孩子听到第一个字 |
|---|---|---|---|---|---|
| 1848-1 | 6.4s | 9.1s | 13.5s | 超时 | **13.5s** |
| 1854-2 | 9.0s | 11.2s | 13.7s | 超时 | **15.2s** |
| 1901-3 | 14.5s | 16.4s | 19.0s | 超时 | **20.4s** |

问题不在总时长(一两分钟可以接受),在于**第一拍早就能播了却在等最后一拍**:第一张卡 6 秒露出,它那句配音 2 秒后就有了,孩子却要等到 13–20 秒。而且现在的等待是空的:卡露着、没声音、没提示。

另外三处结构问题:

1. 后期整节一次,必须等老师写完才能起,它天然在关键路径上;超时就全节素版。
2. 后期看不到前文:第二节的卡不知道第一节已经给「定义」用了 sky,同一个词第一节标过、第二节又标。
3. 每道工序的进展只有跑完落盘的 timing 四个数,过程里什么都看不见;`cotutor send` 只在结束时打印结果。

## 二、目标流程:一拍一就绪

### 拍(beat)是什么

板书本来就是「卡、跟着它的几句讲稿、下一张卡、……」。一拍 = 一张卡 + 它后面直到下一张卡之前的讲稿句(讲稿句的锚点规则已经是这个:句子锚到上一张卡)。第一张卡之前的句子是第 0 拍(没有卡,只有话)。拍**不进契约**——`beatsOf(section)` 从卡与句的顺序现算,节的形状一个字不改。

拍什么时候「关」:下一张卡的围栏打开时,或老师进程退出时。关了的拍不再变(partial 解析器已经保证定稿的句子不变;围栏闭合的卡不变)。

### 一拍的就绪 = 配音齐 + 后期回

```
拍 k 关
 ├─ tts   这拍的每句已经在配(定稿即配,现有);全部落盘 → 配音齐
 └─ post  起一次快模型:这拍的卡 + 讲稿,带前面 3–5 张已定的卡;回了 → 套上(标注 / said / 样子 / 这张卡接上一行还是另起一行)
就绪 = 配音齐 ∧ (后期回 ∨ 后期超时)
```

后期超时 → 这一拍素版(机械规则选笔、缺省底色、另起一行),**不重来、不再改**;孩子不知道有这道工序。超时值按拍设,可以比现在宽(建议 10 秒):只有第 0/1 拍的后期在关键路径上,后面的拍在前一拍播放的时候跑,通常被声音盖住。

### 孩子端

- pending 条目不再是「露卡不播」,而是**就绪一拍播一拍**:第一拍就绪就开播;一拍播完下一拍就绪就接着;没就绪就停在那,字幕行是老师的「让我想想…」,喇叭不响、不出错。
- **卡在拍就绪时才铺**(不是围栏闭合时):铺的时候底色、字形、在哪一行都已定,不会先素后彩地闪。代价是卡比现在晚露 1–3 秒;换来的是听到第一个字提早 5–10 秒。
- 老师退出、索引写入(转正)时,页面**不重画、不重播**:正式节 = 已关各拍的拼接,页面只把 pending 标记摘掉、补上老师尾巴之后的东西(转交、家长段孩子看不到)。万一正式解析和各拍拼起来不一样(老师中途用了工具、段落规则选了别的段——`kidSource` 的规则两边同一份,理论上不会),播完当前拍再整节重画,并记一条 warning,让家长端能看见。
- 「继续」「交给老师」「新话题」的语义不变。

### 时间线对比(以 1848-1 为例,估)

```
现在   0───6.4 首卡露出(静)────9.1 老师写完────13.5 配音齐 · 后期超时────► 13.5 开播
目标   0───6.4 拍 0 关 → tts 2s ∥ post 3–5s ───► ≈ 10–11 开播;拍 1、2 在播的时候就绪
       (后期直连 API 的话 post ≈ 1.5s → ≈ 8.5 开播)
```

「首卡就绪」(firstReadyMs:第一拍配音齐且后期回)取代「首卡露出」成为头号埋点;家长端埋点 chip 那行显示它。

## 三、快模型按拍调用,带前文

提示词的骨架沿用《快模型方案.md》§二 A(整份在主题的 post.md,和 kid.css 同一套,占位符是生成的部分),按拍的出厂骨架里 `{context}` 与 `{cards}` `{lines}` 长这样:

```
## 已定的卡(只看,不改)                 ← 前 3–5 张:序号、种类、标题、前 60 字、已定的 tint / look、在第几行、已标过的词
- 0. text cover「勾股定理」 tint night · 第 1 行 · 独占
- 1. text「认边」 tint sky · 第 2 行 · 已标:直角边(tint)、斜边(tint)
## 这一拍
卡 2. text formula:直角边² + 直角边² = 斜边²
讲稿:
  0. 先记住这个公式:直角边² + 直角边² = 斜边²。   ★老师已标:「直角边² + 直角边² = 斜边²」
  1. 两条直角边的平方加起来,就是斜边的平方。
## 输出
{"row":"same"|"new","look":{…},"marks":[{"line":0,"phrase":"…","pen":"…","said":"…"}],"anchor":null|<已定卡序号>}
```

要点:

- **排版变成一个二选一**:这张卡接上一行(`same`)还是另起一行(`new`)。行从左往右长,校验只看「这一行会不会超 3 张、标题行 / 交互卡是否独占」,不用整节回头。整节的 `layout.rows` 由各拍的决定拼出来,契约不变。
- **前文只读**:已定卡的样子、行、已标的词都摆出来,规则里写「同一个词前面标过就别标;底色照顾前后呼应(同类卡同色)」。前文取 3–5 张是够的:再远的孩子已经滚过去了。
- **句子下标是拍内的**,校验器映射回节内下标;`said` 规则不变。
- 第 0 拍(没有卡只有话)不调后期:没有卡就没有可标的东西。
- 一节几张卡就几次调用(通常 3–6 次),每次比现在小;haiku 走 CLI 每次 $0.004–0.05(冷起贵),走直连 API 约 $0.001–0.003。评测(《快模型方案.md》§二 C)改成按拍回放整节:样本还是 section.md,评测顺序起各拍,和线上一模一样。
- `.post.json` 从一份变成一节一个数组(每拍:输入、原文、校验、耗时、费用);`repost` 按拍重跑整节。

## 四、配音:一老师一音色,走 API

- 出厂就是这条路(voxtell → DashScope qwen-tts,一句约 2 秒,3 并行,同文本缓存零成本);浏览器合成声只在两处:mock(测页面)与线上某一句合成失败时的兜底(不响比响错好,但这一句总得念)。
- doctor 加一项 `tutors.voice`:开着的老师没配 voice 报 warn(现在只是「不探配音」);家长端老师团那页音色空着的挂 chip。
- 就绪判定只认 mp3 落盘;没配 voice 的老师(只该出现在测试里)每句视为立刻齐。
- 点读段资产(read 卡的每段)继续后台配,不进就绪判定:那是孩子点了才念的。

## 五、控制台:分道看每一道工序

### 事件是唯一来源

runner 在每个关键点发一条结构化事件(内存 EventEmitter + 追加到 `<日期>.<job>.events.jsonl`),消费者只有三个,都不各自再算一遍:

```
{ t: 6381, lane: 'main', kind: 'card', beat: 0, card: 0, label: 'text cover「勾股定理」' }
{ t: 6402, lane: 'tts',  kind: 'queued', line: 0, text: '先认边。' }
{ t: 7100, lane: 'main', kind: 'beat-close', beat: 0 }
{ t: 7101, lane: 'post', kind: 'start', beat: 0, context: 0 }
{ t: 8300, lane: 'tts',  kind: 'done', line: 0, ms: 1898, cached: false }
{ t: 9900, lane: 'post', kind: 'done', beat: 0, ms: 2799, kept: { marks: 1, look: 1, row: 'new' }, dropped: 0, costUsd: 0.004 }
{ t: 9901, lane: 'ready', kind: 'beat', beat: 0, first: true }
{ t: 16433, lane: 'main', kind: 'exit', code: 0, costUsd: 0.111, turns: 3 }
{ t: 19030, lane: 'ready', kind: 'all' }
{ t: 19100, lane: 'index', kind: 'written' }
{ t: 19150, lane: 'handoff', kind: 'started', to: 'scene-maker', job: '1902-4' }
```

道(lane):`main`(老师:卡、句、工具调用、子代理、退出)、`tts`(每句排队 / 完成 / 失败)、`post`(每拍起 / 回 / 超时 / 丢了什么)、`ready`(每拍就绪、首拍、全部)、`index`、`handoff`、`ledger`。

### 三个消费者

1. **`cotutor send`** 现场逐行打印(现在只在结束打结果),`cotutor serve --trace` 对每一轮同样打印。一行一事件,左边相对秒,中间道名着色,右边一句话:

```
  0.00 main   起 claude(math-tutor,resume 3f2a…)
  6.38 main   卡 0 text cover「勾股定理」
  6.40 tts    句 0 排队「先认边。」
  7.10 main   拍 0 关 → post 起(前文 0 张)
  8.30 tts    句 0 ✓ 1.9s
  9.90 post   拍 0 ✓ 2.8s  标 1 · 样 sky · 另起一行 · 丢 0 · $0.004
  9.90 ready  拍 0 ✓  ← 首拍就绪 9.9s
 11.20 main   卡 1 text「认边」 · 句 1、2 排队
 …
 16.43 main   退出 0  $0.111 · 3 turns
 19.03 ready  全部就绪(4 拍)
 19.10 index  写入
 19.15 handoff scene-maker 起了 1902-4
```

`--lane post,tts` 只看某几道;`--raw` 打 JSON 行。

2. **家长端「看原文」加一站「时间线」**:读 events.jsonl 画成横向甘特(一道一行,拍为块),点一块展开那条事件;超时、失败的块标红。第七站「板书后期」按拍列。
3. **`cotutor trace <老师> <job>`** 离线回放一份 events.jsonl,格式同 1(排查昨天那轮用)。

### 索引里留什么

timing 加 `firstReadyMs`、`beats: [{card, closedMs, dubbedMs, postMs, readyMs}]`;旧的四个数保留。家长端那行 chip:首拍就绪 / 老师写完 / 全部就绪 / 后期几拍几超时。

## 六、测试怎么跟

- **纯函数**:`beatsOf` / `closedBeats`(partial + done 标记 → 哪些拍关了)、按拍拼 `layout.rows`、拍内下标映射;样本还是 `tests/fixtures/board/` 那 7 份。
- **runner 全流程**(假 CLI `--stream` + 假配音 + 假 CLI json 模式当后期):断言事件顺序——首拍 ready 在老师 exit 之前;某拍后期超时 → 那拍 ready 仍发、素版;转正后节 == 各拍拼接。事件是流水线的可观测面,测事件就是测流程。
- **mock**:`cotutor mock` 按拍模拟(卡 + 句一拍一拍露,每拍延迟可调),页面的「就绪一拍播一拍」「没就绪停下」「转正不重播」在 mock 上过;探针脚本(`scripts/probe-*.mjs`)照旧用真窗口看。
- **评测**:《快模型方案.md》的 `post-eval` 改成按拍跑整节,分数按拍聚合。

1. 卡在拍就绪时才铺(晚露 1–3 秒,不闪)。
