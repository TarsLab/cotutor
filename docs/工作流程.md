# 一轮问答的工作流程:一拍一就绪、控制台(2026-09-13,已拍板)

材料:`src/server/runner.ts`(spawn)、`src/server/tts.ts`(DubQueue / LineDubber)、`src/server/post.ts`、`src/server/kid-page.ts`(pending / partial / 转正);续《快模型方案.md》。

结论先行:**一拍一就绪**(原来是「一轮一节」:老师写完、配音配完、后期回来,全齐才转正)。一张卡加它后面的讲稿是一拍,一拍的配音齐了、后期回了就能播,老师还在写后面的时候孩子已经在听第一拍。配套两件事:快模型按拍调用并带上前面几张卡;运行时的每一道工序都发事件,控制台按道打印,家长端按道回看。

## 一、目标流程:一拍一就绪

### 拍(beat)是什么

板书本来就是「卡、跟着它的几句讲稿、下一张卡、……」。一拍 = 一张卡 + 它后面直到下一张卡之前的讲稿句(讲稿句的锚点规则已经是这个:句子锚到上一张卡)。第一张卡之前的句子是第 0 拍(没有卡,只有话)。拍**不进契约**——`beatsOf(section)` 从卡与句的顺序现算,节的形状一个字不改。

拍什么时候「关」:下一张卡的围栏打开时,或老师进程退出时。关了的拍不再变(partial 解析器已经保证定稿的句子不变;围栏闭合的卡不变)。

### 一拍的就绪 = 配音齐 + 后期回

```
拍 k 关
 ├─ tts   这拍的每句已经在配(定稿即配,现有);全部落盘 → 配音齐
 └─ post  起一次快模型:这拍的卡 + 讲稿,带前面 3–5 张已定的卡;回了 → 套上(标注 / said / 样子 / 这张卡接上一行还是另起一行)
就绪 = 配音齐 ∧ (后期回 ∨ 后期超时)
```

后期超时 → 这一拍素版(机械规则选笔、缺省底色、另起一行),**不重来、不再改**;孩子不知道有这道工序。超时值按拍设,缺省 10 秒:只有第 0/1 拍的后期在关键路径上,后面的拍在前一拍播放的时候跑,通常被声音盖住。

### 孩子端

- pending 条目不再是「露卡不播」,而是**就绪一拍播一拍**:第一拍就绪就开播;一拍播完下一拍就绪就接着;没就绪就停在那,喇叭不响、不出错:第一拍前板上铺一张占位卡、字幕行「我写给你看」(8 秒后「再等我一下下」);拍与拍之间留着刚念那句,变暗加跳动的点。
- **卡在拍就绪时才铺**(不是围栏闭合时):铺的时候底色、字形、在哪一行都已定,不会先素后彩地闪。代价是卡晚露 1–3 秒;换来的是听到第一个字提早 5–10 秒。
- 老师退出、索引写入(转正)时,页面**不重画、不重播**:正式节 = 已关各拍的拼接,页面只把 pending 标记摘掉、补上老师尾巴之后的东西(家长段孩子看不到)。万一正式解析和各拍拼起来不一样(老师中途用了工具、段落规则选了别的段——`kidSource` 的规则两边同一份,理论上不会),播完当前拍再整节重画,并记一条 warning,让家长端能看见。
- 「继续」「交给老师」「新话题」的语义不变。
- **再听**(2026-09-18):卡讲完右上角露喇叭,点了重念第一遍时让它亮起来的句(标注落在哪张算哪张,没标注看锚点;不按拍分——写在卡 0 后、标注在卡 1 的句按拍算会点 0 亮 1);节念完节头露喇叭,点了整节重念;点字幕的字重念那句。只念句子与标注(撤掉重描),不执行 cue、不推答题卡;念完回到原位置(在念的变暂停,等答的还等着),重念中再点 / 点暂停就停。**板上安静才能再听**(停下等答、念完、孩子自己暂停):老师在想、正在念时喇叭全藏、点字幕不响——2026-09-18 真机,新回答念到一半点了旧卡的喇叭,回答停住、同一个声音念旧内容听着像答非所问。再听时字幕淡一档、前面一个小喇叭,钮是 ■ 停(不是暂停);停下后回到等答,「继续」灰 0.8 秒才能点——同一真机那次,想停再听的一下落在刚变出来的「▶ 继续」上,老师把「继续」当成答应了。状态机在 `kid-board.ts` 的 `replayLines`(分组复用 `nowCard`)/ `startReplay`,`advance` 认 `replay`。

#### 播放器:谁能打断谁(2026-09-18)

孩子端所有改播放状态的事(孩子点的、声音念完的、老师新内容到的、舞台回来的)都走 `kid-board.ts` 的 `step(状态, 事件) → { 新状态, 要做的事 }`,页面只 `dispatch` 并照单执行,不直接改状态。由来:以前 27 处直接改状态、20 处停声音散在十几个入口,加再听时漏了两处,真机上新回答被打断、「继续」被误点发给老师。

**改规则的顺序:先改下面这张表 → 再改 `tests/player.test.ts` 里对应那行 → 最后改 `step`。** 表的每一格在测试里有一条;另有随机事件序列(3000 条 × 120 步)每步查不变式,和一条「页面里 `S.state =` 只有 dispatch 那一处」的检查。

| 正在…… | 来了…… | 结果 |
|---|---|---|
| 停下等答 | 点「继续」 | 发「继续」给老师;再听刚停 0.8 秒内不发 |
| 停下等答 / 念完 / 孩子暂停 | 点喇叭 · 点节头 · 点字幕 | 再听;念完回到原位置(暂停的还暂停,等答的还等答),不推答题卡、不发任何东西 |
| 老师在念 · 老师在想 · 等下一拍 · 交给场景 · 舞台开着 | 点喇叭 · 点节头 · 点字幕 | 不响(喇叭本来就藏着) |
| 老师在念 | 点暂停 / 点卡开舞台 / 点读 | 暂停(点读念那一段) |
| 老师在念 | 一句念完 | 下一句;末句问句 → 等答并把锚点上能做的卡推到舞台(以前的话题不等答);带 `[[play]]` → 交给场景 |
| 交给场景 | 场景播完或孩子关了 | 接着念下一句 |
| 老师在念 / 暂停 | 孩子说话、打字、交答案 | 停声音,算念完 |
| 再听 | 点 ■ / 再点同一个喇叭 | 停,回原位置,「继续」灰 0.8 秒 |
| 再听 | 点别的喇叭 | 换成那个;念完回的还是最初的位置 |
| 再听 | 一句念完 | 下一句;没了回原位置 |
| 再听 | 开舞台 · 孩子说话 · 新的一节到了 | 再听停,再照那件事的规则走 |
| 等下一拍 | 新的一拍就绪 | 接着念(不自动念时只把标注画齐) |
| 老师在念某节 | 老师写完这节 | 不重播;定稿句子对不上时按文字找回位置;等着的接上 |
| 任何 | 老师出错撤掉这节 | 停声音,停在最后一节末尾 |

不变式(每步都查):会让页面再 dispatch 的事(念、发、开舞台、推答题卡)最多一个且在最后;「继续」只由孩子在等答、不在再听、过了防误点时点出;再听只在板上安静、舞台没开时开始;要念就一定在念;再听不改「念到哪」;位置不越界;新的一拍就绪、孩子没手动停,回答不会卡住。

「首卡就绪」(firstReadyMs:第一拍配音齐且后期回)取代「首卡露出」成为头号埋点;家长端埋点 chip 那行显示它。

## 二、快模型按拍调用,带前文

提示词骨架整份在主题的 `post.md`(和 kid.css 同一套,占位符是生成的部分,《快模型方案.md》§一 A):HTML 方言,`{board}` 进、`{patch}` 出。每拍给模型这一拍的卡与讲稿,加前面 3–5 张已定的卡。

要点:

- **排版变成一个二选一**:这张卡接上一行(`same`)还是另起一行(`new`)。行从左往右长,校验只看「这一行会不会超 3 张、标题行 / 交互卡是否独占」,不用整节回头。整节的 `layout.rows` 由各拍的决定拼出来,契约不变。
- **前文只读**:已定卡的样子、行、已标的词都摆出来,规则里写「同一个词前面标过就别标;底色照顾前后呼应(同类卡同色)」。前文取 3–5 张是够的:再远的孩子已经滚过去了。
- **句子下标是拍内的**,校验器映射回节内下标;`said` 规则不变。
- 第 0 拍(没有卡只有话)不调后期:没有卡就没有可标的东西。
- 一节几张卡就几次调用(通常 3–6 次);haiku 走 CLI 每次 $0.004–0.05(冷起贵),走直连 API 约 $0.001–0.003。评测(《快模型方案.md》§一 C)`--serial` 按拍顺着起整节,和线上一模一样。
- `.post.json` 从一份变成一节一个数组(每拍:输入、原文、校验、耗时、费用);`repost` 按拍重跑整节。

## 三、配音:一老师一音色,走 API

- 出厂就是这条路(voxtell → DashScope qwen-tts,一句约 2 秒,3 并行,同文本缓存零成本);浏览器合成声只在两处:mock(测页面)与线上某一句合成失败时的兜底(不响比响错好,但这一句总得念)。
- doctor `tutor.<名>.voice`:开着的老师没配 voice 报 warn;家长端老师团那页音色空着的挂 chip。
- 就绪判定只认 mp3 落盘;没配 voice 的老师(只该出现在测试里)每句视为立刻齐。
- 点读段资产(read 卡的每段)继续后台配,不进就绪判定:那是孩子点了才念的。

## 四、控制台:分道看每一道工序

### 事件是唯一来源

runner 在每个关键点发一条结构化事件(内存 EventEmitter + 追加到 `<日期>.<job>.events.jsonl`),消费者只有三个,都不各自再算一遍:

```
{ t: 6381, lane: 'main', kind: 'card', beat: 0, card: 0, label: 'text「勾股定理」' }
{ t: 6402, lane: 'tts',  kind: 'queued', line: 0, text: '先认边。' }
{ t: 7100, lane: 'main', kind: 'beat-close', beat: 0 }
{ t: 7101, lane: 'post', kind: 'start', beat: 0, context: 0 }
{ t: 8300, lane: 'tts',  kind: 'done', line: 0, ms: 1898, cached: false }
{ t: 9900, lane: 'post', kind: 'done', beat: 0, ms: 2799, kept: { marks: 1, look: 1, row: 'new' }, dropped: 0, costUsd: 0.004 }
{ t: 9901, lane: 'ready', kind: 'beat', beat: 0, first: true }
{ t: 16433, lane: 'main', kind: 'exit', code: 0, costUsd: 0.111, turns: 3 }
{ t: 19030, lane: 'ready', kind: 'all' }
{ t: 19100, lane: 'index', kind: 'written' }
{ t: 19150, lane: 'scene', kind: 'started', bundle: '2026-09-12-guilv', job: '1902-4' }
```

道(lane):`main`(老师:卡、句、工具调用、子代理、退出)、`tts`(每句排队 / 完成 / 失败)、`post`(每拍起 / 回 / 超时 / 丢了什么)、`ready`(每拍就绪、首拍、全部)、`index`、`scene`(场景卡起的画图作业,2026-09-17 前叫 `handoff`)、`ledger`。

### 三个消费者

1. **`cotutor send`** 现场逐行打印,`cotutor serve --trace` 对每一轮同样打印。一行一事件,左边相对秒,中间道名着色,右边一句话:

```
  0.00 main   起 claude(math-tutor,resume 3f2a…)
  6.38 main   卡 0 text「勾股定理」
  6.40 tts    句 0 排队「先认边。」
  7.10 main   拍 0 关 → post 起(前文 0 张)
  8.30 tts    句 0 ✓ 1.9s
  9.90 post   拍 0 ✓ 2.8s  标 1 · 样 sky · 另起一行 · 丢 0 · $0.004
  9.90 ready  拍 0 ✓  ← 首拍就绪 9.9s
 11.20 main   卡 1 text「认边」 · 句 1、2 排队
 …
 16.43 main   退出 0  $0.111 · 3 turns
 19.03 ready  全部就绪(4 拍)
 19.10 index  写入
 19.15 scene   课包 2026-09-12-guilv 起了 scene-maker 1902-4
```

`--lane post,tts` 只看某几道;`--raw` 打 JSON 行。

2. **家长端「看原文」加一站「时间线」**:读 events.jsonl 画成横向甘特(一道一行,拍为块),点一块展开那条事件;超时、失败的块标红。「板书后期」那站按拍列。
3. **`cotutor trace <老师> <job>`** 离线回放一份 events.jsonl,格式同 1(排查昨天那轮用)。

### 索引里留什么

timing 加 `firstReadyMs`、`beats: [{card, closedMs, dubbedMs, postMs, readyMs}]`;旧的四个数保留。家长端那行 chip:首拍就绪 / 老师写完 / 全部就绪 / 后期几拍几超时。

## 五、测试怎么跟

- **纯函数**:`beatsOf` / `closedBeats`(partial + done 标记 → 哪些拍关了)、按拍拼 `layout.rows`、拍内下标映射;样本还是 `tests/fixtures/board/` 那 7 份。
- **runner 全流程**(假 CLI `--stream` + 假配音 + 假 CLI json 模式当后期):断言事件顺序——首拍 ready 在老师 exit 之前;某拍后期超时 → 那拍 ready 仍发、素版;转正后节 == 各拍拼接。事件是流水线的可观测面,测事件就是测流程。
- **mock**:`cotutor mock` 按拍模拟(卡 + 句一拍一拍露,每拍延迟可调),页面的「就绪一拍播一拍」「没就绪停下」「转正不重播」在 mock 上过;探针脚本(`scripts/probe-*.mjs`)照旧用真窗口看。
- **评测**:`scripts/post-eval.ts` 按拍跑整节,分数按拍聚合。

## 六、拍板记录(2026-09-13)

1. 卡在拍就绪时才铺(晚露 1–3 秒,不闪)。

5. 「首拍就绪」(firstReadyMs)取代「首卡露出」当头号埋点。
6. 快模型的提示词骨架和主题 css 同一套:`themes/<主题>/post.md` 整份可改,占位符是生成的部分(《快模型方案.md》§一 A)。
