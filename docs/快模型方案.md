# 快模型(板书后期)使用方案(2026-09-13,已拍板)

材料:`src/server/post.ts`、`src/lib/postprocess.ts`、`tests/postprocess.test.ts`;真跑数据 `~/cotutor/ray/conversations/math-tutor/2026-09-12.*.post.json` 与索引里的 timing;今天实测 claude CLI 起 haiku 的开销。

结论先行:**后期这道工序的设计(老师定内容、快模型提案、契约校验、坏了素版)不用改;要改的是它现在没法被开发者摆弄。** 提示词埋在 ts 里、没有样本、没有评测、超时值是拍脑袋的——结果是上线三轮全部超时,快模型一次都没交付过,而没人知道。方案分四块:提示词成文件、样本即测试、评测命令、时间预算按数据定。

## 一、现状与证据

| 问题 | 证据 | 后果 |
|---|---|---|
| **真跑三轮全超时** | 9-12 三轮 post.json:`ms` 4010 / 4006 / 4005,全是「超时(4000ms),先出素版」 | 上线以来孩子看到的一直是素版;家长端要点进「看原文」第七站才知道 |
| **claude CLI 缺省让 haiku 思考**(2026-09-13 按拍上线后真跑) | 三拍全部 10 秒超时;单独跑一条真实提示词:`duration_api_ms` 35–69 秒,`thinking_tokens` 3–6K,`--effort low` 反而更慢,`--system-prompt` 换掉系统提示也没用(还剩 22K 缓存输入);`MAX_THINKING_TOKENS=0` → 4 秒、0 思考、输出不变 | 后期子进程统一带 `MAX_THINKING_TOKENS=0`(post.ts);关掉之后一拍 3.4–3.7 秒、$0.015,两拍都在孩子要之前回来 |
| **claude CLI 不适合 4 秒预算** | 今天实测 `claude -p … --model haiku --output-format json` 回一个 `{"ok":true}`:`duration_api_ms` 5034 / 2764,进程总时长再加 1–2 秒起动;冷起那次费用 $0.054(CLI 自己带的系统提示走了一遍),热的 $0.004 | 4 秒预算在 CLI 这条路上结构性地不够;不是提示词的问题 |
| **提示词在代码里** | `postPrompt()` 是一个模板字符串,改一个字要改 ts、重起 serve、过 typecheck | 想试「换一句话会不会好」的门槛太高;没法 diff 两版提示词的效果 |
| **规则写了两遍** | 提示词里的「一句最多 2 处」等来自常量,但「phrase 必须在卡上」「标题行不能标」是手写的一句话,校验器里另有一份逻辑 | 改校验忘改提示词(或反过来)不会有任何测试报错 |
| **测试只测形状** | `postprocess.test.ts`:解析能取出 JSON、校验的每条规则一正一反;runner 测试走假 CLI 的 json 模式 | 「提示词好不好」「模型会不会照做」「超时该设几秒」没有任何测试能回答 |
| **样本没有** | `tests/fixtures/board/` 有 7 份老师原文,但没有一份「这节后期应该出什么」 | 没有基准,评测无从谈起 |
| **不能离线重放** | `repost` 能重跑一轮,但要有 workspace、要真起模型、一次一轮 | 调提示词时没法「对着 7 个样本一口气跑完看分」 |

| 轮 | 老师出完 doneMs | 配音收尾 dubbedMs | 后期 postMs | 配音比老师晚 |
|---|---|---|---|---|
| 1848-1 | 9140 | 13538 | 13538(超时) | 4.4s |
| 1854-2 | 11175 | 13652 | 15183(超时) | 2.5s |

## 二、主张

### A. 提示词成文件:骨架和主题 css 同一套,占位符是生成的部分(2026-09-13 拍板改写)

提示词整份是一个文件 `themes/<主题>/post.md`,地位和 `kid.css` 完全一样:出厂在包里的 `themes/default/`,init 拷进 workspace,目录 hash 进 shipped.json,`cotutor upgrade` 没改过的换新、改过的报 diff,`cotutor add-theme` 拷一份来改;服务每次按 mtime 现读,读不到 / 缺必需占位符就退包里那份并在 doctor `theme.post` 点名。**家长或主题作者可以改任何一句话**——开场白、口味、例子、段落顺序;唯一不能改的是占位符里生成的内容:

- **生成的占位符**(代码填,与契约同源):`{rules}`(一句几处、一卡几处、phrase 必须在卡上、said 必须在讲稿里、行的上限、标题行与交互卡独占——从校验器用的同一组常量生成,改校验器这段自动跟着变)、`{output}`(输出形状,从 PostOutputSchema 生成)、`{cards}` `{lines}`(这一拍的卡与讲稿,格式和解析器绑定)、`{context}`(前文已定的卡)、`{device}`、`{tints}` `{looks}` `{pens}` `{defaultTint}`(从 theme.json 槽表拼)。
- **必需占位符**:`{cards}` `{lines}` `{output}` `{rules}`——缺一个模型不知道要干什么,整份退出厂骨架并 warn;其余可选,不写就是不给模型这段信息(比如主题作者觉得端的说明多余)。
- 主题和提示词放一起的理由:槽表(theme.json)说「这个槽给什么用」,提示词说「怎么选」,样子的真相全在一个目录里;换主题 = 换一整套审美。

出厂骨架(Markdown,占位符 `{名}`;下面是整节版,按拍版见《工作流程.md》§三):

```markdown
你是一节板书的后期(排版与划重点),不是老师。……只输出一个 JSON 对象。

## 端
{device}

## 底色槽 tint(缺省 {defaultTint};一张卡一个)
{tints}

## 字形槽 look
{looks}

## 笔 pen
{pens}

## 怎么选(口味)
- 一节只有一两处值得荧光笔;定义用术语底;……(主题作者随便写)

## 规则
{rules}          ← 代码生成,与校验器同源

## 卡
{cards}

## 讲稿
{lines}

## 输出(只这一个 JSON)
{output}         ← 代码生成,与 PostOutputSchema 同源
```

`postPrompt(section, device, theme)` 变成 `renderPrompt(template, slots)`:读主题的 post.md,没有就用包里 `themes/default/post.md`,再没有就用代码里的一份兜底(永远能跑)。`{cards}` `{lines}` 的逐条格式仍在代码里(`cardLine` / `lineLine`),因为它们和解析器绑定。

不放的地方:不放 `.cotutor/`(那是机器文件,每次刷新)、不放 cotutor.json(太长)、不放老师文件(后期不是老师)。

### B. 样本即测试:`tests/fixtures/post/<名>/`

一份样本 = 一个目录:

```
tests/fixtures/post/math-pythagoras/
  section.md      老师原文(与 tests/fixtures/board 同一种写法;家长端 /fixture 站下载即得)
  expect.json     期望:{ device, must: [{line, card, phrase, said?}], never: [{card, phrase}], layout?: [[…]], look?: {…}, maxDropped?: n }
  prompt.md       渲染快照(测试生成、提交入库;改了模板 diff 里一眼看到提示词变了什么)
  runs/           评测留档(gitignore):<日期>-<运行时>.json,每次真跑的原始输出、校验、分数
```

`expect.json` 故意是**部分匹配**,不是精确答案:审美有余地,评测只问「该标的标了没(must)、不该标的没标(never)、行合法、丢了几条」。精确到每个 pen 就变成在测模型的脾气。

### C. 三层测试,只有一层花钱

| 层 | 命令 | 花钱 | 测什么 |
|---|---|---|---|
| 1 离线 | `pnpm test`(`tests/post-fixtures.test.ts`) | 否 | 每份样本:section.md 过解析器 → 渲染提示词 == prompt.md 快照(不等就报 diff,`--update` 重写);`expect.must` 里的每条过 `validatePost` 必须收下(证明期望本身合法);`never` 里的每条必须被校验丢掉或不在卡上;规则段与常量一致(`rulesBlock()` 含 `MAX_MARKS_PER_LINE` 等的当前值);主题 post.md 的占位符齐全 |
| 2 评测 | `cotutor post-eval [--runtime x] [--only 名] [--repeat n]` | 是,每样本约 $0.005–0.05 | 对每份样本真起快模型 n 次:解析成功率、must 命中率、never 误标率、layout 合法率、dropped 均值、p50 / p95 延迟、费用;打印一张表,留档到 runs/;`--compare <日期>` 与上次并排 |
| 3 回放 | `cotutor repost <老师> [日期] --all`(现有命令加 `--all`) | 是 | 对真 workspace 今天所有有卡的轮次重跑后期;家长端第七站已能看结果与「再做一次」 |

调提示词的日常就是:改 post.md → `pnpm test` 看快照 diff 是不是自己想改的 → `post-eval` 看分有没有掉 → 满意了提交(快照一起提交)。

评测走的就是 `runPost`(同一条路,同一个校验),只是把 workspace 换成临时目录、主题按参数指定;假 CLI 的 json 模式已经能让评测命令本身在 `pnpm test` 里过一遍(不花钱)。

### D. 时间预算按数据定,不按感觉

三条,按顺序:

1. **缺省 `timeoutMs` 从 4000 抬到 8000**,并在评测表里把 p95 打出来,以后改缺省值要有数。依据:CLI 一趟 4–6 秒,配音让前 3 秒免费,8 秒对孩子多等 3–5 秒——不理想,但比「永远素版」强,而且下一条能把它抹掉。
2. **晚到也套,分两档**:后期在超时后才回来 → 不丢,写进 `.post.json` 与索引,页面下次 poll 拿到:**标注、锚点、样子**当场套(标注本来就是念到才画,样子只是属性;孩子无感),**排版**只在这节还没开播时套(播放中重排会跳)。这样超时值只决定「排版能不能赶上」,划重点永远不会白跑。
3. **后期专用运行时走直连**(要拍板):CLI 的 1–2 秒起动和 $0.05 冷起是给带工具的会话准备的,后期是一问一答无工具,直连 API(`runtimes` 加一种形状 `{api: 'anthropic', model: 'claude-haiku-4-5', keyEnv: 'ANTHROPIC_API_KEY'}`)能把一趟压到 1–2 秒、费用降一个量级,前两条的补丁就都用不上了。代价:多一条鉴权路(API key 而不是订阅),qwen 用户要另一种 api。不急,先做 1、2,评测表里 CLI 的 p95 会告诉我们值不值。

### E. 不做的

- **不把快模型做成会话或子代理**:它没有记忆、没有工具、不读 workspace,一次一节。
- **不把校验搬进提示词**:提示词只是让模型少犯错,契约说了算;丢掉的提案带原因,是评测的信号,不是要消灭的东西。
- **不让快模型定时间**:标注什么时候画由 `markTiming` 按讲稿算(有时间戳后按时间戳),模型只给 `said`(见 CLAUDE.md 2026-09-13)。
- **不做精确答案的样本**:见 B。
