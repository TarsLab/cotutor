# 快模型(板书后期)使用方案(2026-09-13,已拍板)

材料:`src/server/post.ts`、`src/lib/postprocess.ts`、`tests/postprocess.test.ts`;真跑数据 `~/cotutor/ray/conversations/math-tutor/2026-09-12.*.post.json` 与索引里的 timing;今天实测 claude CLI 起 haiku 的开销。

结论先行:**后期这道工序的设计(老师定内容、快模型提案、契约校验、坏了素版)不用改;要改的是它现在没法被开发者摆弄。** 提示词埋在 ts 里、没有样本、没有评测、超时值是拍脑袋的——结果是上线三轮全部超时,快模型一次都没交付过,而没人知道。方案分四块:提示词成文件、样本即测试、评测命令、时间预算按数据定。

## 二、主张

### A. 提示词成文件:骨架和主题 css 同一套,占位符是生成的部分(2026-09-13 拍板改写)

提示词整份是一个文件 `themes/<主题>/post.md`,地位和 `kid.css` 完全一样:出厂在包里的 `themes/default/`,init 拷进 workspace,目录 hash 进 shipped.json,`cotutor upgrade` 没改过的换新、改过的报 diff,`cotutor add-theme` 拷一份来改;服务每次按 mtime 现读,读不到 / 缺必需占位符就退包里那份并在 doctor `theme.post` 点名。**家长或主题作者可以改任何一句话**——开场白、口味、例子、段落顺序;唯一不能改的是占位符里生成的内容:

- **生成的占位符**(代码填,与契约同源):`{rules}`(一句几处、一卡几处、phrase 必须在卡上、said 必须在讲稿里、行的上限、标题行与交互卡独占——从校验器用的同一组常量生成,改校验器这段自动跟着变)、`{output}`(输出形状,从 PostOutputSchema 生成)、`{cards}` `{lines}`(这一拍的卡与讲稿,格式和解析器绑定)、`{context}`(前文已定的卡)、`{device}`、`{tints}` `{looks}` `{pens}` `{defaultTint}`(从 theme.json 槽表拼)。
- **必需占位符**:`{cards}` `{lines}` `{output}` `{rules}`——缺一个模型不知道要干什么,整份退出厂骨架并 warn;其余可选,不写就是不给模型这段信息(比如主题作者觉得端的说明多余)。
- 主题和提示词放一起的理由:槽表(theme.json)说「这个槽给什么用」,提示词说「怎么选」,样子的真相全在一个目录里;换主题 = 换一整套审美。

出厂骨架(Markdown,占位符 `{名}`;下面是整节版,按拍版见《工作流程.md》§三):

```markdown
你是一节板书的后期(排版与划重点),不是老师。……只输出一个 JSON 对象。

## 端
{device}

## 底色槽 tint(缺省 {defaultTint};一张卡一个)
{tints}

## 字形槽 look
{looks}

## 笔 pen
{pens}

## 怎么选(口味)
- 一节只有一两处值得荧光笔;定义用术语底;……(主题作者随便写)

## 规则
{rules}          ← 代码生成,与校验器同源

## 卡
{cards}

## 讲稿
{lines}

## 输出(只这一个 JSON)
{output}         ← 代码生成,与 PostOutputSchema 同源
```

`postPrompt(section, device, theme)` 变成 `renderPrompt(template, slots)`:读主题的 post.md,没有就用包里 `themes/default/post.md`,再没有就用代码里的一份兜底(永远能跑)。`{cards}` `{lines}` 的逐条格式仍在代码里(`cardLine` / `lineLine`),因为它们和解析器绑定。

不放的地方:不放 `.cotutor/`(那是机器文件,每次刷新)、不放 cotutor.json(太长)、不放老师文件(后期不是老师)。

### B. 样本即测试:`tests/fixtures/post/<名>/`

一份样本 = 一个目录:

```
tests/fixtures/post/math-pythagoras/
  section.md      老师原文(与 tests/fixtures/board 同一种写法;家长端 /fixture 站下载即得)
  expect.json     期望:{ device, must: [{line, card, phrase, said?}], never: [{card, phrase}], layout?: [[…]], look?: {…}, maxDropped?: n }
  prompt.md       渲染快照(测试生成、提交入库;改了模板 diff 里一眼看到提示词变了什么)
  runs/           评测留档(gitignore):<日期>-<运行时>.json,每次真跑的原始输出、校验、分数
```

`expect.json` 故意是**部分匹配**,不是精确答案:审美有余地,评测只问「该标的标了没(must)、不该标的没标(never)、行合法、丢了几条」。精确到每个 pen 就变成在测模型的脾气。

### C. 三层测试,只有一层花钱

| 层 | 命令 | 花钱 | 测什么 |
|---|---|---|---|
| 1 离线 | `pnpm test`(`tests/post-fixtures.test.ts`) | 否 | 每份样本:section.md 过解析器 → 渲染提示词 == prompt.md 快照(不等就报 diff,`--update` 重写);`expect.must` 里的每条过 `validatePost` 必须收下(证明期望本身合法);`never` 里的每条必须被校验丢掉或不在卡上;规则段与常量一致(`rulesBlock()` 含 `MAX_MARKS_PER_LINE` 等的当前值);主题 post.md 的占位符齐全 |
| 2 评测 | `cotutor post-eval [--runtime x] [--only 名] [--repeat n]` | 是,每样本约 $0.005–0.05 | 对每份样本真起快模型 n 次:解析成功率、must 命中率、never 误标率、layout 合法率、dropped 均值、p50 / p95 延迟、费用;打印一张表,留档到 runs/;`--compare <日期>` 与上次并排 |
| 3 回放 | `cotutor repost <老师> [日期] --all`(现有命令加 `--all`) | 是 | 对真 workspace 今天所有有卡的轮次重跑后期;家长端第七站已能看结果与「再做一次」 |

调提示词的日常就是:改 post.md → `pnpm test` 看快照 diff 是不是自己想改的 → `post-eval` 看分有没有掉 → 满意了提交(快照一起提交)。

评测走的就是 `runPost`(同一条路,同一个校验),只是把 workspace 换成临时目录、主题按参数指定;假 CLI 的 json 模式已经能让评测命令本身在 `pnpm test` 里过一遍(不花钱)。

### D. 时间预算按数据定,不按感觉

三条,按顺序:

1. **缺省 `timeoutMs` 从 4000 抬到 8000**,并在评测表里把 p95 打出来,以后改缺省值要有数。依据:CLI 一趟 4–6 秒,配音让前 3 秒免费,8 秒对孩子多等 3–5 秒——不理想,但比「永远素版」强,而且下一条能把它抹掉。
2. **晚到也套,分两档**:后期在超时后才回来 → 不丢,写进 `.post.json` 与索引,页面下次 poll 拿到:**标注、锚点、样子**当场套(标注本来就是念到才画,样子只是属性;孩子无感),**排版**只在这节还没开播时套(播放中重排会跳)。这样超时值只决定「排版能不能赶上」,划重点永远不会白跑。
3. **后期专用运行时走直连**(要拍板):CLI 的 1–2 秒起动和 $0.05 冷起是给带工具的会话准备的,后期是一问一答无工具,直连 API(`runtimes` 加一种形状 `{api: 'anthropic', model: 'claude-haiku-4-5', keyEnv: 'ANTHROPIC_API_KEY'}`)能把一趟压到 1–2 秒、费用降一个量级,前两条的补丁就都用不上了。代价:多一条鉴权路(API key 而不是订阅),qwen 用户要另一种 api。不急,先做 1、2,评测表里 CLI 的 p95 会告诉我们值不值。

### E. 不做的

- **不把快模型做成会话或子代理**:它没有记忆、没有工具、不读 workspace,一次一节。
- **不把校验搬进提示词**:提示词只是让模型少犯错,契约说了算;丢掉的提案带原因,是评测的信号,不是要消灭的东西。
- **不让快模型定时间**:标注什么时候画由 `markTiming` 按讲稿算(有时间戳后按时间戳),模型只给 `said`(见 CLAUDE.md 2026-09-13)。
- **不做精确答案的样本**:见 B。

### F. HTML 方言:HTML 进、补丁出(2026-09-14 验证,结论:留作选项,缺省不换)

问题的起点:JSON 方言把卡压成一行(`卡 2. read:楚有祠者… / 舍人相谓曰… / 请画地为蛇…`)、用拍内下标指句、用卡号指卡,9-13 评测丢掉的 3 处标注全是「指错了」(词取自讲稿不在卡上、拍内下标当节内下标)。主张:把板书按孩子看到的结构给模型看(HTML:`div.row` 一行、`div.c` 一张卡带 `data-tint / data-look`、已画的标注原地 `<mark data-pen data-done>`、这一拍的卡 class 带 now、讲稿 `p.line`),模型只回 now 那张卡的壳 `<div class="c" id="cN" data-row data-tint data-look data-emoji>`(里面 `<mark data-pen data-said data-card>词</mark>` 与空的 `<p class="line" data-n data-for></p>`),不复述卡、不数下标。**全是标准 HTML,自定义的都是 data-\***(2026-09-14 晚拍板:原来输出是自造的 `<c row tint>` 壳、输入的 `pen` `done` `card` `n` `for` 也是自造属性;改成标准的理由是模型看到的和要回的是同一个标签、`data-*` 是它最熟的挂属性方式,补丁多约 20 token;解析器新旧两种都认);校验器不分方言。落地在 `src/lib/post-html.ts`,骨架用了 `{board}` 就是这种方言(`{patch}` 是输出段),`scripts/post-eval.ts --dialect html --serial` 能比。token 估算(中文一字一 token):输入精简 HTML 比压成一行多一成(202 对 190),输出补丁与 JSON 同量级(约 40);整张卡回 HTML 是 131–177,不做。

真跑(haiku 走 claude CLI,三份样本各拍顺着起、每份两遍,共 16 拍;`tests/fixtures/post/*/runs/2026-09-13T16-*`):

| 骨架 | 拍收到 | never 失手(提了不该提的) | 底色对 | 丢 | 每拍 p50 / p95 | 费用 |
|---|---|---|---|---|---|---|
| JSON(出厂) | 16/16 | 0/18 | 5/8 | 6(全是指错:词取自讲稿 4、下标 1、整句 1) | 3.1s / 6.9s | $0.238 |
| HTML v1:板书夹在规则与输出之间 | 13/16(2 拍回的是话没有补丁、1 超时) | 0/18(因为多半什么都没提) | 2/8 | 1 | 6.5s / 10s | $0.246 |
| HTML v3:**板书放最前**,结尾「现在就为 now 那张卡回一个 <c>」 | 15/16 | 9/18 | 8/8 | 12(再标已画的 8、said 错 2、跨卡 1、没这句 1) | 3.8s / 7.1s | $0.241 |
| HTML v3 + 已画的标注带 `done` | 15/16 | 8/18 | 8/8 | 15(再标已画的 7、said 错 3、词不在卡上 3、行 1) | 3.5s / 10s | $0.222 |
| HTML **标准写法**(div 壳 + data-*,haiku) | 14/16(2 超时) | 7/18 | 7/8 | 11(再标已画的 5、词不在卡上 3、其余 3) | 3.9s / 10s | $0.265 |
| HTML 混合 a:已标过的词不画在卡上,改成壳后一行文字列表 `{marked}` | 15/16 | 9/18 | 8/8 | 18 | 3.8s / 8.2s | $0.250 |
| HTML 混合 b:再把已标的词挂在卡与讲稿句的 `data-marked` 上,规则写「没有值得标的就不放」(**现在的 `POST_TEMPLATE_HTML`**) | 16/16 | 10/18 | 8/8 | 14(再标已画的 8、词不在卡上 5、其余 1) | 3.4s / 6.4s | $0.252 |
| **sonnet** JSON(同骨架,`--model sonnet`) | 16/16 | 5/18 | 3/8 | 12(词取自讲稿 7、再标已画的 5) | 4.7s / 6.4s | $0.701 |
| **sonnet** HTML v3 + done | 15/16(1 拍把 `<c` 写成 `<`) | 9/18 | 7/8 | 20(再标已画的 8、词取自讲稿 4、said 错 4、其余 4) | 4.6s / 7.7s | $0.595 |

三个发现:

1. **板书放在中间,haiku 把整份当「系统说明」**:16 拍里 9 拍回「我还没看到板书,请把 HTML 给我」,先写两三百字分析再说。不是 CLI 传丢了——让它复述「## 板书」一节,一字不差复述得出来;是读法问题。板书放最前、任务放后面就好了(v3),和 JSON 方言一样 40 多 token、3.5 秒回补丁。但仍有 1/16 的尾巴滑进分析(600 token,超时)。
2. **它总要在卡上标一个词,而最好的那个词老师已经标了**:HTML 各版本再标已画的词都是 7–10/18,JSON 是 0/18。起初以为是原地 `<mark>` 太显眼,改成壳后的文字列表(混合 a)没变,再改成挂在卡与讲稿句上的 `data-marked` 并写明「没有值得标的就不放」(混合 b)还是 10/18。真正的差别是:HTML 让它看见了卡的全文,它挑的就是最值得标的那个词,而那个词老师已经挑过;JSON 里卡压成一行,它挑的是讲稿里的词(「几个人」「《战国策》」),同样被校验器丢掉。**两种方言在这三份样本上都没贡献过一处新标注**,只是丢的理由不同;孩子看不见这项差别。评测里 never 失手这一栏对 HTML 方言是噪声,别拿它当退步。
3. **换成标准 HTML(div 壳 + data-*)分数没动,输出更规矩**(2026-09-14 晚):16 拍全是 29–99 token 的裸补丁,没有一拍写分析(有 4 拍包了 ```html 围栏、1 拍把卡的正文抄进壳里,解析器都吃得下);再标已画的还是 5–7 次,底色 7/8,两拍超时是 API 那头慢(raw 空)。它买到的就是上面说的那两样:一套文法、更稳的输出。
4. **换 sonnet 结论不变,只是更贵更慢**(2026-09-14 补跑):sonnet 两种方言都是 40–70 token 直接回、不写分析,但一样把原地的 `<mark done>` 抄回来(9/18),连 JSON 方言的「★老师已标」它也犯 5/18(haiku 0/18);底色 HTML 7/8 对、JSON 3/8;每拍 4.6–4.7 秒,一节费用是 haiku 的 3 倍。「再标已画的」是原地显示引起的,和模型大小无关;「词取自讲稿」两种方言、两个模型都有,是校验器该兜的。
5. **它确实更懂排版与底色**:底色 8/8 对(JSON 5/8),下标类错误归零;跨卡的「词不在卡上」两边都还有 1–3 处,那是模型的事,不是格式的事。

结论(2026-09-14 拍板,同日晚改):**出厂缺省换成 HTML 方言(混合 b)**——`themes/default/post.md` 与代码里的兜底都是 `POST_TEMPLATE_HTML`,JSON 骨架留作 `POST_TEMPLATE_JSON`(评测 `--dialect json`、老 workspace 拷过的 post.md 照跑)。换的理由:孩子看得见的两样,拍收到(16/16)与底色(8/8),都是各版本里最好的,p95 6.4 秒也最好;never 失手不进门槛(见发现 2)。门槛没等到「样本过 40 拍」,先换、边跑边收样本,掉了就把 post.md 换回 JSON 骨架,一行的事。要再推进 HTML,下一步不是改 CSS 类名,是把「已画的标注」从卡上拿掉、改成文字列表(和 JSON 一样),并把输出的 `<c>` 例子从「形状」改成一个真例子。JSON 方言这边更值得做的是同一个思路的便宜版:`{cards}` 给老师原文的 markdown 而不是压成一行,marks 去掉 `line` 下标、靠 said / 词本身找句——两个「指错」都在结构上消失,不改模型看到的样子。

## 三、落地顺序(每步独立可交付、可回退)

| 步 | 做什么 | 量 | 产出 |
|---|---|---|---|
| 1 | 超时抬到 8000;晚到也套(标注 / 样子当场,排版看播放状态);家长端第七站「超时」改成「晚到 x 秒,已补套」 | 半天 | 真 workspace 立刻不再全素版 |
