## 二、主张

### A. 提示词成文件:骨架和主题 css 同一套,占位符是生成的部分(2026-09-13 拍板改写)

提示词整份是一个文件 `themes/<主题>/post.md`,地位和 `kid.css` 完全一样:出厂在包里的 `themes/default/`,init 拷进 workspace,目录 hash 进 shipped.json,`cotutor upgrade` 没改过的换新、改过的报 diff,`cotutor add-theme` 拷一份来改;服务每次按 mtime 现读,读不到 / 缺必需占位符就退包里那份并在 doctor `theme.post` 点名。**家长或主题作者可以改任何一句话**——开场白、口味、例子、段落顺序;唯一不能改的是占位符里生成的内容:

- **生成的占位符**(代码填,与契约同源):`{rules}`(一句几处、一卡几处、phrase 必须在卡上、said 必须在讲稿里、行的上限、标题行与交互卡独占——从校验器用的同一组常量生成,改校验器这段自动跟着变)、`{output}`(输出形状,从 PostOutputSchema 生成)、`{cards}` `{lines}`(这一拍的卡与讲稿,格式和解析器绑定)、`{context}`(前文已定的卡)、`{device}`、`{tints}` `{looks}` `{pens}` `{defaultTint}`(从 theme.json 槽表拼)。
- **必需占位符**:JSON 方言 `{cards}` `{lines}` `{output}` `{rules}`,HTML 方言 `{board}` `{rules}` `{patch}`(`REQUIRED_SLOTS`)——缺一个模型不知道要干什么,整份退出厂骨架并 warn;其余可选,不写就是不给模型这段信息(比如主题作者觉得端的说明多余)。
- 主题和提示词放一起的理由:槽表(theme.json)说「这个槽给什么用」,提示词说「怎么选」,样子的真相全在一个目录里;换主题 = 换一整套审美。

出厂骨架就是 `themes/default/post.md`,直接看文件。

渲染:读主题的 post.md,没有就用包里 `themes/default/post.md`,再没有就用代码里的一份兜底(永远能跑)。`{cards}` `{lines}` 的逐条格式仍在代码里(`cardLine` / `lineLine`),因为它们和解析器绑定。

不放的地方:不放 `.cotutor/`(那是机器文件,每次刷新)、不放 cotutor.json(太长)、不放老师文件(后期不是老师)。

### B. 样本即测试:`tests/fixtures/post/<名>/`

一份样本 = 一个目录:

```
tests/fixtures/post/math-pythagoras/
  section.md      老师原文(与 tests/fixtures/board 同一种写法;家长端 /fixture 站下载即得)
  expect.json     期望:{ device, must: [{line, card, phrase, said?}], never: [{card, phrase}], layout?: [[…]], look?: {…}, maxDropped?: n }
  prompt.md       渲染快照(测试生成、提交入库;改了模板 diff 里一眼看到提示词变了什么)
  runs/           评测留档(gitignore):<日期>-<运行时>.json,每次真跑的原始输出、校验、分数
```

`expect.json` 故意是**部分匹配**,不是精确答案:审美有余地,评测只问「该标的标了没(must)、不该标的没标(never)、行合法、丢了几条」。精确到每个 pen 就变成在测模型的脾气。

### C. 三层测试,只有一层花钱

| 层 | 命令 | 花钱 | 测什么 |
|---|---|---|---|
| 1 离线 | `pnpm test`(`tests/post-fixtures.test.ts`) | 否 | 每份样本:section.md 过解析器 → 渲染提示词 == prompt.md 快照(不等就报 diff,`--update` 重写);`expect.must` 里的每条过 `validatePost` 必须收下(证明期望本身合法);`never` 里的每条必须被校验丢掉或不在卡上;规则段与常量一致(`rulesBlock()` 含 `MAX_MARKS_PER_LINE` 等的当前值);主题 post.md 的占位符齐全 |
| 2 评测 | `cotutor post-eval [--runtime x] [--only 名] [--repeat n]` | 是,每样本约 $0.005–0.05 | 对每份样本真起快模型 n 次:解析成功率、must 命中率、never 误标率、layout 合法率、dropped 均值、p50 / p95 延迟、费用;打印一张表,留档到 runs/;`--compare <日期>` 与上次并排 |
| 3 回放 | `cotutor repost <老师> [日期] --all`(现有命令加 `--all`) | 是 | 对真 workspace 今天所有有卡的轮次重跑后期;家长端「看原文」的「板书后期」那站能看结果与「再做一次」 |

调提示词的日常就是:改 post.md → `pnpm test` 看快照 diff 是不是自己想改的 → `post-eval` 看分有没有掉 → 满意了提交(快照一起提交)。

评测走的就是 `runPost`(同一条路,同一个校验),只是把 workspace 换成临时目录、主题按参数指定;假 CLI 的 json 模式已经能让评测命令本身在 `pnpm test` 里过一遍(不花钱)。

### E. 不做的

- **不把快模型做成会话或子代理**:它没有记忆、没有工具、不读 workspace,一次一节。
- **不把校验搬进提示词**:提示词只是让模型少犯错,契约说了算;丢掉的提案带原因,是评测的信号,不是要消灭的东西。
- **不让快模型定时间**:标注什么时候画由 `markTiming` 按讲稿算(有时间戳后按时间戳),模型只给 `said`。
- **不做精确答案的样本**:见 B。

### F. HTML 方言:HTML 进、补丁出(2026-09-14 验证,结论:留作选项,缺省不换)

问题的起点:JSON 方言把卡压成一行(`卡 2. read:楚有祠者… / 舍人相谓曰… / 请画地为蛇…`)、用拍内下标指句、用卡号指卡,9-13 评测丢掉的 3 处标注全是「指错了」(词取自讲稿不在卡上、拍内下标当节内下标)。主张:把板书按孩子看到的结构给模型看(HTML:`div.row` 一行、`div.c` 一张卡带 `data-tint / data-look`、已画的标注原地 `<mark data-pen data-done>`、这一拍的卡 class 带 now、讲稿 `p.line`),模型只回 now 那张卡的壳 `<div class="c" id="cN" data-row data-tint data-look data-emoji>`(里面 `<mark data-pen data-said data-card>词</mark>` 与空的 `<p class="line" data-n data-for></p>`),不复述卡、不数下标。**全是标准 HTML,自定义的都是 data-\***(2026-09-14 晚拍板:原来输出是自造的 `<c row tint>` 壳、输入的 `pen` `done` `card` `n` `for` 也是自造属性;改成标准的理由是模型看到的和要回的是同一个标签、`data-*` 是它最熟的挂属性方式,补丁多约 20 token;解析器新旧两种都认);校验器不分方言。落地在 `src/lib/post-html.ts`,骨架用了 `{board}` 就是这种方言(`{patch}` 是输出段),`scripts/post-eval.ts --builtin --serial` 能比。token 估算(中文一字一 token):输入精简 HTML 比压成一行多一成(202 对 190),输出补丁与 JSON 同量级(约 40);整张卡回 HTML 是 131–177,不做。

真跑(haiku 走 claude CLI,三份样本 16 拍,各骨架对照;原始表与发现见 git log,留档在 `tests/fixtures/post/*/runs/`):HTML 方言(混合 b)拍收到 16/16、底色 8/8、p95 6.4 秒,都是各版里最好的;JSON 方言底色 5/8,丢的全是「指错」(词取自讲稿、拍内下标当节内下标)。两种方言在这三份样本上都没贡献过一处新标注——HTML 让模型看见卡的全文,它总去再标老师已标的词(7–10/18,校验器丢),所以 never 失手这一栏对 HTML 是噪声,别当退步。板书要放在提示词最前,放中间 haiku 会当成系统说明、回「我还没看到板书」。换 sonnet 结论不变,费用约 3 倍、每拍慢 1 秒。

结论(2026-09-14 拍板,同日晚改):**出厂缺省换成 HTML 方言(混合 b)**——`themes/default/post.md` 与代码里的兜底都是 `POST_TEMPLATE_HTML`,JSON 骨架留作 `POST_TEMPLATE_JSON`(2026-09-17 连同 JSON 方言一起删了)。换的理由:孩子看得见的两样,拍收到(16/16)与底色(8/8),都是各版本里最好的,p95 6.4 秒也最好;never 失手不进门槛(见上段)。门槛没等到「样本过 40 拍」,先换、边跑边收样本,掉了就把 post.md 换回 JSON 骨架,一行的事。要再推进 HTML,下一步不是改 CSS 类名,是把「已画的标注」从卡上拿掉、改成文字列表(和 JSON 一样),并把输出的 `<c>` 例子从「形状」改成一个真例子。JSON 方言这边更值得做的是同一个思路的便宜版:`{cards}` 给老师原文的 markdown 而不是压成一行,marks 去掉 `line` 下标、靠 said / 词本身找句——两个「指错」都在结构上消失,不改模型看到的样子。
