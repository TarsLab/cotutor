# 首页:家长批准的一页卡

> 2026-09-17 起;2026-09-18 第一期(老师卡与发布)落地,鼓励、再看看、课程表、这一周的卡(第二、三期)还没做,本文里写它们的段落是设计。孩子端首页从「应用按规则算」改成「家长和 LLM 商量、家长批准后发布」。拍板在文末;本文给文件形状、卡种、接口、技能正文、测试与分期。材料:`src/server/app.ts` `kidHome`、`src/server/kid-page.ts` 首页与话题、`src/server/runner.ts` `send`、`src/cards/`、`src/cli/skills.ts`。
> **词**:「首页」= 孩子端打开的第一页,代码里叫 home。「入口文件」仍是 vault 里 `cotutor: subject` 的那篇(《obsidian仓库设计.md》),两者无关。

结论先行:workspace 多一个 `home/`,家长在 Claude Code 里用技能 `cotutor-home` 写 `home/draft.md`(板书同一套围栏语法 + 五种首页卡),`cotutor home publish` 校验后生成 `home/published.json`,孩子端首页只读它。每位老师一张**老师卡**,卡上的按钮决定进老师页之后是新话题、接着哪个话题、还是带着家长备好的讲法开场;老师页不再自己猜话题。

## 一、流程

```
孩子学完
 └ 家长在 workspace 根开 Claude Code:「总结一下今天,排明天的首页」(技能 cotutor-home)
    1 看今天:读当天对话 + cotutor home show(上次首页被点了什么)→ 对话里给总结
    2 记账(可跳过,花钱先问):cotutor rate → cotutor bookkeep → 日记是总结的真相
    3 商量下次:对话里列提案,家长改到点头
    4 写 home/draft.md → cotutor home check → 家长端「首页」页预览
    5 家长明说「发布」→ cotutor home publish → home/published.json
孩子打开 /
 └ 首页 = published.json(没有就是缺省首页)→ 点老师卡上的按钮 → 老师页(意图明确)
    └ 这条消息记下 via(哪份首页、哪个按钮)→ 下次第 1 步能看到
```

## 二、workspace 里的文件

```
home/
  draft.md                  草稿:技能写、家长可手改;孩子端与服务都不读
  published.json            已发布:publish 生成,孩子端只读它(机器件,不手改)
  history/<id>.md           每次发布的原文(id = 发布时刻 YYYY-MM-DD-HHMM)
  audio/<hash>.mp3          鼓励卡的配音(hash = 音色 + 文本;同文本复用;可重建)
```

- `home/` 由 publish 建,**不进骨架**(骨架缺目录 doctor 判必需项不过,老 workspace 不该为一个可选功能补 init);技能写草稿时自己建。
- `.gitignore` 在第二期(鼓励卡配音)加 `home/audio/`;draft、published、history 进 git(一年后翻「那阵子推荐过什么」的只有它们)。
- 为什么在 workspace 不在 vault:首页是运行件(围栏语法、话题 id、卡 id),过不了「一年后还想翻」那一问;值得留的「为什么这么排」在记账时进日记。

`published.json`(形状真相在 `src/schema/home.ts`):

```jsonc
{
  "id": "2026-09-17-2130",
  "publishedAt": "2026-09-17T21:30:05.123Z",
  "for": "2026-09-18",                          // 草稿 frontmatter 带的;没写就没有
  "source": "home/history/2026-09-17-2130.md",
  "cards": [                                    // 解析后的卡,文件顺序;讲法(brief)留在这里,下发孩子前剥
    { "kind": "tutor", "props": { "tutor": "chinese-tutor", "buttons": [ { "kind": "start", "label": "我要预习小蝌蚪找妈妈", "brief": "第 22 课…" } ] } },
    { "kind": "cheer", "props": { "tutor": "chinese-tutor", "text": "…" } }

  "note": "## 为什么这么排\n…",                  // 家长段,孩子看不到
  "warnings": ["…"]                             // 发布时的提醒(家长端「首页」页显示)
}
```

## 三、首页文件的写法

### 3.1 规则(和板书同一个解析器)

- **frontmatter**(可选):只认 `for: YYYY-MM-DD`(给哪天用的);别的键报提醒。
- **围栏 = 卡**:标签第一个词是种类,其余是修饰;正文规则按种类。
- **第一个 H2 起是家长段**(`## 为什么这么排`),存进 `note`,孩子看不到。
- 普通行:首页不念讲稿,**不显示**,check 报提醒(「写进卡里,或挪到家长段」)。

### 3.2 能用哪些卡

| 卡 | 哪里能用 | 首页上是什么 |
|---|---|---|
| `tutor` 老师卡 | 只首页 | 一位老师 + 几个按钮,点了进这位老师 |
| `cheer` 鼓励 | 只首页 | 一句话,点了用某位老师的声音念 |
| `again` 再看看 | 只首页 | 以前板书上的某张卡,原样再摆出来 |
| `timetable` 课程表 | 只首页 | vault 课程表的今天(或一周) |
| `week` 这一周 | 只首页 | 本周七天一条,几件给孩子看的事 |
| `text` `image` `tianzige` `read` | 板书与首页 | 同板书(标题、一张图、写几个字、点读一段) |
| `choice` `fill` `canvas` `scene` `code` | 只板书 | 首页写了 = 要改(它们要交给某位老师,首页没有老师;想放就用 `again` 指过去) |

注册表加一个字段区分:`CardKind.where?: ('board' | 'home')[]`,缺省 `['board']`;`parseCard(tag, body, place)` 遇到不属于这里的种类,板书里退文字卡 + 提醒(老师写了首页卡),首页里记要改。`cotutor-board` 技能只列 `where` 含 board 的,`cotutor-home` 技能列首页能用的。

### 3.3 老师卡 `tutor`

````markdown
```tutor chinese-tutor
我要预习小蝌蚪找妈妈
讲法: 第 22 课。先带他把 1–3 自然段读顺,重点字 塘、脑、袋;读完问他小蝌蚪先遇到了谁
接着 2026-09-16 1930-1 接着写看图写话
讲法: 上次第二句卡住了,先把他写的两句念给他听再往下
```
````

- 标签修饰 = 老师的键(cotutor.json 里的,`-tutor` 结尾)。
- 正文一行一个按钮,孩子看到的字就是这一行(≤ 16 字,孩子的口吻):
  - `接着 <日期> <话题> <字>`:接着那天的那个话题(话题 id = 那个话题第一条的 job)。指向家长交给孩子的备课话题时(2026-09-24,《备课设计.md》§4),孩子端按钮带 `open`:只打开、不发字,从这节课第一张卡播;这行是家长端「交给孩子」追加进草稿的。
  - 其余的行:开场按钮。
  - `新话题` 不用写(应用永远放第一个;写了也只算一个)。
- `讲法:` 行挂在上一个按钮下面,写给老师的(从哪开始、重点、讲到哪收);可多行,拼成一段;**下发孩子前剥掉**(`strip`),孩子端 JSON 里没有。
- 最多 4 个按钮(不算新话题);多了、字超了、`讲法:` 前面没按钮、`接着` 的日期或话题 id 格式不对 → 这张卡没解析成(要改)。

props:

```ts
{ tutor: string; buttons: ({ kind: 'start'; label: string; brief?: string } | { kind: 'continue'; label: string; date: string; thread: string; brief?: string })[] }
```

### 3.4 鼓励 `cheer`

````markdown
```cheer chinese-tutor
昨天那道题,你自己倒着数回去检查了一遍。
```
````

- 修饰 = 用哪位老师的声音;正文一句 ≤ 40 字。
- 只说过程与努力、具体到一件事。正文里有结果评判的词(真棒、聪明、厉害、第一、满分、最…、比…强)→ 提醒,不拦。
- `assets`:publish 时用那位老师的 voice 合成到 `home/audio/<hash>.mp3`;没配音色或合成失败 → 孩子端用浏览器的声(和点读卡同一个兜底)。

### 3.5 再看看 `again`

````markdown
```again chinese-tutor 2026-09-16 1930-2/1
再写一遍这三个字
```
````

- 修饰 = 老师、日期、卡 id(`<job>/<n>`,n 从 0 起,和上下文包的 `focus.card`、`cards:` 同一种写法;`cotutor show` 改成每张卡前打出这个 id)。
- 正文可省:一句给孩子的话(≤ 16 字),显示在卡的上方。
- **引用不拷贝**:孩子端每次请求时去那天的索引取那张卡,剥答案、并上孩子当时的状态与点读配音;源没了、那轮出错了、老师关了 → 这张卡不出现。
- 点了:田字格点字就写、点读点段就念(在首页原地);其余种类 → 打开那位老师页的那个话题(今天的照常能聊,以前的只读),不自动播,滚到那张卡。

### 3.6 课程表 `timetable`、这一周 `week`

````markdown
```timetable
```

```week
三 听写第 21 课
五 数学小测
六 去图书馆还书
```
````

- `timetable`:正文空;修饰 `today`(缺省)或 `week`。数据现读 vault 课程表(`parseTimetable`,和现在首页侧栏同一份);没有课程表 → 卡不出现(check 提醒)。
- `week`:一行一件,行头是星期(`一`…`日`,也认 `周三` `星期三`),每件 ≤ 12 字,一天最多 2 件。哪一周 = `for` 所在的 ISO 周(没写就是发布那天的);孩子端今天不在那一周 → 卡不出现。字是写给孩子的,**不抄计划原文**(计划是写给老师的)。

## 为什么这么排

- 语文:16 号小蝌蚪只读到第 1 段;看图写话第二句卡住,日记观察「句子接不上时会停很久」。
- 数学:近两周观察里两次跨十停顿,计划里写了周五小测。
- 英语老师今天没有要接的,只留新话题。

## 四、应用保证的几件事(不靠 LLM)

1. **每位老师都有卡**:cotutor.json 里 enabled、不 hidden、键以 `-tutor` 结尾的每一位。文件里没写的,补一张只有「新话题」的,排在写了的后面(按 cotutor.json 的顺序)。文件里写了但现在不在、关了、藏了的 → 丢掉。同一位老师写两张 → 只认第一张(check 要改)。
2. **老师卡永远在最上面**:按文件里的先后;其余卡按文件顺序排在下面。
3. **按钮顺序**:`新话题` 第一;今天和这位老师聊过的,第二个是应用加的「接着刚才的」(孩子端最后一条所在的话题,字 = 那个话题第一句孩子的话,截到 10 字;文件里已经有接着这个话题的按钮就不加);然后是文件里的。
4. **条数用完 / 服务不通**:老师卡整张变灰,按钮点不了(和现在的头像一样)。
5. **没发布过、published.json 坏了**:缺省首页 = 第 1、3 条的老师卡(刚装好就是每位老师一张只有「新话题」的卡,别的什么都没有)。首页永远能开,孩子端不报错。
6. **旧首页照常显示**:`for` 早于今天不影响孩子端;家长端「首页」页挂「N 天前发布的」,doctor 超过 3 天提醒。
7. **引用坏了就不出现**:`again` 的卡、`接着` 的话题在请求时找不到 → 这张卡 / 这个按钮不出现。

## 五、孩子端

### 5.1 首页长什么样

- 顶上标题(cotutor.json 的 `title`);整页单列居中(平板最宽 1040),没有侧栏。
- **老师区**:每位老师一张大卡,头像 + 显示名 + 竖排的按钮(胶囊,左侧小图标:✨ 新话题、↻ 接着、▶ 开场)。平板横屏一行 2–3 张,手机一张一行。
- **卡区**:其余卡按顺序铺,平板两栏、手机一栏;复用板书卡的样式与主题底色(`tintFor` 机械规则,首页不走板书后期)。鼓励卡大字 + 喇叭;再看看卡上方一行小字「再看看 · 语文老师 · 9月16日」+ 说明句,下面是原卡的紧凑态。
- 拿掉:mock 里的「今天可以问」(`suggestions`)、「今天的产物」叠(`stacks`,只列了课包 id、点不了;要看画图作业用 `again` 指到那张场景卡)、右边的「今天」栏(课程表时段 + 一周小路;2026-09-18 拿掉,见拍板记录——没写课程表时它只是一个空圈,第三期的 `timetable` / `week` 卡更灵活)。`/api/kid/home` 也不再给 `timetable` / `slot` / `day`(上下文包的 `slot` 是 runner 自己读课程表算的,不受影响)。

### 5.2 点按钮之后

| 按钮 | 老师页 | 发什么 | 服务端 |
|---|---|---|---|
| 新话题 | 空白「想问什么?」 | 孩子第一句带 `newThread` + `via` | 新话题;记 via |
| 接着刚才的 | 今天那个话题,照旧铺开、不重播 | 孩子下一句带 `thread` + `via` | resume;记 via |
| 开场(文件里的) | 空白 → **立刻把按钮上的字发出去** | `text` = 按钮字、`newThread`、`via` | 从 published.json 查讲法 → 上下文包 `home:`;记 via;计每日条数 |
| 接着(今天的话题) | 那个话题 → 立刻发按钮字 | `thread` + `via` | resume;有讲法就带 `home:` |
| 接着(以前的话题) | 空白,头部写「接着 9月16日」→ 立刻发按钮字 | `newThread` + `via` | 新话题;上下文包 `continue:`(+ `home:`);消息记 `continues` |

`via` 只带 id:`{ home: <首页 id> | null, button: <下标> | 'new' | 'recent' }`,卡由老师定(一位老师一张)。**讲法永远从服务端的 published.json 取**,不经过孩子设备。via 对不上(首页 id 不是当前发布的、下标越界)→ 400,孩子端照「不通」处理(不报错,刷新首页)。

按钮字不是孩子说的:日记的「孩子问」(`kidQuestions`)跳过带 via 的开场消息;「以前的」列表里话题的标题照用它(「我要预习小蝌蚪找妈妈」正好是个好标题)。

### 5.3 老师页不再猜话题

原来:今天第一条开新话题(runner 的话题规则),否则老师页接着末条那个话题(kid-page 的 `loadDay`)。

改成:`openTutor(t, intent)`,intent 是 `new`(空白新话题)/ `thread`(今天的某个话题)/ `today`(今天的当前话题,只给调试入口),再带 `via`(下一条消息带上)、`send`(打开就发出去的字)、`cont`(接着的是哪天);第二期加 `view`(再看看点进来的,只看不播)。老师页照 intent 定话题,不再默认接末条话题;调试入口 `?tutor=<名>` = `today`(截图与探针靠它停在已有的板书上,`&new=1` 看空白)。服务端的缺省规则不动(家长端与 `cotutor send` 还在用),孩子端每次发消息都显式带 `newThread` 或 `thread`。头部的「新话题」「以前的」保留。

## 六、老师收到什么

上下文包加两段,只在**带 via 的那条**(话题的第一条,或接着今天话题的那条)出现:

```yaml
cotutor:
  from: kid
  ...
  home:
    button: 我要预习小蝌蚪找妈妈
    brief: "第 22 课。先带他把 1–3 自然段读顺,重点字 塘、脑、袋;读完问他小蝌蚪先遇到了谁"
  continue:
    from: 2026-09-16 1930-1
    title: 看图写话                     # 记过账 = 日记里的话题名;没记 = 那个话题孩子的第一句
    said:                               # 那个话题最后一节的讲稿,最多 6 句
      - "…"
    cards:                              # 那一节的卡,一张一句(describeCard,含孩子做的与答案)
      - "1930-2/0 canvas「把第二句画出来」 画了 12 笔"
    index: /Users/…/conversations/chinese-tutor/2026-09-16.json
---
我要预习小蝌蚪找妈妈
```

- `ContextPackSchema` 加 `home?: { button, brief? }`、`continue?: { from, title?, said, cards, index }`;`renderContextPack` 放在 `cards:` 前面。
- 三位出厂老师的正文加一行(「先看上下文包」那段末尾):「有 `home:` 就是孩子从首页的按钮进来的:`brief` 是家长和你事先商量好的讲法,照着开场,别念出来;有 `continue:` 就是接着以前的话题,先用一两句接上上次停的地方,要更多自己 Read `index`。」出厂件改了,`upgrade` 对没改过的直接换,改过的报 diff。
- `cotutor-vault` 技能(机器件)的「上下文包各行」加这两段的说明。
- 消息 schema 加 `via?: { home: string | null, button: number | 'new' | 'recent', label: string }`、`continues?: { date, thread }`;家长端对话页那条消息头上挂「首页 · 我要预习…」,「看原文」上下文包站自然能看到 brief。

## 七、检查、预览、发布

### 7.1 命令

```
cotutor home check [--published] [--json]          检查草稿(或已发布的那份):逐张卡说孩子会看到什么、每条问题带修法;不花钱
cotutor home publish [--force] [--from <文件>] [--json]   检查 → 留历史 → 写 published.json → 给鼓励卡配音;有「要改」的拒绝(--force 丢掉那几张照发)
cotutor home show [--json]                         现在发布的是哪份、几天前、每个按钮被点了几次(哪天、哪个话题)
```

`home show` 的点击统计:扫发布那天起每位老师的索引,`via.home === id` 的消息按按钮聚合;缺省首页(`home: null`)的新话题 / 接着刚才的也数。

`cotutor show` 顺带改一处:卡那一行每张前面打 id(`1930-2/0 text 认边 | 1930-2/1 tianzige 塘脑袋`),技能写 `again` 时照抄。`--force` 的值可省(`upgrade --force <老师>` 照旧)。

回放(`cotutor replay`)一轮带 via 的消息:讲法按 `via.home` 从 `home/history/<id>.md` 取,`continue:` 段从原 workspace 读,和原轮一样。

### 7.2 check 的两级

| 级 | 情况 |
|---|---|
| **要改**(publish 拒绝) | 卡没解析成;只板书的卡写在首页;老师卡 / 鼓励卡的老师不在、关着、藏着、不是 `-tutor`;同一位老师两张老师卡;`接着` 的话题在那天的索引里找不到;`again` 的索引 / 那轮 / 第 n 张找不到,或那轮出错 |
| **提醒**(照发) | 有老师没写卡(会补「新话题」);普通行不显示;鼓励里有评判词;`for` 早于今天;鼓励的老师没配音色;`week` 的一周已经过去;没有课程表(`timetable` 不显示);没有家长段;frontmatter 有不认识的键 |

每条带行号与修法,和 `parsePlan` 一个风格。

### 7.3 家长端「首页」页

顶栏第五个标签(对话 / 老师团 / 音色 / 设置 / **首页**):

- 左:预览,`草稿 | 已发布` 与 `手机 | 平板` 两个切换;里面是 iframe `/dev/home-preview?which=draft&device=phone`——**就是孩子端页面本身**,带预览标记:数据走 `/api/home?which=…`(家长接口,讲法在),按钮不真发,点了弹一行「会发给语文老师:我要预习小蝌蚪找妈妈 · 讲法:…」。渲染和孩子端一份代码,不会漂。
- 右:check 结果(要改红、提醒灰)、家长段、每位老师的按钮与讲法明细、「发布」按钮(有要改时灰掉,勾「丢掉这几张照发」才亮,= `--force`);下面是已发布的那份:id、几天前、点击统计(= `home show`)。
- 接口:`GET /api/home`(草稿的检查、卡、家长段;已发布那份的 id、几天前、提醒、现在坏着的引用;点击统计;老师显示名)、`GET /api/home/preview?which=draft|published`(孩子端首页的形状,讲法留着)、`POST /api/home/publish`(`{force?, from?}`,from 只认历史 id;和 CLI 同一个函数,有要改的回 409)。

draft 不经过孩子端的任何接口;预览页只挂在工作台 `/dev` 下(2026-09-22 之前是 `/parent`;那条路现在是家长端)。

# 排首页

你在一个 cotutor workspace 的根目录(有 cotutor.json)。孩子端打开就是首页:每位老师一张卡,卡上几个按钮,点了就进那位老师;下面是鼓励、再看看、课程表、这一周。首页由你和家长商量,**家长批准后发布**,孩子只看得到发布的那份。

## 铁律

- **发布要家长在这次对话里明说**(「发吧」「可以发布」)。草稿随便改;cotutor home publish 只在明说之后跑。
- 不写 vault:总结的真相是日记,由记账落盘(第二步)。不改 conversations/、ledger/、cotutor.json、老师文件;home/published.json 与 home/history/ 是机器件,不手改。
- 孩子看得到的字(按钮、鼓励、再看看的说明、这一周)不评判:不写对错、分数、名次、「真棒」「聪明」「最…」;鼓励只说过程和努力,具体到一件事。
- .claude/agents/ 里的老师是给 cotutor 起 claude -p 用的,不要当子代理派,也不要替老师回答孩子。

## 一、看今天

1. cotutor home show:现在发布的是哪份、每个按钮被点了几次——先知道上次推荐的,孩子选了什么。
2. 有脸的老师(cotutor.json 里键以 -tutor 结尾、enabled、不 hidden)逐位读 conversations/<老师>/<今天>.json:话题(thread)、孩子的话(from: kid,带 via 的是按钮字不是孩子说的)、每轮的 kidText 与 section.cards、parentText(老师写给家长的)、remembered。细看一轮用 cotutor show <老师> <job>,卡的 id(<job>/<n>)在那里。
3. 孩子在卡上做的:conversations/<老师>/<日期>.<job>.cards/<n>.json。

总结在对话里说,不落文件:每位老师两三行——学了什么、停在哪、哪里卡住(引孩子的原话或卡上做的)。

## 二、记账

要留下来的走记账:家长给值得记的话题打星(cotutor rate <老师> <话题> <1-5>,到 vault.keepScore 摘要才进日记),再 cotutor bookkeep <老师>。记账每个话题起老师一轮,**花钱,先问**;家长说不记就跳过。记完读当天日记核对一眼(日记在哪见 cotutor-vault 技能)。

## 三、商量下次

先在对话里列提案,不写文件。材料:今天停在哪、日记最近的「- 观察:」、本周计划里各位老师那段、课程表、这科这学期的入口文件与教材(下一课是什么)、上次首页被点了什么。

老师卡(每位老师一张,不写应用也会补一张只有「新话题」的):
- 按钮最多 4 个,「新话题」应用自己加,不写。孩子看的字 ≤ 16 字,孩子的口吻:「我要预习小蝌蚪找妈妈」「接着写看图写话」「再练两道退位减法」。
- 每个按钮下一行「讲法:」,写给老师:从哪开始、重点是什么、讲到哪收。孩子看不到。
- 「接着」要指到那一天的那个话题(日期 + 话题 id);老师会拿到那个话题最后一节的讲稿与卡。
- 没什么要推荐的老师,不写按钮。

其余的卡按需,不必每种都有:
- 鼓励(cheer):一两张,说今天孩子自己做到的一件事,选哪位老师的声音。
- 再看看(again):指到以前板书上的某张卡(<老师> <日期> <job>/<n>),挑孩子卡住的、做了一半的、家长点名的;下一行可写给孩子的一句。
- 这一周(week):给孩子看的几件事(听写、小测、还书),不抄计划原文——计划是写给老师的。
- 课程表(timetable):有课程表就放一张。

每条提案带一句「为什么」;家长改、删、加,直到点头。

## 四、写草稿、检查、预览

1. 家长点头后写 home/draft.md(整份覆盖;写法见 references/首页语法.md,每种卡的细则在 references/<卡>.md)。最后写「## 为什么这么排」,把第三步每条的「为什么」放进去——给家长的,孩子看不到。
2. cotutor home check。「要改」的改到没有;「提醒」的跟家长说一声。
3. 服务开着就请家长打开工作台「首页」页(/dev#home)看预览,手机、平板两种尺寸;预览里点按钮不会真发,会显示发给谁、讲法是什么。
4. 家长要改就改草稿,再 check。

## 五、发布

家长明说之后:cotutor home publish。它再检查一遍、留历史、给鼓励卡配音,打印发布的 id;孩子端刷新就是新首页,不用重起服务。发完告诉家长:发了哪几张卡、哪几条提醒还在。

回到以前的某份:cotutor home publish --from home/history/<id>.md(同样先问)。

## 报告怎么写

总结先行(每位老师两三行),再是下次的提案(按卡列,带为什么),最后是做了什么:记没记账、花了多少、草稿写没写、check 结果、发没发布。
~~~~
