# 首页:家长批准的一页卡

> 2026-09-17 起。老师卡与发布已落地;鼓励、再看看、课程表、这一周的卡(第二、三期)没做,写它们的段落(原 §3.4–3.6、§十一与各处带到的几句)移出本文,原文在 git 历史 b3d4904。孩子端首页由家长和 LLM 商量、家长批准后发布。拍板在文末;本文给文件形状、卡种、接口。材料:`src/server/app.ts` `kidHome`、`src/server/kid-page.ts` 首页与话题、`src/server/runner.ts` `send`、`src/cards/`、`src/cli/skills.ts`。
> **词**:「首页」= 孩子端打开的第一页,代码里叫 home。「入口文件」仍是 vault 里 `cotutor: subject` 的那篇(《obsidian仓库设计.md》),两者无关。

结论先行:workspace 多一个 `home/`,家长在 Claude Code 里用技能 `cotutor-home` 写 `home/draft.md`(板书同一套围栏语法:老师卡 + 几种板书卡),`cotutor home publish` 校验后生成 `home/published.json`,孩子端首页只读它。每位老师一张**老师卡**,卡上的按钮决定进老师页之后是新话题、接着哪个话题、还是带着家长备好的讲法开场;老师页不再自己猜话题。

## 一、流程

```
孩子学完
 └ 家长在 workspace 根开 Claude Code:「总结一下今天,排明天的首页」(技能 cotutor-home)
    1 看今天:读当天对话 + cotutor home show(上次首页被点了什么)→ 对话里给总结
    2 记账(可跳过,花钱先问):cotutor rate → cotutor bookkeep → 日记是总结的真相
    3 商量下次:对话里列提案,家长改到点头
    4 写 home/draft.md → cotutor home check
    5 家长明说「发布」→ cotutor home publish → home/published.json
孩子打开 /
 └ 首页 = published.json(没有就是缺省首页)→ 点老师卡上的按钮 → 老师页(意图明确)
    └ 这条消息记下 via(哪份首页、哪个按钮)→ 下次第 1 步能看到
```

## 二、workspace 里的文件

```
home/
  draft.md                  草稿:技能写、家长可手改;孩子端与服务都不读
  published.json            已发布:publish 生成,孩子端只读它(机器件,不手改)
  history/<id>.md           每次发布的原文(id = 发布时刻 YYYY-MM-DD-HHMM)
```

- `home/` 由 publish 建,**不进骨架**(骨架缺目录 doctor 判必需项不过,老 workspace 不该为一个可选功能补 init);技能写草稿时自己建。
- draft、published、history 进 git(一年后翻「那阵子推荐过什么」的只有它们)。
- 为什么在 workspace 不在 vault:首页是运行件(围栏语法、话题 id、卡 id),过不了「一年后还想翻」那一问;值得留的「为什么这么排」在记账时进日记。

`published.json`(形状真相在 `src/schema/home.ts`):

```jsonc
{
  "id": "2026-09-17-2130",
  "publishedAt": "2026-09-17T21:30:05.123Z",
  "for": "2026-09-18",                          // 草稿 frontmatter 带的;没写就没有
  "source": "home/history/2026-09-17-2130.md",
  "cards": [                                    // 解析后的卡,文件顺序;讲法(brief)留在这里,下发孩子前剥

  "warnings": ["…"]                             // 发布时的提醒

```

## 三、首页文件的写法

### 3.1 规则(和板书同一个解析器)

- **frontmatter**(可选):只认 `for: YYYY-MM-DD`(给哪天用的);别的键报提醒。
- **围栏 = 卡**:标签第一个词是种类,其余是修饰;正文规则按种类。
- **第一个 H2 起是家长段**(`## 为什么这么排`),存进 `note`,孩子看不到。
- 普通行:首页不念讲稿,**不显示**,check 报提醒(「写进卡里,或挪到家长段」)。

### 3.2 能用哪些卡

| 卡 | 哪里能用 | 首页上是什么 |
|---|---|---|
| `tutor` 老师卡 | 只首页 | 一位老师 + 几个按钮,点了进这位老师 |
| `text` `image` `tianzige` `read` `word` | 板书与首页 | 同板书(标题、一张图、写几个字、点读一段、一个单词) |
| 其余板书卡(`choice` `fill` `canvas` `code` `lecture` `record`) | 只板书 | 首页写了 = 要改(它们要交给某位老师,首页没有老师) |

注册表加一个字段区分:`CardKind.where?: ('board' | 'home')[]`,缺省 `['board']`;`parseCard(tag, body, place)` 遇到不属于这里的种类,板书里退文字卡 + 提醒(老师写了首页卡),首页里记要改。`cotutor-board` 技能只列 `where` 含 board 的,`cotutor-home` 技能列首页能用的。

### 3.3 老师卡 `tutor`

````markdown
```tutor chinese-tutor
我要预习小蝌蚪找妈妈
讲法: 第 22 课。先带他把 1–3 自然段读顺,重点字 塘、脑、袋;读完问他小蝌蚪先遇到了谁
接着 2026-09-16 1930-1 接着写看图写话
讲法: 上次第二句卡住了,先把他写的两句念给他听再往下
```
````

- 标签修饰 = 老师的键(cotutor.json 里的,`-tutor` 结尾)。
- 正文一行一个按钮,孩子看到的字就是这一行(≤ 16 字,孩子的口吻):
  - `接着 <日期> <话题> <字>`:接着那天的那个话题(话题 id = 那个话题第一条的 job)。
  - `小课堂 <课包或视频的 id> <字>`:先铺满看这一课,看完才能开口(《小课堂设计.md》)。
  - 其余的行:开场按钮。
  - `新话题` 不用写(应用永远放第一个;写了也只算一个)。
- `讲法:` 行挂在上一个按钮下面,写给老师的(从哪开始、重点、讲到哪收);可多行,拼成一段;**下发孩子前剥掉**(`strip`),孩子端 JSON 里没有。
- 最多 4 个按钮(不算新话题);多了、字超了、`讲法:` 前面没按钮、`接着` 的日期或话题 id 格式不对 → 这张卡没解析成(要改)。

props:

```ts
{ tutor: string; buttons: ({ kind: 'start'; label: string; brief?: string } | { kind: 'continue'; label: string; date: string; thread: string; brief?: string } | { kind: 'lecture'; label: string; bundle: string; brief?: string })[] }
```

- 语文:16 号小蝌蚪只读到第 1 段;看图写话第二句卡住,日记观察「句子接不上时会停很久」。
- 数学:近两周观察里两次跨十停顿,计划里写了周五小测。
- 英语老师今天没有要接的,只留新话题。

## 四、应用保证的几件事(不靠 LLM)

1. **每位老师都有卡**:cotutor.json 里 enabled、不 hidden、键以 `-tutor` 结尾的每一位。文件里没写的,补一张只有「新话题」的,排在写了的后面(按 cotutor.json 的顺序)。文件里写了但现在不在、关了、藏了的 → 丢掉。同一位老师写两张 → 只认第一张(check 要改)。
2. **老师卡永远在最上面**:按文件里的先后;其余卡按文件顺序排在下面。
3. **按钮顺序**:`新话题` 第一;今天和这位老师聊过的,第二个是应用加的「接着刚才的」(孩子端最后一条所在的话题,字 = 那个话题第一句孩子的话,截到 10 字;文件里已经有接着这个话题的按钮就不加);然后是文件里的。
4. **条数用完 / 服务不通**:老师卡整张变灰,按钮点不了(和现在的头像一样)。
5. **没发布过、published.json 坏了**:缺省首页 = 第 1、3 条的老师卡(刚装好就是每位老师一张只有「新话题」的卡,别的什么都没有)。首页永远能开,孩子端不报错。
6. **旧首页照常显示**:`for` 早于今天不影响孩子端;doctor 超过 3 天提醒。
7. **引用坏了就不出现**:`接着` 的话题在请求时找不到 → 这个按钮不出现。

## 五、孩子端

### 5.1 首页长什么样

- 顶上标题(cotutor.json 的 `title`);整页单列居中(平板最宽 1040),没有侧栏。
- **老师区**:每位老师一张大卡,头像 + 显示名 + 竖排的按钮(胶囊,左侧小图标:✨ 新话题、↻ 接着、▶ 开场)。平板横屏一行 2–3 张,手机一张一行。
- **卡区**:其余卡按顺序铺,平板两栏、手机一栏;复用板书卡的样式与主题底色(`tintFor` 机械规则)。
- **老师头像 = C 形开口环**(2026-10-09,拍板 15):学科色的一圈在右边断开约 70°、圆头,里面白底圆放图或字;开口朝右,朝着老师说出来的话。首页、老师页左上、空白板、等待卡、字幕、家长端、小课堂播放器左上都是这一个样子。会动的只有开口:

  | 叫法 | 怎么动 | 什么时候 | 在哪 |
  |---|---|---|---|
  | 画出来 | 从右上起笔逆时针一笔写出 C,写完头像冒出来,几位老师错开 0.15 秒 | 打开首页、从老师页回来(5 秒一轮的刷新不画);空白板出来 | 首页老师卡、空白板 |
  | 想 | 慢慢转圈,开口一呼一吸 | 孩子发出去、老师还没回 | 老师页左上、等待卡、字幕 |
  | 说 | 开口一张一合 | 念讲稿(含再听) | 老师页左上 |
  | 听 | 开口转向下面的输入条,一呼一吸 | 孩子按住说话、录音卡在录 | 老师页左上 |
  | 该你了 | 点一下头 | 念着停下来(等孩子答、一节念完) | 老师页左上 |
  | 点一下 | 按着时扭一下,松开弹回 | 手指按在老师卡上 | 首页老师卡 |
  | 休息 | 不动:开口朝下、变灰 | 次数用完、服务不通 | 首页老师卡 |

  同时有几样时:听 > 想 > 说 > 该你了。系统开了「减弱动态效果」就都不动。
- **给老师换样子**(2026-09-30,figshot R6 拍板 4):`cotutor.json` 配了 `figshot: { port }`(缺省 8477)时,老师区下面多一张固定的入口卡「给老师们换个样子」,点了去同一台电脑上的 figshot pick(协议与主机跟着本页,只换端口)。它不是首页发布的卡,家长的草稿里不写它;页面先用 `no-cors` 探 figshot 的 `/api/health`,连不上就不出现——孩子不该点进 Safari 的「无法连接」。

### 5.2 点按钮之后

| 按钮 | 老师页 | 发什么 | 服务端 |
|---|---|---|---|
| 新话题 | 空白「想问什么?」 | 孩子第一句带 `newThread` + `via` | 新话题;记 via |
| 接着刚才的 | 今天那个话题,照旧铺开、不重播 | 孩子下一句带 `thread` + `via` | resume;记 via |
| 开场(文件里的) | 空白 → **立刻把按钮上的字发出去** | `text` = 按钮字、`newThread`、`via` | 从 published.json 查讲法 → 上下文包 `home:`;记 via;计每日条数 |
| 接着(今天的话题) | 那个话题 → 立刻发按钮字 | `thread` + `via` | resume;有讲法就带 `home:` |
| 接着(以前的话题) | 空白,头部写「接着 9月16日」→ 立刻发按钮字 | `newThread` + `via` | 新话题;上下文包 `continue:`(+ `home:`);消息记 `continues` |

`via` 只带 id:`{ home: <首页 id> | null, button: <下标> | 'new' | 'recent' }`,卡由老师定(一位老师一张)。**讲法永远从服务端的 published.json 取**,不经过孩子设备。via 对不上(首页 id 不是当前发布的、下标越界)→ 400,孩子端照「不通」处理(不报错,刷新首页)。

按钮字不是孩子说的:日记的「孩子问」(`kidQuestions`)跳过带 via 的开场消息;「以前的」列表里话题的标题照用它(「我要预习小蝌蚪找妈妈」正好是个好标题)。

### 5.3 老师页不再猜话题

`openTutor(t, intent)`,intent 是 `new`(空白新话题)/ `thread`(今天的某个话题)/ `today`(今天的当前话题,只给调试入口),再带 `via`(下一条消息带上)、`send`(打开就发出去的字)、`cont`(接着的是哪天)。老师页照 intent 定话题,不再默认接末条话题;调试入口 `?tutor=<名>` = `today`(截图与探针靠它停在已有的板书上,`&new=1` 看空白)。服务端的缺省规则不动(工作台与 `cotutor send` 还在用),孩子端每次发消息都显式带 `newThread` 或 `thread`。头部的「新话题」「以前的」保留。

## 六、老师收到什么

上下文包加两段,只在**带 via 的那条**(话题的第一条,或接着今天话题的那条)出现:

```yaml
cotutor:
  at: 2026-09-17T16:20
  ...
  home:
    button: 我要预习小蝌蚪找妈妈
    brief: "第 22 课。先带他把 1–3 自然段读顺,重点字 塘、脑、袋;读完问他小蝌蚪先遇到了谁"
  continue:
    from: 2026-09-16 1930-1
    title: 看图写话                     # 记过账 = 日记里的话题名;没记 = 那个话题孩子的第一句
    said:                               # 那个话题最后一节的讲稿,最多 6 句
      - "…"
    cards:                              # 那一节的卡,一张一句(describeCard,含孩子做的与答案)
      - "1930-2/0 canvas「把第二句画出来」 画了 12 笔"
    index: /Users/…/conversations/chinese-tutor/2026-09-16.json
---
我要预习小蝌蚪找妈妈
```

- `ContextPackSchema` 加 `home?: { button, brief? }`、`continue?: { from, title?, said, cards, index }`;`renderContextPack` 放在 `cards:` 前面。
- 老师怎么用这两段,写在守则里(`skills/cotutor-tutor/SKILL.md` 与 `references/上下文包.md`)。
- 消息 schema 加 `via?: { home: string | null, button: number | 'new' | 'recent', label: string }`、`continues?: { date, thread }`;工作台对话页那条消息头上挂「首页 · 我要预习…」,「看原文」上下文包站自然能看到 brief。

## 七、检查、预览、发布

### 7.1 命令

```
cotutor home check [--published] [--json]          检查草稿(或已发布的那份):逐张卡说孩子会看到什么、每条问题带修法;不花钱
cotutor home publish [--force] [--from <文件>] [--json]   检查 → 留历史 → 写 published.json;有「要改」的拒绝(--force 丢掉那几张照发)
cotutor home show [--json]                         现在发布的是哪份、几天前、每个按钮被点了几次(哪天、哪个话题)
```

`home show` 的点击统计:扫发布那天起每位老师的索引,`via.home === id` 的消息按按钮聚合;缺省首页(`home: null`)的新话题 / 接着刚才的也数。

`cotutor show` 顺带改一处:卡那一行每张前面打 id(`1930-2/0 text 认边 | 1930-2/1 tianzige 塘脑袋`)。`--force` 的值可省(`upgrade --force <老师>` 照旧)。

回放(`cotutor replay`)一轮带 via 的消息:讲法按 `via.home` 从 `home/history/<id>.md` 取,`continue:` 段从原 workspace 读,和原轮一样。

### 7.2 check 的两级

| 级 | 情况 |
|---|---|
| **要改**(publish 拒绝) | 卡没解析成;只板书的卡写在首页;老师卡的老师不在、关着、藏着、不是 `-tutor`;同一位老师两张老师卡;`接着` 的话题在那天的索引里找不到 |
| **提醒**(照发) | 有老师没写卡(会补「新话题」);普通行不显示;`for` 早于今天;没有家长段;frontmatter 有不认识的键 |

每条带行号与修法,和 `parsePlan` 一个风格。

### 7.3 家长端「首页」页(2026-09-28 退掉)

工作台 `/dev` 只做后台运维与调试、不参与日常使用(拍板 13),这一页没有了。留下的路:`cotutor home check` 看孩子会看到什么,`cotutor home publish` 发,发了在孩子端首页看,`cotutor home show` 看点击。首页草稿要不要进家长端 `/parent` 预览,等真跑有需求再说。
