# 场景契约

场景是纯数据 TS 模块:`import type { ChalkScene, ChalkSkeleton } from 'drawtell'`(运行时被擦除;
drawtell 仓内的场景用相对路径 `'../src/player'`)。确定性约束(append-only、笔顺即步序、
text-overlap 等)由 `drawtell check` 强制——机制在 CLI 仓,本 skill 只写怎么写得对。

## 结构契约

- 场景文件 `scenes/<id>.ts`,id:小写字母数字连字符。**工作区场景的 id 约定 `<YYYY-MM-DD>-<题眼>`**
  (生成日 + 1–2 个拼音词,如 `2026-08-25-wazi`;同日同题眼加 `-2`,写前查一下文件是否已存在)——
  id 是机器引用,人读的是 `title`,日期段管唯一性与排序。工具仓种子(dengche 等)是教学参考,不入此规
- 导出用 `export default`(或任一单个具名导出;loader 不要求导出名等于 id——日期开头的 id 不是合法标识符)
- skeletons 数组顺序 = 笔顺;steps 的 elementIds 按顺序连续覆盖全部元素(笔顺即步序);
  每步至少 1 个元素——"只说不画"的验证步(倒着数回来核对)要挂一条文字才成立
- `pauseAfter` 默认每步 `true`(气口:孩子点一下才继续)
- 单笔时长用 `animateDuration` 字段(毫秒),经验值:主笔画 600–1400,小元素 200–450
- 笔顺里还可以放两种**动作**(和画一笔一样进 steps、占时间,只是不画东西;不用写 x / y):
  `{ type: 'erase', id, targets: [...] }` 擦掉前面画过的几样(经验 800–1400);
  `{ type: 'board', id, background? }` 换一块画板(经验 1200–1800)。类型 `ChalkErase` / `ChalkBoard`,
  check 查:只能擦前面画过、还在这块板上的;第一笔不能是 board(第一块画板的背景图写在场景的 background 上)
- 重复图形写辅助函数(小人、成排圆圈、划掉斜线),坐标尽量用算式不用魔数;辅助函数暂时写在各自文件里
- 场景 TS 从同名说明文件 `scenes/<id>.md` 来(格式在 drawtell-teaching):`steps[].line` **逐字抄**它的讲稿;
  文件头注释写题面、表征、假设与参考的范例

## 给画面上的东西起名字(groups、label)

孩子看课时会停下来圈一处,应用要说出他圈的是什么。不起名字,只能说「第 1 步画的 3 条线」;起了名字,就能说「散的 3 根小棒」。

- 合起来是一样东西的几笔,写一个分组:`groups: [{ id: 'loose', label: '散的 3 根小棒', elementIds: ['s-1', 's-2', 's-3'] }]`
- label 用讲稿里的说法,孩子听到的和老师说的是一个词。
- 一个元素可以在几组里(「一捆 10 根」「13 根小棒」);圈住哪一组的大半,就说哪一组。
- 单独一笔有自己的意思(圈出答案的红圈、划掉的斜线),写在元素上:`label: '圈出剩下的 2 根'`。
- 文字不用起名字,应用说的就是字本身。
- 只是名字,不改画法、不改笔顺;`drawtell check` 查分组的 id 不重、成员都在。

## 试卷式布局(自上而下)

像试卷:**页宽固定(~720),高度随内容长**,说明文件的段落自上而下一段接一段,段间留呼吸(≥24)。
草稿段(图)排布自由;作答段像书写行——左对齐、一行一句、字号一致,放在它对应的草稿段下方。
元素可选打 `customData: { role: 'draft' | 'answer' }`(协议只认领 `layer`,其余透传,零引擎改动)方便 verify 数;
不打不算错,check 不管。
**引擎现状**:播放器按整场包围盒等比缩放、不跟笔滚动——所以高度先控制在一屏内(约 ≤350,两三段);
更长的题拆成多个场景,或等 CLI 仓做完"按宽缩放 + 跟笔滚动"(camera-free 的收窄定义,见 teaching 讲解模板三档)。

## 背景图(在原题照片上圈画)

场景可选 `background: { src, width, height }`:一张图垫在笔迹底下(题目原图、课本照片)。
`src` 相对场景文件,`drawtell build` 把图拷进课包(`background.<ext>`);`width` / `height` 是图片像素。
**有背景图时画板 = 图片**:场景坐标 (0,0)–(width,height) 就是图片像素,圈、下划线直接按像素量;
画到图外的笔迹会被裁掉(check 报 `background-bounds` 警告)。图片上要圈的字贴边时,先给图片补边再量。
荧光笔 = 矩形 `fillStyle: 'solid'` + `opacity: 45`(半透明,底下的字还看得清)。
读题用背景图、做题换白板:做题那段前面放一个 `{ type: 'board', id: 'clean' }`,之后照白板的坐标写
(新板的视口按它上面的东西自己算,不用缩放、不用避开照片的坐标)。下一页还是照片就写 `background`。
每块画板各自查重叠、出界;擦掉以后在同一处写的字不算重叠。

## 布局经验

- 页宽 ~640–760(试卷式取 720)、高 ~250–350(引擎跟笔滚动前);干扰项分行隔离;答案在作答段(下方);
  竖的东西(楼、竖式)把说明文字放右侧把画面拉宽
- 要圈算式里的一个数,把它拆成单独的 text 元素(如 `'27 + 4 ='` 与 `'31'`),间距 ≥22;
  "括号留空后来填"等标准小件的写法见 drawtell-teaching
- 用色是政策不是几何,单一真相在 drawtell-teaching「用色」,同一批课包里保持一致

## 数量与画面(经验值,画面宽约 700–760)

- 被计数的对象一行 ≤18 个用直径 26、列距 40 很舒服(圈还能留边);≤25 个用直径 22、列距 28 勉强;
  干扰项可以更小(16 / 22)到 30 个一行。**超过 20 个且不需要逐个数 → 线段图**。
- 要在一行中间"停圈"(圈住前 k 个),列间空隙 ≥14px,否则圈尖必蹭到第 k+1 个。
- 圈的几何:椭圆要装下一排圆,高度约 ≥3.5× 圆径;圈矩形区域时半轴 = 半边 × √2 + 留边;
  椭圆越长两端越尖,粗略"每多 3 个对象 padX +4"。圈要么完整落在容器里(≥8px),要么完整穿出去(≥8px),别贴边。
  名字/标签与圈顶留 ≥12px。
- 捆怎么画最省元素:不拆的捆 = 竖长矩形 + hachure + 标 10(2 元素);要拆开从里面减的捆 =
  方框 + 10 根可见小棒 + 标 10(12 元素,方框上下留 ≥24 给后面的圈);新捆成的一捆 = 红色矩形框圈 10 根 + 标 10。

## 渲染事实(不算错,先知道)

- `dashed` 短于 ~50px 只剩两段;涂色会盖住同位置先画的线;字幕超 ~38 个汉字折行;
  播放器按整场包围盒定比例,前几步画面偏空是设计使然(试卷式的"按宽缩放"待引擎)
