# 说明文件:scenes/<id>.md

一道题的讲法,写给**不懂 drawtell 的人**看的:家长、别的模型、将来的孩子端都能读、能改。它是阶段 1 的产物、阶段 2 的输入、
verify 的对照物、验收后的范例(最佳实践的单位)。与场景 TS 同名同居:`scenes/<id>.md` ↔ `scenes/<id>.ts`
(`drawtell ls` 只认 `.ts`,不受影响)。

## 粒度:画布词汇那一层

写"画一个红色的圈",不写圈的粗细、时长、坐标。允许出现的词:

- 动作:画布词汇表(添画 / 划掉 / 圈 / 箭头 / 分行 / 虚线 / 涂色)+ 写字
- 对象与数量:"4 个圆""13 个""三个空"
- 颜色角色:主笔迹 / 强调(红)/ 划掉(橙)——不写色值
- 相对位置:一行、下一行、左侧、右侧、下方、对齐、同列

**不写**:px、ms、元素 id、椭圆还是矩形、直径列距——那是阶段 2(drawtell-scene)的决定。说明文件说"圈住全部 13 个",
用椭圆还是矩形由几何决定。

## 两种段落:草稿与作答

贴近孩子真实的做题体验:草稿纸上画图想思路,卷子上写答案。

- **草稿段**:图。灵活、个性化,用图形表达思路——点阵、线段、数轴、小棒、划掉、圈,怎么想就怎么画。
- **作答段**:偏书本里的答案——算式、答、结论文字;需要作图的题(画角、画线段)作图也算作答。像书写行:一行一句。

竖向交替:草稿 → 作答 → 草稿 → 作答……**这是引导,不是分区**:一步可以只有草稿、只有作答,或先草稿后作答;
不强求每步都分、不强求二者数量对等。多数题的形状是"几步草稿 + 最后一段作答"。

## 形状

```markdown
---
id: 2026-08-30-guilv                 # = 场景 id
tags: [册子/人教数学一下/4, 题型/交错数列分行, 孩子/Ray]   # 知识点(册子/<册>/<节>)必备;题型、孩子可选
表征: 交错数列分行                    # = models/<名>.md;库里没有合适的写 ★新,并在步里写清自己的画法
template: paper-strict
范例: 2026-08-25-xxx                  # 参考过的已验收说明文件(可省)
假设: []                              # 缺图 / 看不清处的假设,一行一条
---
## 题面
53、50、47、__、__、__

## 步 1
- 讲稿:先把这串数抄下来:53、50、47,后面三个空要我们填。
- 草稿:一行抄数列,三个空画短横线
- 检验:数列 3 个数 + 3 条横线

## 步 2
- 讲稿:从 53 到 50 少了 3,从 50 到 47 又少了 3——每次都少 3!
- 草稿:相邻两数之间连弧形箭头,箭头上标「−3」,主笔迹
- 检验:2 个箭头,标注 −3

## 步 3
- 讲稿:47 再少 3 是几?减 3 等于 44,填进第一个空。
- 草稿:第一个空上方写 44(强调红)
- 检验:第一个空填 44

## 步 4
- 讲稿:44 再少 3,等于 41,填进第二个空。
- 草稿:第二个空上方写 41(强调红)
- 检验:第二个空填 41

## 步 5
- 讲稿:41 再少 3,等于 38,填进第三个空。
- 草稿:第三个空上方写 38(强调红)
- 检验:第三个空填 38

## 步 6
- 讲稿:圈出三个答案。倒着检查:38 加 3 是 41,加 3 是 44,再加 3 正好回到 47!
- 草稿:圈出三个答案(强调红)
- 作答:44、41、38
- 检验:3 个圈;倒推心算成立
```

每步:**讲稿**(一句,孩子听到的全部;≤ 38 字为宜)必有;**草稿** / **作答** 至少一栏;**检验**(这一步画完该数出什么:数量、位置、心算)必有。

## 讲稿行是两个文件的 join key

TS 的 `steps[].line` 与说明文件的讲稿**逐字一致**(dub 按行 hash 音频,改一句只重合成一句)。改讲法先改说明文件,再改 TS;
试跑期靠这条纪律,稳定后 `drawtell check` 会拦。

## 怎么写(阶段 1 该想到的六件事)

按顺序:知识点 → 表征 → 口径 → 历史 → 范例 → 段落。

1. **知识点**(转交单与上下文包的 profile):这题在教什么;孩子已学到哪、哪些工具不能用(没学竖式就别上竖式)。
2. **表征**:先看同知识点的已验收范例与题面,再翻 `models-index.md`;库里有骨架照骨架,
   没有就按画布词汇自己设计,frontmatter `表征: ★新`,给家长看时点明"这是新画法"。**不停下来问,不硬套别的骨架。**
3. **口径**(转交单 why 里的讲法要点、教材那一节的口径):用词、算式写法、忌讳,压倒本 skill 的缺省。
4. **历史**(转交单里孩子刚才的话、上下文包的 recent):上次错在哪、讲过什么,讲稿里点一句,别重复上次的讲法问题。
5. **范例**:结构照抄验收过的那份,只换数字与讲稿——比自由发挥稳。范例层空、拿现成的 `.ts` 当结构参考时,
   **只抄步骤结构与讲稿套路**,代码里的形状与几何(椭圆 / 矩形 / 直径 / 坐标)一个词都不带进说明文件——写回画布词汇「圈住」。
6. **段落**:哪几步草稿、哪一步作答;检验点带数字。

## 给家长看一眼(对话模式)

直接用 drawtell 时,说明文件写完先给家长一条消息:题面一行 + 每步一句讲稿 + 一句"草稿画什么、作答写什么" + "回「好」就画,要改直接说"。
不带坐标、不带文件名以外的机器词。家长改了任何一句 → 改说明文件后**重呈现**,不直接画(修订 ≠ 确认)。
应用无人值守跑(如 cotutor 的 scene-maker)不设这道门:一口气写说明文件 + TS,说明文件照样落盘。

## 验收后

家长验收通过(工作区 `reviews.json` accepted)的说明文件就是**范例**:下次同知识点的题先翻它,取最近 2–3 份。不删旧范例——限的是取用数,不是存量。家长点名"这个讲得好"的排前。
