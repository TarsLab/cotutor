# 检验动画质量

输入:场景 TS 路径(`scenes/<id>.ts`)或已 build 的课包 id;同名说明文件 `scenes/<id>.md`(格式见 drawtell-teaching)若在,
它每步的「检验」行就是对照物。评审者应是**另一个上下文**(子 agent 或独立进程)——生成方自己加载本 skill 自评不算独立检验。工作区与 CLI 调用方式见 drawtell-cli
(同在 drawtell 包的 `skills/` 下)。
评判清单在本 skill `references/评判标准.md`。

## 流程

1. 输入是 `.ts` 时先 `drawtell check <path> --json`;有 error 直接把 findings
   整理成问题清单返回,不必截图(层 2–3 的错误截图也救不了)。

2. `drawtell snap <目标> --no-cursor` → `snaps/<id>/`:`step-<n>.png` + `index.json`。
   `--no-cursor` 不画笔尖,帧里只剩笔迹;不加也行,但要知道笔尖停在本步末笔处,不算画面元素。
   index.json(v2)的 shots[] 已把每张图和该步讲稿配好对,**并列出该步新增元素**
   (`added[]`:id / type / strokeColor / backgroundColor / text / bbox)与画板 `board.viewBox`——
   报问题按 id 说话,数数对着 added 数,越界对着 viewBox 判(bbox 是场景坐标,图像像素 =
   (坐标 − viewBox 原点) × 图宽 / viewBox 宽)。评审按它走,不要自己翻场景源码猜。

3. **逐张评审**(step-0 是空板配题面,从它开始),参考 `references/评判标准.md` 的视角:
   - **检验点**(有说明文件时先做):逐步核它的「检验」行——数量、位置、心算;讲稿行与 TS `line` 逐字一致,不一致直接列问题
   - **对应**:画面是否就是该步讲稿所述,有没有多画、少画、提前画;讲稿里的动作词
     (数、指、连、划、圈)画面有没有对应笔迹;口头计数"1、2……"不要求画面出数字
   - **计数**:圈住的、划掉的、添画的对象逐个数,与讲稿和题目里的数字核对;还要核**位置**
     (涂色的是第几个、圈的是不是第 1、3、5 位)——经验上计数与位置是最常见的错误来源。
     对象多(≥15)时把图局部放大再数,别凭感觉
   - **布局**:文字重叠、越界截断(对着 viewBox)、疏密;圈两端是否擦到相邻对象、被圈对象是否完整在圈内;
     颜色是否用在讲稿强调处;衍生行(数列分行、竖式)与源行是否同列
   - **板书感**:paper-strict 下效果是否纸上可复现;笔顺是否自然(先主体后标注);
     强调笔迹应保留到终帧(纸上画了不会消失)
   - **跨帧一致**:同一场景里"捆/圈/框"只用一种画法、措辞一致;对象状态变了旧标签是留是改;
     分段标注是"每段"还是"累计"要与讲稿口径一致
   - **段落**:作答段像书本答案(算式 / 答 / 结论),与前面草稿段的结论一致——判断项,不拦;草稿段自由,不按此挑毛病

4. **输出报告**:
   - 通过:说明"逐张核对通过",附每步一句话摘要(画了什么、对上哪句讲稿)
   - 有问题:每条尽量给全——**步 n / 元素 id / 期望 vs 实际 / 修复建议**,
     让生成方(agent 或人)拿到就能改
5. 修复后重跑本流程;之后进家长验收。

## 评审经验

- 拿不准就列出来标"存疑",让人裁量,不拦流程
- 说明文件在时先对它的检验点,再看讲稿:它是生成方承诺的清单,比从讲稿反推省事也更准
- 不要只看终帧:中间步的"讲到哪画到哪"才是产品灵魂(图的价值在生成过程,不在成品)
- 教学正确性(这道题该不该这么讲)是家长验收的事;本 skill 聚焦"画得对不对";
  但讲稿或画面有明显数学错误、讲稿与画面口径不一(讲稿"又走了 1 层"画面标"2 层")要指出
- 默认分工是评审与修改分离(发现问题交回生成方);试跑期这个分工本身也可以调
- 定格帧不能看出批内笔顺方向(从右起划还是从左起划);要核对方向就看源码顺序或回放,标明是这样看的
- 第一批真题(2026-08-17,12 题)里检验方抓到生成方自检漏掉的:半截虚线没连到对象、最右侧文字被裁、
  两种"捆"画法并存、新添对象没区别色——这几类都是"逐帧看单张"看不出来、要跨帧/跨元素比对的
