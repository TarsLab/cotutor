# 评判标准

drawtell-verify 的参考清单(随试跑修订;第一批真题 2026-08-17 后补了不少条)。评审对象:`snaps/<id>/` 的
keyframe 序列 + index.json 的图↔讲稿对照与每步新增元素清单;同名说明文件 `scenes/<id>.md` 在时,它每步的「检验」行是首要对照物
(格式见 drawtell-teaching `references/说明文件.md`)。一般先过 `drawtell check`,层 2–3 的问题不必进视觉评审。

## 不算问题(渲染事实,先排除)

- 每张图底部一行是当步讲稿字幕(左侧蓝点是气口提示,终帧有绿勾);字幕折行会让帧高不同
- 未加 `--no-cursor` 时,笔尖图标停在本步末笔处,不是画面元素
- 播放器按整场包围盒等比缩放,前几步画面偏空
- 行首标签、算式、"辅助标注"(如"爸爸吃了 4 个")讲稿未必逐句提到,不算多画;但**内容元素**(被数的对象、圈、划痕)必须与讲稿对应

## 视角(1–4 拦,5 只判断)

### 1. 对应(画面 ↔ 讲稿)

- [ ] 有说明文件:该步「检验」行说的数量 / 位置 / 心算逐条成立;讲稿与 TS `line` 逐字一致
- [ ] 该步新出现的元素(index.json 的 `added[]`),讲稿都提到了或属辅助标注;讲稿提到的动作,画面都发生了
- [ ] 讲稿含动作词(数、指、连、划、圈、搬)的步,画面有对应可见笔迹;口头计数"1、2……"不要求画面出数字记号
- [ ] 没有"提前画"(后面步骤的内容出现在当前帧)——对照上一帧核对新增量
- [ ] step-0 空板只配题面;终帧包含答案文本
- [ ] 算式出现的步 = 讲稿说出该算式的步;算式必须心算一遍

### 2. 计数与位置(有数字就必须数)

- [ ] 添画的对象数量 = 题目/讲稿的数字
- [ ] 圈起来的对象:逐个数圈内元素,核对讲稿("圈出没划掉的"→ 圈内不得含划掉的)
- [ ] 划掉的对象:数划掉记号的数量,且划的是正确的那一批(位置核对);划掉后剩余数 = 下一步讲稿说的剩余数
- [ ] **位置索引**:涂色/标记的是第几个、圈的是不是第 1、3、5…位,与讲稿一致
- [ ] 一一对应类:两行对象逐列对齐(容差 ≤2px 或 ≤ 间距 10%);连线**两头都到**(两端距对象几个笔宽内)
- [ ] 分解式(5 → 3、2)的两个数分别对应画面上"搬走/划掉的"和"剩下的"
- [ ] 数轴刻度与标签一一对应,时刻推算正确;箭尖停在讲稿所说的线/刻度上;分段标注是"每段"还是"累计",与讲稿口径一致
- [ ] 同一行"原有 + 添画"没有可见分界时,列为存疑

### 3. 布局

- [ ] 文字互不重叠、不被图形意外遮盖(刻意圈选除外)、不越出画面——越界按 index.json 的 `board.viewBox` 判,
      不要只看图片边缘(墨迹在边缘被硬裁而背景色延续,肉眼难察觉)
- [ ] 圈选的对象**完整**落在圈内:椭圆两端垂直空间收窄,边缘对象容易穿出;圈两端与相邻对象/相邻标记
      ≥ 半个对象间距、上下 ≥ 对象高的 1/3,低于就列存疑(第一批真题里最常见的返工)
- [ ] 圈与圈、圈与容器不贴边:要么完整在里面(≥8px)要么完整穿出;同色相邻(红圈紧挨红涂色)缩略下会粘连,列存疑
- [ ] 衍生行与源行同列对齐(数列分行、竖式对位)
- [ ] 疏密合理:一行之内等距,行与行有呼吸;留白/重心只作存疑,不拦
- [ ] 颜色与用色政策一致(单一真相在 drawtell-teaching「用色」):主笔迹墨色,红 = 讲稿强调处,
      橙 = 划掉;不出现无来由的颜色;未定政策的(搬移箭头、"新添的"对象)同一场景内保持一致即可
- [ ] 字幕不被裁切、换行合理(数字与量词不拆开)——字幕不是笔迹但是孩子读的内容

### 4. 板书感(paper-strict)

- [ ] 每个效果都能用铅笔在纸上复现(无渐变、无移动残影、无不可解释的图形)
- [ ] 笔顺自然:先主体后标注,先轴后刻度,先物后圈
- [ ] 单帧信息量适合孩子:一步一个新意思,不塞两件事
- [ ] 强调笔迹保留到终帧(纸上画了不会消失)
- [ ] 跨帧一致:同一场景里"捆 / 圈 / 框"只用一种画法、讲稿措辞与画法一致;对象状态变了(拆开、划掉)之后旧标签留不留要说得通

### 5. 段落(草稿 / 作答;判断项,不拦)

- [ ] 作答段像书本答案:算式、答、结论(需要作图的题作图也算),一行一句;与前面草稿段的结论一致
- [ ] 草稿段自由——不按整齐与否挑毛病;只在它与讲稿 / 检验点对不上时才列

## 结论怎么给

- **通过**:各视角没发现问题。报告写"逐张核对通过"+ 每步一句摘要。
- **有问题**:每条尽量给全:步 n / 元素 id(取自 index.json `added[]`)/ 期望 vs 实际 / 修复建议。
- **存疑**:近似判断拿不准的(疏密、美感、同色相邻),列出来标"存疑"交人裁量,不拦流程。

教学正确性(该不该这么讲、用词是否合适)不在本清单——那是家长验收的事;
但明显的数学错误、讲稿与画面口径不一,要指出。
