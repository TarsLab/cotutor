# 排首页

你在一个 cotutor workspace 的根目录(有 cotutor.json)。

孩子端打开就是首页:

- 老师的头像叠在一起,一次只展开一位老师的卡,卡上几个按钮。孩子点哪个,就带着哪个意思进那位老师。
- 一进来展开的是草稿里第一张老师卡的那位。最想让孩子先做的,写在最前面。
- 还有几张给孩子看的卡:一段字、几个字的田字格、一张图、一段点读。

首页由你和家长商量,**家长批准后发布**。孩子只看得到发布的那份。

## 铁律

- **发布要家长在这次对话里明说**(「发吧」「可以发布」)。草稿随便改;cotutor home publish 只在明说之后跑。
- 不写 vault。总结要留下来,走记账(第二步),由应用落进日记。
- 不改 conversations/、ledger/、cotutor.json、老师文件。
- home/published.json 与 home/history/ 是机器件,不手改。
- 孩子看得到的字(按钮、卡)不评判:不写对错、分数、名次、「真棒」「聪明」「最…」。
- .claude/agents/ 里的老师是由 cotutor 读正文传给 Qwen 的。不要当子代理派,也不要替老师回答孩子。

## 一、看今天

1. `cotutor home show`:现在发布的是哪份、每个按钮被点了几次。先知道上次推荐的,孩子选了什么。
2. 有脸的老师逐位读 conversations/<老师>/<今天>.json。有脸的老师 = cotutor.json 里键以 -tutor 结尾、enabled、不 hidden 的。要看的:
   - 话题(thread)。
   - 孩子的话(from: kid)。带 via、且 button 是数字的那条,是按钮上的字,不是孩子说的。
   - 每轮的 kidText 与 section.cards。
   - parentText:老师写给家长的。
   - remembered。
3. 细看一轮,用 `cotutor show <老师> <job>`。卡的 id(`<job>/<n>`)在「卡」那一行。
4. 孩子在卡上做的:conversations/<老师>/<日期>.<job>.cards/<n>.json。

总结在对话里说,不落文件。每位老师两三行:学了什么、停在哪、哪里卡住。引孩子的原话,或卡上做的。

## 二、记账

要留下来的,走记账:

1. 家长给值得记的话题打星:`cotutor rate <老师> <话题> <1-5>`。到 vault.keepScore 的,摘要才进日记。
2. 再跑 `cotutor bookkeep <老师>`。

- 记账每个话题起老师一轮;记完,每位有记忆的老师再整理一轮记忆,结果直接落进记忆文件。**花钱,先问。**
- 家长说不记,就跳过。
- 记完读当天日记核对一眼。日记在哪,见 cotutor-vault 技能。

## 三、商量下次

先在对话里列提案,不写文件。

材料:

- 今天停在哪。
- 日记最近的「- 观察:」。
- 本周计划里各位老师那段、课程表。
- 这科这学期的入口文件与教材:下一课是什么。
- 上次首页被点了什么。

### 老师卡

每位老师一张。不写的,应用会补一张只有「新话题」的。

- 按钮最多 4 个。「新话题」应用自己加,不写。
- 孩子看的字最多 16 个,孩子的口吻:「我要预习小蝌蚪找妈妈」「接着写看图写话」「再练两道退位减法」。
- 每个按钮下一行「讲法:」,写给老师:从哪开始、重点是什么、讲到哪收。孩子看不到。
- 「接着」要指到那一天的那个话题:日期 + 话题 id。老师会拿到那个话题最后一节的讲稿与卡。今天的话题,就是接着聊。
- 「小课堂」要指到 `bundles/` 里一份课包,或 `lectures/` 里一份视频的 id。孩子先从头看完这一课,才能问老师。
- 看完怎么聊,在这位老师的 `agents/<老师>/activities/小课堂.md`;没有这份,小课堂按钮不出(首页检查报)。
- 小课堂的讲法写孩子在这一课常卡在哪,别写课里已经讲过的。
- 「activity」是老师的一种做法,写在 `agents/<老师>/activities/<名>.md`(如语文老师的「你说我画」)。`cotutor activity check <老师>` 列出这位老师有哪些、每个要家长填什么。
- 看图说话、你说我画都是语文老师的 activity:`activity 看图说话`、`activity 你说我画`。孩子在新话题里拍看图说话,老师不走那套;要他照那套说,就摆按钮。
- 小课堂看完要接着照某个 activity 聊(如看图说话的课),在小课堂按钮下面挂一行 `activity: 看图说话`。
- activity 按钮写 `activity <名> [孩子看到的字]`,下面一行一个参数(`词: 播种、羞愧`),照那个文件「## 家长填的」填;同一个 activity 填不同的参数可以是两个按钮(你说我画、我来出题)。
- 家长想改 activity 本身怎么带,不在这里改,用 cotutor-tune。

### 老师想要的小课堂

老师讲到要画出来才讲得清的题,会在给家长的尾巴里写一段 `## 想要小课堂`:`题面:` 和 `讲法:`。

- 家长问「老师想要哪些小课堂」,在 `conversations/<老师>/<日期>.json` 里找 `parentText` 带「## 想要小课堂」的消息,从近往远列。
- 照题面和讲法做一堂课包小课堂(下一节),挂到那位老师的卡上。

### 课包小课堂

- drawtell 用 `.cotutor/drawtell`,和服务端烤画面是同一版;没有它才用全局的 `drawtell`。
- 课包用 drawtell 做:场景怎么写看 drawtell-scene 技能,怎么讲看 drawtell-teaching。做好 build、dub,把整个课包目录拷进 `bundles/<id>/`。
- 画面上孩子可能画到的东西,在场景里起名字:几笔合起来是一样东西写 `groups`,单独一笔写 `label`。写法见 drawtell-scene。
- 名字用讲稿里的说法,如「散的 3 根小棒」。
<!-- 为什么:孩子在它上面画了,老师拿到的是这个名字;不起名字只能说「第 1 步画的 3 条线」。《小课堂设计.md》拍板 28 -->
- 起了名字要重新 build,再拷一次。配音不用重配。
- 拷之前烤一下画面:`.cotutor/drawtell bake <id>`(跑过 snap 就已经烤了)。烤过的课包,孩子端不用现画,iPad 上顺;首页检查会提醒没烤的。
- 改了画面要重烤;只改讲稿、重配音不用。

### 视频小课堂

家长要放一段现成的视频当小课堂,在 `lectures/<id>/` 放两个文件:

- `video.mp4`:声音烧在视频里。
- `lecture.md`:第一行 `# 标题`,下面一行一句「分:秒 原话」,是这一句在视频里的起点和说的话。
- 原话照视频里说的抄,老师靠它知道课里讲了什么。
- 句子按时间排,第一句从 `0:00` 起。
- 可以在开头写 frontmatter `subject: 数学`,首页检查拿它对老师的科目。
- id 用小写字母、数字、连字符,如 `2026-10-06-pingjunfen`。

```markdown
---
subject: 数学
---
# 平均分:一个一个轮着分

0:00 12 块饼干分给 3 个小朋友,怎么分才公平?
0:05 一个一个轮着分:你一块、我一块、他一块。
0:11 分完了,每人 4 块,一样多。这就是平均分。
```

写好挂上首页按钮,`cotutor home check` 会说哪里不对。
- 没什么要推荐的老师,不写按钮。

### 其余的卡

按需,一两张就够。写在哪,孩子就在哪看到:

- 写在某张老师卡后面:只在那位老师展开时看到。跟这位老师的事有关的,写在他后面。
- 写在所有老师卡前面:谁展开都看得到。只放今晚先看一眼的那一句。
- 听写卡写了老师(`dictation chinese-tutor`),就归那位老师,不看写在哪。

- 要孩子今晚先看一眼的一句话:`text`。
- 要再写一遍的字:`tianzige`。
- 一张图:`image`。
- 一段要读的:`read`。

每条提案带一句「为什么」。家长改、删、加,直到点头。

## 四、写草稿、检查、预览

1. 家长点头后,写 home/draft.md,整份覆盖。
   - 先读已发布那份的原文当底稿:home/published.json 里 `source` 指的那个文件。家长可能在家长端改过首页(加了开场按钮、设了这周的词、调了老师的先后),那些都在原文里,不在 draft.md 里。家长没说要删的,照留。
   - 按钮下面的 `留到: <日期>` 是家长定的留多久,过了的按钮可以去掉。
   - 写法见 references/首页语法.md,老师卡的细则在 references/tutor.md。
   - 最后写「## 为什么这么排」,把第三步每条的「为什么」放进去。这段给家长,孩子看不到。
2. `cotutor home check`。「要改」的改到没有;「提醒」的跟家长说一声。
3. 想先看样子:`cotutor home check` 列出孩子会看到的每张卡、每位老师的按钮与讲法;要看真页面,发布后在孩子端首页看,不满意改草稿再发(每次发布留一份历史,`--from` 能回去)。
4. 家长要改就改草稿,再 check。

## 五、发布

家长明说之后:`cotutor home publish`。

- 它再检查一遍、留历史,打印发布的 id。
- 孩子端刷新就是新首页,不用重起服务。
- 发完告诉家长:发了哪几张卡、哪几条提醒还在。

回到以前的某份:`cotutor home publish --from home/history/<id>.md`,同样先问。

## 报告怎么写

1. 总结先行:每位老师两三行。
2. 再是下次的提案:按卡列,带为什么。
3. 最后是做了什么:记没记账、花了多少、草稿写没写、check 结果、发没发布。
