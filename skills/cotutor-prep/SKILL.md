# 备课:写课文件

你在一个 cotutor workspace 的根目录(有 cotutor.json)。

一节课 = 一份课文件 lessons/<课名>.md:板书同一套语法(讲稿一行一句,围栏是卡),`---` 分节,排版写在围栏行上,末尾「## 讲法」写给老师。交给孩子后,孩子首页上多一个按钮,按下去看到、听到的就是这几节,原样、不花钱;他答了第一句,老师(新会话)拿着课文件和讲法接着讲。

写法全在 references/课文件语法.md,先读它。命令在 references/命令.md。

## 铁律

- **写文件要家长点头**,交给孩子要家长在这次对话里明说(「交吧」「给他」)。cotutor lesson hand 只在明说之后跑。
- **不写 vault**,不改 conversations/、home/、cotutor.json、老师文件。要记的东西走记账。
- 卡上、讲稿里**不评判**:不写对错、分数、「真棒」「聪明」。对错由老师口头说。
- 答案只写在卡的语法里(choice 的 `[x]`、fill 的 `= 答案`),讲稿里不说答案。
- 卡上是名词(定义、公式、题),讲稿是动词(说给孩子听的话);一张卡至少能指着讲三句;一节 3–5 张卡、6–12 句;末句问孩子。
- .claude/agents/ 里的老师是给 cotutor 起 claude -p 用的,不要当子代理派,也不要替老师回答孩子。

## 一、先看

1. 这科这学期的入口文件(vault 里 `cotutor: subject` 的那篇)、家长的档案:学到哪、哪些方法还没学别用、家长想怎么讲。找法见 cotutor-vault 技能。
2. 教材那一节(入口文件里链着)。
3. 日记最近的「- 观察:」、本周计划里这位老师的那几行。
4. 已有的课文件:`cotutor lesson list`;改一份旧的就先读它。

## 二、商量

在对话里说,不写文件:讲什么、分几节、每节几张卡讲什么、末句问什么、讲法是什么。每条带一句「为什么」(从入口文件、观察里来的)。家长改、删、加,直到点头。

## 三、写、检查、预览

1. 家长点头后写 lessons/<课名>.md(目录没有就建)。课名:中英文、数字、- 与 _,如 `分数-比大小`、`2026-09-28-小蝌蚪`。
2. `cotutor lesson check <课名>`。「要改」的改到没有;「提醒」的跟家长说一声。
3. 排版是写的一部分:写卡的时候就按 references/排版.md 排好(围栏行上的 same / tint= / look= / emoji=,讲稿里的 [词]),不另起一步。家长手写的文件没排版,可以你自己按规则改,或 `cotutor lesson post <课名> --write`(花钱,先问)。
4. 服务开着,请家长在 iPad 或电脑上开家长端 /parent:清单里这位老师块下面「课文件」一栏点进这份,整份铺开(卡、老师会说的话、要改的、讲法),文件一改几秒后自己跟上。
5. 家长要改就改文件,再 check。

## 四、交给孩子

家长明说之后:`cotutor lesson hand <课名> [--label <按钮字>]`。

- 按钮字 ≤ 16 个,孩子的口吻(「我们来切披萨」);不给就取第一句截 16 字。
- 它配音、建话题、往首页草稿追加一行「接着」再发布;首页别处有「要改」的这次发不出去,会列出来——去改 home/draft.md(cotutor-home 技能)再 `cotutor home publish`。
- 同一文件孩子没开口再交是覆盖;孩子开口后再交是新话题。
- 交完告诉家长:几节几张卡、首页按钮是什么、花了多少。

## 报告怎么写

1. 先说备了什么:几节、每节讲什么、末句问什么。
2. 再是为什么这么备(引入口文件、观察)。
3. 最后是做了什么:文件写没写、check 结果、post 花了多少、交没交。
