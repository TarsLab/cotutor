# 家长的 Obsidian 仓库怎么读、记账怎么回

## 这个仓库是什么,谁写谁读

家长在 Obsidian 里看和改的那个目录(下面叫 vault)是关于孩子的**长期记忆**;对话、板书、照片都在 workspace,不在这里。六种文件:

| 文件 | 里面是什么 | 谁写 | 你怎么读到 |
|---|---|---|---|
| 档案(孩子.md) | 「现在」callout(abstract 类型):学到哪、会用的说法、还没学别用;下面是家长观察、忌讳 | 家长 | callout 那几行每轮在上下文包 `profile:` 里;其余按需 Read |
| 课程表.md | 一周的时段表 | 家长 | 命中的时段在上下文包 `slot:` 里 |
| 日记/YYYY-MM-DD.md | 一天一篇,一个话题一段 | 应用追加(记账),家长随时手写 | `- 观察:` 行每轮在 `recent:` 里;别的 Grep / Read |
| 教材/<册>.md | 一册一篇,一单元一节,节下 `### 口径` 是家长怎么讲这一单元 | 家长(缺了应用建骨架) | 讲某单元前 Read 那一节 |
| 计划/YYYY-Www.md | 规划老师的周计划草稿,家长改成 confirmed 才算数 | 规划老师新建,家长改 | 本老师的行每轮在 `plan:` 里 |
| 参考/ | 家长自己的政策、分类、笔记 | 家长 | 只有教材口径或档案里 `[[链过去]]` 你才会读到 |

硬规则:**家长写的字是真相**。机器只新建或追加,从不改、不删;你连新建和追加都不做——记账时回一段文本,应用替你落盘(唯一例外是规划老师新建计划文件)。

## 路径在哪

上下文包里有一段 `vault:`:`root` 是 vault 的绝对路径(常在 workspace 外面,可能含空格),`diary` / `textbooks` / `profile` / `plans` / `reference` / `timetable` 相对 root(在 root 外面就是绝对路径)。拼成 `<root>/<diary>/` 交给 Read / Grep;别猜缺省名、别去读 cotutor.json。

## 每轮不用工具的那部分

上下文包的 `profile:`(档案「现在」)、`plan:`(本周计划里你的行)、`recent:`(最近 14 天日记里本学科的「- 观察:」行)已经是从 vault 机械抽的。**问答模式到此为止**,一句话答完,不读文件。

## 讲解与任务模式才读:读什么、怎么读

| 想… | 做什么 |
|---|---|
| 讲某一单元之前 | Read `教材/<册>.md` 里那一节(`## N 单元名` + `### 口径`);口径里的 `[[链接]]` 跟一跳(多半到 `参考/`),就一跳 |
| 这单元以前讲过什么、怎么讲的 | Grep `[[<册>#<节>` 在 `日记/`,看命中那几段的摘要与 `骨架:` 行 |
| 孩子最近问过什么 | Grep `孩子问` 加 `-A3` 在 `日记/` |
| 做周计划(规划老师) | Read 上两周日记全文、档案、课程表、上周的计划文件 |

教材目录的单元标题就是知识点的身份:引用一律写 `[[人教数学一下#4 100以内数的认识]]`,Obsidian 的反链面板天然列出讲过这一单元的所有日记。代码不认题型、不认标签,家长想按题型整理是她在 `参考/` 里自己做、在口径里链过去的事。

## 日记长什么样(认这些行头)

```markdown
## 数学 · 100 以内数的认识

> [!question] 孩子问
> 88 后面是 89 还是 98
> 为什么要凑十

先用小棒摆 88,再一根一根往上数到 100;孩子在 89→90 处卡住,是十位进位没建立。★ → [[人教数学一下#4 100以内数的认识]] 课包 2026-09-14-shubang
骨架:摆 88 → 数到 89 → 问再加一根是几捆 → 换捆 → 90
- 观察:数到整十要停一下想,进位还不熟
- 家长:晚上用扑克牌又练了一遍
```

H2 = `学科 · 话题名`。「孩子问」callout 总在;摘要行(末尾 ★ 与 `→ [[册#节]]`、课包 id)和 `骨架:` 只有家长给这个话题打分够时才有;`- 观察:` 0–3 条是上下文包 recent 的来源;`- 家长:` 与别的行是家长手写的。打分不够的话题只有孩子问。

## 记账任务:回什么

触发:上下文包 `from: system`,消息说「给刚才这个话题记账(话题 xxx,家长打了 n 星)」,这轮 resume 的是那个话题的会话,你记得聊了什么。

- 只回一段「## 记账」,别的一个字都不写,**不用工具**;字段、消息原样、解析器认什么、应用替你补什么,都在本目录 `references/记账.md`。
- summary / steps 只在消息里要了才写(打分够);没要的写了应用也丢。
- textbook 从消息里列的教材目录挑一条**原样抄**;都不是就不写这行,别自己编一个目录里没有的。
- 话题里有作业照片:摘要把你认出的册子 / 页 / 题号 / 题面写成文字,**不写路径**——日记不存图。
- observations 写不写,过**写入前三问**:一年后家长还想翻到它吗;你或别的老师下次讲同类东西需要它吗;能不能被机械取出来(固定行头)。过不了的别写。孩子的问题永远值得记,但那是应用抄的,不用你写。

## 谁能写 vault(封闭清单)

| 写什么 | 怎么写 | 谁 |
|---|---|---|
| 日记 | 只追加,文件不在就建 | 应用,按你的「## 记账」段 |
| 计划 | 只新建 `计划/<YYYY-Www>.md`,已存在不碰 | 规划老师(唯一直接写文件的老师) |
| 教材骨架 | 只在那一册缺失时建 | 应用 init |

永不:写 `#标签`、写图片或照片路径、改家长写过的字、删文件、写档案 / 课程表 / 参考。

## 常见错法

- 问答里去 Grep 日记:白花一轮,问答只用上下文包。
- 把 `captures/…` 路径写进记账:日记里只留你认出的文字。
- textbook 自己编一个「册#节」:教材目录里没有的链不到任何东西。
- 打分不够还写 summary:应用会丢,别白写。
- 自己去 vault 里写文件或建目录:那是家长的地盘,机器写它只有上面三处。
